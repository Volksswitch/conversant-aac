# CR-004: Choosing a 'say it again / rephrase / expand' repair card crashes on an undefined variable

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** high
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed; reproducer: reproduced)
- **Location:** `app/js/app.js:2249`
- **Also affects:** `app/js/app.js:2179 handleRepairOfSelf`; `app/js/app.js:8475 unhandledrejection -> reportStartupFailure`; `app/js/app.js:2249 (merged duplicate: Repairing your own turn throws a ReferenceError: undeclared `source` in handleRepairOfSelf)`; `app/js/app.js:2249 (merged duplicate: Repair-of-self references an undefined variable `source`, so every 'repeat/rephrase/expand what I said' throws after speaking)`; `app/js/app.js:2249 (merged duplicate: Choosing any repair card after the partner says "What?" crashes: `source` is undefined in handleRepairOfSelf)`
- **Source:** app-b-01, llm-engine-01, x-contracts-01, live-runtime-01

**What a user notices.** When the other person says "What?" and the user picks one of the cards to repeat, reword or expand what they said, the app speaks it but then stops partway: the repeated line never appears in the conversation, it is not saved, the microphone does not come back on, and the transcript turns red as if something failed.

**What is wrong.** handleRepairOfSelf ends with `storage.logUserResponse({ ..., allOptions: [], source })`. There is no `source` variable in scope: handleRepairOfSelf takes only `response`, and app.js declares no module-level `source` (grep shows the only other `source` identifiers are parameters of speakAsUserTurn/take/dropGoalsFrom and object keys). Reading an undeclared identifier throws ReferenceError. The throw happens after the user's restatement has been spoken and pushed to conversationHistory, but before ui.renderConversation, ui.setLiveTranscript('') and resumeOrIdle() run. The promise from handleResponseSelected -> handleRepairOfSelf is not caught by the card click handler, so it reaches window 'unhandledrejection' -> reportStartupFailure, which logs 'startup:promise' (tripping the red wash). Introduced in b3219e6 (Aug 7 2026) when the source field was added; the respeak/rephrase/expand ops all reach this line (only op 'retry' returns earlier).

**How it happens.** Start a conversation, say something with a card, have the partner say "What?" (classified is_repair_initiator) so the repair-of-self palette appears. Tap 'Repeat what I said' (or the rephrase/expand card). The sentence is spoken, then: ReferenceError: source is not defined; the pane does not show the restated turn; the saved conversation has the partner's 'What?' finalized but no user turn; the Listen button stays off even with auto-resume on; the repair cards stay on screen.

**Suggested fix.** Replace the bare `source` with an explicit value. These are the user's own earlier words or a rewording of them produced by the app, so use `source: 'control'` (the same value logSpokenUserTurn uses at line 3214 for 'Repeat what I said'). If finding 'repair-of-self bypasses commitExchange' is fixed at the same time by routing this path through commitExchange, the explicit object literal goes away and commitExchange's own `source` computation applies.

**How to verify the fix.** Manual: reproduce the scenario above in Practice Mode (scenario partner prompted to say "What?") or with a stubbed llm; confirm no ReferenceError in the console, the restated turn appears in the pane, the conversation file gets a user turn with source 'control', and listening resumes when auto-resume is on. Add a source-level guard in tests/placeholders.test.mjs (where other app.js source guards live): strip comments from handleRepairOfSelf's body and assert it contains no bare `source }` / `, source,` shorthand without a value.

**Do not break.** Keep the 'retry' op behavior unchanged (it deliberately returns early). Do not change what the log records for other paths.

<details><summary>Merged duplicate llm-engine-01: Repairing your own turn throws a ReferenceError: undeclared `source` in handleRepairOfSelf</summary>

handleRepairOfSelf (the respeak / rephrase / expand path) ends with `storage.logUserResponse({ ..., source })` using object shorthand for an identifier `source` that is not declared anywhere in scope (no module-level variable, no parameter, no import, no element with id="source"). Reading an undeclared identifier throws ReferenceError in an ES module. The throw happens after the user's words were spoken and after `conversationHistory.push`, so: the turn is never written to the conversation file, `ui.renderConversation` and `ui.setLiveTranscript('')` never run, and `resumeOrIdle()` never runs (mic not reopened even with auto-resume on). The rejection escapes the async click handler and lands in the global unhandledrejection handler, which logs it as 'startup:promise' (red transcript wash) but recovers nothing. Introduced in commit b3219e6 (Aug 7 2026) when `source` was added to every logUserResponse call; the other two call sites pass a literal ('control') or have a parameter named source, this one does not. Only the 'retry' card avoids it because it returns early.

Fix as proposed by that reviewer: In handleRepairOfSelf replace the shorthand with an explicit value: `storage.logUserResponse({ selectedText: text, spokenText: spokenFormFor(text), ttsUsed: tts.lastVoiceUsed(), selectedIndex: -1, allOptions: [], source: 'control' });`. Use 'control' (not 'composed'): rephrase/expand text is the model's wording and must never be harvested as a voice exemplar (voice-harvest.collectExemplars treats 'composed' as the user's own words). If a distinct value is preferred, use 'repair' and confirm voice-harvest/usage-summary treat unknown sources as non-exemplars.

</details>
