# CR-012: Words typed during a 'Don't save this conversation' conversation are stored permanently and resurface as suggestions; there is no way to clear them

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** high
- **Category:** privacy
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/prediction.js:55`
- **Also affects:** `app/js/keyboard.js:370`; `app/js/keyboard.js:476`; `app/js/app.js:330`; `app/js/worldview-ui.js:440`; `app/js/keyboard.js:370 (merged duplicate: "Don't save this conversation" still records the words the user types into the word-prediction list)`
- **Source:** keyboard-05, x-security-05

**What a user notices.** A private conversation is promised to leave nothing behind, but every word typed on the app's keyboard during it is kept on the device and can later pop up, in bold, as a suggested word while someone else is watching. Nothing in the app can erase that list, not even About Me's Restart.

**What is wrong.** keyboard.js learns every word of 2+ letters committed by a separator or by accepting the ghost (learnCurrentWord / acceptGhost -> prediction.learn), regardless of the conversation's privacy state. prediction.learn writes the whole map to localStorage 'aac_word_freq' with no gate. Learned words outrank the dictionary in predict(), so a private term (a diagnosis, a name) becomes the top completion for its prefix in later, saved conversations. No code anywhere reads or removes aac_word_freq besides prediction.js (grep), so About Me Restart and every reset leave it intact. The manuals say a private conversation 'simply leaves nothing behind' and the Security and Privacy document says 'nothing either of you says is written down'.

**Evidence.**

```
prediction.js:55-61 `export function learn(word) { const w = ...; if (w.length < 2) return; const uf = loadUserFreq(); uf[w] = (uf[w] || 0) + 1; saveUserFreq(); }` (no privacy gate); keyboard.js:370-373 `function learnCurrentWord() { const w = currentWordPrefix(); if (w) prediction.learn(w); }`; app.js:330-332 `function applyPrivacyState() { storage.setConversationSaving(!conversationPrivate); ui.setPrivacyState(conversationPrivate); }` (single choke point, does not touch prediction). User Manual 4.5: 'The conversation works normally on screen; it simply leaves nothing behind.'
```

**How it happens.** Tap 'Don't save this conversation', open 'In my own words', type 'my chemotherapy starts Monday' and Speak. End the conversation. Later, in an ordinary conversation, type 'ch' - the ghost offers 'chemotherapy'.

> **Verifier correction to the trigger:** Only happens in on-screen keyboard mode, where words reach prediction.learn() through the app keyboard; a user typing on a physical keyboard learns nothing. The words are kept as single entries (for example 'chemotherapy'), not as the sentence.

**Suggested fix.** In prediction.js add `let learning = true; export function setLearning(on) { learning = !!on; }` and make learn() return immediately when `!learning`. In app.js import prediction ('./prediction.js') and call `prediction.setLearning(!conversationPrivate);` inside applyPrivacyState() (it already runs at every privacy change and conversation reset). Optionally add `export function clearLearned()` (sets userFreq = {} and removes FREQ_KEY) and call it from worldview-ui onRestart, mentioning it in the Restart confirmation text.

**How to verify the fix.** Add to tests/prediction.test.mjs: `prediction.setLearning(false); prediction.learn('zebrafish'); assert.ok(!prediction.predict('zeb',3).includes('zebrafish'))`, then setLearning(true) and confirm learning resumes. Manual: the failure scenario no longer suggests the private word.

**Do not break.** Learning must keep working in ordinary conversations and in About Me. Do not route the gate through keyboard.js field checks only - the composer is used for both private and saved conversations, so the state must come from the privacy toggle.

**Design reference.** CLAUDE.md SEC-2 ('Don't save this conversation' must cover every persistence path); User Manual section 4.5; 'Conversant AAC Your Security and Privacy.docx'

**Verification notes.** prediction.learn() writes every committed word of two or more letters to localStorage 'aac_word_freq' with no gate. keyboard.js calls it from learnCurrentWord() on every separator and from acceptGhost(). Nothing outside prediction.js reads or clears that key: grep finds no reference in app.js, worldview-ui.js or storage.js, so About Me Restart, the resets and applyPrivacyState() leave it intact. predict() ranks learned words ahead of the dictionary, so a privately typed word becomes the visible bold ghost for its prefix in later conversations. This breaks the stated privacy promise (the manuals' 'leaves nothing behind', and CLAUDE.md's 'a technical error is still noted and never what was being said'), so it rates high under the rubric. The trigger is narrower than 'every word typed': learning runs only through the app's on-screen keyboard (handleKey), never with a physical keyboard, and stores single words, not sentences.

<details><summary>Merged duplicate x-security-05: "Don't save this conversation" still records the words the user types into the word-prediction list</summary>

With the on-screen keyboard, every completed word in the composer (space, Enter, punctuation, or accepting the ghost completion) calls prediction.learn(), which increments a per-word count in localStorage key 'aac_word_freq'. Nothing checks storage.isConversationSaving(). Those learned words are then ranked first by predict() and shown as the inline ghost completion in any later typing, so private vocabulary (a diagnosis, a name, a sensitive topic) persists indefinitely after a conversation the user explicitly asked not to be recorded. The User Manual (section 4.5) says that while the button is on neither the partner's nor the user's words are written down, with technical-error notes as the only exception.

Fix as proposed by that reviewer: In keyboard.js, skip learning while the current conversation is private. keyboard.js should not import storage's conversation state directly if avoidable; simplest: add an exported setter in prediction.js, `let learning = true; export function setLearning(on) { learning = !!on; }`, and make learn() return early when `!learning`. In app.js applyPrivacyState(), call `prediction.setLearning(!conversationPrivate)` (app.js already sets storage.setConversationSaving there; import prediction if not already imported). Apply only to the composer - learning in Settings fields can continue, or gate all learning; either is acceptable.


Verifier correction: Also gate the learning in the review word editor (#reviewWordInput) only if desired; the essential part is gating learn() while the conversation is private. Note the physical-keyboard path, if it also calls learn, needs the same gate - putting the check inside prediction.learn() (via setLearning) covers every caller at once, which is better than gating in keyboard.js.
