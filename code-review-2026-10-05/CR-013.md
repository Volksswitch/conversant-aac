# CR-013: Weekly report automatically sends the names of the people the user talks to and the places they go, contradicting the 'counts only' disclosure

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** high
- **Category:** privacy
- **Verdict:** confirmed (skeptic: confirmed; reproducer: reproduced)
- **Location:** `app/js/weekly-send.js:274`
- **Also affects:** `app/js/usage-summary.js:430`; `app/js/usage-summary.js:285`; `app/js/usage-summary.js:290`; `app/js/weekly-send.js:119`; `scripts/weekly-report-endpoint.gs:174`; `app/js/weekly-send.js:274 (merged duplicate: Automatic weekly report sends the names of the people the user talks to and the places they go)`; `app/js/weekly-send.js:274 (merged duplicate: The automatic weekly report sends communication partners' and places' names, contradicting 'counts and timings only')`
- **Source:** reporting-platform-02, x-security-01, x-contracts-05

**What a user notices.** Every week the app quietly sends the names of the user's partners (for example 'Dr. Aldrich', 'Ms. Whitaker') and places (for example 'The rehab clinic') to the project's spreadsheet, while the app and the privacy documents tell the user the report contains only counts and the tester's own name.

**What is wrong.** gatherPayload sends `usage = summarize(...)` almost verbatim (only `weeks` is removed). summarize() builds `out.partners` as rows carrying the partner LABEL, and `out.hearingByPartner` / `out.hearingByPlace` are objects KEYED by partner label and place label. These go into the payload's `usage` field, which the endpoint stores whole in the 'raw' column. The in-app disclosure (PAYLOAD_FIELDS.usage: 'Counts and timings ...') and 'Your Security and Privacy' §7 ('What it does carry that is personal. A name assigned to you at setup') say the only personal item is the tester's name. These partners are third parties who never agreed to anything - the reason CLAUDE.md gives for evaluate-beta never printing them - and the problem-report disclosure explicitly warns about names precisely because they need consent, but the automatic weekly path sends them without any. Measured on the bundled demo data: partners labels Mom, Devon, Dr. Aldrich, Ms. Whitaker...; hearingByPlace keys 'The rehab clinic', 'West High School', ... all present in the summary object that is sent.

**Evidence.**

```
app/js/weekly-send.js:274-278: `usage = summarize(await storage.listConversationLogs()); ... if (usage) delete usage.weeks;` (nothing else removed)
app/js/usage-summary.js:430-431: `out.partners = [...partnerRows.entries()].map(([label, r]) => ({ label, conversations: ..., weeks: ..., turns: r.turns }))`
app/js/usage-summary.js:285-293: `if (!out.hearingByPartner[who]) out.hearingByPartner[who] = hearingRow(); ... if (!out.hearingByPlace[where]) out.hearingByPlace[where] = hearingRow();`
app/js/weekly-send.js:119: `usage: 'Counts and timings: how many conversations, how often a suggestion fitted, how long people waited',`
scripts/weekly-report-endpoint.gs:174: `_raw(p)` stores the whole payload.
```

**How it happens.** Tester adds 'Dr. Aldrich' in About Me > People and 'The rehab clinic' in My Places, taps them on the Express Panel during a conversation. At the next weekly send the raw column in the Sheet contains `"partners":[{"label":"Dr. Aldrich",...}]` and `"hearingByPlace":{"The rehab clinic":{...}}`.

**Suggested fix.** Add and export a pure function in weekly-send.js, e.g. `export function redactUsage(u)`, and call it in gatherPayload right after `delete usage.weeks`: replace `u.partners` with the same rows but `label` set to an ordinal (`'person ' + (i+1)`) or drop the label field entirely (keep conversations/weeks/turns so `(usage.partners || []).length` and returningPartners still work at the endpoint); replace `u.hearingByPartner` and `u.hearingByPlace` with arrays of their row values (no keys) or ordinal keys ('person 1', 'place 1'). Do not change summarize() itself - the on-device Troubleshooting summary may keep showing names to the user.

Either sort by a stable value or accept the change. Two ways forward: (a) redact as proposed, keeping partners.length, returningPartners and the per-row counts; or (b) if Ken wants names in the Sheet, correct PAYLOAD_FIELDS.usage, Security and Privacy §7 and the Partner Privacy weekly row instead. This is Ken's decision; one of the two must happen. Note that hearingByPlace can fall back to place.id as its key when no label is present.

Also extend the existing PAYLOAD_FIELDS drift test is not needed.

**Do not break.** Keep `partners.length`, `returningPartners` and the per-row counts, which the endpoint's 'people named' and 'returning people' columns and evaluate-beta rely on. Do not touch the problem-report path, which discloses names explicitly.

<details><summary>Merged duplicate x-security-01: Automatic weekly report sends the names of the people the user talks to and the places they go</summary>

gatherPayload() puts the whole summarize() result into the automatic weekly payload, deleting only `weeks`. summarize() builds three structures keyed or labelled by user-entered names: `usage.partners` is an array of `{label, conversations, weeks, turns}` where `label` is the partner's name from the turn's partner stamp; `usage.hearingByPartner` is an object keyed by partner name; `usage.hearingByPlace` is keyed by place name. The endpoint stores the entire payload verbatim in the `raw` column (_raw(p)), so these third-party names land in the Google Sheet on every weekly report. This includes people the user marked Private. The in-app disclosure (PAYLOAD_FIELDS.usage: 'Counts and timings ...'), describeReport(), the Beta Test Plan and 'Your Security and Privacy' all say the only personal item is the assigned tester name. The manual problem report discloses names explicitly (REPORT_DISCLOSURE), which shows the names were meant to be disclosed wherever they go - the automatic path was missed.

Fix as proposed by that reviewer: In weekly-send.js add an exported pure function `redactUsage(usage)` that returns a copy with: `partners` replaced by rows without `label` (e.g. `usage.partners.map(({conversations, weeks, turns}) => ({conversations, weeks, turns}))`, which keeps `.length` for the endpoint's 'people named' column and keeps returningPartners valid), and `hearingByPartner` / `hearingByPlace` replaced by arrays of their values (`Object.values(...)`) or by anonymous keys ('person 1', 'place 1'). Call it in gatherPayload right after `delete usage.weeks`: `usage = redactUsage(usage)`. Do NOT change summarize() itself, because the Troubleshooting tab and the manual problem report show names locally and that is disclosed. Leave hearingByRecognizer (service names) as is.


Verifier correction: The suggested redactUsage() is right. Also: (1) the names already sent sit in the Sheet's raw column of every existing reports row, so Ken should clear or scrub those cells after the fix ships; (2) add a test that runs assemblePayload on a summarize() result built from labelled fixtures and asserts the serialized payload contains neither label, so a future breakdown keyed by a name is caught.

<details><summary>Merged duplicate x-contracts-05: The automatic weekly report sends communication partners' and places' names, contradicting 'counts and timings only'</summary>

gatherPayload puts the full usage summary into the payload (only `weeks` is removed). summarize() includes `partners: [{ label, conversations, weeks, turns }]` where label is the partner stamp's display name (e.g. 'Mom', 'Dr. Patel'), plus `hearingByPartner` and `hearingByPlace` objects keyed by partner and place names. No redaction step exists in weekly-send.js, and the Apps Script stores the entire payload in the 'raw' column. The person named never consented and the payload is sent automatically by default. PAYLOAD_FIELDS.usage and the 'Your Security and Privacy' / Beta Test Plan text promise counts and timings; CLAUDE.md's evaluate-beta note ('counts of them are printed and names never are') shows names were never meant to be used, yet they are transmitted.

Fix as proposed by that reviewer: In weekly-send.js gatherPayload, after `delete usage.weeks`, anonymize: `usage.partners = (usage.partners || []).map(({ conversations, weeks, turns }) => ({ conversations, weeks, turns }));` and replace `usage.hearingByPartner` / `usage.hearingByPlace` with arrays of their values (no keys), e.g. `usage.hearingByPartner = Object.values(usage.hearingByPartner || {});` (same for hearingByPlace). Keep returningPartners and counts. Leave the local Troubleshooting summary (which reads summarize directly) unchanged.


Verifier correction: Also check the problem-report path is out of scope (it is user-reviewed and deliberate). Put the anonymization in an exported pure function used by gatherPayload so the test exercises the real code, and keep influencers.distinctPartners and returningPartners as computed before stripping.
