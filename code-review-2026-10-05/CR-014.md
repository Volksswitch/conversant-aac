# CR-014: Keyboard focus is invisible on the Command Bar, response cards and New 4 in the dark schemes, and very faint in the light ones

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:1761`
- **Also affects:** `app/css/styles.css:1770`; `app/css/styles.css:2099`; `app/css/styles.css:2842`; `app/css/styles.css:3036`; `app/css/styles.css:720`; `app/css/styles.css:826`; `app/css/styles.css:1078`; `app/css/styles.css:1761 (merged duplicate: Command Bar, New-N and response-card keyboard focus is effectively invisible (outline removed, faint shadow only))`
- **Source:** x-a11y-03, live-visual-02

**What a user notices.** A person moving through the conversation screen with a keyboard or switch cannot see which button is selected. In the Dark, High-contrast dark and Yellow-on-black schemes - the ones chosen by people with low vision - there is no visible marker at all.

**What is wrong.** The focus style for .cmd-btn, .cmd-btn-end, .response-card, .regenerate-btn and .persist-btn removes the outline and substitutes only `box-shadow: 0 2px 10px var(--shadow)`. --shadow is rgba(0,0,0,0.16) in Default (a faint blur barely distinguishable on white), and rgba(0,0,0,0.55-0.7) in the dark schemes, where the surfaces are #212629 or pure #000000 - a black shadow on a black surface is invisible. This falls short of a perceivable focus indicator (WCAG 2.4.7) for exactly the low-vision users the high-contrast schemes exist for. The 'no fill' decision (Ken, Aug 20 2026) rules out a fill, not a visible ring. Practice cards (styles.css:1078) rely on a border-color change only.

**Evidence.**

```
styles.css:1761-1764 `.cmd-btn:focus-visible { box-shadow: 0 2px 10px var(--shadow); outline: none; }`
styles.css:2099-2102 `.response-card:focus-visible { box-shadow: 0 2px 10px var(--shadow); outline: none; }`
styles.css:2842-2845 `.regenerate-btn:focus-visible { box-shadow: 0 2px 10px var(--shadow); outline: none; }`
styles.css:720 (hc-dark) and 826 (yellow) `--shadow: rgba(0, 0, 0, 0.7);`
Measured: hc-dark and yellow schemes give --surface-raised #000000 and page background rgb(0,0,0), so the focus shadow is black on black.
```

**How it happens.** 1. Settings > Text & Color > Color scheme = 'Yellow on black' (or 'High contrast, dark'). 2. Close Settings, start a conversation, and press Tab repeatedly. 3. Focus moves through Listen ... Settings, New 4 and the response cards with no visible change on any of them.

**Suggested fix.** Replace `outline: none` in those five :focus-visible rules with a visible ring that is not a fill, e.g. `outline: 3px solid var(--focus-ring); outline-offset: 2px;` (keep the box-shadow if desired). Add a `--focus-ring` token to each scheme's palette block (Default/Bold: var(--link) or var(--info); dark schemes: a light value such as the scheme's --ink or the yellow scheme's accent) and include it in the contrast pairs checked by tests/theme.test.mjs at 3:1 against every surface. Do the same for `.practice-card:focus-visible` (styles.css:1078). An outline does not change layout, so no keyguard hole moves.

> **Verifier correction to the fix (takes precedence):** Leave .practice-card out of this fix, or treat it as optional, because its border-color change is already a visible indicator. The rest of the suggested fix (an outline ring from a per-scheme --focus-ring token, no fill) is sound.

**How to verify the fix.** Add a check to tests/theme.test.mjs that every scheme defines --focus-ring with >= 3:1 contrast against --surface-raised and the page background, and a check in tests/styles.test.mjs that no `:focus-visible` rule sets `outline: none` without also setting a non-shadow indicator. Manual: in each of the seven schemes, Tab across the Command Bar and response cards and confirm a ring is visible on each.

**Do not break.** Must not be a FILL on the Command Bar - a filled Command Bar button means 'this control is on' (Rule 6, comment at styles.css:1756-1760). Use outline (paint only) so geometry and keyguard holes are unchanged. Keep :focus-visible outside the @media (hover: hover) block (Rule 20).

**Design reference.** UI Layout Rule 6, Rule 20 (':focus-visible stays OUTSIDE this block, so keyboard users keep their focus styling'), Rule 23 (colour schemes)

**Verification notes.** I checked the five rules at styles.css:1761, 1770, 2099, 2842 and 3036. Each sets `outline: none` and adds only `box-shadow: 0 2px 10px var(--shadow)`. --shadow is rgba(0,0,0,0.16) in Default and 0.45 to 0.7 in the dark schemes (515, 617, 720, 826), so the cue is a black shadow on a dark or black surface. No later global focus rule overrides these. One part is overstated: `.practice-card` at 1078 does change its border color to the initiative blue, which is a visible indicator, so it is weaker evidence than the other five.

<details><summary>Merged duplicate live-visual-02: Command Bar, New-N and response-card keyboard focus is effectively invisible (outline removed, faint shadow only)</summary>

:focus-visible on the Command Bar buttons, the New-N button and the response cards sets outline:none and replaces it with a soft drop shadow (0 2px 10px var(--shadow)). In light mode the shadow is rgba(0,0,0,0.16) — barely visible; in the dark schemes --shadow is a black shadow on a black/near-black page, so the focused button looks identical to the others. This contradicts the recorded rule that :focus-visible must keep a visible focus style for keyboard users on every device. The Express Panel buttons (2507-2511) and Settings tabs do get a real 2-3px outline, so the conversation surface is inconsistent with itself.

Fix as proposed by that reviewer: Keep the no-fill decision (a fill means 'latched on') but add a paint-only outline drawn inside the box so geometry is unchanged, e.g. for .cmd-btn:focus-visible, .cmd-btn-end:focus-visible, .regenerate-btn:focus-visible, .response-card:focus-visible:
    outline: 3px solid var(--info);
    outline-offset: -5px;
Keep the existing box-shadow if desired. Use a themed token (var(--info) or var(--edge-strong)) so all seven schemes get a contrasting ring; check it reaches 3:1 against --surface-raised in every scheme.
