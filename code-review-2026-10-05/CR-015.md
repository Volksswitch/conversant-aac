# CR-015: Reduced-motion setting is ignored for the 'cards may change' stripe, the breathing cards and card transitions

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:2068`
- **Also affects:** `app/css/styles.css:2260`; `app/css/styles.css:2281`; `app/css/styles.css:2097`; `app/css/styles.css:4414`
- **Source:** x-a11y-01

**What a user notices.** A person who has told their device to reduce motion (common with vestibular problems, migraine or some visual impairments) still sees a stripe sliding back and forth and the suggestion cards pulsing every time the app is fetching new suggestions, which happens on most turns.

**What is wrong.** The @media (prefers-reduced-motion: reduce) block at styles.css:2068 is placed BEFORE the base rules it is meant to override. Media queries add no specificity, so for equal-specificity selectors the later rule wins. `.palette-refreshing::before` (media, line 2077) is overridden by the base `.palette-refreshing::before` at 2260 (which re-sets `animation: palette-refresh-sweep` and `width: 30%`); `.palette-refreshing .response-card:not(.response-card-empty)` (media, 2078) is overridden by the identical selector at 2281 (`animation: palette-refresh-breathe`); and `.response-card { transition: none }` (2070) is overridden by `.response-card { ... transition: box-shadow 0.12s, transform 0.05s }` at ~2097. Only `#listenBtn.listening` and `.palette-grid.palette-enter` work, because their base rules come earlier in the file. The About Me `.wv-card.wv-flash` animation (4414) has no reduced-motion rule at all.

**Evidence.**

```
styles.css:2068 `@media (prefers-reduced-motion: reduce) {` ... 2077 `.palette-refreshing::before { animation: none; width: 100%; opacity: 0.55; }` 2078-2081 `.palette-refreshing .response-card:not(.response-card-empty) { animation: none; opacity: 0.85; }`
styles.css:2260-2269 `.palette-refreshing::before { ... width: 30%; ... animation: palette-refresh-sweep 1.3s ease-in-out infinite;`
styles.css:2281-2283 `.palette-refreshing .response-card:not(.response-card-empty) { animation: palette-refresh-breathe 1.6s ease-in-out infinite alternate; }`
Measured in headless Chrome with prefers-reduced-motion: reduce emulated and #responseOptions given class palette-refreshing: ::before animationName = 'palette-refresh-sweep', width = 344px (30%, not 100%); a response card's animationName = 'palette-refresh-breathe'; transitionProperty = 'box-shadow, transform'.
```

**How it happens.** 1. Turn on 'Reduce motion' in Windows (Settings > Accessibility > Visual effects > Animation effects off) or iPadOS. 2. Start a conversation with an API key; let the partner speak and pause twice so a reprompt runs. 3. The slate stripe sweeps along the top of the response area and the cards pulse in opacity throughout the round trip, exactly as without the setting.

**Suggested fix.** Move the whole `@media (prefers-reduced-motion: reduce) { ... }` block (currently styles.css lines 2068-2082) to just after the `@keyframes palette-refresh-breathe` rule (~line 2288), or to the end of the stylesheet, so it comes after every base rule it overrides. Add inside it: `.wv-card.wv-flash { animation: none; }`. Keep the existing steady-state values (stripe full width at opacity 0.55, cards at 0.85) so the 'request in flight' information still reaches the user.

**How to verify the fix.** Add a test to tests/styles.test.mjs that parses styles.css and asserts that the reduced-motion block's start offset is greater than the offset of the last `.palette-refreshing::before` and `.palette-refreshing .response-card` base rules (or simply that every selector inside a prefers-reduced-motion block has no later same-selector rule outside a media block). Manually: in Chrome DevTools > Rendering > Emulate prefers-reduced-motion: reduce, add class palette-refreshing to #responseOptions and confirm getComputedStyle(el,'::before').animationName === 'none' and width spans the region.

**Do not break.** Opacity/position only - must not change any box (Rule 1, keyguard geometry). Keep the 'a request is out' cue visible in its steady form (the comment in the block explains why it must not be dropped). Do not move the block above the #listenBtn.listening rule's later overrides (it currently works; keep it after line 1811).

**Design reference.** CLAUDE.md 'WHEN THE RESPONSE CARDS CHANGE' (the provisional cue) and the comment at styles.css:2068-2081; UI Layout Rule 1

**Verification notes.** The reduced-motion block opens at styles.css:2068. The base rules it is meant to override come later in the file and have the same selectors: `.response-card` with its transition at 2097, `.palette-refreshing::before` with the sweep animation and 30% width at 2260, and `.palette-refreshing .response-card:not(.response-card-empty)` with the breathe animation at 2281. A media query adds no specificity, so the later base rules win. `.wv-card.wv-flash` (4414) has no reduced-motion rule anywhere; the only other reduced-motion block (3237) covers just the Settings help button.
