# CR-020: With 'In my own words' open, a goodbye or repair turn is drawn under the box and an older held set replaces it on Cancel

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1846`
- **Also affects:** `app/js/app.js:1760-1773 closing fast path (no composerOpen check)`; `app/js/app.js:2176 prefetchRepairOptions ui.showResponses (no composerOpen check)`; `app/js/app.js:2858 showHeldForComposer`; `app/js/app.js:1850 composerOpen hold branch`; `app/js/app.js:1846 (merged duplicate: Goodbye cards (and repair wordings) are drawn under the open In-my-own-words box)`
- **Source:** app-b-08, app-c-13

**What a user notices.** If the other person starts saying goodbye while the user is typing their own words, and the user then cancels the typing, the screen can show an older set of ordinary suggestions instead of the goodbye cards, so the user cannot easily say goodbye back.

**What is wrong.** generateOptions holds a new palette while the composer is open (heldForComposer), but only in the final else-branch. The PRE_CLOSING_CLOSING branch (line 1846) is checked first and calls renderStaticPalette directly, as does the windingDown fast path (1760-1773); neither checks composerOpen nor clears heldForComposer. So the goodbyes render under the composer, and if an earlier reprompt left a held set, handleCancelComposed -> showHeldForComposer() then shows that older AI set over the goodbyes, while the engine is in PRE_CLOSING_CLOSING. prefetchRepairOptions likewise calls ui.showResponses under an open composer, bypassing the hold (and showPalette's bookkeeping).

**Evidence.**

```
app/js/app.js:1846-1849 `if (snap.mode === engine.MODE.PRE_CLOSING_CLOSING) {\n            renderStaticPalette('closing', snap.palette, ...);\n        } else if (composerOpen) {`
app/js/app.js:1867 `heldForComposer = { palette: snap.palette, at: Date.now() };`
app/js/app.js:2858-2864 `function showHeldForComposer() { if (!heldForComposer) return false; ... showPalette(palette);`
app/js/app.js:2176 `ui.showResponses(snap.palette, handleResponseSelected);`
```

**How it happens.** User opens In my own words. Partner keeps talking; a reprompt lands and is held (set A). Partner says "Well, I should let you go." -> classified CLOSING -> goodbyes rendered under the composer, heldForComposer still = A. User taps Cancel -> showHeldForComposer shows set A (ordinary responses) and status 'Select a response'; the goodbye and 'Actually, before you go' cards are gone.

**Suggested fix.** In generateOptions, test composerOpen first: when composerOpen, hold whatever would have been rendered, including a static closing palette. Simplest: in the PRE_CLOSING_CLOSING branch and in the fast path, if composerOpen, set `heldForComposer = { palette: [...snap.palette, ...declineClosingCard()], at: Date.now(), kind: 'closing' }` and have showHeldForComposer call renderStaticPalette('closing', ...) when kind is 'closing' (pin the decline card) instead of showPalette. Otherwise (composer closed) keep current behavior. In prefetchRepairOptions, if composerOpen, update heldForComposer.palette = snap.palette instead of calling ui.showResponses.

**How to verify the fix.** Manual in Practice Mode: open the composer, let the practice partner produce a closing line, cancel the composer; confirm the goodbye cards with the decline card are shown. Repeat with a 'What?' turn and confirm the prefetched rephrase/expand wording appears after cancel.

**Do not break.** Do not render anything under the composer; keep the rule that Speak from the composer discards held results and Reframe replaces them. Keep the decline-closing card pinned (renderStaticPalette pin option).

**Design reference.** CLAUDE.md 'WHEN THE RESPONSE CARDS CHANGE' ('In my own words' — the reprompt is KEPT and shown on CANCEL); 'Closing detection ... decline-the-closing card'.

**Verification notes.** In generateOptions the PRE_CLOSING_CLOSING branch is tested before composerOpen and calls renderStaticPalette directly; the winding-down fast path (1760-1773) returns before reaching any composerOpen check; neither clears heldForComposer. handleCancelComposed -> showHeldForComposer() then calls showPalette(heldPalette) and sets status 'Select a response', replacing the goodbyes with an older held AI set while the engine is in PRE_CLOSING_CLOSING. prefetchRepairOptions calls ui.showResponses with no composerOpen check. Requires a reprompt held while composing followed by a closing turn, so the trigger is narrow but reachable.

<details><summary>Merged duplicate app-c-13: Goodbye cards (and repair wordings) are drawn under the open In-my-own-words box</summary>

The composerOpen hold applies only in the `else if (composerOpen)` branch. A partner-initiated close (PRE_CLOSING_CLOSING) and the closing fast path both call renderStaticPalette('closing', ...) unconditionally, which runs showPalette under the composer overlay: it logs an offer, starts the deliberation clock, and sets status. prefetchRepairOptions likewise calls ui.showResponses directly while the composer may be open, and its updated wordings are lost from heldForComposer/shownCards/lastPalette (they hold engine snapshot copies). The recorded decision is that cards must not be rendered under the composer while it is open.

Fix as proposed by that reviewer: Hold static closings too: in both closing branches, when composerOpen, store `heldForComposer = { palette: snap.palette, at: Date.now(), static: { kind: 'closing', full: snap.palette, pin: declineClosingCard() }, status: 'Say goodbye — or hold them a moment' }` instead of rendering; extend showHeldForComposer to use renderStaticPalette when `held.static` is set. In prefetchRepairOptions, if composerOpen, update `heldForComposer.palette = snap.palette` (when held) instead of calling ui.showResponses.

</details>
