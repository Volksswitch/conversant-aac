# CR-021: A failed AI request leaves the replaced cards' offer record open and shownCards stale, so later actions are attributed to cards no longer on screen

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1959`
- **Also affects:** `app/js/app.js:3371`; `app/js/app.js:3465`; `app/js/app.js:3556`; `app/js/app.js:3574`; `app/js/app.js:2972`; `app/js/app.js:2891`; `app/js/app.js:2914`; `app/js/ui.js:413`
- **Source:** g-app-flow-overflow-02

**What a user notices.** When the AI fails on a later pause, the suggestions the user was reading are swapped for an error box, but the app's records still say those suggestions are showing. Whatever the user does next (an Express phrase, typing, Wrap up) is recorded as turning down cards that were already gone, and pressing Wrap up then cancelling brings those old cards back for a shorter version of what the other person said, removing the Try again option.

**What is wrong.** Every catch path that calls ui.showResponseError replaces the #responseOptions content with the error box (ui.js:413-431 sets innerHTML = ''), but none of them update the app's bookkeeping that showPalette/clearPalette normally maintain: storage's pendingOffer stays open, shownCards still lists the replaced cards, cardsShownAt/decideTaken (the deliberation clock) keep running from when those cards appeared, metrics' openPalette stays open, and lastPalette is unchanged. Effects: (a) the next user action calls noteUserAction(kind) which runs storage.finalizeOffer({outcome: kind}) on the dead offer - e.g. outcome 'express' or 'composer' - and its shownMs includes the time the error box was up; the DECIDE metric is emitted with a span measured from cards that were removed; (b) Wrap up → overlayEnter photographs shownCards (the pre-failure cards) → cancel → overlayCancel → showPalette restores them; showResponses removes 'has-error', so the error box and its Try again are gone and cards built for an earlier, shorter partner text are now live. This review documents ONLY the stale-record half; whether the error box itself should exist is the open 'amber box' decision in CLAUDE.md.

**Evidence.**

```
app/js/app.js:1933-1960 (catch in generateOptions): logs, `placeholders.stop();`, `updatePartnerLive(partnerText);`, `ui.setTranscriptState('uncleaned');`, `ui.showResponseError(...)` - no finalizeOffer, no shownCards update, no clock reset.
app/js/ui.js:414-416: `responseOptions.classList.add('has-error'); responseOptions.innerHTML = '';`
app/js/app.js:2980-2982: `if (cardsShownAt && !decideTaken) { storage.finalizeOffer({ outcome: kind, selectedIndex, shownMs: shownSpanMs() }); }`
app/js/app.js:2894-2896: overlayEnter stores `cards: shownCards.cards`.
Same pattern at app.js:3371 (regenerate), 3465 (choice chip), 3556 and 3574 (reframe).
```

**How it happens.** 1) Partner speaks, pauses; cards appear (offer recorded, pending). 2) Partner says more, pauses; the reprompt fails (e.g. a 529 overload). The error box replaces the cards. 3) The user taps an Express phrase 'Yes'. The conversation file's earlier offer is finalized with outcome 'express' and a shownMs covering the whole error period, although the user never saw those cards when they acted. Alternative step 3: the user taps Wrap up, then Wrap up again: the pre-failure cards reappear (for the shorter partner text), the error box and Try again are gone.

**Suggested fix.** Add a small helper beside clearPalette, e.g. `function notePaletteReplacedByError() { if (storage.hasPendingOffer()) storage.finalizeOffer({ outcome: 'error', shownMs: shownSpanMs() }); metrics.paletteAbandoned('generation failed'); shownCards = { cards: [], kind: 'error' }; cardsShownAt = 0; decideTaken = false; }` and call it immediately before each of the five `ui.showResponseError(...)` calls (app.js:1959, 3371, 3465, 3556, 3574). Leave lastPalette as is (Reframe uses it to choose rework mode and Try again uses the partner text). If the amber box is later removed per the open TODO, keep the helper call wherever the cards are cleared on failure.

> **Verifier correction to the fix (takes precedence):** Setting shownCards to { cards: [], kind: 'error' } means a later Wrap up cancel calls showPalette([], 'error'), which logs an empty offer via storage.logOffer and emits PALETTE_SHOWN with 0 cards (the same thing already happens today when cancelling over an empty panel, kind 'none'). Also change overlayCancel to call clearPalette() instead of showPalette() when back.cards is empty, so neither case writes an empty offer. The finalizeOffer/paletteAbandoned calls in the helper are no-ops on the regenerate/chip/reframe paths (already finalized), which is fine.

**How to verify the fix.** Manual: with a deliberately invalid API key after a first successful set (or by stubbing fetch in devtools to fail on the second call), make the reprompt fail, then tap an Express phrase; the conversation JSON must show the first offer with outcome 'error', not 'express'. Press Wrap up twice after a failure; the panel must return to the empty/error state, not to the earlier cards. Source-level guard in tests/placeholders.test.mjs (where app.js source guards live): assert every `ui.showResponseError(` call in app.js is preceded within a few lines by the helper call.

**Do not break.** Do not change the visible error box or Try again behavior (open decision). Do not clear the partner's live words. 'error' is a new outcome value; check usage-summary.js / report tooling treat unknown outcomes gracefully (they read outcomes as strings).

**Design reference.** CLAUDE.md: 'EVERY SET OF CARDS IS RECORDED, NOT ONLY THE ONES PICKED FROM' (outcome is part of the record); 'Wrap up and Start conversation are TOGGLES'; Open Questions 'decide the disposition of the amber box (showResponseError)'.

**Verification notes.** All five ui.showResponseError calls (app.js:1959, 3371, 3465, 3556, 3574) replace #responseOptions content (ui.js:413-431) without touching shownCards, cardsShownAt/decideTaken, the pending offer or metrics' openPalette. On the reprompt path (1959) no user action preceded the failure, so the earlier offer stays pending and the next noteUserAction finalizes it with that action's kind and a shownMs spanning the error period. For the regenerate/chip/reframe paths the offer was already finalized by noteUserAction, but shownCards is still stale, so Wrap up -> cancel (overlayEnter/overlayCancel 2891-2915) restores the pre-failure cards and showResponses drops 'has-error', removing Try again. Not tracked in TODO.md; the amber-box decision in CLAUDE.md is about the error box itself, not this bookkeeping.
