# CR-022: Repair wordings fetched after 'What?' are drawn on screen only: Wrap up cancel and composer Cancel bring back blank hint cards, and the saved offer never gets the real wording

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2176`
- **Also affects:** `app/js/app.js:1867`; `app/js/app.js:1911`; `app/js/app.js:2858`; `app/js/app.js:2891`; `app/js/app.js:2905`; `app/js/app.js:3016`; `app/js/engine.js:217`; `app/js/engine.js:454`; `app/js/storage.js:2307`
- **Source:** g-app-flow-overflow-01

**What a user notices.** After the other person says "What?", two of the repair cards fill in with real wording a moment later. If the user then presses Wrap up and changes their mind, or opens In my own words and cancels, those two cards come back showing only "Say it differently" / "Explain it more" with the wording gone, and tapping one makes the user wait for a fresh AI round trip. The saved record of what was offered also shows those two cards as blank.

**What is wrong.** prefetchRepairOptions fills the rephrase/expand text through engine.setRepairOptions and then repaints with ui.showResponses directly, deliberately bypassing showPalette. But showPalette is the only place that keeps the app's records of what is on screen: shownCards (what Wrap up / Start conversation photograph and restore), the pending offer entry in the conversation file (storage.logOffer), and lastPalette. engine.getSnapshot returns COPIES of the palette entries (state.palette.map(m => ({...m}))), and setRepairOptions mutates the engine's own state.palette, so the copies already stored in shownCards.cards, lastPalette and heldForComposer.palette keep text:'' for rephrase/expand. Consequences: (a) Wrap up → overlayEnter photographs shownCards (hint-only copies) → cancel → overlayCancel → showPalette(back.cards) repaints hint-only cards; (b) when 'In my own words' is open during the 'What?' turn, generateOptions holds the hint-only palette in heldForComposer (line 1867) and still calls prefetchRepairOptions (line 1911), which then paints the full cards UNDER the composer with ui.showResponses; Cancel → showHeldForComposer → showPalette(hint-only held copy); (c) the pending offer written by logOffer at the original showPalette has text '' for two of four options and is never revised, so the conversation file cannot show what wording was actually offered (fails the 'recreate it to the second' standard); (d) lastPalette is stale.

**How it happens.** 1) In a conversation the user says something; the partner says "What?". 2) The four repair cards appear; a second later 'Say it differently' and 'Explain it more' fill in with real sentences. 3) The user taps Wrap up (wind-down cards appear), then taps Wrap up again to cancel. 4) The repair cards return with the two real sentences replaced by the hints. Tapping 'Say it differently' now triggers llm.repairSelf (a new paid round trip and a delay) instead of speaking instantly. Variant: the user has 'In my own words' open when the partner says "What?"; on Cancel the same hint-only cards appear. In both cases the conversation file's offer entry lists '' for the rephrase and expand options.

**Suggested fix.** In prefetchRepairOptions, after `const snap = engine.setRepairOptions(opts);`: (1) set `lastPalette = snap.palette;`; (2) if `heldForComposer` is set, replace `heldForComposer.palette = snap.palette;` and DO NOT call ui.showResponses (return after updating) so nothing is painted under the open composer; (3) otherwise call ui.showResponses as now and then set `shownCards = { cards: snap.palette, kind: shownCards.kind };` (do not call showPalette, preserving the deliberate no-new-offer/no-clock-restart rule); (4) add a storage function, e.g. `export async function reviseOffer(options)` in storage.js next to finalizeOffer, that, when `pendingOffer` exists, rewrites `pendingOffer.options` with the same `{slot, text}` mapping logOffer uses and calls flushLog(); call it with snap.palette from prefetchRepairOptions. If paletteOverlay is active (it should not be, because Wrap up bumps generationToken and the prefetch bails), leave it alone.

> **Verifier correction to the fix (takes precedence):** The suggested fix is sound. Additionally note that overlayCancel calls engine.resumeConversation(), which takes the engine out of REPAIR_OF_SELF, so prefetchRepairOptions' own mode check would correctly bail on any later prefetch; no further change needed there. Updating shownCards must keep shownCards.kind unchanged (it is 'ai'), as the fix says.

**How to verify the fix.** Manual: Practice or real conversation, trigger a repair-initiator ('What?'), wait for the wording to fill in, press Wrap up twice; the two cards must still show their sentences, and tapping one must speak at once with no 'Rephrasing…' status. Repeat with In my own words open when 'What?' arrives, then Cancel. Open the conversation JSON and confirm the offer entry for the repair set carries the rephrase/expand text. Unit: add a test to tests/storage-transcript.test.mjs that calls logOffer with empty texts, then reviseOffer with filled texts, and reads the file back.

**Do not break.** Keep the decision that the prefetch does not restart the deliberation clock or count a fresh offer (do not route through showPalette/noteCardsShown). Do not paint anything under the open composer. handleRepairOfSelf's fallback round trip must remain for when the prefetch failed.
