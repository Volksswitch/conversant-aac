# CR-023: Repair-of-self replies skip the shared commit step, so they are recorded without context and break several counters

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2228`
- **Also affects:** `app/js/app.js:2282 commitExchange (comment at 2286-2287 claims repair-of-self uses it)`; `app/js/app.js:1967 handleResponseSelected returns before noteUserAction for op cards`; `app/js/app.js:2207-2210 and 2220-2224 early returns after stt.stopListening()`
- **Source:** app-b-07

**What a user notices.** When the user repeats or rewords themselves after "What?", the saved record does not say who they were talking to or where, the holding phrases do not ease off, the app's usage measures never count the repair, and if the reword request fails the microphone is left off with no indication.

**What is wrong.** handleRepairOfSelf writes the user turn itself instead of calling commitExchange. As a result it skips: placeholders.noteExchange() (ease-off counter), setOfferedChoices([]) / setOfferedRange(null) / clearTurnSteering() / dropHeldForComposer(), the partner/feeling/place/goals stamps and selectedSlot on the user turn, and the partner turn's place/uncertain fields. handleResponseSelected returns into it before noteUserAction('card') and metrics.paletteTaken, so the repair palette's offer is never finalized with outcome 'card' and REPAIR selections never appear in the category distribution (CLAUDE.md: 'heavy REPAIR use means something upstream is failing'). It also reads `raw = currentPartnerText` (last checkpoint only) rather than heardPartnerText(). Finally, it calls stt.stopListening() at the top, and the 'Nothing to repeat yet' and repairSelf-error returns never resume listening, leaving the mic off with the repair cards still up.

**How it happens.** Partner says "What?"; the user taps 'Say it differently' before the prefetch arrived; the on-demand llm.repairSelf call fails (offline). Status shows an error, the mic is off, the repair cards remain, and nothing resumes listening even though auto-resume is on. On the success path (once the ReferenceError is fixed) the saved user turn has partner:null, place:null, goals:null and no selectedSlot, and the placeholder delay does not grow.

**Suggested fix.** Restructure handleRepairOfSelf's success tail: capture the shown cards and call `const decideMs = noteUserAction('card', index)` (pass index from handleResponseSelected: change line 1967 to `return handleRepairOfSelf(response, index);` and record `metrics.paletteTaken({ slot: response.slot || null, index, decideMs })`). Capture `raw = heardPartnerText()` before stt.stopListening(). After speaking, call `engine.completeRepairOfSelf(text)` then `await commitExchange(raw, text, index, { decideMs, chosenFrom: shownAtTap })` instead of the hand-written finalize/push/logUserResponse block (commitExchange already finalizes the pending partner entry in place). Then clear the palette and resumeOrIdle(). On the two early-return paths, if the mic was on before (`const wasListening = isListening` captured at the top), call resumePartnerCapture() before returning, mirroring playAudioTurn's failure path.

**How to verify the fix.** Manual: trigger repair-of-self and pick each card; inspect the saved conversation: user turn has selectedSlot (the repair slot), partner/place stamps, source 'card' (or 'control' if you decide repair picks are 'our words' — keep it consistent with voice-harvest expectations); the offer entry has outcome 'card'. Force repairSelf to fail and confirm listening resumes.

**Do not break.** voice-harvest classifies turns by `source`; confirm with Ken/CLAUDE.md whether a rephrase should count as 'card' (model wording) or 'control' before changing it — it must never be counted as the user's own composed words. Keep 'retry' op behavior unchanged. Fix the ReferenceError finding at the same time.

**Design reference.** CLAUDE.md 'Beta instrumentation and error reporting' (category selection distribution, selectedSlot); 'Placeholders EASE OFF over a conversation' (exchange counted in commitExchange, the one choke point).

**Verification notes.** Verified by reading: handleResponseSelected returns into handleRepairOfSelf at line 1967 before noteUserAction('card') and metrics.paletteTaken; handleRepairOfSelf writes its own partner finalize + conversationHistory.push + logUserResponse instead of commitExchange, so placeholders.noteExchange, setOfferedChoices/setOfferedRange/clearTurnSteering/dropHeldForComposer, selectedSlot and the partner/feeling/place/goals stamps are skipped; it uses currentPartnerText rather than heardPartnerText(); and the 'Nothing to repeat yet' and repairSelf-error returns leave the mic stopped (stt.stopListening at the top) with no resume. commitExchange's comment claiming repair-of-self uses it is stale.
