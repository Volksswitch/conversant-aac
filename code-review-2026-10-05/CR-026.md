# CR-026: When the practice partner's turn is interrupted, its spoken line is lost, the Listen button stays lit, and the 'cards may change' look never clears

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2619`
- **Also affects:** `app/js/app.js:2605-2617`; `app/js/app.js:2625`; `app/js/app.js:2723-2732`; `app/js/app.js:3136`; `app/js/app.js:3613`; `app/js/app.js:3285`; `app/js/app.js:2156-2166`; `app/js/ui.js:328-335`
- **Source:** app-c-05

**What a user notices.** If the user taps Wrap up, Start conversation or Ask them to repeat while the pretend partner is talking, the partner's words are heard but never written into the conversation, and the Listen button stays red so the next tap only 'pauses' something that is not happening. If the AI cannot be reached, or the user pauses, the cards stay dimmed with a moving stripe as if new ones were coming.

**What is wrong.** advancePracticePartner sets ui.setPaletteBusy(true) and isListening=true, then returns early on supersession (token !== generationToken) at 2619 and again after tts.speak at 2625 without (a) resetting isListening / the Listen button, (b) clearing the busy look, or (c) recording the line that was already spoken. handleWindDown and handleInitiate bump generationToken but do not cancel TTS, so the partner line plays to the end and is then discarded; handlePardon cancels it and has nothing to keep because the line was never fed into currentPartnerText. The error path (2612-2617) also leaves setPaletteBusy on, and togglePracticeCue's pause branch never clears it. ui.setPaletteBusy's contract is that 'every completion, failure and abort path' renders something that clears it; these paths render nothing. prefetchRepairOptions' catch (2163-2165) has the same stuck-busy defect.

**Evidence.**

```
app/js/app.js:2604-2607 `const token = ++generationToken; ... ui.setPaletteBusy(true); ... isListening = true; ui.setListenButtonState(true);`
app/js/app.js:2619 `if (token !== generationToken || !practiceMode) return;   // superseded (ended/paused)`
app/js/app.js:2624-2625 `await tts.speak(line, partnerVoiceOptions(practiceScenario));
    if (token !== generationToken || !practiceMode) return;`
app/js/app.js:2612-2617 catch: `isListening = false; ui.setListenButtonState(false); return;` (no setPaletteBusy(false))
app/js/app.js:3613 (handleWindDown) `generationToken++;` (no tts.cancel)
app/js/ui.js:328-330 `It is cleared by whatever renders next — showResponses, clearResponseOptions or showResponseError below — which every completion, failure and abort path already goes through.`
```

**How it happens.** 1) In practice, after one exchange (cards showing), tap Start Listening. 2) While the partner line is being spoken, tap Wrap up. 3) The line finishes playing, the wind-down cards show, but the line is absent from the conversation pane and saved file, and Listen is still red; tapping Listen shows 'Paused'. Separately: practice with no internet, tap Start Listening - the old cards stay dimmed with the sweeping stripe indefinitely.

**Suggested fix.** Track the cue: add `let practiceCueToken = 0;` and set `practiceCueToken = token` at the start of advancePracticePartner. Add a helper `endPracticeCue(token)` that, only if `practiceCueToken === token` (no newer cue started), sets `isListening = false; ui.setListenButtonState(false); ui.setPaletteBusy(false);`. Call it on both superseded returns and in the catch. Record the line as soon as it has been spoken even if superseded: after `await tts.speak(...)`, if superseded but still practiceMode, set `currentPartnerText = line; updatePartnerLive(line); storage.logPartnerInterim({ rawTranscript: line, partner: partnerStamp() });` (do not generate options). In togglePracticeCue's pause branch add `ui.setPaletteBusy(false);`. In prefetchRepairOptions' catch add `if (token === generationToken) ui.setPaletteBusy(false);`.

**How to verify the fix.** Manual: the failure scenario above - after the fix the partner line appears in the pane and file, Listen returns to off, and the stripe stops; with no network the stripe stops after the error. Source guard in tests/placeholders.test.mjs that both early returns in advancePracticePartner are followed by a cue-ending call.

**Do not break.** Do not reset isListening when the supersession came from a NEWER advancePracticePartner (that is what the cue token check prevents). Practice must not open a real microphone.

**Design reference.** app/js/ui.js setPaletteBusy contract; CLAUDE.md 'Transcript mirrors the conversation pane' and Practice Mode - full plan

**Verification notes.** advancePracticePartner sets paletteBusy and isListening=true and then returns on supersession (before and after tts.speak) and in the catch without resetting isListening/the Listen button or recording the line. handleWindDown and handleInitiate bump generationToken without tts.cancel, so the line plays out and is discarded. The catch path and togglePracticeCue's pause branch render nothing, so ui.setPaletteBusy's 'cleared by whatever renders next' contract is not met and the stripe stays. prefetchRepairOptions' catch also leaves busy on. Note: in the Wrap up / Start conversation case the busy look is cleared by the static palette render; the stuck-busy part applies to the error and pause paths.
