# CR-027: Tour instructions start speaking 0.7 s after a press and cut off what the user just said

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2680`
- **Also affects:** `app/js/app.js:2636-2644`; `app/js/app.js:2690-2708`; `app/js/tts.js:266-269`; `app/js/practice-tour.js:80-106`; `app/js/app.js:2680 (merged duplicate: The button tour talks over the user's own speech 0.7 seconds after a press)`
- **Source:** phrases-practice-03, app-c-08

**What a user notices.** In the button tour, tapping a card, Repeat what I said, Hold on or Ask them to repeat starts the sentence in the user's voice, and less than a second later the coach starts talking and the user's sentence stops. The tour is meant to show what these buttons do, and it cuts off the very thing it is showing.

**What is wrong.** handleTourPress advances the step and schedules speakTourStep after a fixed 700 ms. speakTourStep calls tts.speak(step.say, ...) with no regard to whether the user's own statement is still playing. tts.speak supersedes the current utterance (speakBuiltin cancels synth if speaking; the speakToken bump makes the earlier utterance's completion a no-op), so the opener, the Say-again re-speak, the Hold on phrase and the pardon phrase are all truncated. hintWhere has the same problem: a wrong press on an Express phrase speaks the hint immediately over the phrase.

**Evidence.**

```
app.js:2678-2680 `// Let the pressed control finish what it is doing ... setTimeout(speakTourStep, 700);`
app.js:2643 `await tts.speak(step.say, partnerVoiceOptions());`
app.js:2707 `tts.speak(step.where, partnerVoiceOptions());`
tts.js:268 `if (synth.speaking) synth.cancel();`
practice-tour.js:83-84 'Tapping one speaks it in your voice — that is how you say almost everything.'
```

**How it happens.** Start the tour, tap Listen, Start conversation, then an opener card such as 'I was just thinking about you.' The opener starts, and after 0.7 s the coach line 'You just said that out loud...' begins and the opener stops partway.

**Suggested fix.** Wait for the user's speech to finish before speaking the next instruction. In speakTourStep (and hintWhere), first wait until neither `speakingUserStatement` nor `tts.isSpeaking()` is true, e.g. `const waitQuiet = async () => { while (speakingUserStatement || tts.isSpeaking()) await new Promise(r => setTimeout(r, 150)); };` and `await waitQuiet();` before tts.speak, keeping the 700 ms as a minimum. Re-check `tour` and the step id after the wait so a press made meanwhile is not talked over by a stale step. In hintWhere, skip the spoken hint (keep the on-screen text) when speakingUserStatement is true.

**How to verify the fix.** Manual: run the tour and confirm the opener, Repeat what I said, Hold on and Ask them to repeat phrases are each heard in full before the next instruction. Repeat with a paid voice selected.

**Do not break.** The tour must never stall: put a ceiling on the wait (e.g. 15 s). Keep observing presses on the capture phase; do not intercept them.

**Design reference.** practice-tour.js header (the tour observes and the button does its real job); app.js comment at 2678.

**Verification notes.** handleTourPress runs on the capture phase, before the control's own handler, and schedules speakTourStep with a fixed 700 ms setTimeout (app.js:2680). speakTourStep calls tts.speak(step.say, ...) with no check on speakingUserStatement or tts.isSpeaking. tts.speak bumps speakToken; speakBuiltin cancels a speaking synth (tts.js:268), and the paid backends are superseded in the same way. So an opener card, a Say-again re-speak, the Hold on phrase or the pardon phrase still playing at 700 ms is cut off. hintWhere speaks immediately with the same effect.

Fix as proposed by that reviewer: Replace the fixed timeout with a wait until the app has finished speaking: e.g. `function speakTourStepWhenQuiet(tries = 0) { if ((tts.isSpeaking() || speakingUserStatement) && tries < 40) { setTimeout(() => speakTourStepWhenQuiet(tries + 1), 250); return; } speakTourStep(); }` and call `setTimeout(speakTourStepWhenQuiet, 700)`. For hintWhere, defer the spoken hint the same way (keep the on-screen coach line immediate).
