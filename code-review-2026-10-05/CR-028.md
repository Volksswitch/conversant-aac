# CR-028: The controls tour calls the AI practice partner when auto-resume is on, breaking the tour's no-API promise

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2742`
- **Also affects:** `app/js/app.js:2602-2611`; `app/js/app.js:2718-2722`; `app/js/app.js:2104-2115`; `app/js/app.js:3731-3745`; `app/js/llm.js:662-669`; `app/js/practice-tour.js:80-83`; `app/js/app.js:2114 (merged duplicate: The button tour calls the AI (and fails without a key) when auto-resume listening is on)`
- **Source:** app-c-03, phrases-practice-02

**What a user notices.** During the button tour, if the user has 'resume listening automatically' turned on, tapping an opener card (a tour step) makes the app invent a nonsense 'other person' line and speak it over the tour's instructions; without an AI key it instead shows an error wash. The tour is supposed to work with no AI at all.

**What is wrong.** togglePracticeCue returns early when `tour` is set, with the comment that this 'keeps the tour free of generation calls (and so free of an API key)'. But practiceResumeOrIdle() and advancePracticePartner() have no tour guard. In the tour, step 'pick-card' asks the user to tap an opener; handleResponseSelected sets manualListenArmed=true for an opener and calls practiceResumeOrIdle(), which calls advancePracticePartner() when storage.loadAutoRelisten() is true. The same happens on any later spoken step (Express phrase via speakAsUserTurn -> resumeOrIdle). advancePracticePartner then calls llm.generatePartnerUtterance(practiceScenario, ...) with the tour scenario, which has no partnerPersona, so the prompt reads 'The person you are playing: undefined'. With a key, a partner line is spoken and fed into the pipeline mid-tour; without one, logError trips the red transcript wash.

**How it happens.** 1) Settings > General: turn on resume listening automatically. 2) Settings > Practice: start the controls tour. 3) Follow it: Listen, Start conversation, tap an opener card. 4) A few seconds later an AI-written partner line is spoken and new cards appear, colliding with the 'Repeat what I said' instruction; with no API key the transcript turns red instead.

**Suggested fix.** Add a tour guard at the top of both functions: in advancePracticePartner `if (!practiceMode || tour) return;` and in practiceResumeOrIdle make the tour take the idle branch: `if (!tour && manualListenArmed && storage.loadAutoRelisten()) { advancePracticePartner(); } else { ...existing idle branch... }`. The idle branch's status line can stay (status bar is hidden).

**How to verify the fix.** Add a source-level test in tests/placeholders.test.mjs asserting advancePracticePartner's first guard references `tour`. Manual: repeat the failure scenario with auto-resume on; no network request to the AI is made during the tour (check the browser network panel) and no partner line is spoken.

**Do not break.** Must not change real practice scenarios (tour === null), where auto-resume cueing is the designed rehearsal behavior. Keep the tour observing presses only (handleTourPress must not intercept).

**Design reference.** CLAUDE.md, Practice Mode - full plan ('Start Listening IS the partner cue'); controls tour comments in app/js/app.js togglePracticeCue

Only reachable with auto-resume on (default off).

The tour is documented as running with no AI, no key and no network. togglePracticeCue guards with `if (tour) return;`, but practiceResumeOrIdle() does not. The tour's 'pick-card' step selects an opener; handleResponseSelected's opener branch sets manualListenArmed = true and, in practice mode, calls practiceResumeOrIdle(), which calls advancePracticePartner() when auto-resume is on. That calls llm.generatePartnerUtterance(practiceScenario) with the tour entry, which has no partnerPersona (the prompt reads 'The person you are playing: undefined'), then speaks the line, then handleSilencePeriod -> generateOptions -> arms placeholders and replaces the opener cards that later tour steps depend on. Any Express phrase or composer Speak during the tour reaches the same path through resumeOrIdle().

Fix as proposed by that reviewer: In practiceResumeOrIdle(), treat the tour as having no partner to cue: `if (tour || !(manualListenArmed && storage.loadAutoRelisten())) { ...existing idle branch... return; } advancePracticePartner();`. Also add a defensive first line to advancePracticePartner(): `if (!practiceMode || tour || !practiceScenario || !practiceScenario.partnerPersona) return;`.
