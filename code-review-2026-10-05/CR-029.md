# CR-029: New N's paging cursor outlives the static palette, so New 4 brings back old openers or goodbyes

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3005`
- **Also affects:** `app/js/app.js:3323-3331`; `app/js/app.js:3551`; `app/js/app.js:1725`; `app/js/app.js:3293`; `app/js/app.js:3717`; `app/js/app.js:5300`; `app/js/app.js:2891-2898`; `app/js/app.js:1846-1849`
- **Source:** app-c-07

**What a user notices.** After the user picks an opener and is waiting for the other person, tapping New 4 puts the conversation openers back on screen. After a Reframe while the other person is saying goodbye, tapping New 4 replaces the user's reworked suggestions with the goodbye cards.

**What is wrong.** handleRegenerate pages a static set whenever currentStatic.kind is set. currentStatic is set by renderStaticPalette but is NOT reset when the panel is emptied (clearPalette, used by startFreshListening, handlePardon, speakAsUserTurn, the sound-button path) nor when handleReframe's partner-turn branch replaces a static palette with AI cards. Example 1: cold Start conversation -> pick an opener -> handleResponseSelected -> startFreshListening -> clearPalette; currentStatic.kind is still 'opener', so New 4 re-renders openers mid-conversation. Example 2: partner closing -> generateOptions renders closings via renderStaticPalette (currentStatic 'closing', lastPalette = closing palette, currentPartnerText set) -> Reframe takes the partner branch and calls showPalette(snap.palette) without resetting currentStatic -> New 4 pages goodbyes over the reframed cards. overlayEnter also snapshots the stale cursor.

**Evidence.**

```
app/js/app.js:3323 `if (currentStatic.kind) {` ... 3329 `renderStaticPalette(currentStatic.kind, currentStatic.full, null, { advance: true, pin });`
app/js/app.js:3005-3014 clearPalette: `ui.clearResponseOptions();
    shownCards = { cards: [], kind: 'none' };` (currentStatic untouched)
app/js/app.js:3548-3551 (handleReframe partner branch) `const snap = engine.refreshPalette(result.responses); ... lastPalette = snap.palette;
            showPalette(snap.palette);` (no currentStatic reset, unlike handleChoiceChip at 3459 `currentStatic = { kind: null, full: [] };`)
```

**How it happens.** A) Start conversation, tap an opener, before the partner replies tap New 4: opener cards reappear. B) Partner says 'Well, I should get going' (goodbye cards + 'Actually, before you go'); open In my own words, type 'ask about her trip', Reframe; tap New 4: goodbye cards replace the reframed cards.

**Suggested fix.** In clearPalette add `currentStatic = { kind: null, full: [], pin: [] };` (do NOT reset staticOffsets - per-kind offsets intentionally persist for the conversation). In handleReframe's partner branch, before `showPalette(snap.palette)`, add `currentStatic = { kind: null, full: [] };  // AI responses — New N regenerates, not pages` matching handleChoiceChip.

**How to verify the fix.** Manual: both scenarios above; after the fix scenario A's New 4 does nothing (no partner turn yet) and B's New 4 regenerates AI options with the steer. Source guard in tests/placeholders.test.mjs that clearPalette assigns currentStatic.

**Do not break.** terminateConversation calls resetStaticPaging then clearPalette - unaffected. overlayCancel restores currentStatic via back.static and calls showPalette (not clearPalette) - unaffected. Keep staticOffsets so re-pressing within a conversation still continues paging.

**Design reference.** CLAUDE.md, 'Wind-down and closing are two distinct steps; static palettes paginate' ('When normal AI response cards show, the static cursor is cleared so New N regenerates')

**Verification notes.** clearPalette resets shownCards but not currentStatic. Cold Start conversation -> pick opener: pendingNewConversation is false, so no terminateConversation; startFreshListening -> clearPalette leaves currentStatic.kind='opener', and handleRegenerate's first branch re-renders openers. Partner closing (both closing branches) sets lastPalette to the closing palette and currentStatic to 'closing'; handleReframe's partner branch then calls showPalette without resetting currentStatic (unlike handleChoiceChip and generateOptions), so New 4 pages goodbyes over the reframed cards. Note conversationInProgress() and refreshForContextChange also read currentStatic.kind; resetting it in clearPalette only makes them reflect what is actually on screen.
