# CR-032: Active partner/place/feeling keep a stale copy after their button is edited or deleted

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:4628`
- **Also affects:** `app/js/app.js:4568 (activePartner = item - a copy made in composedPanel)`; `app/js/app.js:4586 (activeFeeling = item)`; `app/js/app.js:4118-4120 (partner items are re-created on every render)`; `app/js/app.js:723-724 (expressEditor onChange only re-renders)`; `app/js/express-editor.js:426-432 (save replaces the item object)`; `app/js/app.js:4395-4399 (buildSituationBlock uses activePlace.placeId/name)`; `app/js/app.js:4468-4473 (placeStamp uses activePlace.name)`; `app/js/express-editor.js:190 (merged duplicate: Deleting or re-pointing a switched-on place (or partner) button leaves it steering the AI with nothing lit)`
- **Source:** app-d-05, express-05

**What a user notices.** If the person changes or removes a lit person or place button in Settings, the app keeps telling the AI the old person or place, and since a place stays on between conversations, a deleted place can keep shaping suggestions with no button left to switch it off.

**What is wrong.** The toggle handlers store the tapped item object in activePartner/activePlace/activeFeeling. Nothing reconciles these against the Express Panel model afterwards: the editor's save() replaces the item with a new object `{ ...list[at], ...patch }`, and a delete removes it; the editor's onChange only calls renderExpressPanel. Results: (1) editing a lit place button to point at a different place keeps the button lit (litIds matches by id) while buildSituationBlock, places.buildBlock(activePlace.placeId) and placeStamp still use the OLD placeId/name - the panel and what reaches the AI/transcript disagree; same for a partner's personId (situation block, goals, openers) and a feeling's text. (2) Deleting a lit button leaves the value active with nothing lit on screen. For a place this is worst, because clearInfluencers deliberately does not clear it at End conversation, so it persists across every conversation until reload or until another place is tapped - and there is no way to get back to 'no place' at all.

**Evidence.**

```
app/js/app.js:4628  activePlace = (activePlace && activePlace.id === item.id) ? null : item;
app/js/express-editor.js:430  list[at] = { ...list[at], ...patch };
app/js/app.js:724  onChange: renderExpressPanel,
app/js/app.js:4396-4398
  const here = activePlace.placeId ? places.buildHereBlock(activePlace.placeId) : '';
  if (here) lines.push(here);
  else if (activePlace.name) lines.push(`The user is at ${activePlace.name} right now. ...`);
```

**How it happens.** Tap the 'Clinic' place button (lit). Open Settings > Express Panel, delete that button, close Settings. The panel shows no lit place, but every later generation still says 'The user is at Clinic right now', every turn is stamped place Clinic, and End conversation does not clear it.

**Suggested fix.** Add a reconcile step in app.js, e.g. `function reconcileInfluencers() { const ctxList = expressPanel.getModel().context || []; const find = (a) => a && ctxList.find((x) => x && x.id === a.id); if (activePartner && !String(activePartner.id).startsWith('practice:')) { const f = find(activePartner); if (!f) { activePartner = null; dropGoalsFrom('partner'); applyControlPhrases(); } else activePartner = f; } if (activePlace) { const f = find(activePlace); if (!f) { activePlace = null; dropGoalsFrom('place'); } else activePlace = f; } if (activeFeeling) { activeFeeling = find(activeFeeling) || null; } }` and wire the editor with `onChange: () => { reconcileInfluencers(); renderExpressPanel(); }` at line 724. For partner items keep comparing by id; partnerLabel already resolves the face from the graph.

**How to verify the fix.** Manual: light a place, delete its button in Settings, close Settings and trigger a generation in Practice Mode; the request's system text must no longer contain the old place and the next turn's place stamp must be null. Repeat by editing a lit place button to a different My Places entry and confirm the situation block names the new place.

**Do not break.** Do not clear the Practice Mode partner (id 'practice:<personId>'), which deliberately has no Express button. Keep the place-persists-across-End-conversation rule intact for places that still exist.

**Design reference.** CLAUDE.md 'My Places' (place persists across End conversation) and 'A SWITCHED-ON button always shows' (a lit button must never steer the AI with nothing on screen saying so)

**Verification notes.** Traced. activePartner, activePlace and activeFeeling hold the item object captured at tap time (app.js:4568, 4586, 4628). The editor's save() replaces the item with a new object (express-editor.js:430), and a delete removes it. The editor's onChange is just renderExpressPanel (app.js:723), and nothing reconciles the active values against the model. After an edit, buildSituationBlock, places.buildBlock(activePlace.placeId), placeStamp and partnerStamp keep using the stale personId, placeId and text, while the button shows lit because the id still matches. After a delete the value stays active with nothing lit on screen. A place is not cleared at End conversation by design, so a deleted place keeps steering every conversation until reload; the active values are not persisted. Ways out: tap another place twice, or reload.

<details><summary>Merged duplicate express-05: Deleting or re-pointing a switched-on place (or partner) button leaves it steering the AI with nothing lit</summary>

activePlace / activePartner / activeFeeling in app.js hold a snapshot of the tapped item. The Express editor's only callback after a change is onChange -> renderExpressPanel, which re-renders but never reconciles the active influencers with the model. After removePicked() deletes the lit place button, litIds no longer matches any cell (nothing lit), yet buildSituationBlock still emits 'The user is at <old place>' from activePlace.placeId/name. activePlace is deliberately NOT cleared by End conversation, so it persists across conversations. Re-pointing the lit button to a different place in the editor (contextRow save({placeId, name})) leaves activePlace with the OLD placeId while the button (matched by id) shows lit with the NEW name, so the panel says one place and the AI is told another. The same applies to a lit partner (until End conversation) and feeling. express-bands.js states the rule this breaks: a switched-on button must always show, otherwise it is 'still steering the AI with nothing on screen saying so'.

Fix as proposed by that reviewer: In app.js add `function reconcileActiveInfluencers()` that, for each of activePartner/activePlace/activeFeeling, looks up the current item by id in expressPanel.getModel().context; if missing, set the active value to null (and call dropGoalsFrom('partner'/'place') as the toggle handlers do); if present, replace the snapshot with the current item (so personId/placeId/name/text are current). Call it from the editor's onChange callback in app.js init (`onChange: () => { reconcileActiveInfluencers(); renderExpressPanel(); }`) and after a backup import that replaces express-panel.json.


Verifier correction: The reconciliation must skip a Practice Mode partner: app.js:2561 sets activePartner to an item with id 'practice:<personId>' that is never in the Context list, so a naive 'not found in the model -> null' rule would clear the practice partner on any editor change. Skip ids starting with 'practice:' (or skip partner reconciliation while practiceMode is on).
