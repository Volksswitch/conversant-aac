# CR-036: The launch-screen problem report is built before the data folder is connected, so it has no history or transcripts

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6313`
- **Also affects:** `app/js/app.js:6272-6287 (buildProblemReportText)`; `app/js/app.js:6211-6218 (buildUsageText reads listConversationLogs)`; `app/js/app.js:6818-6830 (errorsFromDisk)`; `app/js/app.js:1429-1430 (warmUpStorage is the only routine restore, run from handleStart)`; `app/js/app.js:617-621 (folderReconnectBtn shows a tap can call restoreDataFolder)`
- **Source:** app-e-06

**What a user notices.** A tester who uses 'If something is wrong — send a report' on the opening screen sends a report that says they have no saved conversations and carries none of the conversation text that would explain the problem, even though their data is all there.

**What is wrong.** sendProblemReportFromStart builds the report through buildProblemReportText, which calls buildUsageText (storage.listConversationLogs) and buildErrorReport (readConversationLog / errorsFromDisk). The data folder (FSA folder or the iPad's private storage) is only reconnected by storage.restoreDataFolder, which runs in warmUpStorage from handleStart and in the reconnect card - never before Start. The launch-screen button is only visible before Start, so dirHandle is always null at that moment: the usage summary reports no folder, transcripts read '[not available — no data folder...]', and the disk error fallback returns nothing. This is the same race CLAUDE.md records for the weekly report ('it counted the conversations in a folder not yet reopened'), which was fixed by moving the weekly send after Start; the launch-screen report was never given an equivalent.

**How it happens.** Windows with a data folder whose permission the browser retained, or an iPad (private storage needs no permission). Launch the app; on the opening screen tap 'If something is wrong — send a report'. The preview shows the usage summary for no data folder and every transcript as not available, although Start would connect the folder without any prompt.

**Suggested fix.** At the top of sendProblemReportFromStart, before buildProblemReportText, connect the folder if it is not already: `if (!storage.hasDataFolder()) { try { await withTimeout(storage.restoreDataFolder(), STORAGE_WARMUP_MS, 'report folder'); } catch { /* report without it */ } }`. The button tap is a user gesture, so restoreDataFolder may also ask for folder permission exactly as folderReconnectBtn does; if Ken prefers no prompt there, call it only when `!storage.supportsUserChosenFolder()` or when the stored handle's queryPermission is already 'granted'. Do not call adoptDataFolder (it redraws Settings); reading is enough.

> **Verifier correction to the fix (takes precedence):** The suggested restore is fine. Note that on Windows restoreDataFolderInner awaits idbGet before requestPermission, so the button's gesture may already be spent and the request may throw. That case is caught and simply leaves the folder unconnected, so it is harmless. Prefer connecting only when storage.supportsUserChosenFolder() is false, or when queryPermission is already 'granted', so no prompt appears from the launch-screen path.

**How to verify the fix.** Manual: on Windows with a granted folder and on an iPad Home Screen app, press the launch-screen report button and confirm the preview shows the real conversation counts and transcripts for errored conversations. Confirm Start still behaves normally afterwards (restoreDataFolder is idempotent via restoreInFlight).

**Do not break.** The launch-screen path must not depend on Settings and must not throw; keep the two-step see-then-confirm rule. Do not let the report wait forever on a permission prompt - use the existing withTimeout helper.

**Design reference.** CLAUDE.md 'THE REPORT HANGS OFF START, NOT OFF PAGE LOAD' (weekly report race) and 'Beta instrumentation and error reporting' (pre-start Report a problem affordance).

**Verification notes.** dirHandle is set only through setRoot, which is reached from restoreDataFolder, pickDataFolder and clearDataFolder. In app.js, restoreDataFolder is called only from the reconnect card (621) and from warmUpStorage, which handleStart calls (1518). The launch-screen button (startReportBtn, wired at 609-610) is shown before Start. At that point getConversationsDir() returns null, so listConversationLogs returns [], readConversationLog returns null, and errorsFromDisk returns []. The report therefore shows no conversations and the 'not available - no data folder' transcript line, even on an iPad, where device storage would connect with no prompt. This is the same race CLAUDE.md records for the weekly report, which was fixed only for that path.
