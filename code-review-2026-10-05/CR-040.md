# CR-040: New N, Reframe, choice chip or a context tap during "What?" repair empties the response cards

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/engine.js:428`
- **Also affects:** `app/js/app.js:3317-3374 (handleRegenerate)`; `app/js/app.js:4507-4560 (refreshForContextChange)`; `app/js/app.js:3470-3560 (handleReframe)`; `app/js/app.js:3428 (handleChoiceChip)`; `app/js/llm.js:585 (responses [] when is_repair_initiator)`; `app/js/app.js:4511 (merged duplicate: A context tap during 'What?' repair replaces the repair cards with ordinary replies)`
- **Source:** llm-engine-03, app-d-06

**What a user notices.** If the other person asks "What?" and the user, instead of picking one of the four repeat options, presses New 4 or taps a person, feeling or place button, all four cards disappear and the user is left with nothing to tap except the Express Panel or typing.

**What is wrong.** In REPAIR_OF_SELF the palette is built by the engine (respeak/rephrase/expand/retry), but generateOptions renders it with showPalette, so currentStatic.kind is null, lastPalette is non-empty and currentPartnerText holds the partner's "What?". All refresh paths therefore proceed: they call llm.generateResponses for the same turn, the model again classifies it is_repair_initiator and, per the prompt, returns "responses": []. engine.refreshPalette ignores the classification and replaces the repair palette with paletteFromResponses([]) = []. No anomaly is logged on these paths (generationOutcome is only consulted in generateOptions), so the cards just vanish.

**Evidence.**

```
engine.js:428-431:
    export function refreshPalette(responses) {
        state.palette = paletteFromResponses(responses);
        return getSnapshot();
    }
llm.js:585: 'ALWAYS return all four ... the ONLY time you return "responses": [] is when is_repair_initiator is true'
app.js:3323-3333 (handleRegenerate) only skips when currentStatic.kind is set or there is no partner text/palette; app.js:4511-4512 (refreshForContextChange) has the same guards; app.js:3361 / 4544: `const snap = engine.refreshPalette(result.responses); ... showPalette(snap.palette);`
```

**How it happens.** User says something; partner: "What?"; repair palette shows. User taps a Feeling button (context refresh) or New 4. ~4s later the palette area is empty, mode still REPAIR_OF_SELF.

**Suggested fix.** Two parts. (1) In engine.refreshPalette, never replace the palette with nothing: `const next = paletteFromResponses(responses); if (next.length) state.palette = next; return getSnapshot();`. (2) In app.js, at the top of handleRegenerate, handleChoiceChip, the response-rework branch of handleReframe, and refreshForContextChange, return early (refreshForContextChange: `return false`) when `engine.getMode() === engine.MODE.REPAIR_OF_SELF`; for handleRegenerate in that mode, optionally re-run prefetchRepairOptions(++generationToken) instead so New N gives fresh rephrase/expand wordings.

> **Verifier correction to the fix (takes precedence):** Both parts of the suggested fix are sound. One addition: in REPAIR_OF_SELF, refreshForContextChange should return false before it bumps generationToken. Otherwise the pending prefetchRepairOptions result is thrown away, and the rephrase/expand cards are left showing only their hints.

**How to verify the fix.** tests/engine.test.mjs: set lastUserUtterance via selectResponse, ingest {classification:{is_repair_initiator:true}, responses:[]}, then refreshPalette([]) and assert the palette still has 4 entries with REPAIR_* slots. Manually in Practice Mode with a partner line "What?": tap a Feeling button and New 4; the four repair cards must remain.

**Do not break.** refreshPalette must still never re-ingest the classification (duplicate FPP). Do not stop New N from paging static palettes. Keep the four repair cards in fixed order (Ken, Sep 7 2026).

**Design reference.** CLAUDE.md 'WHEN THE RESPONSE CARDS CHANGE - the whole rule' (cards are replaced, never emptied while a conversation is in progress); repair-of-self palette notes in engine.js.

**Verification notes.** In node, I put the engine in REPAIR_OF_SELF with a 4-card palette, then called refreshPalette([]). The palette became 0 cards with mode still REPAIR_OF_SELF. generateOptions renders the repair palette through showPalette and sets currentStatic.kind=null and lastPalette to the repair palette. currentPartnerText holds the 'What?'. The guards in handleRegenerate (3323-3333) and refreshForContextChange (4511-4512) therefore pass, and neither checks the mode. The model gets the same 'What?' turn, and the prompt (llm.js:585) tells it to return responses [] when is_repair_initiator. If it does, the palette empties. If it ignores the rule, the repair cards are replaced by ordinary cards while the mode stays REPAIR_OF_SELF, which is also wrong. These paths do not consult generationOutcome, so nothing is logged. Bumping generationToken also discards an in-flight prefetchRepairOptions.

<details><summary>Merged duplicate app-d-06: A context tap during 'What?' repair replaces the repair cards with ordinary replies</summary>

refreshForContextChange guards static palettes (currentStatic.kind) but not the repair-of-self palette, which is an AI-mode palette rendered through showPalette with op entries (re-speak/rephrase/expand). With currentPartnerText = 'What?' and lastPalette non-empty, a context tap calls llm.generateResponses for the 'What?' turn and engine.refreshPalette(result.responses) overwrites the repair palette while the engine stays in MODE.REPAIR_OF_SELF, so the user loses the one-tap repair options (and the pre-generated rephrase/expand text) and the status line says 'Select a response'.

Fix as proposed by that reviewer: At the top of refreshForContextChange add `if (engine.getSnapshot().mode === engine.MODE.REPAIR_OF_SELF) return false;` (or equivalently `if (lastPalette.some((m) => m && m.op)) return false;`). The new context still applies at the next generation. Add the same guard to handleRegenerate after its static-palette branch.


Verifier correction: Guard on engine mode (`engine.getSnapshot().mode === engine.MODE.REPAIR_OF_SELF`) rather than on `m.op`. Add the same guard to handleRegenerate, which should probably do nothing (or re-run the repair prefetch) in that mode rather than generate ordinary replies.
