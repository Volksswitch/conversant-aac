# CR-041: A blank Always phrase becomes a live, invisible button that wipes the suggestions and records an empty turn

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-bands.js:243`
- **Also affects:** `app/js/express-editor.js:124-140`; `app/js/express-editor.js:261-267`; `app/js/express-bands.js:217-221`; `app/js/ui.js:638-647`; `app/js/ui.js:828-830`; `app/js/app.js:5182-5188`; `app/js/app.js:3692-3725`
- **Source:** express-01

**What a user notices.** If a phrase in the Always band is left empty (for example after pressing Add a phrase and not typing, or after clearing its words), the panel shows a blank button that still works. Tapping it mid-conversation silently throws away the suggested replies, stops listening, and saves an empty statement as if the user had said something.

**What is wrong.** addPhrase() saves a new phrase with text '' immediately (so it exists before anything is typed), and the text box commits '' if the user deletes the words. composePanel() places every Always item into the band without filtering blank text (only flexFill() skips blank words, so the Flex band is protected and the Always band is not). ui.renderExpressPanel only renders an outline for !item or type 'empty', so a phrase with text '' is drawn as a real phrase button with an empty face, empty title and empty aria-label. Its click goes to handleSpeakExpressItem -> speakAsUserTurn('', ''), which has no empty-text guard: it records palette abandonment, stops STT, clears the palette, calls engine.selectResponse({text:''}) (taking the floor and popping the partner's turn) and commits an empty user turn to the conversation file. This also contradicts the Express Panel Design rule 'No button can go blank'.

**Evidence.**

```
express-editor.js:126 `const item = { id: makeId(), type: 'phrase', text: '' };` then :130 `saveBand(band, list);`
express-bands.js:243 `const always = (model.always || []).filter(Boolean);` (no text check) vs :219-220 `String(item && item.text || '').trim().toLowerCase(); if (!word || seen.has(word)) continue;` (Flex skips blanks)
ui.js:828 `const cellEl = (!item || item.type === 'empty') ? buildUndefinedCell(index, span) : buildItemBtn(item, span);`
ui.js:643-644 `b.title = item.text; b.setAttribute('aria-label', item.text);`
app.js:5187 `await speakAsUserTurn(phrase.text, phrase.speak || phrase.text, 'express');`
app.js:3717 `clearPalette();` with no guard on empty text above it.
```

**How it happens.** Settings > Express Panel > Always > Add a phrase, then close Settings without typing. Start a conversation; the partner speaks and four response cards appear. Tap the blank button in the Always band: the cards vanish, listening stops, the partner's turn is closed, and the saved conversation contains a user turn with empty text.

**Suggested fix.** Two small changes. (1) In app.js handleSpeakExpressItem, after the editedInSettings check, add `if (!String(phrase.text || '').trim() && !String(phrase.speak || '').trim()) return;` so a blank phrase can never speak or take the floor. (2) In ui.js renderExpressPanel, treat a phrase whose text is blank as an undefined cell for drawing: change the condition at line 828 to `(!item || item.type === 'empty' || (item.type === 'phrase' && !String(item.text || '').trim()))`. Keep the pickedId marking below it working (it reads item.id, which is still present). Optionally, in express-bands composePanel, leave the item in place (do not filter it out of the Always list) so the band's positions do not shift while the user is typing a new phrase.

> **Verifier correction to the fix (takes precedence):** The suggested renderer change contradicts its own verification step: buildUndefinedCell wires a Settings tap to onDefineCell(index) -> handleDefineCell -> addToBand, which creates ANOTHER blank phrase instead of selecting the existing one. Either draw a blank phrase as an outline only when there is no onDefineCell (outside Settings) and keep buildItemBtn in Settings so editedInSettings/focusItem still selects it, or in buildUndefinedCell take an optional item and, when the item exists, bind the Settings tap to the item's edit handler (onSpeak path, which calls editedInSettings) rather than onDefineCell. The guard in handleSpeakExpressItem must come after the editedInSettings check, as suggested.

**How to verify the fix.** Add a test in tests/express-bands.test.mjs is not enough on its own (the renderer and handler are where the fix lives); manually: add a blank Always phrase, leave Settings, confirm the cell draws as an empty outline with aria-label 'Empty button slot', and that tapping it during a live conversation leaves the cards and the microphone untouched. Back in Settings, tapping that outline must still select/allow editing (onDefineCell) rather than creating a second blank phrase - verify the picked ring appears on it.

**Do not break.** Do not change the cell's box (Rule 1 keyguard geometry): only switch which builder draws it, and both builders already share .ep-btn sizing. Do not filter the blank item out of the Always list in composePanel, or every phrase after it shifts one cell while the user is typing.

**Design reference.** Conversant AAC Express Panel Design.docx section 5 ('No button can go blank'); CLAUDE.md UI Layout Rule 1

**Verification notes.** addPhrase (express-editor.js:126-130) saves {type:'phrase', text:''} at once; express-panel normalize keeps it (no text filter for always); composePanel (express-bands.js:243) only filters falsy items, while flexFill skips blank words. ui.js:828 draws it through buildItemBtn with an empty face/title/aria-label. handleSpeakExpressItem -> speakAsUserTurn('', '') has no empty guard: noteUserAction/paletteAbandoned, stt.stopListening, clearPalette, engine.selectResponse({text:''}) and commitExchange push an empty user turn. The cited 'No button can go blank' line in the design document is about Flex fill, not empty phrase text, so it is a weak reference, but the defect stands on its own.
