# CR-044: Side Layout 10 has no 123 key: question mark, apostrophe and every other symbol are unreachable, and the number button traps the user on the symbols page

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/keyboard-layouts.js:86`
- **Also affects:** `app/js/keyboard.js:864`; `app/js/keyboard.js:871`; `app/js/app.js:3418`
- **Source:** keyboard-03

**What a user notices.** Someone who picks Side Layout 10 can never type a question mark, an apostrophe (as in "don't"), an exclamation mark or any other symbol. If they use the number button to answer a 'how many' question, the keyboard opens on a symbol page with no key to get back to the letters.

**What is wrong.** S10 rows are letters, `z , . ⌫ ⇧`, two digit rows, and `[SP(4), EN()]` - there is no PG() (page) cell. All symbols other than comma and period live only on the generated symbols page, which is reached solely through the page key, so they are unreachable on S10. The layout-options document says S10's 123 key is 'freed for symbols only' and 'non-digit symbols still need a toggle', i.e. a toggle was intended. Separately, showFor(field, {page:'symbols'}) (used by the number chip via openComposer({page:'symbols'})) sets page='symbols' unconditionally; on S10 the generated symbols page also has no ABC key, so the letters cannot be reached until the keyboard is hidden. Data check: every layout except S10 contains a 'page' action (scripted check of LAYOUTS).

**Evidence.**

```
keyboard-layouts.js:86-91 `S10: { ... rows: [ r('a b c d e'), ..., [C('z'), C(','), C('.'), BK(), SH()], r('1 2 3 4 5'), r('6 7 8 9 0'), [SP(4), EN()], ]},` (no PG()); keyboard.js:871 `if (opts.page === 'symbols' || opts.page === 'letters') page = opts.page;`; keyboard-layouts.js:206 `if (cell.kind === 'action' && cell.action === 'page') return PG('ABC', cell.span);` (only path to ABC). Keyboard Layout Options doc, S10: 'the 123 key is freed for symbols only' / 'non-digit symbols still need a toggle'.
```

**How it happens.** Settings > Express Panel & Keyboard: dock = side, Side Layout 10. Open 'In my own words' and try to type 'Are you OK?' - there is no '?' anywhere. Or: partner asks a numeric question, tap the number button; keyboard opens on symbols, no ABC key, letters unreachable.

**Suggested fix.** 1) Give S10 a page key, e.g. last row `[PG(), SP(3), EN()]` (keeps the row at 5 columns). 2) In keyboard.js showFor(), only honour opts.page === 'symbols' when the active layout has a page key: `const rows = (LAYOUTS[currentDock === 'side' ? sideLayoutId : bottomLayoutId] || {}).rows || []; const hasPage = rows.some(r => r.some(c => c.action === 'page'));` and skip switching to symbols when !hasPage (S10 already shows digits on its letters page). Note show() calls setDock() which sets currentDock, so compute after setting the dock, or use dockFor(field). 3) Add a test in tests/keyboard-layouts.test.mjs: every layout contains exactly one cell with action 'page'.

**How to verify the fix.** tests/keyboard-layouts.test.mjs: assert every layout has a page key (fails today on S10). Manual: on S10 tap 123 and confirm '?', "'" and '!' are present and ABC returns to letters.

**Do not break.** Changing S10's last row moves the space key's hole: any keyguard already cut for S10 must be re-cut; say so in the release note. Keep panelRoles behaviour (the first space key is the Express Panel compose cell) and the dock-congruence test passing.

**Design reference.** Documents/Conversant AAC Keyboard Layout Options.docx (S10); CLAUDE.md UI Layout Rule 1 (keyguard geometry)

**Verification notes.** Ran a node script over LAYOUTS: S10 is the only layout with no cell whose action is 'page'. The only route to the symbols page, and from it back to ABC, is the page key (buildSymbolsPage turns PG into PG('ABC')), so on S10 '?', '\'' and '!' cannot be reached from the letters page. showFor() sets page='symbols' unconditionally when opts.page is passed, and handleRangeChip (app.js:3418) calls openComposer({page:'symbols'}). On S10 the generated symbols page has no ABC key, so the letters cannot be reached until the keyboard is hidden.
