# CR-047: Undo/Redo in review leaves the Composition Pane open, so the typed sentence is then saved against a different turn

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:518`
- **Also affects:** `app/js/review-ui.js:506-516 (goTo closes the composer)`; `app/js/review-ui.js:774-806`
- **Source:** review-backup-04

**What a user notices.** While typing what they would rather have said, if the person presses Undo, the screen can jump to an earlier exchange with the typing box still open; pressing Speak then files their sentence under the wrong exchange.

**What is wrong.** goTo() calls stopEditing() and closeComposer() before changing `at`, but stepHistory() only calls stopEditing() and then moves `at` to the history entry's turn. The Command Bar stays tappable while the composer overlay is open (the composer only covers the response footprint), and the review capture listener handles Undo/Redo. onComposerClick then records `setTypedAnswer(review, turn(), text)` or `setSteer` using the NEW turn(). Even when the turn does not change, the open composer keeps text taken from the pre-undo entry.

**Evidence.**

```
review-ui.js:518-529
function stepHistory(which) {
    const got = which === 'undo' ? history.undo(review, turn().key) : history.redo(review, turn().key);
    if (!got) return;
    review = { ...got.state, reached: ... };
    stopEditing();
    const i = conv.turns.findIndex((t) => t.key === got.turnKey);
    if (i >= 0) at = i;

    closeComposer();

review-ui.js:798-800
    if (btn.id === 'speakBtn') {

```

**How it happens.** Review turn 2: mark a card (answer). Go to turn 5, tap My own words, type 'I want tea'. Press Undo (undoes the turn-2 answer, at becomes turn 2). Composer is still open; press Speak - 'I want tea' is recorded as the turn-2 answer.

**Suggested fix.** In stepHistory, call `closeComposer();` right after `stopEditing();` (same order as goTo), and also set `userPaged = false;` as goTo does.

**How to verify the fix.** Manual in the browser (review-ui is DOM-bound): reproduce the scenario above; after the fix Undo must close the box and nothing is recorded on turn 2. Optionally a source-level guard test in tests/ asserting stepHistory's body contains closeComposer().

**Do not break.** closeComposer must still hide the keyboard (it already calls keyboard.hideKeyboard). Do not change Undo's rule that reached never decreases.

**Design reference.** Conversant AAC Conversation Review.docx §6 (Undo steps back one action), CLAUDE.md 'Conversation Review - first build'

**Verification notes.** goTo() calls stopEditing() and closeComposer() before moving `at`; stepHistory() (review-ui.js ~518) calls only stopEditing() and then sets `at` from got.turnKey. The Command Bar's capture listener (onBarClick on #listenControls) still handles Undo/Redo while composerOpen is true, since the composer overlay covers only the response footprint. createHistory.undo returns the turnKey of the entry pushed, so undoing an answer made on turn 2 while sitting on turn 5 moves `at` to turn 2 with the composer still open. onComposerClick then calls model.setTypedAnswer(review, turn(), text) against the new turn. The suggested fix (closeComposer() plus userPaged = false in stepHistory, matching goTo) is correct.
