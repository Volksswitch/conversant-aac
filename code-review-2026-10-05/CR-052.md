# CR-052: Choosing the FLAT reply on a levity Sound Check item is reported to the AI as choosing the lighter one, granting joke permission

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/voice.js:302`
- **Also affects:** `app/js/voice.js:305-307`; `app/js/voice.js:330-335`; `app/js/sound-check-items.js:258-287 (levity items and their `leads`)`
- **Source:** graph-voice-02

**What a user notices.** A user who picks the plain, no-joke answer on all three "awkward moment" questions is described to the AI as someone who likes to lighten things up, so the app starts offering joking replies in their voice that they never asked for.

**What is wrong.** buildBlock splits Sound Check answers by the ITEM's dimension only: every answer to a 'levity' item goes into chosenLevity regardless of which candidate was chosen. Each levity item deliberately offers a flat candidate alongside lighter ones (levity-dontknow and levity-late lead with the flat reply at index 0; levity-mishap leads with the light one, so its flat reply is the last candidate). The block then tells the model 'this user picked the lighter one... Choosing the lighter option here IS this user telling you a lighter reply suits them, so one light response is welcome'. CLAUDE.md records that choosing the LIGHTER option is permission; choosing the flat one is the opposite signal, and it is being converted into permission. Verified by running voice.js in node: recording the three flat candidates produces the 'picked the lighter one... one light response is welcome' paragraph listing exactly those three flat sentences.

**Evidence.**

```
app/js/voice.js:305-307 `const chosenLevity = answered
        .filter(([id]) => (getItem(id) || {}).dimension === 'levity')
        .map(([, a]) => a.choice);`
app/js/voice.js:332 `'Offered a flat reply and a lighter one ... this user picked the lighter one. This is how they take the edge off:'`
app/js/voice.js:334 `'... Choosing the lighter option here IS this user telling you a lighter reply suits them, so one light response is welcome ...'`
app/js/sound-check-items.js:259-266 `id: 'levity-dontknow', dimension: 'levity', leads: 'flat', ... candidates: ["No, I don't know that one.", ...]`
app/js/sound-check-items.js:269-276 `id: 'levity-mishap', ... leads: 'light', candidates: ['Well, that went beautifully.', ..., "Fine, thanks. Sorry about that."]`
```

**How it happens.** About Me > How I Sound: on the three levity items pick "No, I don't know that one.", "Fine, thanks. Sorry about that." and "It's fine, honestly.". Leave the humor module (B2) unanswered. The next generation's system prompt contains 'this user picked the lighter one ... one light response is welcome', and the model is licensed to put a joke in the PREFERRED slot.

**Suggested fix.** Add an exported helper to sound-check-items.js, e.g. `export function isLighterChoice(item, text) { if (!item || item.dimension !== 'levity') return false; const i = item.candidates.indexOf(text); if (i < 0) return false; const flat = item.leads === 'light' ? item.candidates.length - 1 : 0; return i !== flat; }`. In voice.buildBlock, compute chosenLevity as answers whose item is levity AND isLighterChoice(item, a.choice); route a flat levity choice into the ordinary `chosen` list instead (it is a bland exemplar, safe to reuse). If chosenLevity is empty, the levity paragraph is not emitted. Keep the `leads` convention documented in the item bank so a new levity item stays decodable.

**How to verify the fix.** Add to tests/voice.test.mjs (or create it beside the existing voice tests): record the three flat candidates and assert buildBlock does NOT contain 'picked the lighter one' and DOES contain those sentences under the ordinary examples; record the three light-end candidates and assert the levity paragraph is present; mutation-check by reverting the filter.

**Do not break.** Keep levity exemplars in their own list with the never-reuse instruction (CLAUDE.md B2 decision); a flat reply moved to the bland list must not carry that instruction. An explicit B2 humor decline must still override.

**Design reference.** CLAUDE.md 'B2 — humor': 'DECIDED: choosing the lighter option in Sound Check IS permission' and 'Silence is not permission'.

**Verification notes.** voice.js:305-307 puts every answer to a levity item into chosenLevity regardless of which candidate was picked, and the paragraph at 330-335 tells the model 'this user picked the lighter one ... one light response is welcome'. The bank's levity items each include a flat candidate (index 0 for levity-dontknow and levity-late, last for levity-mishap). Ran voice.js in node with the tests/env.mjs shim: recording the three flat candidates makes buildBlock contain 'picked the lighter one'. CLAUDE.md's B2 decision grants permission for choosing the LIGHTER option only; converting a flat choice into permission contradicts it. An explicit B2 decline still overrides via the prompt wording, so the trigger needs the humor module unanswered, which is the default state.
