# CR-053: The five 'starting things off' Sound Check answers are cut from the prompt when the user answers the bank in order

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/voice.js:311`
- **Also affects:** `app/js/voice.js:300-304`; `app/js/sound-check-items.js:206-254 (initiating items placed after the 12 responsive ones)`; `app/js/worldview-ui.js:489-496 (renders items in bank order)`
- **Source:** graph-voice-03

**What a user notices.** The answers a user gives about how they open a conversation, ask for help or say goodbye never reach the AI if they answered the earlier questions first, so the effort is wasted and conversation starters keep sounding like the app instead of the user.

**What is wrong.** Non-levity Sound Check choices are listed with `chosen.slice(0, 12)`. Object.entries(p.soundCheck) returns answers in first-answered order (re-answering an item keeps its original key position). The bank has 12 responsive items followed by 5 initiating items (17 non-levity), rendered in that order on the How I Sound page. A user who works down the page answers the 12 responsive items first, so all 5 initiating items fall past index 12 and are silently dropped. The initiating items were added specifically to close the gap that 'none of the initiating text is governed by anything the user has told us'. Verified in node: recording a choice for every item in bank order, none of the initiate-* chosen sentences appear in buildBlock's output.

**Evidence.**

```
app/js/voice.js:311 `for (const t of chosen.slice(0, 12)) lines.push(`  "${t}"`);`
app/js/sound-check-items.js:206-209 comment `// -- INITIATING ITEMS (no `partner` -- nobody has spoken) ... Placed at the END as a coherent group`
app/js/worldview-ui.js:489 `for (const item of SOUND_CHECK_ITEMS) {`
```

**How it happens.** About Me > How I Sound: pick a reply for every question from top to bottom. Generate suggestions and inspect the system prompt: 'Examples of how this user prefers to reply' lists only the 12 responsive choices; 'Can you help me?' / 'I should get going.' etc. are absent.

**Suggested fix.** Raise the cap so the whole bank fits, e.g. `const MAX_CHOSEN = SOUND_CHECK_ITEMS.filter((i) => i.dimension !== 'levity').length;` (import SOUND_CHECK_ITEMS alongside getItem) and use `chosen.slice(0, MAX_CHOSEN)`. If a cap is wanted for prompt size, select in bank order rather than answer order and guarantee the initiating items are included (e.g. take every initiating choice plus the first N responsive ones). Update the 'matches what buildBlock will show' comment in voice-harvest.js only if MAX_EXEMPLARS is touched (it is a separate list; leave it at 12).

**How to verify the fix.** In tests/voice.test.mjs: record a choice for every item in SOUND_CHECK_ITEMS order and assert each initiate-* choice appears in buildBlock(); mutation-check by restoring slice(0, 12).

**Do not break.** The voice block sits in the cached system-prompt prefix; a few more short lines are fine, but the block must stay byte-stable between turns (do not order by anything time-dependent).

**Design reference.** CLAUDE.md 'GAP IN THE SHIPPED BANK ... every one of the twelve items is RESPONSIVE' and the sound-check-items.js header 'A GAP TO FILL'.

**Verification notes.** buildBlock lists non-levity choices with `chosen.slice(0, 12)` (voice.js:311) in Object.entries insertion order. The bank has 12 responsive items then 5 initiating items (17 non-levity), rendered top to bottom by worldview-ui.js. Ran it in node: recording a choice for every item in bank order, none of the five initiate-* choices appear in buildBlock's output. Because 17 > 12, at least five non-levity answers are always dropped whatever order is used; answering in page order guarantees the dropped ones are exactly the initiating items the bank was extended to cover.
