# CR-055: tap-guard.js is missing from the service worker's precache list, so the app cannot start offline after a first install

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/sw.js:39`
- **Also affects:** `app/js/app.js:66`; `app/index.html:16`; `app/sw.js:1 (merged duplicate: tap-guard.js is missing from the service worker's offline file list)`; `app/sw.js:39 (merged duplicate: tap-guard.js is missing from the service worker's offline precache list)`
- **Source:** reporting-platform-04, x-security-09, x-contracts-07

**What a user notices.** Someone who installs the app, then opens it later with no internet (in a car, a hospital basement), gets a broken start instead of the Express Panel and 'In my own words', which are supposed to work without a connection.

**What is wrong.** app.js statically imports './tap-guard.js', but SHELL in sw.js does not list it (every other module in app/js is listed; checked with a directory diff). On the first visit the page's modules load from the network BEFORE the service worker controls the page, so tap-guard.js is never runtime-cached; install() precaches only SHELL. On a later offline launch networkFirst finds no cached copy, returns Response.error(), the ES module graph fails, and app.js never runs. (Online launches mask it, because networkFirst caches the file the first time it is fetched through the worker.) apple-touch-icon.png is also absent from SHELL (cosmetic). Nothing tests that SHELL matches the files shipped.

**Evidence.**

```
app/js/app.js:66: `import * as tapGuard from './tap-guard.js';`
app/sw.js:39-114: SHELL lists './js/app.js' ... './js/metrics.js' but no './js/tap-guard.js' (diff of `ls app/js` against SHELL: only tap-guard.js missing).
app/sw.js:184-202: no cache hit and not a navigation -> `return response || Response.error();`
```

**How it happens.** 1) Fresh device, open the app online once (service worker installs). 2) Close it. 3) Turn on airplane mode and open the app from the Home Screen / installed shortcut. 4) The shell loads from cache but the module import of tap-guard.js fails and the app does not start.

> **Verifier correction to the trigger:** The realistic trigger is: install the app, then launch it offline for the first time before any second online launch. After an update, the online reload normally re-caches the file, so the window is narrow. That is why medium, not high.

**Suggested fix.** Add `'./js/tap-guard.js',` to SHELL (next to './js/sections.js' or alphabetically) and `'./apple-touch-icon.png',`. Add a test (e.g. tests/sw-shell.test.mjs) that reads app/sw.js, extracts the './js/*.js' entries and asserts they equal the set of files in app/js, so the next new module cannot be forgotten.

**How to verify the fix.** Run the new test (fails before, passes after). Manually: in Chrome DevTools > Application, unregister the worker and clear storage, load once online, then set Network to Offline and reload: the app must reach the Start screen.

**Do not break.** cache.addAll is atomic - every listed path must exist or install fails; list only files that ship.

**Design reference.** CLAUDE.md 'The app updates itself on launch and on Start' and 'AI is an enhancement layer, not a hard dependency'

**Verification notes.** Diffing app/js/*.js against SHELL shows tap-guard.js is the only module missing, and app.js:66 imports it statically. On a first visit the modules load before the worker controls the page; install precaches SHELL only; the controllerchange reload is skipped on first install (hadController false). So tap-guard.js is not in the cache until some later online launch fetches it through the worker. An offline launch before that point fails in networkFirst (no cache, Response.error()) and the module graph does not load. Every activate also deletes the old cache, but the reload that follows an update is online and re-caches the file, so the gap is mainly 'first install, then offline'. No test compares SHELL with app/js. apple-touch-icon.png is also missing from SHELL (cosmetic).
