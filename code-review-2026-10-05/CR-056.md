# CR-056: The documents' British-phrase check never matches anything, and the app-text version cannot see a phrase broken across a line

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `scripts/doc-tests/check-docs.py:452`
- **Also affects:** `tests/american-spelling.test.mjs:80`; `tests/american-spelling.test.mjs:87`; `writing-conventions.json:433`; `scripts/doc-tests/check-docs.py:454`
- **Source:** g-test-suite-01

**What a user notices.** The check that is supposed to stop British phrases like "tick the box" from reaching the manuals does nothing at all, so any such phrase in a document is reported as clean. The app-text check catches them only when the phrase sits on one line.

**What is wrong.** Rule L1 in check-docs.py builds each britishPhrases pattern as re.sub(r'\s+', r'\\s+', re.escape(brit)). On Python 3.7+, re.escape escapes a space as a backslash followed by a space ('tick\ the\ box'). The re.sub then replaces only the space, leaving the escaping backslash in front of the inserted \s+, so the pattern becomes 'tick\\s+the\\s+box' = a literal backslash followed by one or more 's'. It can never match real prose; the phrase half of rule L1 is dead for every document, while 'check docs' reports clean. The JavaScript test has a separate over-escaping bug of the same family: b.replace(/\\s+/g, '\\\\s+') in a regex literal matches a literal backslash-s (never present), so the substitution never happens and phrases only match with exactly one ordinary space; the comment at line 77 and writing-conventions.json both claim 'flexible whitespace' so a phrase wrapped across a line still matches, which is false. findPhrases' key normalisation (line 87) has the same dead /\\s+/g. source-hygiene.test.mjs only catches the opposite failure (an escape eaten to a control byte), not a doubled one, so nothing caught either.

**Evidence.**

```
scripts/doc-tests/check-docs.py:452: pat = r'\b%s\b' % re.sub(r'\s+', r'\\s+', re.escape(brit))
tests/american-spelling.test.mjs:80: ? new RegExp(`\\b(?:${BRITISH_PHRASES.map(([b]) => b.replace(/\\s+/g, '\\\\s+')).join('|')})\\b`, 'gi')
tests/american-spelling.test.mjs:77: * Whitespace is flexible so a phrase broken across a line still matches
Experiment (scratchpad phrase.py, same construction): pattern '\\btick\\\\s+the\\\\s+box\\b'; 'please tick the box' -> False; 'it can be ticked' (phrase 'be ticked') -> False. Experiment phrase2.mjs with the test's exact expression: 'please tick the box' -> true, 'please tick\nthe box' -> false, 'please tick  the box' -> false.
```

**How it happens.** 1) Put the sentence "Please tick the box to show joke voices." in any User Manual paragraph. 2) Run python scripts/doc-tests/check-docs.py. 3) It reports the manual clean. Separately, in CHANGELOG.md write a bullet ending "...you can tick" and start the next wrapped line with "the box"; npm test stays green.

**Suggested fix.** check-docs.py line 452: build the pattern from the words, not from the escaped whole: pat = r'\b%s\b' % r'\s+'.join(re.escape(w) for w in brit.split()). tests/american-spelling.test.mjs line 80: change to b.trim().split(/\s+/).map(escapeRegExp).join('\\s+') (add a small escapeRegExp helper: s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')); line 87 and 88: replace /\\s+/g with /\s+/g. Write these edits with the Write/Edit tool, never a heredoc (CLAUDE.md source-hygiene rule). Also at check-docs.py:454 the proper-noun exemption skips the WHOLE paragraph when an exempt phrase appears anywhere in it; mirror the JS test instead and strip the exempt phrase from the text before matching.

**How to verify the fix.** Add to tests/american-spelling.test.mjs a test 'the phrase detector matches a phrase wrapped across a line' asserting findPhrases('tick\nthe box','x') and findPhrases('tick  the box','x') each return one hit. For the Python side, add a case to the doc-tests self-check (or a new tests/check-docs-phrases.test.mjs that shells out to python -c and imports l1 logic) feeding a fake paragraph 'Please tick the box' and expecting one L1 finding. Re-run check docs over Documents/ (a fixed-pattern scan today finds no hidden hits, so the run should stay clean).

**Do not break.** Keep the explicit-list approach (CLAUDE.md: never a pattern). Do not widen the per-paragraph exemption logic in a way that starts flagging the Irish persona's exempt phrases. Write the regex edits with the Write tool so no quoting layer alters the backslashes.

**Design reference.** CLAUDE.md 'IT IS AMERICAN ENGLISH, NOT AMERICAN SPELLING' (britishPhrases is the mechanism that makes vocabulary enforceable); 'A test suite for the documents — check docs'.

**Verification notes.** Checked the real bytes of both lines. Python: re.escape('tick the box') gives 'tick\ the\ box'; the re.sub swaps only the space for \s+, leaving the escaping backslash, so the pattern becomes '\btick\\s+the\\s+box\b' (a literal backslash followed by s+).
