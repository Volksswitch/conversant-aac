# CR-057: A partial restore is announced as a complete one

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6476`
- **Also affects:** `app/js/app.js:6544-6551 (importPackageText only logs done.failed)`; `app/js/data-transfer.js:367-371 (applyPackage contract: report honestly)`; `app/js/data-transfer.js:396-401 (store write failures)`; `app/js/data-transfer.js:439-443 (conversation write failures counted silently)`; `app/js/data-transfer.js:454-459 (sound file failures)`; `app/js/app.js:6547 (merged duplicate: The restore-finished card never mentions what failed or what was skipped (conversations, sounds, data files))`
- **Source:** app-e-03, review-backup-03

**What a user notices.** When a backup only partly restores (for example the device runs out of storage space), the app still says 'Your backup has been imported' and restarts, so the person may delete the backup or wipe the old device believing everything came across, and lose the missing parts for good.

**What is wrong.** applyPackage returns `failed` (stores whose cache write failed, 'Sound files') and `conversations` (count actually written, which can be lower than the number in the file because writeConversationLog returning false is silently skipped). Its own comment says it 'Returns what was actually restored, so the caller can report it honestly rather than claiming success for pieces that failed.' importPackageText only writes done.failed to the error log and then calls offerRestart, which reports heldBack, renamed, legacySettings and profiles - but never done.failed and never a conversation shortfall. The notice therefore always reads 'Your backup has been imported.'

**How it happens.** Restore a large backup on an iPad Safari tab near its storage quota: the localStorage write for the Express Panel cache throws QuotaExceededError and several conversation writes return false. The busy card closes and the notice says 'Your backup has been imported. Conversant AAC needs to restart to use it.' Nothing tells the user their Express Panel and 40 conversations did not come across.

**Suggested fix.** In offerRestart, before the final 'needs to restart' line, add: `if (done && done.failed && done.failed.length) bits.push('Some parts could not be restored: ' + done.failed.join(', ') + '. Keep your backup file.');` and, by passing the number of conversations in the file (e.g. have importPackageText pass `{ ...done, conversationsInFile: (pkg.conversations || []).length }`), add `if (done.conversationsInFile > done.conversations) bits.push(`${done.conversationsInFile - done.conversations} saved conversation(s) could not be restored.`);`. Also change the opening sentence to 'Your backup has been partly imported.' when either condition holds.

> **Verifier correction to the fix (takes precedence):** Separate the no-data-folder case from real write failures. On a computer with no data folder chosen, writeConversationLog returns false for every conversation, so the message should say the conversations need a data folder, matching the existing profile sentence. It should not say they 'could not be restored'. Check storage.hasDataFolder() (or the backend) when wording the shortfall. Pass the count in the file from importPackageText, as suggested.

**How to verify the fix.** Add a test in tests/data-transfer.test.mjs that makes localStorage.setItem throw for one cache key and asserts applyPackage returns that label in `failed` (already the contract). Manual: stub storage.writeConversationLog to return false for one id, run Import, and confirm the restart notice names the shortfall.

**Do not break.** showNotice must stay undismissable except by its button; keep the held-back / renamed sentences. Plain American English, no file or code names in the notice.

**Design reference.** data-transfer.js applyPackage comment ('report it honestly rather than claiming success for pieces that failed'); CLAUDE.md 'Confirm before destroying significant work'.

**Verification notes.** applyPackage (data-transfer.js:376-468) pushes a store's label into restored.failed when its localStorage write fails, adds 'Sound files' when a clip write fails, and counts conversations only when writeConversationLog returns true. writeConversationLog returns false with no folder, or on any write error. importPackageText (app.js:6544-6551) only logs done.failed. offerRestart (6476-6504) reports heldBack, renamed, legacySettings and the profile shortfall, but never done.failed or a conversation shortfall. The notice therefore always begins 'Your backup has been imported.'

<details><summary>Merged duplicate review-backup-03: The restore-finished card never mentions what failed or what was skipped (conversations, sounds, data files)</summary>

importPackageText only logs done.failed to the error log; offerRestart reports heldBack settings, renamed profiles, legacy settings and profiles-without-folder, but never `done.failed` ('Sound files', data files whose cache write failed) and never compares `done.conversations` with the number of conversations in the package. writeConversationLog returns false without a data folder or on any write error, so conversations can be dropped wholesale while the card claims success. The design rule recorded in data-transfer.js ("Returns what was actually restored, so the caller can report it honestly rather than claiming success for pieces that failed") is not honored by the caller.

Fix as proposed by that reviewer: In applyPackage record `restored.conversationsInFile = convos.length` and `restored.audioInFile = sounds.length`. In offerRestart add: if `done.conversations < done.conversationsInFile`, push `${done.conversationsInFile - done.conversations} of the ${done.conversationsInFile} saved conversations could not be restored` plus ' - they need a data folder' when !storage.hasDataFolder(); same for sounds; and if `done.failed.length` push `These could not be restored: ${done.failed.join(', ')}.`
