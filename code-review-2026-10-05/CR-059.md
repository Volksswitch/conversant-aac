# CR-059: A new practice scenario being filled in is wiped if the user switches Settings tabs

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/practice-editor.js:210`
- **Also affects:** `app/js/practice-editor.js:43`; `app/js/practice-editor.js:184`; `app/js/practice-editor.js:213-216`; `app/js/practice-editor.js:223`; `app/js/app.js:5704`
- **Source:** phrases-practice-05

**What a user notices.** Someone typing a new practice scenario by hand (name, who the person is, the details) who steps to another Settings tab, or closes and reopens Settings, comes back to an empty form. Everything they typed is gone with no warning.

**What is wrong.** In create mode the form is built from view.draft, but renderForm copies it (`const draft = { ...scenario }`) and every input/change handler writes only to that local copy (create mode never saves). view.draft stays the empty scenario from library.emptyScenario(). render() runs again whenever the Practice tab is activated (app.js activateSettingsTab -> renderPracticePanel), and since view.mode is still 'create' it calls renderForm(view.draft, true) with the original blank draft. Edit mode is not affected because it saves on each change.

**Evidence.**

```
practice-editor.js:43 `if (view.mode === 'create') return renderForm(view.draft, true);`
practice-editor.js:184 `goTo({ mode: 'create', draft: library.emptyScenario() })`
practice-editor.js:210 `const draft = { ...scenario };`
practice-editor.js:223 `f.addEventListener('input', () => { draft[prop] = f.value; });`
practice-editor.js:215 `if (!creating) await library.updateScenario(draft.id, fields);`
app.js:5704 `if (tabName === 'practice') { renderPracticePanel(); ...`
```

**How it happens.** Settings > Practice > Fill it in yourself. Type a name, a persona and details. Tap the General tab (e.g. to check something), then tap Practice again: the form is blank.

**Suggested fix.** In renderForm, keep the create-mode draft on the view so it survives re-renders: `const draft = creating ? scenario : { ...scenario };` (scenario is view.draft in create mode, so the input handlers then update view.draft). Leave edit mode as a copy.

**How to verify the fix.** Manual: fill in the create form, switch to another Settings tab and back, and close/reopen Settings; confirm every field (including selects and the custom behavior text) is still filled. Confirm Cancel still returns to the list and a fresh 'Fill it in yourself' starts blank (emptyScenario creates a new object each time).

**Do not break.** Cancel and 'Add scenario' must still work; a new 'Fill it in yourself' must start from a fresh blank draft.

**Design reference.** CLAUDE.md Configurability philosophy: 'Confirm before destroying significant work'.

**Verification notes.** renderForm copies the scenario (`const draft = { ...scenario }`, practice-editor.js:210), and in create mode the input handlers update only that local copy. view.draft keeps the blank emptyScenario(). activateSettingsTab('practice') calls renderPracticePanel() and then practiceEditor.render() (app.js:5704, 2538). Since view.mode is still 'create', it calls renderForm(view.draft, true) again with the blank draft, so everything typed is lost. The suggested fix (`creating ? scenario : { ...scenario }`) is correct, because emptyScenario() returns a fresh object each time.
