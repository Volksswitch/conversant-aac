# CR-061: Settings tabs, radio and checkbox rows and the 'Which side' switch are far below the app's minimum touch-target size

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:3323`
- **Also affects:** `app/css/styles.css:3828`; `app/css/styles.css:3849`; `app/css/styles.css:3782`; `app/css/styles.css:3790`; `app/index.html:986`; `app/css/styles.css:2665`; `app/css/styles.css:3828 (merged duplicate: Every checkbox and radio in Settings is a 13px box on a 17px-tall row, far below the panel's button size)`
- **Source:** x-a11y-05, live-visual-03

**What a user notices.** People with limited hand control must hit Settings tabs about half the height of every other button, choice rows only about a quarter as tall, and a small slider switch, which leads to wrong tabs and wrong options being chosen (for example the wrong hearing or speaking service).

**What is wrong.** The rule 'Button size applies to EVERY tappable element on EVERY surface' (styles.css:2665-2677, Rule 15) is implemented only for `button`, `select` and text inputs. The Settings tabs are <div role=tab> (styles.css:3323: padding 0.5rem, font 0.9rem, no min-height); radio and checkbox rows are <label> elements with no min-height (3828-3835, 3849-3856); the side-dock switch is 3rem x 1.5rem (3782-3788). The switch's real input is opacity:0 (3790-3797) and there is no :focus-visible style on .switch-track, so its keyboard focus is also invisible.

**Evidence.**

```
styles.css:3323-3327 `.settings-tab { padding: 0.5rem 1rem; font-size: 0.9rem; cursor: pointer; }`
styles.css:3849-3856 `dialog label.radio-label { display: flex; align-items: center; gap: 0.5rem; ... }` (no min-height)
styles.css:3782-3788 `.switch { ... width: 3rem; height: 1.5rem; }`
Measured at 1280x800 in headless Chrome: --btn-min-dim floor = 58.4px; Settings tab heights 32px (49px when the label wraps); a Speech-tab radio row 17px tall; the switch 43.8 x 21.9px; switch focus: input opacity 0, track outline none and box-shadow none.
```

**How it happens.** 1. Open Settings on a tablet. 2. Tap between 'Speech' and 'Screen Layout' tabs - each is 32px tall in a 14-tab column. 3. On the Speech tab, try to choose 'Azure transcription (paid)' among six radio rows each 17px tall with 6px gaps; a motor-impaired tap frequently selects the neighbour. 4. On the Express tab, Tab to 'Which side': nothing on screen shows the switch has focus.

**Suggested fix.** In styles.css: give `.settings-tab` `min-height: var(--btn-min-dim); display: flex; align-items: center;`; give `dialog label.radio-label, dialog label.checkbox-label, label.checkbox-row, .wv-person-checkbox-row` `min-height: var(--btn-min-dim);` (the whole label is the tap target, so this enlarges the target without enlarging the native control); enlarge `.switch` to `width: calc(var(--btn-min-dim) * 1.6); height: var(--btn-min-dim);` and scale `.switch-track::before`/translateX accordingly; add `.switch input:focus-visible + .switch-track { outline: 3px solid var(--link); outline-offset: 2px; }`.

**How to verify the fix.** Extend tests/ui-standards.test.mjs (it already walks every Settings tab) to assert getBoundingClientRect().height >= the --btn-min-dim floor for `.settings-tab`, `label.radio-label`, `label.checkbox-label` and `.switch`. Manual: open each Settings tab at 1280x800 and confirm tabs and option rows are at least as tall as the Settings buttons.

**Do not break.** The Settings tab column must still fit 14 tabs; if the column then scrolls, check that #settingsTabs has overflow-y:auto and that the tab strip remains usable on the smallest supported viewport (iPad mini ~744px tall). Settings is a supporter-assisted overlay, not keyguard-backed, so this does not move keyguard holes, but the Settings panel's position is aligned to the dock (Rule 11) - change sizes inside the panel only.

**Design reference.** UI Layout Rule 5 and Rule 15; CSS comment at styles.css:2665-2677 (Ken, June 29 2026: button size applies to every tappable element on every surface)

**Verification notes.** `.settings-tab` (3323) has 0.5rem padding and no min-height, and index.html has 14 tabs. `dialog label.radio-label` and `dialog label.checkbox-label` (3828, 3849) have no min-height. `.switch` is 3rem by 1.5rem, and its input is opacity:0 with no :focus-visible rule on the track, so keyboard focus on it is invisible. The rule at 2665 that claims button size applies to every tappable element only reaches `button`, `select` and text inputs. This matches the cited design rule (Rule 15 and the June 29 comment).

<details><summary>Merged duplicate live-visual-03: Every checkbox and radio in Settings is a 13px box on a 17px-tall row, far below the panel's button size</summary>

UI-Design §13 says 'Checkbox, radio, select — Native controls, sized with the buttons around them', and Rule 15 makes the Express-derived minimum (~56px) the floor for Settings targets. Buttons, selects and text inputs get min-height: var(--btn-min-dim) (styles.css ~2740), but checkbox and radio labels have no height rule: the native input is 13x13px and the clickable label row measures 17px. Six radio rows on the Speech tab sit 23px apart; on Conversation > Listening two checkboxes are stacked 17px apart. A mis-tap there flips a setting (e.g. turns automatic weekly reports or auto-resume listening on/off).

Fix as proposed by that reviewer: Give both label kinds the panel's touch-target height and enlarge the native control, e.g.:
dialog label.checkbox-label, dialog label.radio-label { min-height: var(--btn-min-dim); }
label.checkbox-label input[type="checkbox"], label.radio-label input[type="radio"] { width: 1.4rem; height: 1.4rem; }
and drop .radio-row's gap to 0 if the rows themselves now provide spacing. Apply to the .wv-person-checkbox-row in About Me as well.

</details>
