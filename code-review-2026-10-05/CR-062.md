# CR-062: When the AI request fails, the app cancels the holding phrases that are supposed to cover the silence

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1948`
- **Also affects:** `app/js/app.js:1266 placeholders.arm() at the pause`; `app/js/llm.js:457 `if (!apiKey) throw new Error('API key not set');``; `app/js/app.js:1948 (merged duplicate: When the AI request fails (no key, offline, rate limit), the holding phrases are switched off)`
- **Source:** app-b-05, phrases-practice-04

**What a user notices.** If the internet drops, the AI service is busy, or no AI key has been entered, the app goes completely silent after the other person speaks, instead of saying a 'thinking about that' phrase while the user decides what to say by hand. With no key set, the holding phrases never play at all.

**What is wrong.** placeholders.arm() at the silence checkpoint schedules the first placeholder initialDelay after the pause, independent of the AI (CLAUDE.md: 'They are armed by the PARTNER'S SILENCE, never by the AI round trip ... So they speak even when the AI is slow, failing, or absent'). But generateOptions' catch block calls placeholders.stop(), which cancels the armed ladder. With no API key, llm.generateResponses throws synchronously-fast ('API key not set'), so stop() runs within milliseconds of every pause and no placeholder ever speaks. A fast 401/429/network failure has the same effect. The user is then left to reply via the Express Panel or composer — exactly the slow path a placeholder exists to cover.

**Evidence.**

```
app/js/app.js:1266 `placeholders.arm();`
app/js/app.js:1933-1948 `} catch (err) { ... storage.logError('generateOptions', ...); placeholders.stop();`
app/js/llm.js:457 `if (!apiKey) throw new Error('API key not set');`
CLAUDE.md 'PLACEHOLDERS ARE PART OF THIS SAME FLOW': 'So they speak even when the AI is slow, failing, or absent.'
```

**How it happens.** Remove the API key (or go offline after Listen started). Partner says "How are you?" and pauses. generateOptions throws immediately; placeholders.stop() cancels the ladder armed at the pause; the 2-second placeholder never speaks; the partner hears nothing while the user hunts for an Express phrase.

**Suggested fix.** Delete the `placeholders.stop();` call at line 1948. The ladder remains bounded by its own cap (max per turn) and is still stopped by every user action (card, Express, Say again/Hold on/Wind down) and by the partner resuming, so no further change is needed. If a reason to stop exists for a specific failure (none does today), gate it explicitly rather than stopping on every error.

**How to verify the fix.** Manual: clear the API key, Start, tap Listen, speak and pause; confirm the first placeholder is spoken at the initial delay and the ladder runs to its cap, and that tapping an Express phrase still silences it. Add a source-level guard in tests/placeholders.test.mjs asserting generateOptions' catch block (comments stripped) does not call placeholders.stop().

**Do not break.** Keep the success-path confirm-or-cancel logic (pEpoch and shouldPlayPlaceholder) unchanged; it still must stop on a repair-initiator turn.

**Design reference.** CLAUDE.md 'Placeholders are gated by PARTNER SILENCE, not by the AI round-trip' and 'PLACEHOLDERS ARE PART OF THIS SAME FLOW'; 'AI is an enhancement layer, not a hard dependency'.

**Verification notes.** handleSilencePeriod calls placeholders.arm() (which itself schedules the first placeholder via setTimeout, placeholders.js:208-219) then generateOptions. The catch block in generateOptions calls placeholders.stop(), which clears the timer and cancels speech. llm.generateResponses throws 'API key not set' immediately with no key, so the ladder is cancelled within milliseconds of every pause; a fast network/401/429 failure does the same. CLAUDE.md states placeholders 'speak even when the AI is slow, failing, or absent'; no recorded decision to stop them on failure. The comment above arm() in handleSilencePeriod (saying the placeholder is still gated on classification) is also stale.
