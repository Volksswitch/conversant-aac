# CR-063: A choice-button tap and a Reframe do not combine: each request drops the other's steering while the screen still shows it

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3546`
- **Also affects:** `app/js/app.js:3451-3454`; `app/js/app.js:3354-3359`; `app/js/app.js:3437`; `app/js/app.js:3543`; `app/js/app.js:4529-4530`
- **Source:** app-c-06

**What a user notices.** If the user taps one of the other person's offered choices (for example 'milk') and then types a Reframe ('mention I'm lactose intolerant'), the new cards ignore 'milk' even though the milk button still shows as chosen; doing it the other way round loses the typed guidance. Pressing New 4 afterwards suddenly applies both.

**What is wrong.** CLAUDE.md records that the per-turn activeSteer holds a chip's focusChoice and a Reframe's steer independently 'so they can compose', and handleRegenerate and refreshForContextChange send both. But handleReframe's partner-turn request passes only `steer`, and handleChoiceChip passes only `focusChoice`. activeSteer keeps both values, so the chip stays rendered as chosen (activeChoice: activeSteer.focusChoice) while the cards just produced ignore it, and the next New N silently switches to the combined steering.

**Evidence.**

```
app/js/app.js:3546 `const result = await llm.generateResponses(history, engine.buildRequestContext(), { reason: 'reframe', steer, perCategory: storage.loadResponsesPerCategory() });`
app/js/app.js:3451-3454 `{ reason: 'choice chip',
            focusChoice: pick,
            perCategory: storage.loadResponsesPerCategory(),
        }`
app/js/app.js:3357-3358 (handleRegenerate) `focusChoice: activeSteer.focusChoice || undefined,
            steer: activeSteer.steer || undefined,`
```

**How it happens.** 1) Partner: 'Do you want milk or cream?' -> choice buttons appear. 2) Tap 'milk' (cards about milk; button shows chosen). 3) Open In my own words, type 'mention I am lactose intolerant', tap Reframe. 4) New cards no longer answer 'milk' while the milk button is still lit. 5) Tap New 4: cards now combine both.

**Suggested fix.** In handleReframe's partner branch pass `focusChoice: activeSteer.focusChoice || undefined` alongside `steer`. In handleChoiceChip pass `steer: activeSteer.steer || undefined` alongside `focusChoice: pick`. No other change: activeSteer already stores both.

**How to verify the fix.** Add a source-level test (tests/placeholders.test.mjs or a new tests/app-steering.test.mjs reading app.js) asserting both generateResponses calls in handleReframe and handleChoiceChip mention both activeSteer.focusChoice/steer. Manual: steps above - after step 3 the cards reflect both.

**Do not break.** Steering must still clear at turn boundaries (clearTurnSteering) and stay one-shot across turns. The Reframe lead-mode (no partner turn) path is unaffected.

**Design reference.** CLAUDE.md, Closed-set turns: 'Steering persists across New N WITHIN a turn ... the two are independent so they can compose ("milk" + "mention I'm lactose intolerant")'

**Verification notes.** handleReframe's partner branch passes only {steer} and handleChoiceChip passes only {focusChoice}, while handleRegenerate and refreshForContextChange pass both from activeSteer. activeSteer keeps both, so the chip renders as chosen while the reframed cards ignore it, and the next New N applies both. Contradicts the CLAUDE.md record that the two 'are independent so they can compose'.
