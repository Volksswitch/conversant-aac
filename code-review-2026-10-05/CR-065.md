# CR-065: Tapping an empty panel cell in Settings ignores which cell was tapped and can shift every learned phrase

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:101`
- **Also affects:** `app/js/express-editor.js:124-131`; `app/js/express-editor.js:153-161`; `app/js/app.js:3925-3960`; `app/js/express-items.js:124-131`; `app/js/app.js:3959 (merged duplicate: Tap-to-define does not create the button in the tapped cell)`
- **Source:** express-02, app-d-07

**What a user notices.** When setting up the panel, tapping an empty spot to put a new phrase there does not put it there. If the user had just selected an existing phrase (say 'Yes' at the top), the new phrase is slipped in right after it and every phrase below moves down one place, so buttons the user has learned the position of all move.

**What is wrong.** handleDefineCell(index) in app.js is documented as 'the index of the tapped cell is the whole point' and says empty placeholder items are padded so the new button lands in the tapped cell. But it passes only the band to expressEditor.addToBand(band); the index is discarded. addToBand -> addPhrase/addContext then inserts relative to pickedId (the row last selected) if that row is in the same band, otherwise appends to the end. newEmptyItem() is never called anywhere. Two consequences: (a) tapping the 3rd of 4 empty Always cells places the phrase in the 1st empty cell; (b) because pickedId persists until the tab is left, tapping an empty cell after having selected an earlier phrase inserts the new phrase mid-band and pushes every following phrase one cell down, which is exactly the spatial-stability harm the delete confirmation warns about ('every button after it moves up one place'). For the Flex band the phrase goes into the editor's current situation (flexPartner/flexPlace), which may not be the situation the live panel beside it is showing, so the new phrase may not appear in the tapped cell at all.

**Evidence.**

```
app.js:3931-3933 comment: `every cell before the tapped one gets an empty placeholder, so the new button lands in the cell that was actually tapped.`
app.js:3959 `expressEditor.addToBand(band);` (index unused)
express-editor.js:101-107 `export function addToBand(band) { ... if (key === 'context') addContext('feeling'); else if (key === 'flex') addPhrase('flex'); else addPhrase('always'); }`
express-editor.js:127-128 `const at = list.findIndex((x) => x.id === pickedId); if (at >= 0) list.splice(at + 1, 0, item); else list.push(item);`
`grep newEmptyItem app/js` finds only its definition.
```

**How it happens.** Settings > Express Panel. Tap the 'Yes' button on the panel (it is selected for editing). Now tap an empty outline at the bottom of the Always band. A blank phrase is inserted directly after 'Yes', so 'No' and every later Always phrase move one cell down the grid.

**Suggested fix.** Give addToBand a cell position. In app.js handleDefineCell pass the band-relative ordinal: compute `const pos = composed.bands.slice(0, index).filter((b) => b === band).length;` and call `expressEditor.addToBand(band, pos)`. In express-editor addToBand(band, pos) forward pos to addPhrase(key, pos). In addPhrase(band, pos): when `Number.isInteger(pos)`, pad the list with `newEmptyItem()` (import from express-items.js) up to pos and then set `list[pos] = item` if pos >= list.length, otherwise insert at pos; ignore pickedId in that case. Toolbar 'Add a phrase' keeps the current insert-after-picked behaviour (it passes no pos). Note the Always band's page-0 offset when the band is paged (pos only applies to page 0; if composed.paging is non-null, fall back to appending). For the Flex band, before adding, set flexPartner/flexPlace to the situation the live panel is showing (the active partner/place) or tell the user which situation will receive it; at minimum do not silently add to a situation the panel is not displaying.

> **Verifier correction to the fix (takes precedence):** Only the Always band maps cleanly from a cell to a list position. In the Flex band the cells begin with goal buttons and are filled from up to four situational lists, so a band-relative ordinal is not an index into the editor's current list; Context is lit-first and type-sorted, so the same applies there. Apply the position-aware insert (pad with newEmptyItem) to Always on its first page only; for Context and Flex keep appending but ignore pickedId when the add comes from a cell tap (pass a flag such as addToBand(band, {fromCell:true})), so a tapped outline never splices a phrase into the middle of the band. For Flex, also set flexPartner/flexPlace to the live panel's situation before adding, or say which situation receives it.

**How to verify the fix.** Manual: with 26 Always phrases on a layout with 30 Always positions, select 'Yes', then tap the 4th empty outline: the new phrase must appear in that 4th cell, and 'No' must not move. Add a unit-style test in tests/express-panel-store.test.mjs that calls the editor helper with an explicit position (or test the padding helper directly if extracted to express-items.js).

**Do not break.** Empty items render as outlines and are origin DEFAULT; keep that so the personalization count is not inflated. Do not change how the toolbar 'Add a phrase' behaves. Keep pads out of the Flex band if flexFill would then skip them (flexFill skips blank text; 'empty' items have no text and would be skipped, which is fine).

**Design reference.** CLAUDE.md 'AS BUILT (August 8 2026)' under Sounds Like Me / tap-to-define; app.js handleDefineCell header; express-items.js 'WHY empty HAS TO EXIST'

**Verification notes.** handleDefineCell (app.js:3925-3960) documents placing the button in the tapped cell but calls expressEditor.addToBand(band) with no index; newEmptyItem() has no caller anywhere in app/js. addPhrase inserts after pickedId when that row is in the same list, else appends. pickedId survives the tap because activateSettingsTab -> hostExpressPanel(true) does not clear it. So selecting 'Yes' then tapping an empty Always outline inserts after 'Yes' and shifts every later phrase. Trigger requires empty Always outlines (larger layout or after deleting phrases), which is reachable.

handleDefineCell resolves only the band of the tapped index and calls expressEditor.addToBand(band); the index is otherwise ignored. addPhrase inserts the new item immediately after pickedId when the picked item is in the same list, and pickedId persists for the whole time the Express tab is open (focusItem sets it on every defined-cell tap; clearPicked runs only when leaving the tab). So 'tap Thank you, then tap an empty Always cell' inserts the new phrase after Thank you and shifts every later Always phrase one cell, contradicting the documented intent that 'the button is created where it will live'. For the Flex band, addPhrase writes to the editor's currently selected flex list (flexPartner/flexPlace, set by an earlier focusItem or the editor's dropdowns), not the Anyone/Anyplace list that fills empty Flex cells on the live panel, so the new phrase may not appear on the panel at all.

Fix as proposed by that reviewer: In handleDefineCell call `expressEditor.clearPicked();` before `expressEditor.addToBand(band);` so the new entry is appended (an empty cell is always after the band's last entry). Add an option to addToBand for the Flex band so it appends to the general list: e.g. extend addToBand(band, { general: true }) to set flexPartner = ANYONE and flexPlace = ANYPLACE before addPhrase('flex'), and pass that from handleDefineCell.


Verifier correction: clearPicked() before addToBand makes the new entry append. Appending lands it in the FIRST empty cell of the band, not necessarily the one tapped, unless the tapped cell is the first empty one; say so, or pad as the JSDoc describes. Also update the stale JSDoc.
