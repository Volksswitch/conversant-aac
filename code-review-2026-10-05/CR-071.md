# CR-071: System information is re-sent in every weekly report because the change-detection hash includes a timestamp and live counters

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/weekly-send.js:298`
- **Also affects:** `app/js/diagnostics.js:80`; `app/js/diagnostics.js:130`; `app/js/diagnostics.js:131`; `app/js/diagnostics.js:56`; `app/js/diagnostics.js:50`
- **Source:** reporting-platform-03

**What a user notices.** Each weekly report is much larger than it needs to be and the spreadsheet can no longer show when a tester's device or settings actually changed.

**What is wrong.** gatherPayload sends systemInfo only when hashOf(info) differs from the stored hash, intended (CLAUDE.md) to send it only when the setup changes and to make a change conspicuous in the Sheet. But collectSystemInfo puts volatile values in the hashed object: `when: new Date().toISOString()`, storage usageMB, the folder-reconnect trace, stt.listenActivity() and stt.listenTimings(). The hash therefore differs every time, systemInfo (with the full voice list) is sent every week, and the Sheet's 'system info' column always reads 'included', so a real change is invisible. It also pushes the 'raw' cell toward the 50,000-character limit (see the oversized-cell finding).

**Evidence.**

```
app/js/weekly-send.js:298-303: `const info = await diagnostics.collectSystemInfo(...); const h = hashOf(info); if (h !== storage.loadWeeklyInfoHash()) { systemInfo = info; storage.saveWeeklyInfoHash(h); }`
app/js/diagnostics.js:80: `when: new Date().toISOString(),`
app/js/diagnostics.js:130-131: `info.speech.listening = stt.listenActivity(); ... info.speech.listenDelay = stt.listenTimings();`
app/js/diagnostics.js:56: `if (est.usage) info.usageMB = ...`
```

**How it happens.** Tester changes nothing for three weeks; each weekly report still carries a full systemInfo block, and the Sheet shows 'included' every week.

**Suggested fix.** In weekly-send.js add `export function stableInfo(info)` that deep-copies info and deletes the volatile parts: `when`, `storage.usageMB`, `storage.quotaMB`, `storage.reconnect`, `speech.listening`, `speech.listenDelay`. Compute `hashOf(stableInfo(info))` instead of `hashOf(info)` (still send the full `info` when it changes).

> **Verifier correction to the fix (takes precedence):** The proposed stableInfo() is right. Also remove `app.url` (location.href can carry a query string) and `display` values that change with window size, or keep only the screen fields. Otherwise the hash will still change whenever a desktop window is resized.

**How to verify the fix.** Add to tests/weekly-send.test.mjs: two info objects identical except `when`, `storage.usageMB` and `speech.listening` produce the same `hashOf(stableInfo(...))`; changing `settings.colorScheme` produces a different one.

**Do not break.** Keep sending the full object (including the volatile fields) when it IS sent; only the comparison changes. API keys stay excluded via reportableSettings().

**Design reference.** CLAUDE.md 'AS BUILT — item 4, the automatic weekly report' ('System info is sent only when its hash changes')

**Verification notes.** collectSystemInfo sets `when: new Date().toISOString()` at the top level (diagnostics.js:80) and also includes storage usageMB, the reconnect trace, listenActivity and listenTimings. gatherPayload hashes the whole object (weekly-send.js ~298-303, with hashOf being a plain djb2 over JSON.stringify). The timestamp alone guarantees a different hash on every report, so systemInfo is sent every week and the 'system info' column always reads 'included'.
