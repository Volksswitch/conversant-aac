# CR-072: No undeclared-identifier check: the handleRepairOfSelf ReferenceError shipped with every test green

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** other
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2249`
- **Also affects:** `package.json:2`; `tests/source-hygiene.test.mjs:67`
- **Source:** g-test-suite-03

**What a user notices.** A typo that crashes a feature the moment it is used can reach testers, because nothing in the automated checks looks for names that were never defined.

**What is wrong.** app.js cannot be loaded by a unit test (CLAUDE.md says so), so a reference to an undefined variable inside it is invisible to npm test. Running ESLint 8 with only no-undef over app/js (browser + es2022 env, module source type) reports exactly one error: 'source' is not defined at app.js:2249:149 — the already-reported repair-of-self crash. The full suite (1037 tests, 1031 pass, 6 opt-in live skips) passes over it. A one-rule static check would have caught it at the moment it was written and will catch the next one; other correctness rules (no-dupe-keys, no-unreachable, no-self-assign, no-dupe-else-if, valid-typeof, no-cond-assign, no-duplicate-case) found nothing, so adding them costs no noise.

**Evidence.**

```
app/js/app.js:2249: storage.logUserResponse({ selectedText: text, spokenText: spokenFormFor(text), ttsUsed: tts.lastVoiceUsed(), selectedIndex: -1, allOptions: [], source });
npx eslint@8.57.0 --no-eslintrc --env browser,es2022 --parser-options=sourceType:module --rule 'no-undef:error' app/js -> app.js 2249:149 error 'source' is not defined; 1 problem.
npm test: tests 1037, pass 1031, fail 0, skipped 6 (all Tier-3 live).
```

**How it happens.** 1) Edit any handler in app.js and reference a variable that is not in scope. 2) Run npm test: green. 3) Release. 4) The first user to reach that handler gets an uncaught ReferenceError and the feature silently stops partway.

**Suggested fix.** Add eslint (8.x, which supports --no-eslintrc CLI config) as a devDependency beside puppeteer, a minimal .eslintrc.json scoped to app/ (env browser+es2022, parserOptions sourceType module; for app/sw.js override env serviceworker and add globals AbortController) enabling only no-undef plus the correctness rules listed above, and a test tests/lint.test.mjs that runs it via child_process and asserts zero errors — skipping LOUDLY with t.skip('eslint is not installed ...') when the package is absent, the same pattern docx-toolkit.test.mjs and dock-congruence.test.mjs use for optional tools.

**How to verify the fix.** With the repair-of-self bug unfixed, the new test must fail naming app.js:2249 'source'. After that bug is fixed (separately reported), it passes. Mutation: add `foo;` inside any function in ui.js and confirm the test fails.

**Do not break.** Do not enable stylistic rules (no-unused-vars, no-unused-expressions): the codebase uses `x && x.method()` idioms on purpose and they would bury real findings. scripts/doc-generators are CommonJS and must stay out of the module-scoped config.

**Design reference.** CLAUDE.md 'A CHANGE THAT CROSSES LAYERS GETS ONE CHECK THAT CROSSES ALL OF THEM' (app.js is not testable, so name what was never run) and the source-hygiene rationale ('a check ... reports everything clean while testing nothing').

**Verification notes.** app.js:2249 sits inside async handleRepairOfSelf (line 2179) and passes a shorthand 'source' to logUserResponse. Neither that function nor app.js at module level declares 'source', and it is not a browser global, so reaching that line throws a ReferenceError. package.json has no eslint and no lint test exists, so npm test cannot see an undeclared identifier in app.js, which no unit test can load. The gap is real and matches the reviewer's account.
