# CR-073: No test checks that the service worker precaches every module the app imports (how tap-guard.js slipped)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** other
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/sw.js:39`
- **Also affects:** `app/js/app.js:66`; `app/sw.js:19`; `app/js/app.js:102`; `app/index.html:16`
- **Source:** g-test-suite-02

**What a user notices.** A file the app needs to start can be left out of the offline copy without any test noticing, so the installed app fails to open with no internet connection. This has already happened once.

**What is wrong.** SHELL in sw.js is a hand-maintained list. A transitive walk of static imports from app/js/app.js finds every module listed except js/tap-guard.js (imported at app.js:66), which is the already-reported offline-start bug. Nothing in tests/ reads sw.js (grep for 'sw.js' / 'SHELL' / 'CACHE_VERSION' in tests returns nothing), so the next new module will be missed the same way. Related unguarded consistency: CACHE_VERSION ('aac-v0.13.5-@@BUILD@@') must carry the same version as APP_VERSION (app.js:102) and both are bumped by hand in the release ritual; today they agree but no test enforces it. The fetched data files (data/words.json, data/pricing.json, data/worldview-questions.json) are listed; apple-touch-icon.png (index.html:16) is not, which is harmless.

**Evidence.**

```
app/js/app.js:66: import * as tapGuard from './tap-guard.js';
app/sw.js:39-114: const SHELL = [ './', './index.html', ... './js/metrics.js', './data/words.json', ... ]  (no './js/tap-guard.js')
Experiment precache.mjs (transitive import walk from js/app.js): reachable not in SHELL: [ 'js/tap-guard.js' ]; SHELL js not reachable: []
```

**How it happens.** 1) Add a new module app/js/foo.js and import it from app.js. 2) Forget to add it to SHELL in sw.js. 3) npm test passes. 4) Deploy; a user installs, goes offline, relaunches: the module request fails and the app does not start.

**Suggested fix.** Add tests/service-worker.test.mjs (zero-dependency, node:test): read app/sw.js, extract SHELL entries with /'\.\/([^']*)'/g; starting from 'js/app.js', walk static imports (regexes for `import ... from './x.js'`, `export ... from './x.js'`, `import './x.js'`, and dynamic `import('./x.js')`) resolving relative paths with path.posix; assert every reachable module is in SHELL and every SHELL js entry exists on disk and is reachable. Also collect string arguments of fetch('data/...') in app/js and assert each is in SHELL. Add a second test asserting the version inside CACHE_VERSION (/aac-v([\d.]+)-/) equals APP_VERSION from app.js. Then add './js/tap-guard.js' to SHELL (that part is the already-reported bug).

**How to verify the fix.** Run the new test before adding tap-guard.js to SHELL: it must fail naming js/tap-guard.js. Add the entry: it passes. Mutation check: remove './js/metrics.js' from SHELL and confirm it fails; change CACHE_VERSION to 0.13.4 and confirm the version test fails.

**Do not break.** Do not make the test depend on @@BUILD@@ being substituted (it is only replaced at deploy). addAll is atomic, so the test must also assert every SHELL file exists on disk, or a typo would break install entirely.

**Design reference.** CLAUDE.md 'The app updates itself on launch and on Start' and the sw.js header comment ('keep SHELL in sync with what actually ships'); RELEASING.md bump steps.

**Verification notes.** Walked every static and dynamic import starting from js/app.js and compared it with SHELL in sw.js. The only module reachable but not precached is js/tap-guard.js, imported at app.js:66. Every SHELL entry exists on disk, and every precached js file is reachable. No file under tests/ mentions sw.js, SHELL or CACHE_VERSION. CACHE_VERSION (aac-v0.13.5) and APP_VERSION (0.13.5) agree today, but nothing enforces it. Nothing in TODO.md tracks this.
