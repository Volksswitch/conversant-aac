# CR-074: Problem report includes the saved transcript of the current conversation even after it was marked Don't save

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** privacy
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6856`
- **Also affects:** `app/js/app.js:6861-6865 (private check reached only if no disk transcript)`; `app/js/app.js:402-405 (handlePrivacyToggle only flips the flag)`; `app/js/app.js:6376-6382 (REPORT_DISCLOSURE promise)`
- **Source:** app-e-05

**What a user notices.** If the user turns on 'Don't save this conversation' part-way through a conversation, a problem report sent afterwards still contains what was said earlier in that conversation, even though the report screen promises that a conversation marked Don't save has no transcript in it.

**What is wrong.** buildErrorReport reads the conversation file from disk first and prints it whenever it has exchanges; the SEC-2 private-conversation check (`id === storage.getConversationId() && !storage.isConversationSaving()`) is an else-if that is only reached when the disk read came back empty. Turning privacy on mid-conversation (handlePrivacyToggle) only stops future writes; the turns already written stay in <id>.json under the same conversation id, and errors logged before the toggle keep extra.partner. So for the current conversation that is now private, the disk transcript (and partner speech in error extras) is printed into the report, contradicting REPORT_DISCLOSURE ('A conversation you marked "Don't save" has no transcript here').

**How it happens.** Data folder connected. Partner says something personal, user replies (both written to disk). User taps the privacy button to mark the conversation Don't save. An AI error occurs. User opens Troubleshooting > Send: the preview shows the personal exchange under 'Transcript:', and the error line carries extra.partner from before the toggle.

**Suggested fix.** Reorder the branches in buildErrorReport so the private check runs first: `if (id === storage.getConversationId() && !storage.isConversationSaving()) { out.push('Transcript: [private conversation — transcript withheld]'); } else if (convLog && ...) {...} else if (...live...) ...`. In the same private case, print errors without their `extra` (e.g. use `''` instead of the JSON.stringify(e.extra) suffix when the group is private).

> **Verifier correction to the fix (takes precedence):** Reordering the branches only works while that conversation is still current. Once the user ends it, storage.getConversationId() changes, and the partial file's transcript appears in every later report. Record that the conversation was made private in a way that persists. For example, have storage note the id, or write a `private: true` marker into the already-saved log when the toggle turns on. buildErrorReport (and errorsFromDisk) should then check that marker, withhold the transcript, and drop `extra` for those conversations. Leave deleting the earlier turns to Ken, as the cautions say.

**How to verify the fix.** Manual: with a folder, hold two exchanges, toggle privacy on, trigger an error (e.g. a bad API key), open Troubleshooting and press Send; the preview must show the withheld line and no partner text. Add a source-level guard (tests/storage-transcript.test.mjs or a new test) that the private branch precedes the disk-transcript branch in buildErrorReport.

**Do not break.** Do not change the weekly report (it never carries transcripts). Keep the disk fallback for ordinary saved conversations. Whether toggling privacy mid-conversation should also delete the turns already on disk is a separate decision for Ken - do not delete files in this fix.
