# CR-077: A second card or Express tap while the first is still being spoken cuts the first off but records it as said, and clears the 'user is speaking' guard early

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** race-condition
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:265`
- **Also affects:** `app/js/ui.js:295-298 (card click has no in-flight guard)`; `app/js/app.js:1966-2124 (handleResponseSelected)`; `app/js/app.js:3692-3746 (speakAsUserTurn)`; `app/js/app.js:5182-5188 (handleSpeakExpressItem)`; `app/js/tts.js:266-268 (speakBuiltin cancels the previous utterance; its promise resolves)`; `app/js/app.js:558 (placeholder gate reads speakingUserStatement)`
- **Source:** x-async-06

**What a user notices.** With the default single-tap setting, a user who taps a second reply (or the same one twice) while the first is still being spoken hears the first cut off, but both appear in the transcript and are sent to the AI as if both were said in full.

**What is wrong.** Response cards stay on screen and live while their speech plays (the palette is cleared only after commit), and Express phrases are always live. Each tap re-enters handleResponseSelected/speakAsUserTurn. The second tts.speak supersedes the first (builtin: synth.cancel() fires the first utterance's onerror -> its promise resolves), so the first handler continues and commits its text as a complete user turn, then the second commits too. speakUserStatement's `finally` from the first call sets speakingUserStatement = false while the second statement is still playing, so the placeholder gate (and conversationInProgress) read false during it. Both handlers also call resumeOrIdle/startFreshListening, starting the mic twice.

**Evidence.**

```
ui.js:295-298 `card.addEventListener('click', () => { if (roundtrip) card.classList.add('working'); onSelect(response, index); });`
app.js:265-270 `async function speakUserStatement(text, { announce = false } = {}) { speakingUserStatement = true; announcingUserStatement = announce; try { await tts.speak(text); } finally { speakingUserStatement = false; announcingUserStatement = false; } }`
tts.js:268 `if (synth.speaking) synth.cancel();`
```

**How it happens.** Single-tap mode (the default). Partner asks a question; user taps card A ('Yes, I'd love to come on Saturday...'), then a tremor lands a tap on card B 0.5 s later. A stops after two words, B is spoken. The transcript and conversation file show A then B as two complete user turns; the next AI request treats both as said.

**Suggested fix.** Make a user statement exclusive. Simplest, consistent with the existing double-press guards (importInProgress): at the top of handleResponseSelected (after the `response.op` branch) and speakAsUserTurn and handleSpeakExpressItem add `if (speakingUserStatement) return;`. Additionally make speakUserStatement clear the flag only for the latest call: `let statementSeq = 0;` ... `const mine = ++statementSeq; ... finally { if (mine === statementSeq) { speakingUserStatement = false; announcingUserStatement = false; } }`.

**How to verify the fix.** Manual: single-tap mode, tap two cards in quick succession; confirm only the first is spoken and only one user turn is recorded. Source-level test in tests/placeholders.test.mjs that handleResponseSelected and speakAsUserTurn return early on speakingUserStatement.

**Do not break.** This is a behavior choice (ignore the second tap vs. let it replace the first); confirm with Ken. 'Hold on' must stay exempt (it is wired straight through on purpose). Do not block the stop-a-sound tap.

**Design reference.** CLAUDE.md UI Layout Rule 10 (one tap or two; this population taps imprecisely) and 'Transcript mirrors the conversation pane'

**Verification notes.** Cards stay rendered and clickable while handleResponseSelected speaks (clearPalette happens later; ui.js card click has no guard; default expressTapMode is 'single' per storage.js:1642). A second tap re-enters; speakBuiltin's synth.cancel fires the first utterance's onerror, whose finish() resolves its promise, so the first handler commits its full text, and speakUserStatement's finally sets speakingUserStatement=false while the second statement plays. Express phrases via speakAsUserTurn behave the same. Fix choice (ignore vs replace the second tap) is a product decision for Ken, as the reviewer notes.
