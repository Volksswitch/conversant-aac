# CR-079: Tapping a partner, place, feeling or goal while a reprompt is running discards that reprompt's classification

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** race-condition
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:4507`
- **Also affects:** `app/js/app.js:4514 (const token = ++generationToken)`; `app/js/app.js:4544 (engine.refreshPalette instead of ingestClassification)`; `app/js/app.js:1743-1911 (generateOptions: everything skipped when superseded)`; `app/js/app.js:1819-1826 (superseded reprompt returns early)`; `app/js/app.js:3334 and 3361 (handleRegenerate has the same supersede-then-refreshPalette shape when New N is pressed mid-reprompt)`
- **Source:** app-d-02

**What a user notices.** If the person taps who they are talking to just after the other person has said something new, the app can miss what kind of thing was just said: a goodbye is answered with ordinary replies instead of goodbyes, a 'What?' does not bring up the 'say it again' choices, and the partner's offered menu choices never appear as buttons.

**What is wrong.** refreshForContextChange() bumps generationToken, which silently supersedes an in-flight generateOptions() for the newest partner text. generateOptions is the only path that runs engine.ingestClassification(result, partnerText) - so the classification for that checkpoint (CLOSING -> goodbyes + decline card, is_repair_initiator -> REPAIR_OF_SELF palette and prefetchRepairOptions, offered_options/offered_range -> choice chips via setOfferedChoices/setOfferedRange, placeholders.start()/stop(), ui.setTranscriptState('ready'), worldview.recordGaps) is never applied. The refresh then calls engine.refreshPalette(result.responses), which only replaces state.palette and throws away the refresh result's own classification. The refresh path is taken whenever currentPartnerText and lastPalette are both non-empty, i.e. on the second and later silence checkpoints of a turn - which at the 0.5s default is the common case. A related gap: when the in-flight reprompt is the FIRST checkpoint of a turn (lastPalette empty), refreshForContextChange returns false and the reprompt that lands was built from buildSituationBlock() captured before the tap, so the new context is silently not applied to the cards that appear.

**How it happens.** Partner: 'Hi, how are you?' (pause -> cards shown). Partner continues: '...anyway, coffee or tea?' (pause -> reprompt starts). Within the ~3s round trip the user taps their partner's button. The reprompt is superseded; the refresh lands with CHOICE cards via refreshPalette, but no Coffee/Tea chips appear on the Express Panel and the engine never ingested the menu. Same with the partner saying 'Well, I should let you go' (CLOSING never ingested, ordinary reply cards shown instead of goodbyes) or 'What?' (no repair-of-self).

**Suggested fix.** Track the reprompt in flight: add `let repromptToken = 0;` and `let lastIngestedPartnerText = '';` near the other conversation state. In generateOptions set `lastIngestedPartnerText = partnerText` right after the successful engine.ingestClassification call (line 1830). At the top of refreshForContextChange (after the currentStatic.kind check), if `currentPartnerText && currentPartnerText !== lastIngestedPartnerText` then call `generateOptions(currentPartnerText); return true;` instead of the refresh path - generateOptions rebuilds the situation block (now including the new partner/place/feeling/goal) and does the full ingest. Keep the existing refresh path for the case where the newest text has already been ingested. Apply the same guard to handleRegenerate (line 3333).

> **Verifier correction to the fix (takes precedence):** The suggested direction (call generateOptions(currentPartnerText) when the newest text has not been ingested) works. Set lastIngestedPartnerText after the CLOSING fast path's ingest as well, not only after the AI-path ingest. Put the guard before the `!lastPalette.length` early return so the first-checkpoint case is covered too. Be aware that generateOptions clears turn steering (choice-chip focus and typed Reframe text) by design.

**How to verify the fix.** Unit-level is hard because app.js cannot be imported; verify in the browser with Practice Mode: let the AI partner ask an alternative question across two pauses, and tap a partner button during the second generation (status 'Generating response options...'). The choice chips must appear and engine mode/floor must reflect the classification. Add a source-level guard test in tests/placeholders.test.mjs (where app.js source guards live) asserting refreshForContextChange references lastIngestedPartnerText.

**Do not break.** Do not re-ingest the classification on the ordinary refresh path when the text was already ingested (handleRegenerate's comment: re-ingesting can push a duplicate FPP). Do not touch the placeholder ladder in the refresh path (CLAUDE.md: context taps must not abort placeholders). Calling generateOptions drops turn steering by design (the partner said more).

**Design reference.** CLAUDE.md 'WHEN THE RESPONSE CARDS CHANGE' (five things replace the set) and the July 10 2026 no-turn-completion-gate decision; refreshForContextChange header comment (Ken, September 10 2026)

**Verification notes.** Traced. refreshForContextChange() (app.js:4507) bumps generationToken. An in-flight generateOptions() for the newer partner text then returns at its superseded check (about line 1819) without running engine.ingestClassification. Everything after that check is skipped: the CLOSING and REPAIR_OF_SELF palettes, setOfferedChoices and setOfferedRange (the choice chips), setTranscriptState('ready'), placeholders.start/stop and prefetchRepairOptions. The refresh then calls engine.refreshPalette(result.responses), which by design (engine.js:428) only replaces state.palette and drops the refresh result's own classification. handleRegenerate (about line 3333) has the same shape. The refresh path runs whenever currentPartnerText and lastPalette are both non-empty, which is every second and later checkpoint of a turn. The first-checkpoint gap is also real: with lastPalette empty the refresh returns false, and the in-flight reprompt keeps the situation block it captured before the tap.
