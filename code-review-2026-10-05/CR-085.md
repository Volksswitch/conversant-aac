# CR-085: A sound previewed in Settings keeps playing after Settings closes, including into a live conversation

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** resource-leak
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:394`
- **Also affects:** `app/js/express-editor.js:297`; `app/js/express-editor.js:72-77`; `app/js/express-editor.js:704-708`; `app/js/app.js:3907-3923`; `app/js/express-editor.js:394 (merged duplicate: A sound previewed in the Express Panel editor keeps playing after Settings closes and is heard by the microphone as the partner)`
- **Source:** express-04, x-a11y-06

**What a user notices.** If the user taps the speaker beside a sound button in Settings to hear a song or recording and then closes Settings, the sound keeps playing with no button to stop it. If listening is on, the app can write the recording down as if the other person said it and answer it.

**What is wrong.** The editor's preview player lives in the module-level `previewAudio` and is only stopped by tapping the same speaker button again or another row's speaker. Nothing stops it when Settings closes, when the user leaves the Express tab (hostExpressPanel(false) -> clearPicked()), or when render() rebuilds the editor with innerHTML = '' (the Audio element is not in the DOM, so removing rows does not stop it). Clips can be up to 10 MB (several minutes). The comment says preview 'plays and stops without touching the microphone: this is Settings, not a conversation', but Settings can be open while the microphone is listening, and the preview outlives Settings; the panel's own playback mutes the mic precisely because a recording would otherwise be transcribed as the partner. The object URL is also never revoked if play() rejects.

**Evidence.**

```
express-editor.js:297 `let previewAudio = null;`
express-editor.js:406-411 `const player = new Audio(url); previewAudio = { id: item.id, el: player, url }; player.onended = () => { ... };`
express-editor.js:72-77 clearPicked() (called on tab switch / Settings close via app.js:3916) does not touch previewAudio.
express-editor.js:708 `container.innerHTML = '';` (no pause).
```

**How it happens.** Add a sound button with a 3-minute song in Settings > Express Panel, tap its speaker, then close Settings and press Listen. The song continues; the microphone hears it and the transcript fills with song lyrics attributed to the partner, which the AI then answers.

**Suggested fix.** Add an exported `stopPreview()` in express-editor.js that pauses previewAudio.el, revokes its URL and sets previewAudio = null. Call it from clearPicked() (which already runs on every tab switch and Settings close through hostExpressPanel(false)) - but clearPicked returns early when pickedId is null, so call stopPreview() before that early return or call it separately from app.js hostExpressPanel when inSettings is false. Also call it at the top of render() only if the previewed item no longer exists. In the play() catch handler, revoke the URL and clear previewAudio.

> **Verifier correction to the fix (takes precedence):** As the reviewer notes, clearPicked returns early when pickedId is null, so call stopPreview() unconditionally from hostExpressPanel(false) in app.js (or before the early return in clearPicked), not only inside clearPicked's body.

**How to verify the fix.** Manual: preview a long clip, close Settings: audio must stop immediately. Preview, switch to the General tab: audio stops. Preview, add a phrase (editor re-renders): audio keeps playing (acceptable) or stops - either is fine, but closing must stop it.

**Do not break.** Do not route preview through the conversation's audio player or log a turn - preview is not a conversational act. Keep the two-tap stop behaviour of the speaker button.

**Design reference.** CLAUDE.md 'SOUND buttons on the Express Panel' (a tap mutes the microphone; a recording would be transcribed as the partner)

**Verification notes.** previewAudio is module-level (express-editor.js:297) and referenced only inside audioRow's speaker handler. clearPicked, render (innerHTML='') and the Settings close path never pause it; openSettings does not stop listening. A detached Audio element keeps playing after the rows are removed. Reopening Settings and tapping any speaker stops it, which is the only workaround. The microphone-transcription consequence follows because the echo filter only matches the app's own spoken words.
