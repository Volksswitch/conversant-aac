# CR-090: After picking a response card with automatic listening off, the old cards stay on screen and can be tapped again

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2122`
- **Also affects:** `app/js/app.js:2381-2390 resumeOrIdle idle branch`; `app/js/app.js:3717 speakAsUserTurn clears the palette`; `app/js/app.js:2252 handleRepairOfSelf same`; `app/js/app.js:2181 handleRepairOfSelf bumps the token without setPaletteBusy(false)`; `app/js/app.js:2122 (merged duplicate: After a card is spoken with auto-resume off, the used set of cards stays on screen and can be tapped again)`
- **Source:** app-b-06, live-runtime-07

**What a user notices.** With the default setting, after the user taps a suggestion and it is spoken, the same four suggestions stay up. A stray tap on one of them says an out-of-date answer out loud as if it were a new reply. Answering with an Express button, by contrast, clears them, so the screen behaves differently depending on how the user answered.

**What is wrong.** In handleResponseSelected the normal branch ends in resumeOrIdle(). When auto-resume is off or the session is not armed, resumeOrIdle only sets the transcript state and status; nothing clears the palette (ui.showEngineState does not touch the cards). The engine's palette is consumed by selectResponse, but the DOM cards and shownCards stay. speakAsUserTurn explicitly calls clearPalette() ('any AI palette shown is now stale'), and CLAUDE.md states cards return to the empty reserved outlines when something has been spoken. A second tap on a stale card calls handleResponseSelected again: raw is '' (buffer reset), so it commits a standalone user turn, speaks it, and records it against the old set. The repair path has the same gap and additionally leaves the 'palette-refreshing' (cards may change) look on if prefetchRepairOptions was in flight, since handleRepairOfSelf bumps generationToken without ui.setPaletteBusy(false).

**Evidence.**

```
app/js/app.js:2121-2123 `} else {\n        resumeOrIdle();\n    }`
app/js/app.js:2386-2389 `} else {\n        ui.setTranscriptState('idle');\n        ui.setStatus('Ready — tap Listen for the next exchange');\n    }` (no clearPalette)
app/js/app.js:3717 `clearPalette();               // any AI palette shown is now stale` (speakAsUserTurn)
app/js/app.js:2181 `generationToken++;` (handleRepairOfSelf, no setPaletteBusy(false))
```

**How it happens.** Auto-resume off. Tap Listen; partner asks a question; tap the PREFERRED card. It is spoken and committed; the four cards remain. The user's finger brushes the INITIATIVE card: a second, unrelated sentence is spoken to the partner and committed as a new user turn.

**Suggested fix.** In handleResponseSelected, in the final `else` branch, call clearPalette() before resumeOrIdle() (startFreshListening already clears when armed, so clearing first is harmless). Do the same in handleRepairOfSelf before resumeOrIdle() at line 2252, and add `ui.setPaletteBusy(false);` next to `generationToken++` at line 2181. Leave the defers branch (2016-2025) alone — it intentionally keeps the cards up.

**How to verify the fix.** Manual: auto-resume off, pick a card; confirm the response region returns to the four empty reserved outlines and the offer is finalized (no further 'card' outcome possible). Repeat for a repair card. Check the keyguard geometry is unchanged (clearResponseOptions draws the reserved cells).

**Do not break.** Rule 1 reserved real estate: clear via clearPalette() (which draws the empty reserved cells and resets shownCards), never by emptying the region. Do not clear in the 'defers' path or when the wind-down/closing/decline branches replace the palette.

**Design reference.** CLAUDE.md 'WHEN THE RESPONSE CARDS CHANGE — the whole rule' ('The cards return to the empty reserved outlines only when something has been SPOKEN').

**Verification notes.** In handleResponseSelected's final else branch resumeOrIdle() idles without clearing; ui.showEngineState only updates the mode/diagnostic cells and never touches the cards; the card click handler (ui.js:295) does not disable or mark the card. So with auto-resume off the DOM cards and shownCards remain and remain clickable. speakAsUserTurn and playAudioTurn call clearPalette(), so behavior differs by reply path, contrary to CLAUDE.md 'The cards return to the empty reserved outlines only when something has been SPOKEN'. handleRepairOfSelf bumps generationToken without setPaletteBusy(false).
