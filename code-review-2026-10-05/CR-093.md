# CR-093: Practice partner and spoken help can be read in a foreign-language Google voice

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** bug
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/app.js:1133`
- **Also affects:** `app/js/app.js:1160-1165`; `app/js/app.js:288`; `app/js/speech-catalog.js:146-151`; `app/js/app.js:2408-2440`; `app/js/app.js:1139 (merged duplicate: On Google Cloud, the practice partner and spoken help pick a voice from another language)`
- **Source:** app-a-02, x-providers-06

**What a user notices.** A user whose voice is a Google Cloud voice may hear the practice partner, and the spoken help in Settings, in a voice built for another language, which can be hard or impossible to understand.

**What is wrong.** pickRestPartnerVoice resolves 'Auto' by taking the first voice in the cached catalog whose id differs from the user's own voice, with no language check. For Google Cloud the catalog is the full /v1/voices listing, which the catalog reader does not filter by language (unlike Azure, whose fetchVoices filters to English voices). The full Google list contains voices for dozens of languages and is very likely to start with a non-English one (e.g. af-ZA-...), so Auto hands back a voice for another language. The request still succeeds because the language code is derived from the voice name, so the English text is spoken with foreign phonology. The browser-voice picker (pickPartnerVoice) explicitly prefers a different voice IN THE SAME LANGUAGE for exactly this reason; the REST version lost that rule. partnerVoiceOptions feeds this into the practice partner, the practice tour and spoken Settings help (line 288).

**Evidence.**

**How it happens.** Choose Google Cloud as the speaking voice, paste a key so the catalog is fetched and cached, leave 'Practice partner voice' on Auto. Start a practice scenario or tap the Settings '?' and then a control: the partner/help speaks English text in the first non-matching Google voice, typically an Afrikaans or Arabic voice.

**Suggested fix.** In pickRestPartnerVoice, prefer a voice in the same language as the user's own before falling back: derive a language for each entry (for Google use languageOfGoogleVoice from speech-catalog.js on the id; otherwise accept any) and do `const lang = langOf(own); const other = list.find(v => v.id !== own && langOf(v) === lang) || list.find(v => v.id !== own);`. Additionally consider filtering the Google catalog reader to English voices, matching tts-azure.js fetchVoices, so the Settings picker is not hundreds of foreign voices long.

> **Verifier correction to the fix (takes precedence):** The suggested fix is right. languageOfGoogleVoice falls back to en-US for an unrecognised id, so for non-Google providers derive the language only for Google (id matches /^[a-z]{2,3}-[A-Z]{2}-/) and treat other providers as 'any'. Filtering the Google catalog to the user's language family is worth doing too, but filter to the language of the user's OWN chosen voice (or en-*), not hard-coded en-US, so a British or Australian user's partner list is not emptied.

**How to verify the fix.** Extract the selection into a pure helper (or test it via a source-level guard) and add a case to tests/suggest-provider.test.mjs or a new tests/partner-voice.test.mjs: catalog ['af-ZA-Standard-A','en-US-Neural2-F','en-US-Neural2-D'], own 'en-US-Neural2-F' -> expect 'en-US-Neural2-D'. Manual: with a Google key, practice partner Auto speaks in an English voice.

**Do not break.** Keep the 'never the user's own voice when another exists' rule; help and practice must stay audibly distinct from the user. Do not change ElevenLabs (multilingual voices, no language in the id) behavior beyond the fallback.

**Design reference.** CLAUDE.md UI Layout Rule 17 'Voice: the PRACTICE PARTNER's' (intelligibility first) and the pickPartnerVoice same-language rule

**Verification notes.** The code half is confirmed: pickRestPartnerVoice (app.js:1133-1141) takes list.find(v => v.id !== own) with no language check, and the Google catalog reader (speech-catalog.js:146-151) maps the full /v1/voices listing with no language filter; refreshVoices (app.js:7898-7910) caches that unfiltered list, and partnerVoiceOptions feeds the result to the practice partner, the tour and spoken help. The request would still succeed because languageCode is derived from the voice name (speech-catalog.js:126). What I could not verify here is the order Google returns the listing in (no key on this machine); with roughly 1,500 voices of which only a minority are English, the first non-own entry is very likely a foreign voice, and if the list is sorted by name it starts with af-ZA. ElevenLabs is unaffected in practice (multilingual voices). The browser path's pickPartnerVoice does prefer the same language, so the REST path is inconsistent with the recorded intelligibility-first rule.

The Google catalog reader maps every voice the account can use, in every language, with no English filter (Azure's fetchVoices filters to English via filterVoices). pickRestPartnerVoice ('Auto') returns the FIRST catalog entry that is not the user's own voice, with no same-language preference, unlike pickPartnerVoice for device voices which prefers the user's language. Google's voice list spans ~50 languages, so the first non-own entry is almost certainly not English. partnerVoiceOptions feeds this into Practice Mode, the controls tour and spoken help (app.js:288), which CLAUDE.md requires to be intelligible. Language is derived from the voice name (languageOfGoogleVoice), so English text is sent with a foreign languageCode.

Fix as proposed by that reviewer: In speech-catalog.js google.catalog.read, keep only English voices: filter `(v.languageCodes || []).some((c) => /^en-/i.test(c))`, and sort en-US first then by name (same shape as tts-azure filterVoices). Additionally make pickRestPartnerVoice prefer a voice whose language matches the user's own: compute `const lang = (id === 'google') ? languageOfGoogleVoice(own) : null;` and try `list.find(v => v.id !== own && (!lang || languageOfGoogleVoice(v.id) === lang))` before falling back to any non-own voice.
