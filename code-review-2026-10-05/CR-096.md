# CR-096: A data file whose folder write fails is reported as restored, but the old folder file wins on restart

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** medium
- **Category:** data-loss
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/data-transfer.js:403`
- **Also affects:** `app/js/worldview.js:142-158`; `app/js/relationships.js:84-92`; `app/js/voice.js:101-109`
- **Source:** review-backup-02

**What a user notices.** If the computer briefly refuses to write a file during a restore (a cloud-sync lock, a full disk), the app says the restore worked, but after the restart some of the person's answers or buttons quietly go back to how they were before.

**What is wrong.** applyPackage writes the cache first and then the folder file, swallowing any folder error and still counting the file as restored. Every model loads the folder file first and only falls back to the cache when the folder file is missing, then overwrites the cache with what it loaded. So a failed folder write means the reload that offerRestart forces reads the OLD folder file, discards the newly written cache, and the user is never told. The comment 'cache write already succeeded; folder is best-effort' is the opposite of the source-of-truth rule.

**Evidence.**

```
data-transfer.js:403-406
        try {
            await storage.writeFile(entry.file, text);   // no-op without a data folder
        } catch { /* cache write already succeeded; folder is best-effort */ }
        restored.files.push(entry.label);
worldview.js:144-153
    const fromDisk = await readFile(PROFILE_FILE);
    if (fromDisk) { try { loaded = JSON.parse(fromDisk); } ... }
    if (!loaded) loaded = readCache();
    ...
    writeCache(profile);
```

**How it happens.** Windows, data folder inside OneDrive. During import OneDrive holds a lock on express-panel.json so createWritable throws. Restart card says imported. After reload the Express Panel shows the pre-import buttons.

**Suggested fix.** In applyPackage's DATA_FILES loop: when `storage.hasDataFolder()` is true and writeFile throws, push `entry.label` to `restored.failed` and `continue` (do not push to restored.files). Then surface `failed` in the restart card (see the separate finding about offerRestart). Optionally retry the write once before giving up.

**How to verify the fix.** Unit test in tests/ (pattern of tests/storage-transcript.test.mjs with the OPFS shim): make the shim's createWritable throw for 'express-panel.json', call applyPackage, assert restored.failed contains 'Express Panel items' and restored.files does not.

**Do not break.** Without any data folder (no remembered folder either) the cache IS the store, so a missing folder must still count as success there. Do not change load precedence in the models.

**Design reference.** CLAUDE.md 'The file in the folder is the source of truth - full stop' (v0.2.25)

**Verification notes.** The mechanism is real: applyPackage swallows a storage.writeFile exception after a successful cache write and still pushes the label into restored.files (data-transfer.js 403-406); every model's load() prefers the folder file and then overwrites the cache with it (worldview.js 142-153, voice.js load), so the reload forced by offerRestart reads the old folder file. Whether a write actually throws during a real import (a OneDrive lock, a full disk) could not be confirmed; the trigger is plausible but unmeasured.
