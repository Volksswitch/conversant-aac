# CR-100: "Which side" switch has no focus indicator, a sub-minimum target and an invisible off-state outline

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:3782`
- **Also affects:** `app/css/styles.css:3790-3826`; `app/index.html:986-989 (#sideDockPositionToggle)`
- **Source:** css-06

**What a user notices.** The Left/Right switch for the side keyboard is hard to see when off, much smaller than every other control in Settings, and shows nothing when reached with a keyboard.

**What is wrong.** The only `.switch` control (Settings, side dock 'Which side') is 3rem x 1.5rem (about 44x22px), well under the --btn-min-dim floor every other Settings control gets. Its real checkbox is opacity:0, and there is no `.switch input:focus-visible + .switch-track` rule, so keyboard focus is invisible. Off, the track is --surface-pressed (#d7dde1) on a white panel with a white knob, about 1.4:1, failing the 3:1 boundary rule that Rule 22 enforces with --edge/--edge-strong.

**Evidence.**

```
styles.css:3782-3788 `.switch { position: relative; display: inline-block; width: 3rem; height: 1.5rem; flex-shrink: 0; }`
styles.css:3790-3797 `.switch input { position: absolute; opacity: 0; ... }`
styles.css:3799-3805 `.switch-track { position: absolute; inset: 0; background: var(--surface-pressed); border-radius: 1.5rem; ... }`
```

**How it happens.** Settings > Buttons & Keyboard > side dock: the switch is a pale pill on white; tabbing to it with a physical keyboard shows no focus; a person with limited motor control must hit a 22px-tall target.

**Suggested fix.** Add `box-shadow: inset 0 0 0 2px var(--edge-strong);` to `.switch-track` (an inset shadow does not move the knob the way a border would). Add `.switch input:focus-visible + .switch-track { outline: 3px solid var(--link); outline-offset: 2px; }`. Enlarge the hit area by setting `.switch { width: 4.5rem; height: 2.25rem; }` and scale the knob: `.switch-track::before { top: 0.25rem; left: 0.25rem; width: 1.75rem; height: 1.75rem; }` and `.switch input:checked + .switch-track::before { transform: translateX(2.25rem); }`.

> **Verifier correction to the fix (takes precedence):** Enlarging the switch to 4.5rem x 2.25rem is fine, but the hit area could instead stay small visually and grow via min-height on the label; either way make sure the slider-row with its Left/Right labels still fits on the narrow side-dock Settings panel.

**How to verify the fix.** Manual in Settings at default and Dark schemes: the off switch has a visible outline; Tab reaches it and shows a ring; toggling still moves the dock. tests/styles.test.mjs edge-contrast checks still pass.

**Do not break.** Settings only; no keyguard geometry involved. Keep the checkbox as the real control (aria and label for= rely on it).

**Design reference.** CLAUDE.md UI Layout Rule 22 (every boundary drawn from --edge tokens, 3:1) and the --btn-min-dim floor note at styles.css:2665

**Verification notes.** .switch is 3rem x 1.5rem (styles.css:3782-3788), the real checkbox is opacity 0, and there is no focus-visible rule for .switch input or .switch-track anywhere in the stylesheet. The off track is --surface-pressed (#d7dde1 default) with a --surface-raised knob on a --surface-raised panel, well under 3:1. It is the only .switch in index.html (986-989, #sideDockPositionToggle). Not in the ui-standards DELIBERATE list.
