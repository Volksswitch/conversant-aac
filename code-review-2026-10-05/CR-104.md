# CR-104: aria-label placed on plain divs (Command Bar, Express Panel, composer) is ignored by assistive technology

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/index.html:136`
- **Also affects:** `app/index.html:166`; `app/index.html:191`
- **Source:** ui-shell-11

**What a user notices.** Screen readers do not announce the names 'Command Bar', 'Express Panel' or 'In my own words' for these areas, so a user navigating by region cannot tell them apart.

**What is wrong.** aria-label is not supported on a generic <div> with no role (ARIA 1.2 prohibits naming the generic role), so #listenControls, #epGrid and #composerOverlay carry names that are never exposed.

**Evidence.**

```
index.html:136  <div id="listenControls" aria-label="Command Bar">
index.html:166  <div id="composerOverlay" class="composer-overlay" hidden aria-label="In my own words">
index.html:191  <div id="epGrid" aria-label="Express Panel"></div>
```

**How it happens.** Inspect #listenControls in the accessibility tree: role generic, no name.

**Suggested fix.** Add roles: `role="toolbar"` on #listenControls, `role="group"` on #epGrid, and `role="group"` on #composerOverlay (keep the existing aria-label values).

> **Verifier correction to the fix (takes precedence):** Prefer role="group" (or role="region") on #listenControls rather than role="toolbar": toolbar tells screen-reader users to expect arrow-key roving focus, which the Command Bar does not implement. role="group" on #epGrid and #composerOverlay is fine.

**How to verify the fix.** Chrome devtools Accessibility pane shows the roles and names; tests/ui-standards.test.mjs still passes (no geometry change).

**Do not break.** Attributes only - no CSS or layout change, so no keyguard hole moves.

**Design reference.** CLAUDE.md UI Layout Rule 4/12 (keep accessible names)

**Verification notes.** index.html:136, 166 and 191 put aria-label on plain divs with no role, and nothing in ui.js assigns a role to them later (grep found none). ARIA 1.2 prohibits naming the generic role, so these names are not exposed.
