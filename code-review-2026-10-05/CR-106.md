# CR-106: The Settings dialog has no accessible name

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/index.html:196`
- **Also affects:** `app/index.html:200`; `app/js/app.js:6999`
- **Source:** g-a11y-overflow-05

**What a user notices.** When Settings opens, a screen reader announces only 'dialog' rather than 'Settings', so the user is not told where they are.

**What is wrong.** <dialog id="settingsDialog"> has no aria-labelledby or aria-label, although its title span #settingsTitle exists. openSettings() then parks focus on #settingsHeader, a generic div with tabindex=-1 and no role, so the first announcement is an unnamed dialog followed by an unnamed group.

**Evidence.**

```
app/index.html:196 <dialog id="settingsDialog">
app/index.html:200-201 <div id="settingsHeader" tabindex="-1"> <span id="settingsTitle">Settings</span>
app/js/app.js:6999 document.getElementById('settingsHeader')?.focus();
```

**How it happens.** With Narrator on, tap the Settings button: Narrator says 'dialog' (or reads the header div contents ambiguously) instead of 'Settings, dialog'.

**Suggested fix.** In index.html change line 196 to <dialog id="settingsDialog" aria-labelledby="settingsTitle">.

**How to verify the fix.** Manual: open Settings with a screen reader and confirm it announces 'Settings, dialog'. Optionally a source check in tests/ui-standards.test.mjs that #settingsDialog has aria-labelledby resolving to non-empty text.

**Do not break.** Do not move focus to a control on open; the header focus is deliberate (avoids raising the on-screen keyboard).

**Design reference.** none

**Verification notes.** <dialog id="settingsDialog"> (index.html:196) has neither aria-labelledby nor aria-label, although #settingsTitle exists. openSettings focuses #settingsHeader, a generic div with tabindex=-1. The one-attribute fix is correct and harmless.
