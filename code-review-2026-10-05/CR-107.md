# CR-107: Settings radio groups have no group name (no fieldset/legend or radiogroup label)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/index.html:336`
- **Also affects:** `app/index.html:333`; `app/index.html:335`; `app/index.html:600`; `app/index.html:604`; `app/index.html:627`; `app/index.html:628`; `app/index.html:933`; `app/index.html:934`; `app/index.html:957`; `app/index.html:958`; `app/index.html:970`; `app/index.html:971`; `app/js/sections.js:98`
- **Source:** g-a11y-overflow-04

**What a user notices.** A screen-reader user landing on a choice such as 'Two taps' or 'Bottom of the screen' is not told what question it answers, so the six choice groups in Settings (taps, hearing service, speaking voice, review list, keyboard type, keyboard position) are hard to understand without sight.

**What is wrong.** All six radio groups (expressTapMode, sttProvider, ttsProvider, reviewListKind, keyboardMode, keyboardDock) are a bare <div class="radio-row"> of <label class="radio-label"> elements. The text that names each group is a <label> with no for attribute and no wrapped control, so it labels nothing: 'How many taps a button needs', 'Keyboard for typing', 'Where it sits'. For sttProvider and ttsProvider the naming label is the group heading, which sections.js removes and replaces with a summary span, and sections.js only adds aria-labelledby when the heading had htmlFor - so these groups also lose their name. No role=radiogroup, fieldset or legend exists anywhere in the app.

**Evidence.**

```
app/index.html:335 <label>How many taps a button needs</label>
app/index.html:336 <div class="radio-row">
app/index.html:338 <input type="radio" name="expressTapMode" value="single" checked>
app/index.html:600 <label>Hearing the other person</label>
app/index.html:604 <div class="radio-row">
app/js/sections.js:101-104 const control = heading.htmlFor ? document.getElementById(heading.htmlFor) : null; if (control && !control.getAttribute('aria-label')) { control.setAttribute('aria-labelledby', title.id); }
```

**How it happens.** Open Settings > Screen layout tab... (Express Panel and Keyboard tab), open the section, Tab into the radios: the reader says 'Bottom of the screen, radio button, checked, 1 of 2' with no 'Where it sits'.

**Suggested fix.** In index.html add role="radiogroup" and a name to each .radio-row. Where the group's naming label is NOT a section heading (lines 335, 957, 970), give that label an id and point to it: e.g. <label id="tapModeLabel">How many taps a button needs</label> <div class="radio-row" role="radiogroup" aria-labelledby="tapModeLabel">; same for 'Keyboard for typing' (id keyboardModeLabel) and 'Where it sits' (id keyboardDockLabel). For the three whose name is the section heading (sttProvider at 604 'Hearing the other person', ttsProvider at 628 'Your speaking voice', reviewListKind at 934 'Saved conversations'), use aria-label with the same words, because sections.js replaces that heading with a span of a generated id.

**How to verify the fix.** Extend tests/ui-standards.test.mjs (it walks every Settings tab) to assert every input[type=radio] has an ancestor [role=radiogroup] with a non-empty accessible name (aria-label or aria-labelledby resolving to text). Manual: Narrator reads 'Where it sits, grouping' on entry.

**Do not break.** Do not use <fieldset>/<legend> unless styled, because fieldset adds a border and padding that would change Settings layout and the ui-standards measurements; role=radiogroup has no visual effect. Do not add a for= to the heading labels (sections.js would then put aria-labelledby on one radio only). Spoken-help (help-mode.js resolveTap) keys off data-help on the group, which is unchanged.

**Design reference.** UI-Design.docx §13 control standards; CLAUDE.md UI Layout Rule 18

**Verification notes.** I checked all six groups. Each is a bare .radio-row with no role, and no radiogroup, fieldset or legend exists anywhere in the app. The labels 'How many taps a button needs' (index.html:335), 'Keyboard for typing' and 'Where it sits' have no for attribute and wrap no control. For sttProvider, ttsProvider and reviewListKind, the naming label is the group heading. sections.js (lines 87-108) turns that heading into a summary span and adds aria-labelledby only when heading.htmlFor is set, so these groups get no name. The radios still sit inside a details element whose summary names the section, which helps a little but gives the group no name.
