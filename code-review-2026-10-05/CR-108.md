# CR-108: When a phrase-at-a-time speech service stops, the screen-reader status still says 'Listening...'

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1346`
- **Also affects:** `app/js/app.js:1304 'idle' is treated as stopped for isListening`
- **Source:** app-b-13

**What a user notices.** A person using a screen reader with the OpenAI, Google or ElevenLabs hearing service is told the app is still listening after it has stopped.

**What is wrong.** handleSttStatus maps 'idle' to isListening=false (the REST sources report 'idle' when they stop), but the status-line branch only handles 'stopped', so ui.setStatus('Ready') never runs for 'idle'; the hidden aria-live status keeps the stale 'Listening...'.

**Evidence.**

```
app/js/app.js:1304 `if (status === 'stopped' || status === 'idle' || status === 'error') isListening = false;`
app/js/app.js:1346-1347 `} else if (status === 'stopped') {\n        ui.setStatus('Ready');`
```

**How it happens.** Settings: hearing via OpenAI. Tap Listen, then tap Listen to stop. The visible button turns off but the status region still reads 'Listening...'.

**Suggested fix.** Change line 1346 to `} else if (status === 'stopped' || status === 'idle') {`.

**How to verify the fix.** Manual with a screen reader or by reading #status text after stopping a REST-backed session.

**Do not break.** none

**Design reference.** none

**Verification notes.** stt-rest.js stop() emits onStatus('idle'); stt.js passes external-source statuses straight to onStatusChange; stt.stopListening returns externalSource.stop() before its own 'stopped' emit. handleSttStatus sets isListening=false for 'idle' but only calls ui.setStatus('Ready') for 'stopped', and toggleListening's stop branch sets no status, so the aria-live #statusBar keeps 'Listening...'.
