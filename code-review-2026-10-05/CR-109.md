# CR-109: Settings tab panels are not tabpanels and are not linked to their tabs

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:5452`
- **Also affects:** `app/index.html:211`; `app/index.html:228`; `app/js/app.js:5622`; `app/js/app.js:6985`
- **Source:** g-a11y-overflow-03

**What a user notices.** A screen-reader user who picks a Settings tab is told a tab was selected, but the reader cannot say which panel belongs to it or jump into it, and the panel contents are announced with no indication of which tab they came from.

**What is wrong.** initSettingsTabs() gives the nav role=tablist and each .settings-tab div role=tab, aria-selected and a roving tabindex, but never sets aria-controls on the tabs, and the .tab-panel divs get no role=tabpanel, no id, and no aria-labelledby. The tab pattern is therefore half-implemented: assistive technology announces 'tab, selected, 3 of 14' with no relationship to the content, and the panel region has no name. Neither activateSettingsTab() nor the reset in openSettings() touches the panels' semantics.

**Evidence.**

```
app/js/app.js:5455 tablist.setAttribute('role', 'tablist');
app/js/app.js:5458 tab.setAttribute('role', 'tab');
app/js/app.js:5461 tab.setAttribute('aria-selected', String(on));
app/index.html:212 <div class="settings-tab active" data-tab="general">General</div>
app/index.html:228 <div class="tab-panel active" data-tab="general">   (no role, id or aria-labelledby)
```

**How it happens.** Open Settings with a screen reader, arrow to 'Speech'. The reader says 'Speech, tab, selected' but its 'go to controlled element' command does nothing and the panel is read as anonymous generic content.

**Suggested fix.** In initSettingsTabs(), for each tab: const name = tab.dataset.tab; tab.id = `settingsTab-${name}`; const panel = document.querySelector(`#settingsContent .tab-panel[data-tab="${name}"]`); if (panel) { panel.id = `settingsPanel-${name}`; panel.setAttribute('role','tabpanel'); panel.setAttribute('aria-labelledby', tab.id); tab.setAttribute('aria-controls', panel.id); }. Optionally give each panel tabIndex=-1 is NOT needed since panels contain focusable controls. No change is needed in activateSettingsTab because hidden panels are display:none.

**How to verify the fix.** Add a check in tests/ui-standards.test.mjs (browser test that already walks the tabs) asserting every [role=tab] has aria-controls pointing to an element with role=tabpanel whose aria-labelledby is the tab's id. Manual: Narrator reads 'Speech tab panel' when entering the panel.

**Do not break.** help-mode.js resolves taps on .settings-tab by class and data-tab; adding ids/roles must not change classes. Do not set hidden on panels via attribute (CSS display:none already hides them).

**Design reference.** CLAUDE.md UI Layout Rule 18 (Settings tabs); UI-Design.docx §13 control standards

**Verification notes.** initSettingsTabs (app.js:5452-5481) sets role=tablist, role=tab, aria-selected and a roving tabindex. It never sets aria-controls on the tabs. No .tab-panel gets role=tabpanel, an id, or aria-labelledby, and a grep for 'tabpanel' and 'aria-controls' finds nothing. The tab pattern is therefore only half implemented, as described.
