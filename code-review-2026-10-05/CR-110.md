# CR-110: The red confirmation card and the busy/notice cards have no accessible name or description

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/confirm-dialog.js:34`
- **Also affects:** `app/js/confirm-dialog.js:46`; `app/js/confirm-dialog.js:51`; `app/js/confirm-dialog.js:118`; `app/js/confirm-dialog.js:34 (merged duplicate: Danger confirmation dialog has no accessible name or description)`
- **Source:** x-a11y-12, ui-shell-10

**What a user notices.** When the app asks 'Delete this button?' or 'Clear everything?', a screen reader user hears only 'Cancel, button' because focus goes straight to Cancel and the warning itself is never read.

**What is wrong.** confirmDanger builds a <dialog> with an h2 title and a p body but sets no aria-labelledby/aria-describedby, then focuses the Cancel button. A modal dialog without a name or description is announced only by its focused control. neutralCard (showBusy/showNotice) has the same gap.

**Evidence.**

```
confirm-dialog.js:34-38 `const dlg = document.createElement('dialog'); dlg.className = preview ? 'danger-dialog has-preview' : 'danger-dialog';`
confirm-dialog.js:46-53 `const h = document.createElement('h2'); ... const p = document.createElement('p'); p.className = 'danger-body';`
confirm-dialog.js:95 `cancelBtn.focus();`
```

**How it happens.** Settings > About Me > 'Restart — clear all answers' with a screen reader: only 'Keep my answers, button' is announced.

**Suggested fix.** Generate unique ids (e.g. a module counter) and set `h.id = 'dlg-title-' + n; p.id = 'dlg-body-' + n; dlg.setAttribute('aria-labelledby', h.id); dlg.setAttribute('aria-describedby', p.id);` in confirmDanger and in neutralCard. Optionally `role="alertdialog"` on the danger variant.

**How to verify the fix.** Puppeteer: call confirmDanger from the page and assert the open dialog's aria-labelledby resolves to the title text. Existing confirm behaviour (Cancel focused by default, Escape cancels) must still pass.

**Do not break.** Keep Cancel focused by default (CLAUDE.md: a stray Enter must cancel). Do not change the card's styling.

**Design reference.** CLAUDE.md Configurability philosophy - 'Confirm before destroying significant work' (confirmDanger)

**Verification notes.** confirm-dialog.js has no aria-labelledby, aria-describedby or role on the dialog. The only aria attributes are aria-hidden on the warning mark and role=status on a progress element. confirmDanger then focuses Cancel (95), so a screen reader announces the focused button rather than the warning. neutralCard has the same gap and focuses its own button at 199.

confirmDanger builds a <dialog> with an <h2> title and a <p> body but never links them (no aria-labelledby / aria-describedby, no role='alertdialog'). Do the same in neutralCard (role 'dialog' is fine there).


Verifier correction: Use a module counter for the ids rather than Math.random (deterministic and collision-free). showBusy already carries a role=status live region for progress, so its h2/body linkage should use role='dialog' with aria-labelledby; do not make showBusy an alertdialog.
