# CR-111: Commands editor's up/down/delete glyph buttons have no accessible name or tooltip

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/control-phrases-editor.js:80`
- **Also affects:** `app/js/control-phrases-editor.js:37`; `app/js/control-phrases-editor.js:82`; `app/js/control-phrases-editor.js:84`; `app/js/worldview-ui.js:842`; `app/js/worldview-ui.js:1755`
- **Source:** x-rules-06

**What a user notices.** On Settings > Commands, each phrase has three small buttons showing only an arrow or an X. A screen reader reads them as 'upwards arrow', 'downwards arrow' and 'multiplication x', and hovering shows no tooltip saying what they do.

**What is wrong.** The local mkBtn() in control-phrases-editor.js sets only textContent and never sets aria-label or title, unlike the same helper in express-editor.js and placeholder-editor.js, which take a title argument. The reorder and delete buttons are therefore glyph-only with no accessible name. The goal-list buttons in worldview-ui.js have aria-labels but no title, and the multi-entry remove '✕' (worldview-ui.js:1755) has aria-label 'Remove' and no title. The standing rule is that icon-only constant buttons carry both aria-label and title.

**Evidence.**

```
app/js/control-phrases-editor.js:37-43: function mkBtn(label, cls) { const b = document.createElement('button'); b.type = 'button'; b.textContent = label; if (cls) b.className = cls; return b; }
app/js/control-phrases-editor.js:80-84: const up = mkBtn('↑'); ... const down = mkBtn('↓'); ... const del = mkBtn('✕', 'ee-del');
app/js/worldview-ui.js:842-847: el('button', { ..., 'aria-label': 'Move up' }, '↑') ... (no title)
```

**How it happens.** Open Settings > Commands, expand any section, and inspect a row's ↑ ↓ ✕ buttons: no aria-label and no title attribute.

**Suggested fix.** Give control-phrases-editor.js's mkBtn a third 'title' parameter that sets both b.title and aria-label, exactly as placeholder-editor.js:49-55 does, and pass 'Move up', 'Move down' and 'Delete this phrase' at lines 80, 82 and 84. In worldview-ui.js add a matching title to the three goal-list buttons (lines ~842-847) and to the remove button at ~1755.

**How to verify the fix.** Manual: hover each button to see the tooltip, and check the names in the accessibility tree. tests/ui-standards.test.mjs (the browser test that walks Settings) can assert that every button whose text is a single non-letter glyph has a non-empty aria-label and title.

**Do not break.** None. Do not change button sizes; they are governed by the shared .ee-tools styles.

**Design reference.** CLAUDE.md UI Layout Rule 12 / Rule 4 (icon-only constant buttons keep an accessible name: aria-label + title)

**Verification notes.** control-phrases-editor.js mkBtn (lines 37-43) sets only textContent and className. The up, down and delete buttons at lines 80-84 have no aria-label and no title. The worldview-ui.js goal buttons (842-847) and the multi-entry remove at 1755 have aria-label but no title. This conflicts with Rule 12's 'aria-label + title' for icon-only constant buttons.
