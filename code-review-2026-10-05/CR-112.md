# CR-112: In the Express Panel editor, tabbing into a row does not select it, so Move/Delete act on a different button

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:259`
- **Also affects:** `app/js/express-editor.js:304`; `app/js/express-editor.js:422`; `app/js/express-editor.js:164`; `app/js/express-editor.js:177`; `app/js/express-editor.js:500`
- **Source:** x-a11y-07

**What a user notices.** Someone setting up the panel with a keyboard can type into the third phrase, then press the toolbar's Move up and find a different phrase moved, because the editor still thinks the last clicked row is the selected one.

**What is wrong.** Rows are marked as the selected (picked) row only on `pointerdown` (phraseRow 259, audioRow 304, contextRow 422). The band toolbar (▲ ▼ ✕, line 500) acts on `pickedId`. Moving focus into a row with Tab never calls markPicked, so pickedId stays on whatever row was last clicked/tapped (or a panel cell tapped earlier, or null). move() then silently reorders the wrong item; removePicked() deletes the wrong item (its confirmation names it, which is the only safeguard). The panel highlight (pickedId drives `.ep-picked`) also points at the wrong cell.

**Evidence.**

```
express-editor.js:259 `row.addEventListener('pointerdown', () => markPicked(row, item.id));` (same at 304 and 422)
express-editor.js:164-174 `function move(band, dir) { const list = bandList(band).slice(); const i = list.findIndex((x) => x.id === pickedId); ...`
express-editor.js:500-502 toolbar buttons 'Move the selected button up/down', 'Delete the selected button'.
```

**How it happens.** 1. Physical keyboard mode. 2. Settings > Express Panel and Keyboard; open the Always section. 3. Click phrase row 1's text box (row 1 picked). 4. Press Tab until focus is in row 3's text box and type. 5. Shift+Tab back to the ▲ toolbar button and press Enter: row 1 (not row 3) moves.

**Suggested fix.** In phraseRow, audioRow and contextRow, add `row.addEventListener('focusin', () => markPicked(row, item.id));` next to the existing pointerdown listener. markPicked already avoids re-rendering, so focus is kept.

**How to verify the fix.** Puppeteer case in tests/ui-standards.test.mjs or a new browser test: focus row 3's input via element.focus(), then click the ▲ toolbar button and assert the model order changed for row 3's item. Manual repetition of the failure scenario.

**Do not break.** markPicked must keep NOT re-rendering (comment at express-editor.js:198-204 - a rebuild would drop focus and the on-screen keyboard). Do not trigger onPick's panel re-render more than once per focus change (markPicked already returns early when pickedId is unchanged).

**Design reference.** CLAUDE.md UI Layout Rule 20 ('An editor for a grid edits ONE cell at a time') and the 'Express Panel editor' notes

**Verification notes.** markPicked is wired only to `pointerdown` (express-editor.js:259, 304, 422), and the editor has no focusin listener. move() and removePicked() both act on pickedId. Tabbing into a different row therefore leaves the toolbar acting on the last clicked row. Severity is low rather than medium for three reasons: the picked row stays highlighted on screen, Delete goes through a confirmation that names the button, and a wrong move can be undone. The trigger also needs keyboard-only use in Settings.
