# CR-113: Several editor dropdowns have no accessible name

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:458`
- **Also affects:** `app/js/express-editor.js:688-700`; `app/js/express-editor.js:238-250`
- **Source:** express-13

**What a user notices.** A screen-reader user hears only 'combo box, Anyone' or 'combo box, choose' for the partner, place and situation pickers in the Express Panel editor, with no word saying what each one chooses.

**What is wrong.** pickerFor() (partner and place pickers in Context rows) and scopeSelect() (the two Flex 'Editing the Flex band for ... at ...' selects) create <select> elements with no label, aria-label or aria-labelledby. The visible lead text and the 'Partner'/'Place' kind span are not associated. By contrast the recording-kind select (line 319) and the 'Already set up' select (line 576) do carry aria-labels, so the editor is inconsistent. Text inputs rely on placeholder only, which is a weaker fallback.

**Evidence.**

```
express-editor.js:459-460 `const sel = document.createElement('select'); sel.className = 'ee-name-select';` (no aria-label)
express-editor.js:689-690 `const sel = document.createElement('select'); sel.className = 'ee-scope-select';` (no aria-label)
express-editor.js:319 `kind.setAttribute('aria-label', 'What kind of recording this is');` (the one that is labelled)
```

**How it happens.** Use a screen reader on Settings > Express Panel > Flex: the two scope selects are announced only by their current value.

**Suggested fix.** Give pickerFor a label parameter and set `sel.setAttribute('aria-label', label)` - pass 'Which person this button is for' / 'Which place this button is for'. Give scopeSelect a label parameter: 'Which partner the Flex phrases are for' / 'Which place the Flex phrases are for'. For textInput, set aria-label to the placeholder text (`i.setAttribute('aria-label', placeholder)`).

**How to verify the fix.** Run tests/ui-standards.test.mjs; manually inspect the accessibility tree in the browser for the four selects.

**Do not break.** No visible text changes (Rule 14); aria only.

**Design reference.** CLAUDE.md UI Layout Rule 4/12 (retain accessible names)

**Verification notes.** pickerFor and scopeSelect create <select> elements with no aria-label or aria-labelledby, and the lead text and kind span are not associated with them. By contrast the recording-kind select and the situation select do carry aria-labels. Text inputs rely on placeholder alone.
