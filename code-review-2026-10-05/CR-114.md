# CR-114: Spoken help ('?') says nothing for the Always, Context and Flex sections of the Express Panel editor

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:489`
- **Also affects:** `tests/settings-help.test.mjs:61-71`; `app/js/help-mode.js:122-143`; `settings-help.json`; `app/js/express-editor.js:490 (merged duplicate: The Express Panel tab's Always / Flex / Context sections are silent under the spoken-help '?')`
- **Source:** express-09, x-contracts-10

**What a user notices.** With the '?' help armed in Settings, tapping the Always, Context or Flex headings, or any button inside them, says nothing, so it looks as if help is broken on the most-used part of the Express Panel tab.

**What is wrong.** section() builds `.setting-group ee-section` groups with no data-help, and every control inside is built without an id. help-mode.resolveTap therefore finds no control key, no group data-help, and (because id-less controls make the group 'unnameable') no fallback - key is null and nothing is spoken. settings-help.json has no entries for these sections, and tests/settings-help.test.mjs runtimeSectionKeys() scans control-phrases-editor.js, placeholder-editor.js and practice-editor.js but not express-editor.js, so the gap is invisible to the coverage test. CLAUDE.md records this exact failure for the Controls editor and the rule that a runtime-built editor must be added to that list.

**Evidence.**

```
express-editor.js:489-494 `function section(key, title, build) { const wrap = el('div', 'setting-group ee-section'); wrap.dataset.band = key; wrap.appendChild(el('label', null, title)); ...` (no dataset.help)
tests/settings-help.test.mjs:62-66 sources list omits express-editor.js
help-mode.js:140-142 `else unnameable = true; } if (!unnameable && keys.size === 1) key = [...keys][0];`
```

**How it happens.** Settings > Express Panel, tap '?', then tap the 'Always — the words that never move' heading: nothing is spoken.

**Suggested fix.** In section(), set `wrap.dataset.help = 'express' + key[0].toUpperCase() + key.slice(1)` (e.g. expressAlways, expressContext, expressFlex). Add three 15-25 word entries under "sections" in settings-help.json (root), regenerate with `node scripts/apply-settings-help.mjs`, and add `['express-editor.js', /section\('([a-z]+)'/g]` handling to runtimeSectionKeys in tests/settings-help.test.mjs (mapping to the same derived key) so a future section without help fails the test.

> **Verifier correction to the fix (takes precedence):** runtimeSectionKeys passes captured strings straight through as help keys. Either set dataset.help to exactly the band key ('always', 'context', 'flex') and name the settings-help.json entries that way, or make the test's regex capture the derived name. Check those plain keys do not collide with existing section entries before choosing them.

**How to verify the fix.** npm test (settings-help test must now include the three keys and pass); manually tap each heading with '?' armed and hear the phrase.

**Do not break.** Per Rule 14 do not add on-screen hint text; spoken help only. Keep entries under the 35-word cap the test enforces.

**Design reference.** CLAUDE.md UI Layout Rules 17 and 18 ('THE CONTROLS HEADINGS SHIPPED SILENT UNDER THE "?"')

**Verification notes.** section() builds .setting-group ee-section with no data-help, and every control in it is created without an id. help-mode resolveTap: no control key, no group data-help, and the id-less controls set unnameable, so key stays null; decideTap only speaks when tap.key is set, so nothing is said. tests/settings-help.test.mjs runtimeSectionKeys lists control-phrases-editor.js, placeholder-editor.js and practice-editor.js but not express-editor.js.

<details><summary>Merged duplicate x-contracts-10: The Express Panel tab's Always / Flex / Context sections are silent under the spoken-help '?'</summary>

express-editor builds its three band sections at runtime as `.setting-group ee-section` with a <label> heading but no data-help, and its buttons/inputs have no ids. help-mode.resolveTap falls back to `section:<data-help>`, then to the group's controls only if every control has an id; here neither applies, so key stays null and the tap is swallowed silently. CLAUDE.md Rule 17/18 require every Settings section header to speak and records exactly this failure (Controls headings shipped silent because the coverage test only read index.html); the test now scans three runtime editors but not express-editor.js.

Fix as proposed by that reviewer: In express-editor.js section(), add `wrap.dataset.help = 'band' + key.charAt(0).toUpperCase() + key.slice(1);` (bandAlways, bandFlex, bandContext). Add matching short entries (15-25 words, American English) to settings-help.json under `sections`, regenerate app/js/settings-help.js with scripts/apply-settings-help.mjs, and add `['express-editor.js', /section\('([^']+)'/g]` (mapping to the same key scheme) to the runtime-scan list in tests/settings-help.test.mjs.

</details>
