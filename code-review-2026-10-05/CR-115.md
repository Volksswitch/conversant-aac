# CR-115: Practice form fields and the Commands editor's arrow and delete buttons have no accessible names

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/practice-editor.js:70`
- **Also affects:** `app/js/practice-editor.js:218-240`; `app/js/practice-editor.js:271-275`; `app/js/control-phrases-editor.js:37-43`; `app/js/control-phrases-editor.js:80-86`; `app/js/placeholder-editor.js:49-56`
- **Source:** phrases-practice-12

**What a user notices.** Someone using a screen reader hears unnamed boxes and drop-downs on the Practice form, and hears 'up arrow', 'down arrow' and 'multiplication x' on the Commands tab instead of what the buttons do.

**What is wrong.** practice-editor's helpGroup adds a heading <label> with no htmlFor, and the Practice panel's groups are not wrapped by sections.js (they are not direct children of the tab panel), so nothing links the heading to the input/select. The Name input, the Kind / Who speaks first / How they are behaving / Their voice selects therefore have no accessible name. control-phrases-editor's mkBtn sets no title/aria-label, so the ↑ ↓ ✕ buttons are named by their glyphs; placeholder-editor's mkBtn already accepts a title and sets aria-label, so the two editors are inconsistent.

**Evidence.**

```
practice-editor.js:67-72 `const g = el('div', ...); g.dataset.help = key; if (heading) g.appendChild(el('label', { text: heading }));`
control-phrases-editor.js:37-42 `function mkBtn(label, cls) { ... b.textContent = label; if (cls) b.className = cls; return b; }`
control-phrases-editor.js:80 `const up = mkBtn('↑');`
placeholder-editor.js:54 `if (title) { b.title = title; b.setAttribute('aria-label', title); }`
```

**How it happens.** Open Settings > Practice > Fill it in yourself with a screen reader: the Name field is announced as 'edit text' with no name. Open Settings > Commands: buttons announce as 'up arrow', 'multiplication x'.

**Suggested fix.** In practice-editor helpGroup, give the heading an id (`const id = 'pe-' + key;`), and in textField/selectField/voice select set `f.setAttribute('aria-labelledby', id)` (or set label.htmlFor to a generated control id). In control-phrases-editor, port placeholder-editor's mkBtn(label, cls, title) and pass 'Move up', 'Move down', 'Delete'.

**How to verify the fix.** Run the existing browser UI-standards test (tests/ui-standards.test.mjs) if it checks icon-button names, and inspect the accessibility tree in the browser for the Practice form and Commands tab.

**Do not break.** Do not add visible per-control help text (UI Layout Rule 14). Keep `data-help` keys unchanged so spoken help still resolves.

**Design reference.** CLAUDE.md UI Layout Rules 4/12 (icon buttons keep accessible names), Rule 24 (UI standards).

**Verification notes.** helpGroup appends a <label> with no htmlFor. makeCollapsible runs on the tab panel and wraps only `:scope > .setting-group` children (sections.js:79-103). The practice groups sit inside #practicePanel (index.html:950), so they are never wrapped and never given aria-labelledby. The Name input has no placeholder, so it and the selects have no accessible name. control-phrases-editor's mkBtn (lines 37-42) sets no aria-label or title on the ↑ ↓ ✕ buttons, while placeholder-editor's mkBtn does.
