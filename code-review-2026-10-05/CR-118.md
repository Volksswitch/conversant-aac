# CR-118: Leaving Conversation Review leaves aria-pressed="false" on six non-toggle Command Bar buttons, including Listen

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:234`
- **Also affects:** `app/js/app.js:902`; `app/js/review-ui.js:49`; `app/js/ui.js:1099`
- **Source:** x-rules-03

**What a user notices.** After a review, a screen reader announces Repeat what I said, Hold on, Ask them to repeat, End conversation, Settings and Listen as toggle buttons that are 'not pressed'. Listen keeps saying 'not pressed' even while the microphone is on.

**What is wrong.** renderBar() in review mode sets aria-pressed="false" on every Command Bar button it repurposes. When review ends, restoreConversationScreen() calls applyControlIcons() and the three latch setters. That resets aria-pressed for initiateBtn, windDownBtn and privacyBtn, which really are toggles. Nothing removes the attribute from listenBtn, endConversationBtn, sayAgainBtn, holdOnBtn, pardonBtn or settingsBtn, which never carried it in the live app. setListenButtonState() does not manage aria-pressed, so the Listen button reads 'not pressed' while it shows as listening (red, class listening).

**Evidence.**

```
app/js/review-ui.js:228-235: for (const b of BAR) { ui.setCommandBarFace(...); ... el.classList.remove('listening', 'private-on', 'ep-on'); el.setAttribute('aria-pressed', 'false'); }
app/js/app.js:902-911 restoreConversationScreen(): ui.applyControlIcons(); ui.setListenButtonState(isListening); ui.setWrapUpState(false); ui.setStartConversationState(false); applyPrivacyState(); ... (no removeAttribute('aria-pressed'))
app/index.html:137-150: listenBtn, sayAgainBtn, holdOnBtn, pardonBtn, endConversationBtn, settingsBtn have no aria-pressed in markup.
```

**How it happens.** 1. Settings > Conversation Review: open any saved conversation. 2. Leave review with the Settings button. 3. Inspect #sayAgainBtn, #holdOnBtn, #pardonBtn, #endConversationBtn, #settingsBtn and #listenBtn: each has aria-pressed="false". 4. Start listening: #listenBtn has class 'listening' but still aria-pressed="false".

**Suggested fix.** In review-ui.js leave(), in the loop at line 189 that re-enables the BAR buttons, also call el.removeAttribute('aria-pressed') for every BAR button. The three real toggles get their attribute back when restoreConversationScreen() runs their setters afterwards. Optionally, also give the Listen button a correct aria-pressed in ui.setListenButtonState() (listenBtn.setAttribute('aria-pressed', String(listening))), since it is a latched action (Rule 6).

**How to verify the fix.** Manual: enter and leave review, then check in the accessibility tree that only privacyBtn, windDownBtn and initiateBtn have aria-pressed, each with the correct value. Start and stop listening and check the Listen button. A source-level guard in tests/ can assert that review-ui.js leave() removes aria-pressed.

**Do not break.** Do not remove aria-pressed from privacyBtn, windDownBtn or initiateBtn after their setters run; keep the order (remove in leave(), then the setters run in restoreConversationScreen). Review's own rendering still sets it while review is active.

**Design reference.** CLAUDE.md UI Layout Rule 6 (latched actions shown as selected); Conversation Review section (review is a second controller on the same screen)

**Verification notes.** review-ui.js renderBar sets aria-pressed='false' on all nine BAR buttons (listenBtn, initiateBtn, endConversationBtn, sayAgainBtn, holdOnBtn, pardonBtn, windDownBtn, privacyBtn, settingsBtn). leave() only re-enables the buttons and removes review-on, then calls restoreConversationScreen. That runs setWrapUpState, setStartConversationState and applyPrivacyState, which reset aria-pressed on the three real toggles. In ui.js only those three setters and the Express buttons write aria-pressed, and setListenButtonState never does. index.html gives none of the other six buttons an aria-pressed. The stale attribute therefore stays on all six for the rest of the session.
