# CR-120: Empty Express Panel cells are focusable buttons that do nothing on the conversation screen

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/ui.js:716`
- **Also affects:** `app/js/ui.js:742`; `app/js/ui.js:724`; `app/js/app.js:858`
- **Source:** x-a11y-08

**What a user notices.** A keyboard or switch user has to step through every blank button slot (and the reserved 'Choice button' slots) on the panel, each of which does nothing when pressed, before reaching the buttons they want.

**What is wrong.** buildUndefinedCell always creates a <button> (needed for identical geometry). Outside Settings, `onDefineCell` is null, so no click handler is attached, but the button stays in the Tab order and announces itself as a button. With the shipped defaults there are 4 such reserved Context cells; with a Flex band or a new partner/place there can be many more. tap-guard explicitly exempts them, confirming they are inert.

**Evidence.**

```
ui.js:742-746 `b.title = onDefineCell ? 'Empty — tap to put a button here' : 'Empty button slot'; b.setAttribute('aria-label', onDefineCell ? ... : 'Empty button slot'); if (onDefineCell) b.addEventListener('click', () => onDefineCell(index));`
ui.js:734 `if (onDefineCell) b.addEventListener('click', () => onDefineCell(index));` (choice slots)
Measured at default settings: 4 `.ep-undefined` buttons with tabIndex >= 0 on the conversation screen.
```

**How it happens.** Physical-keyboard mode, conversation screen: Tab through the Express Panel; focus stops on four 'Choice button 1..4' / 'Empty button slot' cells; Enter does nothing.

**Suggested fix.** In buildUndefinedCell, when `onDefineCell` is null set `b.tabIndex = -1` and `b.setAttribute('aria-disabled', 'true')` (do NOT use the disabled attribute or change classes that affect the box). Leave them focusable when onDefineCell is set (Settings Express tab).

**How to verify the fix.** Puppeteer: on the conversation screen assert every `#epGrid .ep-undefined` has tabIndex -1; on the Settings Express tab assert they are tabIndex 0. Confirm cell rects are unchanged (existing tests/styles.test.mjs guard on .ep-undefined box properties must still pass).

**Do not break.** Rule 1: the box must stay identical - only attributes change. tapGuard exempts '.ep-undefined'; keep that.

**Design reference.** CLAUDE.md 'Express Panel' tap-to-define notes (cells are defined in Settings and nowhere else); UI Layout Rule 1

**Verification notes.** buildUndefinedCell always creates a focusable <button> (ui.js:716-748). Outside Settings no click handler is attached, but nothing sets tabIndex or aria-disabled, so Tab stops on each of these inert cells. This is a minor keyboard-navigation cost.
