# CR-123: About Me controls lack accessible names and selected state: answer boxes, option chips, Sound Check speaker, goal and relationship selects

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:1666`
- **Also affects:** `app/js/worldview-ui.js:1692`; `app/js/worldview-ui.js:1731`; `app/js/worldview-ui.js:282`; `app/js/worldview-ui.js:541`; `app/js/worldview-ui.js:821`; `app/js/worldview-ui.js:1111`; `app/js/express-editor.js:458`; `app/js/express-editor.js:688`
- **Source:** x-a11y-11

**What a user notices.** Someone using a screen reader or voice control cannot tell which question an answer box belongs to, which answer chips are currently selected, or what the speaker buttons in 'How I Sound' do; and selected chips are shown only by a change of fill, with no check mark like the Express Panel uses.

**What is wrong.** Questionnaire inputs (buildTextish, buildChoice/buildMultiChips 'own words' boxes, renderExtra input) have only a generic placeholder ('Type your answer…') and no label/aria-labelledby tying them to the visible `.wv-question` text. Option chips (`.wv-chip`, single- and multi-select) never set aria-pressed; selection is only the `.wv-chip-on` fill. The Sound Check speaker button's content is the emoji '🔊' with only a title, so its accessible name is the emoji, identical for every candidate. Several selects have no label: the goal 'Add a goal…' select, the relationship select, the Express editor's person/place pickers and its two Flex scope selects.

**Evidence.**

```
worldview-ui.js:1666-1670 `chips.append(el('button', { class: 'wv-chip' + (current === opt ? ' wv-chip-on' : ''), text: opt, onclick: ... }));` (no aria-pressed)
worldview-ui.js:1731-1736 `const input = el('input', { type: ..., class: 'wv-text', placeholder: 'Type your answer…', value: ... });`
worldview-ui.js:541 `el('button', { class: 'wv-btn-speak sc-speak', text: '🔊', title: 'Hear this', onclick: () => speak(text) })`
worldview-ui.js:821 `const goalAdd = el('select', { class: 'wv-select' });`
express-editor.js:688-690 `function scopeSelect(...) { const sel = document.createElement('select'); sel.className = 'ee-scope-select';` (no aria-label)
```

**How it happens.** Settings > About Me > any topic: with a screen reader, Tab to an answer box - it is announced as 'Type your answer, edit text' with no question; Tab to a chip - its selected state is not announced; in How I Sound, the three speaker buttons are each announced as 'speaker high volume'.

**Suggested fix.** In buildCard, give the `.wv-question` div an id (e.g. `wvq-${field.key}`) and pass it to buildInput so every text input/select in the card gets `'aria-labelledby': 'wvq-' + field.key` (renderExtra likewise). In buildChoice and buildMultiChips add `'aria-pressed': String(isOn)` to each chip, and add a visible non-color cue for `.wv-chip-on` (e.g. `.wv-chip-on::after { content: ' ✓'; font-weight: 800; }` matching .ep-on). For the sc-speak button add `'aria-label': 'Hear: ' + text`. Add aria-label to goalAdd ('Add a goal'), relSelect ('Relationship'), pickerFor's select ('Who this button is for' / 'Which place'), and the two scopeSelects ('Partner' / 'Place').

**How to verify the fix.** Extend tests/ui-standards.test.mjs (it already asserts icon-only buttons have names) to assert every input/select/button under #worldviewContent and #expressEditor has a non-empty computed accessible name (aria-label, aria-labelledby, label, or text that is not a single emoji) and that every `.wv-chip` has aria-pressed.

**Do not break.** Rule 14: no new per-control help TEXT on screen - names are programmatic only; the ✓ on a selected chip is state, not help. Chip box size must not change.

**Design reference.** UI Layout Rule 6 (latched/selected state shown), Rule 12 (constant buttons carry an explanatory accessible name), Rule 24 (UI standards)

**Verification notes.** In worldview-ui.js the chips are built with only the wv-chip-on class and never get aria-pressed (1666-1670). buildTextish inputs have only a placeholder and no label or aria-labelledby (1731-1736). The Sound Check speaker is `text: '🔊'` with only a title (541), so its accessible name is the emoji, the same for every candidate. The grep finds aria-labels only on the reorder, remove and hear-it buttons, never on chips or answer inputs. I did not separately verify the Express editor scope selects, but the pattern is the same.
