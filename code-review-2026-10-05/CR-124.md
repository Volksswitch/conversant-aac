# CR-124: Selected answer chips expose their state by color only, with no aria-pressed

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** accessibility
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:1667`
- **Also affects:** `app/js/worldview-ui.js:1693 (multi chips)`; `app/css/styles.css:4477-4481 (.wv-chip-on is a fill/color change)`
- **Source:** worldview-11

**What a user notices.** A screen-reader user, or anyone checking with assistive software, cannot tell which answer chip is currently chosen on an About Me question.

**What is wrong.** Chips in buildChoice and buildMultiChips mark selection only with the class 'wv-chip-on' (accent fill). No aria-pressed is set, so the accessible state of a toggle is missing. The Express Panel chips set aria-pressed for the same kind of selected state (CLAUDE.md UI Rule 21).

**Evidence.**

```
app/js/worldview-ui.js:1666-1670:
    chips.append(el('button', {
        class: 'wv-chip' + (current === opt ? ' wv-chip-on' : ''),
        text: opt,
        onclick: () => saveAndRefresh(field, opt)
    }));
```

**How it happens.** Answer 'she/her' for pronouns, then inspect the chip in the accessibility tree: it is a plain button with no pressed state.

**Suggested fix.** Add `'aria-pressed': String(current === opt)` to the buildChoice chip props and `'aria-pressed': String(selected.includes(opt))` to the buildMultiChips chip props.

**How to verify the fix.** Browser accessibility tree shows aria-pressed=true on the selected chip.

**Do not break.** none

**Design reference.** CLAUDE.md UI Layout Rule 6 and Rule 21 (selected state shown, aria-pressed on chips).

**Verification notes.** buildChoice and buildMultiChips mark the selection only with the 'wv-chip-on' class, and neither sets aria-pressed. The selected state is therefore missing from the accessibility tree.
