# CR-126: Closing fast path shows goodbyes without clearing the turn's choice buttons, number button or steering

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1760`
- **Also affects:** `app/js/app.js:1798`; `app/js/app.js:1881`; `app/js/app.js:3428`; `app/js/app.js:3599`
- **Source:** g-app-flow-overflow-04

**What a user notices.** If the other person offered choices, the user tapped one and then pressed Wrap up, and the person then says a short goodbye, the goodbye cards appear but the choice buttons stay on the Express Panel, one still lit. Tapping one replaces the goodbyes with ordinary replies about that choice.

**What is wrong.** generateOptions' farewell fast path (windingDown && looksLikeClosing) returns before line 1798 `clearTurnSteering()` and never reaches line 1881 `setOfferedChoices(offered); setOfferedRange(range);` that the normal path uses to drop the previous classification's choices (a CLOSING classification has offered_options []). So activeSteer.focusChoice / activeSteer.steer and offeredChoices / offeredRange from earlier in the same partner turn survive under a goodbye palette. Wrap up (handleWindDown) deliberately does not clear them (cancel must restore), so the fast path is where they should go. The AI path for the same classification would have cleared them.

**Evidence.**

```
app/js/app.js:1760-1773: `if (windingDown && convLogic.looksLikeClosing(partnerText)) { placeholders.stop(); updatePartnerLive(partnerText); const snap = engine.ingestClassification(...); ... renderStaticPalette('closing', snap.palette, ...); ui.setTranscriptState('ready'); return; }` - no clearTurnSteering, setOfferedChoices([]) or setOfferedRange(null).
app/js/app.js:1798: `clearTurnSteering();` (only on the non-fast path).
app/js/app.js:1881: `else { setOfferedChoices(offered); setOfferedRange(range); }`
```

**How it happens.** 1) Listening; partner: 'Coffee or tea?' → pause → cards plus choice buttons 'coffee' and 'tea'. 2) User taps 'tea' (lit; steer set). 3) User taps Wrap up (wind-downs shown, mode PRE_CLOSING). 4) Partner continues: 'Bye then.' → combined 'Coffee or tea? Bye then.' is 5 words with 'bye' → fast path shows goodbyes. 5) 'coffee'/'tea' buttons remain, 'tea' lit; tapping 'coffee' calls handleChoiceChip and replaces the goodbyes with ordinary responses.

**Suggested fix.** In the fast-path block, before renderStaticPalette, add `clearTurnSteering(); setOfferedChoices([]); setOfferedRange(null);` (mirroring what the AI path achieves for a CLOSING classification).

**How to verify the fix.** Unit-level source guard in tests/placeholders.test.mjs: assert the looksLikeClosing branch of generateOptions contains `setOfferedChoices([])` and `clearTurnSteering()`. Manual: reproduce the scenario in Practice Mode with a scenario partner line 'Coffee or tea?' followed by 'Bye then.'.

**Do not break.** Do not clear choices in handleWindDown itself: Wrap up cancel must restore the panel exactly. The fast path also renders under an open composer (same root as the already-reported app.js:1846 issue); fix that there, not here.

**Design reference.** CLAUDE.md 'Closed-set (alternative-question) turns override the four-slot structure' (chips cleared at every turn boundary and gated on currentPartnerText); 'Steering persists across New N WITHIN a turn' (clearTurnSteering where the steered turn ends or is replaced).

**Verification notes.** The fast path in generateOptions (app.js:1759-1773) returns before clearTurnSteering (1798) and never reaches setOfferedChoices/setOfferedRange (1881). handleWindDown does not clear chips or steering. Ran looksLikeClosing('Coffee or tea? Bye then.') -> true, so the scenario's accumulated partner text takes the fast path. Chips remain rendered (gated only on currentPartnerText, which is non-empty), activeSteer.focusChoice stays lit, and handleChoiceChip (3428) would replace the goodbyes via showPalette.
