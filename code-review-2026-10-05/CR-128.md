# CR-128: offerClosings restarts listening without closing the turn in metrics, so the next partner turn's checkpoint count continues from the previous turn

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2137`
- **Also affects:** `app/js/app.js:1708`; `app/js/app.js:2381`; `app/js/metrics.js:337`; `app/js/metrics.js:378`; `app/js/metrics.js:388`
- **Source:** g-app-flow-overflow-03

**What a user notices.** Nothing changes on screen. The weekly usage figures that judge the short silence setting (how many times the app asked the AI about one thing the other person said) are inflated after every wind-down or goodbye, and a goodbye set the other person talks over is not counted as passed over.

**What is wrong.** When a wind-down or goodbye card is spoken with auto-resume armed, offerClosings reopens the microphone with its own inline copy of startFreshListening (so the goodbyes stay visible), but the copy omits metrics.turnBoundary() and metrics.paletteAbandoned('new turn'), and the LISTEN {auto:true} event that resumeOrIdle records. metrics.checkpoint() increments checkpointsThisTurn and computes sinceMs from lastCheckpointAt; without turnBoundary both carry over, so the partner's reply after a goodbye reports n = previous count + 1 and a sinceMs spanning the whole user turn - read by the reports as a within-turn checkpoint gap. Also, because the closings palette is shown after the mic opens and is never abandoned at a turn boundary, when the partner's reply produces new cards metrics.paletteShown sees openPalette still set and records PALETTE_REFRESHED instead of an abandonment plus a fresh SHOWN.

**Evidence.**

```
app/js/app.js:2137-2144: `if (!practiceMode && manualListenArmed && storage.loadAutoRelisten()) { currentPartnerText = ''; currentPartnerUncertain = []; generationToken++; ui.setLiveTranscript(''); ui.setTranscriptState('idle'); stt.startListening(); }`
Compare app/js/app.js:1712-1713 in startFreshListening: `metrics.paletteAbandoned('new turn'); metrics.turnBoundary();` and app/js/app.js:2384 in resumeOrIdle: `metrics.event(metrics.EV.LISTEN, { auto: true, status: 'start' });`
app/js/metrics.js:380-382: `checkpointsThisTurn++; const f = { n: checkpointsThisTurn }; if (checkpointsThisTurn > 1 && lastCheckpointAt) f.sinceMs = now - lastCheckpointAt;`
```

**How it happens.** Auto-resume on, Listen pressed once. Partner speaks with two pauses (checkpoints n=1, n=2). User taps Wrap up and picks a wind-down. offerClosings reopens the mic. Partner says 'Okay, see you' and pauses: the CHECKPOINT event is n=3 with sinceMs of ~20 s, instead of n=1 with no sinceMs.

**Suggested fix.** In offerClosings, inside the auto-resume branch before `stt.startListening()`, add `metrics.paletteAbandoned('new turn'); metrics.turnBoundary(); metrics.event(metrics.EV.LISTEN, { auto: true, status: 'start' });` (same three calls the shared paths make). Optionally also `pendingPartnerHistoryIdx = -1;` for parity with startFreshListening. Better still, factor the shared 'new partner turn' bookkeeping out of startFreshListening into a function (e.g. beginPartnerTurn({ keepPalette })) used by both so they cannot drift again.

**How to verify the fix.** Manual with Settings → Troubleshooting event counts, or unit-level: add a source guard in tests/placeholders.test.mjs asserting that offerClosings contains `metrics.turnBoundary()`; and in tests/metrics test (if present) or a new one, show that checkpoint() after turnBoundary() reports n=1. Live check: run the scenario above and read metrics.log; the post-goodbye checkpoint must be n=1.

**Do not break.** The goodbyes must stay visible (do not call clearPalette here). Practice Mode must still not open a microphone.

**Design reference.** CLAUDE.md 'Beta instrumentation and error reporting' → CHECKPOINT METRICS (checkpoints fired per partner turn, generations superseded).

**Verification notes.** offerClosings (app.js:2128-2148) reopens the mic with an inline copy of startFreshListening that omits metrics.paletteAbandoned('new turn'), metrics.turnBoundary() and the LISTEN {auto:true} event. turnBoundary is called only in startFreshListening (1713) and metrics.conversationBoundary (metrics.js:418), so checkpointsThisTurn/lastCheckpointAt carry over into the partner's reply after a wind-down or goodbye (metrics.js:378-386). The closings palette is shown via showPalette -> metrics.paletteShown (openPalette set) and never abandoned at a turn boundary, so the next AI palette is recorded as PALETTE_REFRESHED. Only the auto-resume branch is affected; with auto-resume off the manual Listen press goes through startFreshListening.
