# CR-129: A practice conversation the AI partner opens is never counted as a started conversation

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2602`
- **Also affects:** `app/js/app.js:4871-4873`; `app/js/metrics.js:398-420`; `app/js/app.js:2775`
- **Source:** app-c-15

**What a user notices.** Not visible on screen. The weekly report undercounts practice: rehearsals where the pretend partner speaks first never register as conversations, which skews the beta's adoption and practice numbers.

**What is wrong.** metrics.conversationStarted is only raised via noteConversationStarted(), which is called from startFreshListening, the deferred opener path, speakAsUserTurn (opening statement) and the sound-button path. A practice scenario that opens with the partner goes togglePracticeCue -> advancePracticePartner -> handleSilencePeriod -> card pick -> practiceResumeOrIdle, none of which calls it. conversationBoundary only emits CONVERSATION_ENDED when conversationOpen is true, so the whole practice conversation produces neither event, though the fields carry a `practice` flag intended to count it.

**Evidence.**

```
app/js/app.js:4871-4872 `function noteConversationStarted() {
    metrics.conversationStarted({ practice: practiceMode });`
app/js/metrics.js:415-416 `export function conversationBoundary(fields = {}) {
    if (conversationOpen) event(EV.CONVERSATION_ENDED, fields);`
app/js/app.js:2602-2611 advancePracticePartner (no noteConversationStarted call)
```

**How it happens.** Start a partner-opens scenario, tap Start Listening, exchange a few turns, End conversation. The metrics tally shows no conversation_started/conversation_ended for it.

**Suggested fix.** In advancePracticePartner, after the `if (!practiceMode) return;` guard (and after the tour guard from the related finding), call `noteConversationStarted();` - conversationStarted is idempotent and noteConversationStarted already skips the layout-lock change in practice.

**How to verify the fix.** Manual: check the event ring / weekly payload after a partner-opened practice. Or a source guard in tests/placeholders.test.mjs.

**Do not break.** Do not count the controls tour as a conversation (keep the tour guard before this call).

**Design reference.** CLAUDE.md, 'Beta instrumentation and error reporting' (headline adoption metric; practice counted separately)

**Verification notes.** noteConversationStarted is called only from startFreshListening, the deferred-opener path, speakAsUserTurn's opening statement and the sound-button path. A partner-opens practice where the user answers with cards goes togglePracticeCue -> advancePracticePartner -> handleSilencePeriod -> handleResponseSelected (non-opener) -> practiceResumeOrIdle, none of which calls it; conversationBoundary only emits ENDED when conversationOpen. Impact is limited to the metrics event tally (the usage summary counts conversations from the saved files, not these events).
