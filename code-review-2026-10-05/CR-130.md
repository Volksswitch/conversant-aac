# CR-130: Cancelling Wrap up or Start conversation resets the engine to mid-conversation even when restoring goodbye or repair cards

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2912`
- **Also affects:** `app/js/engine.js:594-600`; `app/js/app.js:1757-1760`; `app/js/app.js:2169`
- **Source:** app-c-16

**What a user notices.** If the other person was saying goodbye and the user taps Wrap up by accident and then cancels, the goodbye cards come back but the app now thinks the conversation is in full swing, so the other person's next 'bye' takes a slower trip to the AI instead of instantly offering goodbyes, and the mode shown is wrong.

**What is wrong.** overlayCancel restores the exact cards (and currentStatic) that were showing but always calls engine.resumeConversation(), which forces phase BODY, mode LISTENING, floor OPEN and empties the engine palette. When the restored cards were a partner-initiated closing palette (phase PRE_CLOSING) or a repair-of-self palette (mode REPAIR_OF_SELF), the engine no longer matches what is on screen: generateOptions' closing fast path (keyed on phase/mode) no longer fires, and an in-flight prefetchRepairOptions bails on the mode check. CLAUDE.md records not restoring the floor as deliberate; restoring phase/mode for a restored static closing/repair palette is not covered by that decision.

**Evidence.**

```
app/js/app.js:2911-2914 `ui.showEngineState(engine.resumeConversation());
    currentStatic = back.static;
    showPalette(back.cards, back.kind);`
app/js/engine.js:594-598 `export function resumeConversation() {
    state.phase = 'BODY';
    state.mode = MODE.LISTENING;`
app/js/app.js:1758-1760 `const windingDown = preSnap.mode === engine.MODE.PRE_CLOSING_CLOSING
        || preSnap.phase === 'PRE_CLOSING' ... if (windingDown && convLogic.looksLikeClosing(partnerText)) {`
```

**How it happens.** Listening; partner says 'Well, I should get going' -> goodbyes + 'Actually, before you go'. Tap Wrap up, tap it again (cancel). Partner says 'Bye!' -> the app waits for an AI round trip rather than re-offering goodbyes instantly; the mode chip shows LISTENING.

**Suggested fix.** Capture the engine's phase/mode in overlayEnter (add `phase: engine.getSnapshot().phase, mode: engine.getMode()` to paletteOverlay) and add an engine function `restorePhase({ phase, mode })` that sets only phase and mode; in overlayCancel call it instead of resumeConversation when the captured mode is PRE_CLOSING_CLOSING or REPAIR_OF_SELF, otherwise keep resumeConversation(). Keep floor OPEN either way per the recorded decision.

**How to verify the fix.** Add tests/engine.test.mjs coverage for restorePhase. Manual: scenario above - after cancel, a partner 'Bye!' re-offers goodbyes immediately.

**Do not break.** CLAUDE.md: resumeConversation deliberately does not restore the floor - do not reconstruct floor. Decline-the-closing (reopenFromClosing) must keep using resumeConversation.

**Design reference.** CLAUDE.md, 'Wrap up and Start conversation are TOGGLES' (engine.resumeConversation note)
