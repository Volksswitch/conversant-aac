# CR-131: Cancelling Wrap up or Start conversation back to an empty panel records a fake empty set of cards

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2914`
- **Also affects:** `app/js/app.js:3016-3040`; `app/js/app.js:2959-2968`; `app/js/storage.js:2307-2314`; `app/js/metrics.js:337-369`
- **Source:** app-c-10

**What a user notices.** Not visible on screen, but a stray tap on Start conversation (opened and cancelled) creates a saved conversation file that contains no conversation, and the usage numbers count an extra set of suggestions as ignored.

**What is wrong.** overlayCancel always calls showPalette(back.cards, back.kind). When the panel was empty before the overlay (cold start, or after a response was spoken), back.cards is [] and back.kind is 'none'. showPalette then calls storage.logOffer({kind:'none', options: []}) - which lazily starts a conversation log if none exists - and noteCardsShown -> metrics.paletteShown({cards: 0}), opening a zero-card palette that later reports as PALETTE_ABANDONED / gets a DECIDE event and an offer outcome. The cold Start conversation press already created a log via the opener offer, so an accidental press-and-cancel leaves a conversation file with nothing in it but two offers.

**Evidence.**

```
app/js/app.js:2913-2914 `currentStatic = back.static;
    showPalette(back.cards, back.kind);`
app/js/app.js:3038-3039 `storage.logOffer({ kind, options: cards });
    noteCardsShown(cards, kind);`
app/js/app.js:3013 clearPalette sets `shownCards = { cards: [], kind: 'none' };`
app/js/storage.js:2313 `if (!currentLogData) await startConversationLog();`
```

**How it happens.** Fresh app, nothing said. Tap Start conversation, then tap it again. With a data folder, the conversations folder now has a new file whose exchanges are an opener offer (outcome 'start conversation') and an offer with kind 'none' and options [].

**Suggested fix.** In overlayCancel replace `showPalette(back.cards, back.kind);` with `if (back.cards && back.cards.length) showPalette(back.cards, back.kind); else clearPalette();`. Optionally (Ken's call) avoid creating a conversation log for a cold opener offer that is cancelled; at minimum the empty offer must not be written.

**How to verify the fix.** Manual: scenario above; after the fix no 'none' offer is written. Source guard in tests/placeholders.test.mjs that overlayCancel checks back.cards.length.

**Do not break.** Cancel must still restore exactly what was on screen (the empty reserved outlines). Keep the one-backout-slot behavior.

**Design reference.** CLAUDE.md, 'Wrap up and Start conversation are TOGGLES'; 'EVERY SET OF CARDS IS RECORDED'
