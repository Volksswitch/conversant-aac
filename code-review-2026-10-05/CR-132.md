# CR-132: Clearing the panel (End conversation, Start-turn clear) does not reset the deliberation clock, so the next action reports a reading time for cards that were gone

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3005`
- **Also affects:** `app/js/app.js:2953`; `app/js/app.js:2972`; `app/js/app.js:2807`; `app/js/app.js:3697`; `app/js/app.js:904`
- **Source:** g-app-flow-overflow-05

**What a user notices.** Nothing visible. The usage report's 'time spent reading the cards' figure picks up false long readings: after ending a conversation with cards still up, the first Express phrase in the next conversation is recorded as minutes of reading.

**What is wrong.** noteCardsShown sets cardsShownAt and decideTaken=false; noteUserAction consumes them once. clearPalette finalizes the pending offer but never resets cardsShownAt or decideTaken. When cards are cleared without a user action - End conversation (handleEndConversation does not call noteUserAction; terminateConversation calls clearPalette), the cards-per-category setting change, or restoreConversationScreen after a review - the clock stays armed. The next noteUserAction (e.g. speakAsUserTurn 'express' at app.js:3697, openComposer, a Command Bar press) emits metrics.EV.DECIDE with ms measured from the old, cleared cards (up to the 10-minute cap) and returns that span as a reading time.

**Evidence.**

```
app/js/app.js:3005-3014: `function clearPalette() { if (storage.hasPendingOffer()) { storage.finalizeOffer({ outcome: 'cleared', shownMs: shownSpanMs() }); } ui.clearResponseOptions(); shownCards = { cards: [], kind: 'none' }; }` (cardsShownAt / decideTaken untouched).
app/js/app.js:2983-2989: `if (!cardsShownAt || decideTaken) return null; decideTaken = true; const ms = Date.now() - cardsShownAt; ... metrics.event(metrics.EV.DECIDE, { kind, ms });`
```

**How it happens.** 1) Cards are showing. 2) User presses End conversation (no card tapped). 3) Within 10 minutes, user taps an Express phrase to open the next conversation. A DECIDE event {kind:'express', ms:<time since step 1's cards appeared>} is recorded although no cards were on screen.

**Suggested fix.** At the end of clearPalette (after the finalizeOffer call, which still needs shownSpanMs()), add `cardsShownAt = 0; decideTaken = false;`. The same reset belongs in the error-box helper proposed in the failed-request finding.

**How to verify the fix.** Add a source guard to tests/placeholders.test.mjs asserting clearPalette resets cardsShownAt. Manual: show cards, press End conversation, tap an Express phrase, and confirm in metrics.log that no DECIDE event is written for it.

**Do not break.** Keep the finalizeOffer call before the reset so the 'cleared' outcome still carries its shownMs.

**Design reference.** CLAUDE.md is silent on this exact path; app.js comment block 'The deliberation clock (Ken, August 16 2026)'.

**Verification notes.** clearPalette (app.js:3005-3014) finalizes the offer but leaves cardsShownAt/decideTaken armed. handleEndConversation never calls noteUserAction, and terminateConversation clears via clearPalette (2807). The next noteUserAction (e.g. speakAsUserTurn 'express' at 3697) passes the guard at 2983 and emits DECIDE with ms measured from cards that were cleared (finalizeOffer itself is a no-op because pendingOffer is null). The same applies to the other non-action clears (settings change at 8199, startFreshListening on a manual Listen press while cards were showing).
