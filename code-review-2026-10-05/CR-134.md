# CR-134: New 4 does nothing over Reframe 'lead' statements, and no-op presses still close out the set's record

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3333`
- **Also affects:** `app/js/app.js:3318`; `app/js/app.js:3562-3576`; `app/js/app.js:3097-3101`; `app/js/app.js:3219-3222`; `app/js/app.js:3429-3432`; `app/js/app.js:2972-2984`
- **Source:** app-c-12

**What a user notices.** After the user taps Reframe when it is their turn (so the app offers statements to steer the conversation), pressing New 4 for different statements silently does nothing. Separately, pressing New 4, Repeat what I said or a choice button when it has nothing to do still marks the cards on screen as rejected in the saved record, so a later pick from those same cards is not recorded as the outcome.

**What is wrong.** handleReframe's lead mode (no partner turn) shows statements via showConversationPalette, which clears currentStatic and sets lastPalette, but currentPartnerText is ''. handleRegenerate then hits `if (!currentPartnerText || !lastPalette.length) return;` - New N is dead and there is no regenerate path for statements. In handleRegenerate, handleSayAgain and handleChoiceChip, noteUserAction(...) is called BEFORE the guard that makes the action a no-op, so storage.finalizeOffer records outcome 'regenerate' / 'say again' / 'choice chip' and decideTaken=true even though nothing happened; the user's subsequent card tap then gets no outcome and no decide time.

**Evidence.**

```
app/js/app.js:3318 `noteUserAction('regenerate');` ... 3333 `if (!currentPartnerText || !lastPalette.length) return;`
app/js/app.js:3565 `const result = await llm.generateStatements(steer, conversationHistory, engine.buildRequestContext(), conversationPaletteCap());`
app/js/app.js:3219-3222 `noteUserAction('say again'); ... if (!text) { ui.setStatus('Nothing to repeat yet'); return; }`
app/js/app.js:3429-3432 `noteUserAction('choice chip'); ... if (!pick || !currentPartnerText) return;`
```

**How it happens.** After the user has replied (their turn), open In my own words, type 'talk about the game Sunday', tap Reframe: statements appear. Tap New 4: nothing changes, and the offer for those statements is recorded as outcome 'regenerate'. Tap one of the statements: the offer record is not updated to 'card'.

> **Verifier correction to the trigger:** Only the dead New 4 over Reframe lead statements is a defect. Recording 'regenerate'/'say again'/'choice chip' as the outcome when the press turns out to do nothing is consistent with the 'first action of any kind ends the deliberation' decision in noteUserAction's comments.

**Suggested fix.** 1) Move each noteUserAction call below its no-op guard (in handleRegenerate: after the static branch and after the `!currentPartnerText` guard - the static branch should still call it first; in handleSayAgain after `if (!text)`; in handleChoiceChip after `if (!pick || !currentPartnerText)`). 2) Remember the lead steer: in handleReframe's lead branch set `activeSteer.lead = steer` (add `lead: null` to activeSteer and to clearTurnSteering), and in handleRegenerate, when `!currentPartnerText && activeSteer.lead && lastPalette.length`, call llm.generateStatements again (add an `avoid` option to generateStatements mirroring generateResponses' avoidBlock, passing the current statement texts) and show via showConversationPalette.

> **Verifier correction to the fix (takes precedence):** Do not move noteUserAction below the no-op guards; that contradicts the recorded 'first action of any kind' rule. Fix only the lead-mode regenerate path (remember the lead steer per turn, regenerate statements with an avoid list, clear it in clearTurnSteering).

**How to verify the fix.** Manual: scenario above - New 4 produces different statements, and the saved offer for the first set has outcome 'regenerate' only when regeneration actually happened. Add a tests/llm.test.mjs case that generateStatements includes an avoid list in its system text when given one.

**Do not break.** Static paging via New N must keep working (and keep recording 'regenerate'). Steering stays one-shot across turns: clear activeSteer.lead in clearTurnSteering.

**Design reference.** CLAUDE.md, 'Reframe' (floor-aware lead statements); 'EVERY SET OF CARDS IS RECORDED' (outcome per set)

**Verification notes.** handleReframe's lead mode shows statements with currentPartnerText empty; handleRegenerate then returns at `if (!currentPartnerText || !lastPalette.length) return;` so New 4 is dead over lead statements. The second half (noteUserAction before the no-op guards) is real in mechanism, but it matches the recorded design that the deliberation clock and offer outcome are taken on the FIRST action of any kind ('one outcome per set, whichever action came first'), so it is not a defect in itself.
