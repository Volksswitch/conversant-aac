# CR-135: Reframe drops the held newer set but also its choice buttons and number button

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3511`
- **Also affects:** `app/js/app.js:1850-1881`; `app/js/app.js:2858-2869`; `app/js/app.js:3394-3409`
- **Source:** app-c-11

**What a user notices.** If the other person offers a list ('muffins, croissants, or scones?') while the user is typing in In my own words and the user then taps Reframe, the choice buttons for that list never appear on the Express Panel (or the buttons from an earlier question stay up instead).

**What is wrong.** While the composer is open, generateOptions defers both the palette and the Express Panel chips: it stores offered/range on heldForComposer instead of calling setOfferedChoices/setOfferedRange. handleReframe resolves the race by intent and calls dropHeldForComposer(), discarding heldForComposer.offered/range along with the palette. Reframe's own path calls engine.refreshPalette (no re-ingest), so nothing re-applies offered_options. The comment's 'NOTHING IS LOST BY DROPPING IT' holds for the cards but not for the chips, which are part of the same turn state (generateOptions: 'so the panel and the palette never describe different versions of the turn').

**Evidence.**

```
app/js/app.js:1880-1881 `if (heldForComposer) { heldForComposer.offered = offered; heldForComposer.range = range; }
        else { setOfferedChoices(offered); setOfferedRange(range); }`
app/js/app.js:3511 `dropHeldForComposer();`
app/js/app.js:2853 `function dropHeldForComposer() { heldForComposer = null; }`
```

**How it happens.** 1) Partner asks an open question; cards show. 2) Open In my own words, start typing. 3) Partner adds 'We've got muffins, croissants or scones - what would you like?' (reprompt held). 4) Type a steer and tap Reframe. Express Panel shows no muffin/croissant/scone buttons.

**Suggested fix.** In handleReframe, before `dropHeldForComposer();`, apply the held chips: `if (heldForComposer) { setOfferedChoices(heldForComposer.offered || []); setOfferedRange(heldForComposer.range || null); }`. Same consideration in handleSpeakComposed is unnecessary (speaking ends the turn).

**How to verify the fix.** Manual: scenario above (Practice Mode works well for this). Source guard in tests/placeholders.test.mjs that handleReframe calls setOfferedChoices with heldForComposer.offered before dropping it.

**Do not break.** Do not show the held palette itself - Reframe must still win (Ken, August 21 2026).

**Design reference.** CLAUDE.md, 'WHEN THE RESPONSE CARDS CHANGE' - 'THE REFRAME RACE IS DECIDED BY INTENT'

**Verification notes.** While composerOpen, generateOptions stores offered/range on heldForComposer instead of setting the chips. handleReframe calls dropHeldForComposer() and its partner branch uses engine.refreshPalette (no re-ingest), so setOfferedChoices/setOfferedRange are never called for that held turn; the panel shows nothing new or the previous question's chips. The 'nothing is lost' comment covers cards, not chips.
