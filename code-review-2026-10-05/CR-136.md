# CR-136: Practice conversations record 'listen off' events although no microphone was ever on

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:3712`
- **Also affects:** `app/js/app.js:2606-2607`; `app/js/app.js:2777`; `app/js/app.js:1298-1329`; `app/js/stt.js:724-738`
- **Source:** app-c-14

**What a user notices.** Not visible on screen. The saved record of a practice conversation says the microphone was switched off at moments it was never on, which can mislead anyone reviewing it.

**What is wrong.** In practice, advancePracticePartner sets isListening=true directly (no microphone, no 'listen on' event). speakAsUserTurn calls stt.stopListening() unconditionally, and terminateConversation does too; stt.stopListening emits 'stopped' synchronously, and handleSttStatus sees was=true/is=false and writes storage.logEvent('listen off') into the practice conversation. CLAUDE.md records that microphone events are recorded only from handleSttStatus precisely so that practice's button use does not log 'listening that never happened'. handleResponseSelected already skips STT in practice (`if (!practiceMode) stt.stopListening()`), so the Express/composer path is inconsistent with it.

**Evidence.**

```
app/js/app.js:3712 `stt.stopListening();` (speakAsUserTurn, no practice guard)
app/js/app.js:2063-2064 `if (!practiceMode) {
        stt.stopListening();`
app/js/stt.js:737 `if (onStatusChange) onStatusChange('stopped');`
app/js/app.js:1328 `if (isListening !== was) storage.logEvent(isListening ? 'listen on' : 'listen off');`
```

**How it happens.** Start a practice scenario, tap Start Listening, let the partner speak, then tap an Express phrase. The practice conversation JSON contains `{ role: 'event', kind: 'listen off' }` with no preceding 'listen on'.

**Suggested fix.** In speakAsUserTurn change `stt.stopListening();` to `if (!practiceMode) stt.stopListening(); else { isListening = false; ui.setListenButtonState(false); }`. In terminateConversation, guard the same way: `if (!practiceMode) stt.stopListening(); else { isListening = false; ui.setListenButtonState(false); }` (practice never opened the mic).

**How to verify the fix.** Manual: scenario above - no 'listen off' event in the practice JSON and the Listen button still goes off. Real conversations still log 'listen on'/'listen off'.

**Do not break.** Real (non-practice) paths must keep stopping the mic. Keep the sound-button path's own mute logic unchanged.

**Design reference.** CLAUDE.md, 'THE STANDARD FOR THE RECORD IS "CAN IT BE RECREATED TO THE SECOND"' (the microphone going on and off)

**Verification notes.** In practice advancePracticePartner sets isListening=true without opening a mic. speakAsUserTurn (and terminateConversation) call stt.stopListening() unconditionally; when a recognizer was initialized (browser STT on desktop), stopListening synchronously emits 'stopped', and handleSttStatus sees was=true/is=false and writes storage.logEvent('listen off'). handleResponseSelected already guards with `if (!practiceMode)`. On a device with no recognizer stopListening returns early, so it depends on the device.
