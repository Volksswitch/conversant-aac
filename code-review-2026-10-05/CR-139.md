# CR-139: Cost display falls back to old Sonnet 4.6 rates if pricing.json fails to load

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6022`
- **Also affects:** `app/data/pricing.json:2-4`; `app/js/suggest-anthropic.js:135 (MODEL)`
- **Source:** llm-engine-10

**What a user notices.** If the price list cannot be read, the spending figure in Settings is about 50% too high for the AI part.

**What is wrong.** loadPricing's catch fallback hardcodes $3/$15 per million tokens, the claude-sonnet-4-6 rates; the app now uses claude-sonnet-5-5 at $2/$10 (pricing.json). Also `await resp.json()` on a non-OK response throws into the same fallback, and nothing compares pricing.model with the adapter's model.

**Evidence.**

```
app.js:6021-6024:
        pricingData = {
            inputCostPerMillionTokens: 3, outputCostPerMillionTokens: 15,
            cacheWriteMultiplier: 1.25, cacheReadMultiplier: 0.1,
        };
pricing.json: "model": "claude-sonnet-5-5", "inputCostPerMillionTokens": 2, "outputCostPerMillionTokens": 10
```

**How it happens.** pricing.json missing from cache or a fetch error offline: spend shown is computed at 3/15.

**Suggested fix.** Change the fallback to `{ model: 'claude-sonnet-5-5', inputCostPerMillionTokens: 2, outputCostPerMillionTokens: 10, cacheWriteMultiplier: 1.25, cacheReadMultiplier: 0.1 }`, add a comment that it must move with pricing.json and suggest-anthropic.js MODEL, and check `resp.ok` before `resp.json()`.

> **Verifier correction to the fix (takes precedence):** The suggested fix is fine. Also consider leaving pricingData null on failure, so that a later call retries instead of caching the fallback for the session.

**How to verify the fix.** Add a source-level check in tests/suggest-provider.test.mjs reading app/data/pricing.json and asserting its `model` equals the adapter's `anthropic.model`; manually rename pricing.json in a local copy and confirm the displayed rate.

**Do not break.** Do not cache a failed fetch result permanently if the file later becomes available (optional: leave pricingData null on failure).

**Design reference.** CLAUDE.md 'A MODEL STRING IS NOT A SETTING' and pricing.json _modelNote (the two must change together).

**Verification notes.** loadPricing (app.js:6015-6026) falls back to $3/$15, the Sonnet 4.6 rates, while pricing.json prices claude-sonnet-5-5 at $2/$10. It also calls resp.json() without checking resp.ok. The trigger is narrow because sw.js precaches data/pricing.json (sw.js:108). The fallback also has no speech rates, so speech spend reads zero in that case.
