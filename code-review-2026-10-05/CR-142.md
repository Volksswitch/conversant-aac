# CR-142: Clearing the error log makes the next problem report pull every old errored conversation from disk

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6836`
- **Also affects:** `app/js/app.js:6847-6851 (misleading explanation line)`; `app/js/app.js:6818-6830 (errorsFromDisk)`; `app/js/app.js:7052-7059 (Clear the error log)`
- **Source:** app-e-07

**What a user notices.** After a tester clears the error list to start fresh, the next problem report includes the full text of every past conversation that ever had an error, and says this happened because browser storage was lost - which is not what happened. Conversely, as soon as one new error is recorded, all the older errors on disk drop out of the report again.

**What is wrong.** buildErrorReport only falls back to errorsFromDisk when the in-browser error list is completely empty. 'Clear the error log' (storage.clearErrorLog) empties exactly that list while the errors stay inside the conversation files on disk, so the next report reads every errored conversation from disk, attaches all their transcripts, and prints '(... which usually means browser storage was cleared or the app changed address)'. The trigger conflates 'the user cleared it' with 'it was lost', and it is all-or-nothing: one new error after a web-address move makes the list non-empty and the disk errors vanish from the report again, reproducing the 'Errors recorded 7 / no errors recorded' contradiction the fallback was written to fix.

**How it happens.** A tester has had errors in 15 conversations over a month. Before reproducing a new bug they press Clear (Troubleshooting > Error log), then reproduce it in Practice... actually before any new error is logged they press Send: the preview contains 15 full transcripts and the 'browser storage was cleared' note.

**Suggested fix.** Record when the user cleared the log: in the clearErrorLogBtn handler, save a timestamp (e.g. storage.saveErrorLogClearedAt(new Date().toISOString())). In buildErrorReport, always merge in errorsFromDisk() entries newer than that timestamp (deduplicate on ts+message, as scripts/beta-eval does), instead of using the disk only when the list is empty; print the 'browser storage was cleared' line only when disk errors were found that are not in the in-app list and newer than the clear mark.

**How to verify the fix.** Manual: with a folder and some past errors, press Clear, then Send: no old transcripts. Then simulate a lost list (delete aac_error_log in localStorage without using Clear) and log one new error: Send must still include the older disk errors.

**Do not break.** The report must still show the full text before sending (confirmDanger preview). Keep private-conversation handling unchanged.

**Design reference.** CLAUDE.md 'Error reporting — audited against expectation and three faults fixed' (FIXED 2, disk fallback).

**Verification notes.** clearErrorLog (storage.js:2612) removes only the localStorage list. buildErrorReport (app.js:6833-6838) falls back to errorsFromDisk() whenever that list is empty. errorsFromDisk reads every conversation file, with no date limit, and returns every one that contains error entries. Each of those is then printed with its full transcript and the 'browser storage was cleared or the app changed address' note. The all-or-nothing fallback also means one new in-app error hides every older disk error again. The report is shown before it is sent.
