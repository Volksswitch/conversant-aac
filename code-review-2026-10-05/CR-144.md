# CR-144: A malformed settings section in a backup wipes every setting back to its default

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/data-transfer.js:304`
- **Also affects:** `app/js/data-transfer.js:413-428`; `app/js/storage.js:733-743 (applyPortableSettings REPLACES the portable subset)`; `app/js/data-transfer.js:331-353 (parsePackage does not check settings' type for v3)`
- **Source:** review-backup-13

**What a user notices.** Restoring a damaged or hand-edited backup can silently reset all of the person's settings (voice, layout, timings) to the factory values.

**What is wrong.** For a v3 package parsePackage never checks that pkg.settings is a plain object. If it is an array, a string, or {} (e.g. truncated by hand), settingsForThisDevice builds a settings object from Object.entries of it, and applyPortableSettings REPLACES the entire portable settings bundle with that (keeping only excluded keys). An array yields junk keys '0','1',...; an empty object resets everything. Values are also not type-checked, though the individual loaders clamp most of them.

**Evidence.**

```
data-transfer.js:305-309
    const incoming = (pkg && pkg.settings) || {};
    ...
    for (const [k, v] of Object.entries(incoming)) {
storage.js:735-742
    const merged = {};
    for (const k of PROFILE_EXCLUDE) { if (current[k] !== undefined) merged[k] = current[k]; }
    for (const k of Object.keys(incoming || {})) {
        if (!PROFILE_EXCLUDE.includes(k)) merged[k] = incoming[k];
    }
    saveSettings(merged);
```

**How it happens.** Import a backup whose "settings" is [] or "x": all voice, dock, button size and timing settings revert to defaults after restart.

**Suggested fix.** In parsePackage, for v3 packages: if `pkg.settings !== undefined && (!pkg.settings || typeof pkg.settings !== 'object' || Array.isArray(pkg.settings))` then `delete pkg.settings` (or throw 'That backup looks damaged - its settings are unreadable.'). In applyPackage only apply settings when `Object.keys(settings).length > 0`.

> **Verifier correction to the fix (takes precedence):** Reject or drop settings that are not a plain object (null, an array, a string or a number) in parsePackage. Do NOT skip applying an empty object {}: exportSettingsBundle on a device left at defaults can legitimately be {}, and applying it faithfully restores the defaults. Skipping it would leave the importing device's own non-default settings in place, contrary to 'Importing replaces'.

**How to verify the fix.** Unit test in tests/ for parsePackage with settings: [] and settings: 'x'; and applyPackage leaving current settings untouched.

**Do not break.** A genuine backup from a device on all defaults may legitimately carry few keys; do not refuse a valid small object.

**Design reference.** data-transfer.js header 'ONE FILE, FILTERED AT IMPORT'

**Verification notes.** For a v3 package parsePackage never type-checks pkg.settings. settingsForThisDevice iterates Object.entries of whatever it is, and applyPackage runs `if (pkg.settings) storage.applyPortableSettings(settings)`, which REPLACES the portable subset (storage.js ~733-743). [] is truthy, so all portable settings reset to defaults; a string yields junk keys such as '0'. The trigger is a damaged or hand-edited backup only.
