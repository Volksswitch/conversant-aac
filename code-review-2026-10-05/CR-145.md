# CR-145: Partner names containing $$, $&, $` or $' are mangled in opener cards (String.replace expands them as replacement patterns)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/engine.js:165`
- **Also affects:** `app/js/engine.js:491`; `app/js/engine.js:673`; `app/js/app.js:2054`; `app/js/app.js:3144`
- **Source:** g-misc-overflow-04

**What a user notices.** If a person or partner button is named with a dollar sign followed by certain characters, the 'Start conversation' cards say the name wrong or repeat half the sentence, and that garbled sentence is spoken in the user's voice if chosen.

**What is wrong.** applyName() substitutes the active partner's label into each opener template with `template.replace(/\{name\}/g, n)`. When the second argument is a string, JavaScript interprets $$, $&, $` and $' (and $<name> with named groups) as replacement patterns. The label is user-typed (partner button label / People name / nickname via partnerLabel(activePartner)), so those sequences are expanded instead of inserted literally. Verified with node through engine.initiate({partnerName}): 'Ca$$ie' -> "Hi Ca$ie, got a minute?"; 'Bo$&b' -> "Hi Bo{name}b, got a minute?"; "A$'Z" -> "Hi A, got a minute?Z, got a minute?"; 'A$`Z' -> "Hi AHi Z, got a minute?". ($1 is harmless here because the pattern has no groups.)

**Evidence.**

```

engine.js:673  state.palette = openerPalette(opts.partnerName || '');
```

**How it happens.** 1. About Me > People: add a person named "Ca$$ie" (or an Express Panel partner button labelled that way). 2. Tap that partner, then Start conversation. 3. The first opener reads "Hi Ca$ie, got a minute?"; with a name containing $' it reads "Hi A, got a minute?Z, got a minute?". 4. Tapping the card speaks the garbled sentence.

**Suggested fix.** Use a replacer function so the name is inserted literally: `if (n) return template.replace(/\{name\}/g, () => n).replace(/\s+/g, ' ').trim();`. No other change is needed; the no-name branch already uses a function.

**How to verify the fix.** Add to tests/engine.test.mjs: for each of ['Ca$$ie', 'Bo$&b', "A$'Z", 'A$`Z'], engine.initiate({ partnerName: n }).palette[0].text === `Hi ${n}, got a minute?` (with default openers loaded via setConversationPhrases or the defaults).

**Do not break.** Keep the existing no-name branch (comma/spacing repair) unchanged, and keep the whitespace collapse. Openers are user-editable, so do not assume the template is a default.

**Design reference.** CLAUDE.md 'Per-partner profile' (openers with {name} merged per partner) and the Controls/Commands editor {name} token

**Verification notes.** Reproduced in node through engine.initiate({partnerName}): 'Ca$$ie' -> 'Hi Ca$ie, got a minute?'; 'Bo$&b' -> 'Hi Bo{name}b, got a minute?'; "A$'Z" -> 'Hi A, got a minute?Z, got a minute?'; 'A$`Z' -> 'Hi AHi Z, got a minute?'. applyName (engine.js:163-165) passes the user-typed name as a replacement string. A name containing those sequences is rare, so low.
