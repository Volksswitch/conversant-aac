# CR-146: Sound-file check looks only at the file name, accepts empty files, and is skipped when restoring a backup

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-audio.js:40`
- **Also affects:** `app/js/express-editor.js:334-343`; `app/js/data-transfer.js:449-454`; `app/js/express-audio.js:63-65`
- **Source:** tts-12

**What a user notices.** A sound file that is not really an MP3 or M4A (just renamed), or is empty, is accepted when added and then fails to play in the middle of a conversation; a backup can bring in sound files of any size.

**What is wrong.** checkAudioFile() decides by extension only (and file.size > 10 MB). It ignores file.type and never tries the format, so a WAV/OGG/WebM renamed to .mp3 or an empty file passes, contradicting the stated rule that the format is checked when the file is added 'not at playback, in the middle of a conversation'. The restore path in data-transfer.js writes clips from a backup after only isSafeAudioName(), so neither the 10 MB cap nor any format check applies to imported clips.

**Evidence.**

```
express-audio.js:42-49 `const ext = audioExtension(file.name); if (!ALLOWED[ext]) {...} if (file.size > MAX_AUDIO_BYTES) {...} return { ok: true, ext, type: ALLOWED[ext] };`
data-transfer.js:450-452 `if (s && isSafeAudioName(s.name) && typeof s.data === 'string') { ... await storage.writeAudioFile(s.name, base64ToBlob(...));`
```

**How it happens.** Rename a .wav recording to clip.mp3 and add it to a sound button; the editor accepts it; on an iPad during a conversation tapping the button logs 'A sound button could not play' and nothing is heard. Or import a backup containing a 200 MB clip; it is written to the data folder and later read fully into memory when the panel is drawn.

**Suggested fix.** In checkAudioFile add `if (!file.size) return { ok: false, reason: 'That file is empty.' };` and, when `file.type` is non-empty and not one of 'audio/mpeg','audio/mp3','audio/mp4','audio/x-m4a','audio/aac', reject it. In express-editor useFile, after the check, optionally verify playability with `new Audio().canPlayType(check.type)` or a trial decode via AudioContext.decodeAudioData before saving. In data-transfer.js restore loop, skip any clip whose decoded byte length (Math.floor(s.data.length * 3 / 4)) exceeds MAX_AUDIO_BYTES.

**How to verify the fix.** Extend tests/express-audio.test.mjs: checkAudioFile({name:'a.mp3', size:0}) is not ok; checkAudioFile({name:'a.mp3', size:100, type:'audio/wav'}) is not ok; {name:'a.mp3', size:100, type:''} stays ok. Add a data-transfer test that a backup clip over 10 MB is not written.

**Do not break.** Some systems report an empty or unusual MIME type for valid files (e.g. 'audio/x-m4a'); do not reject a file only because type is empty.

**Design reference.** CLAUDE.md 'SOUND buttons on the Express Panel' ('MP3 and M4A only, up to 10 MB, checked when the file is ADDED')

**Verification notes.** checkAudioFile() (express-audio.js:40-50) checks only the extension and file.size > 10 MB; it ignores file.type and accepts size 0, so a renamed non-MP3 or empty file is accepted at add time (express-editor.js:334-343). The restore loop in data-transfer.js (449-454) writes any clip with a safe name and string data, with no size limit. Both are real; the triggers are user-made (renamed files, hand-crafted backups), hence low.
