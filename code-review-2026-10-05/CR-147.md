# CR-147: Resetting the Always band marks shipped phrases as the user's own words

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-items.js:270`
- **Also affects:** `app/js/express-panel.js:161-173`; `app/js/express-panel.js:215-220`; `app/js/express-editor.js:660-671`; `app/js/app.js:4326-4331`
- **Source:** express-03

**What a user notices.** After someone edits one of the starting phrases and then uses 'Reset to the app's phrases', the app treats the restored starting phrase (for example 'Maybe') as something the user wrote, and tells the AI it is part of how this person talks.

**What is wrong.** resetBand('always') rebuilds the band from ALWAYS_DEFAULTS, whose ids are fixed ('a0'..'a25') and origin DEFAULT, then calls setModel(), which runs markEdits(n.always, prev.always). markEdits looks up the previous item by id; for any default the user had edited (prev 'a3' text 'Perhaps', origin EDITED) the restored item has the same id but a different signature, so it is re-stamped ORIGIN.EDITED. The restored default is now isUserAuthored() and flows into userAuthoredItems() -> voiceBlockText() ('Words and turns of phrase this user actually uses') and into the personalization-depth count. This is the exact error provenance exists to prevent. Reproduced with node: after edit+reset, a3 = {text:'Maybe', origin:'edited'}, userAuthoredItems() -> ['Maybe'].

**Evidence.**

```
express-panel.js:217 `if (band === 'always') m.always = ALWAYS_DEFAULTS.map((x) => ({ ...x }));` then :219 `return setModel(m);`
express-panel.js:164 `n.always = markEdits(n.always, prev.always);`
express-items.js:274-276 `const was = before.get(it.id); if (!was) return {...}; if (signature(it) !== signature(was)) return { ...it, origin: ORIGIN.EDITED };`
express-items.js:187 `.map((it, i) => ({ id: 'a' + i, ...it, origin: ORIGIN.DEFAULT }))` (fixed ids reused on reset)
```

**How it happens.** Settings > Express Panel > Always: change 'Maybe' to 'Perhaps'. Press 'Reset to the app's phrases' and confirm. 'Maybe' is back, but expressPanel.userAuthoredItems() now includes 'Maybe' and the voice block sent to the AI lists "Maybe" as the user's own wording.

**Suggested fix.** Make resetBand bypass the diff for the band it resets. In express-panel.js resetBand, after building `m`, call setModel(m) and then overwrite the reset band's origin: simplest is to add an optional second argument to setModel, e.g. `setModel(next, { keepOriginFor: ['always'] })`, and in setModel skip markEdits for those bands (use the items' own origin). Alternatively, in markEdits, return the item unchanged when `it.origin === ORIGIN.DEFAULT && signature(it) === signature(shippedDefaultById(it.id))` - but the explicit option on setModel is clearer. Apply the same to resetBand('context').

**How to verify the fix.** Add to tests/express-panel-store.test.mjs (or a new test in tests/express-items.test.mjs): edit always[3] text, call panel.resetBand('always'), assert panel.getModel().always.every(x => x.origin === 'default') and panel.userAuthoredItems().length === 0.

**Do not break.** Edits made AFTER the reset must still be stamped EDITED by the normal diff; only the reset itself is exempt. Do not change the fixed default ids (the seed-revision logic and existing files depend on them).

**Design reference.** express-items.js provenance header (Ken, August 7 2026); CLAUDE.md 'PROVENANCE MARKING is therefore a dependency of Phase 0'

**Verification notes.** Reproduced in node against the real modules: edit always[3] to 'Perhaps', then resetBand('always'); always[3] comes back as {text:'Maybe', origin:'edited'} and userAuthoredItems() returns ['Maybe']. markEdits finds prev id 'a3' with a different signature and re-stamps EDITED. voiceBlockText (app.js:4326) feeds that list to the voice block. The trigger is narrow (edit a default, then reset) and the impact is one or a few plumbing words in the voice block, so low rather than medium.
