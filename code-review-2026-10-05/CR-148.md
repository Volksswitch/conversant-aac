# CR-148: Each pause resets the 'never the same phrase twice in a row' memory for holding phrases

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/placeholders.js:213`
- **Also affects:** `app/js/placeholders.js:241`; `app/js/placeholders.js:184-188`; `app/js/placeholders.js:146-156`; `tests/placeholders.test.mjs:190-199`
- **Source:** phrases-practice-06

**What a user notices.** The other person can hear the exact same holding phrase twice in a row, for example 'I'm thinking.' after one pause and 'I'm thinking.' again after the next, and Hold on can repeat the phrase the app had just said by itself. That repetition is what makes the device sound like a machine.

**What is wrong.** arm() runs at every silence checkpoint (several per partner turn at the 0.5 s default) and sets `lastIndex = { acknowledgment: -1, thinking: -1 }`, as does the defensive path in start(). pick() avoids only lastIndex[key], so after any re-arm the next acknowledgment can equal the one just spoken, and Hold on (phraseOnDemand, which relies on sharing lastIndex) can repeat a 'thinking' phrase spoken just before the partner's last pause. Ken's rule (comment 76) is that the same placeholder can't be said twice in a row; with 14 acknowledgments the chance is about 1 in 14 per pause. The same reset also restarts `count`, so 'Maximum per turn' is effectively per pause.

**Evidence.**

```
placeholders.js:208-213 `export function arm() { ... count = 0; lastIndex = { acknowledgment: -1, thinking: -1 };`
placeholders.js:241 (start) `lastIndex = { acknowledgment: -1, thinking: -1 };`
placeholders.js:153 `} while (index === lastIndex[key]);`
placeholders.js:161-167 comment: 'Sharing `lastIndex` is the load-bearing half ... Hold on could repeat the phrase the app had just spoken'.
```

**How it happens.** Partner speaks, pauses 2 s: app says 'I'm thinking.' Partner adds a sentence and pauses again: arm() resets lastIndex, and 1 time in 14 the app says 'I'm thinking.' again. Or: ladder says 'Still working on it.', partner says 'okay', pause re-arms, user taps Hold on: 1 in 15 it says 'Still working on it.'

**Suggested fix.** Stop resetting lastIndex in arm() and in start(); keep it for the whole session (it is only a 'last index per pool', so leaving it across turns is safe; pick() already tolerates an out-of-range value after an edit). Leave `count` reset as is unless Ken decides 'Maximum per turn' should be per partner turn.

**How to verify the fix.** Add a test to tests/placeholders.test.mjs: stub tts.speak to record phrases, arm(), advance past initialDelay, stop(), arm() again, advance, and repeat ~50 times asserting no two consecutive recorded acknowledgments are identical; also assert phraseOnDemand() never equals the last ladder 'thinking' phrase after an intervening arm().

**Do not break.** Keep the per-pool split (first phrase from acknowledgment, later from thinking). Do not change the cap semantics without Ken.

**Design reference.** CLAUDE.md 'Placeholders are gated by PARTNER SILENCE'; placeholders.js phraseOnDemand comment (Ken, comment 76).

**Verification notes.** arm() (placeholders.js:213) and start()'s defensive path (line 241) both reset lastIndex. arm() runs at every silence checkpoint, so pick() can no longer avoid the phrase spoken just before the pause. phraseOnDemand shares lastIndex, so Hold on after a re-arm can also repeat the last ladder phrase. This contradicts the documented no-repeat rule (Ken, comment 76) quoted in the phraseOnDemand comment.
