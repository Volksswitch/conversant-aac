# CR-149: Device signature uses raw screen width x height, so the same tablet in a different orientation counts as a different screen

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/platform.js:283`
- **Also affects:** `app/js/platform.js:309`
- **Source:** reporting-platform-12

**What a user notices.** Restoring a backup on the same Android or Windows tablet while it is turned sideways can hold back the button-size and keyguard settings as if it came from a different device.

**What is wrong.** deviceSignature records `${screen.width}x${screen.height}`. On Android Chrome and on rotating Windows tablets screen.width/height swap with orientation, so an export made in landscape and an import done in portrait (or vice versa) compare as different screens and compareDevice() returns sameScreen false, withholding screen-bound settings.

**Evidence.**

```
app/js/platform.js:283-284: `w = Math.round(screen.width || 0); h = Math.round(screen.height || 0);`
app/js/platform.js:291: `screen: w && h ? `${w}x${h}` : '',`
app/js/platform.js:309: `sameScreen: ... sig.screen === here.screen,`
```

**How it happens.** Export a backup on an Android tablet held in landscape (1280x800); later restore it on the same tablet while held in portrait (800x1280): sameScreen is false and the keyguard-related settings are not applied.

**Suggested fix.** Normalize the orientation: `const a = Math.max(w, h), b = Math.min(w, h); screen: a && b ? `${a}x${b}` : ''`. In compareDevice, also normalize an incoming `sig.screen` by splitting on 'x' and sorting, so backups written before the change still compare correctly.

**How to verify the fix.** Add to tests/platform.test.mjs: compareDevice({os:'android',shell:'tab',screen:'800x1280'}, {os:'android',shell:'tab',screen:'1280x800'}).sameScreen === true.

**Do not break.** Two genuinely different screens must still compare as different.

**Design reference.** platform.js deviceSignature header (Ken, September 9 2026); Conversant AAC Backup Compatibility.docx

**Verification notes.** deviceSignature uses raw screen.width x screen.height (platform.js:283-291), and compareDevice compares the strings exactly. On Android Chrome and on rotating Windows tablets screen.width and screen.height swap with orientation, so the same device can compare as a different screen and data-transfer.js holds back the SCREEN_BOUND settings. The trigger needs an import done in the other orientation, which is unusual for a landscape-only app, so low.
