# CR-150: Editing a scenario can blank out who the other person is; it then runs with no persona and cannot be copied

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/practice-editor.js:224`
- **Also affects:** `app/js/practice-editor.js:292-296`; `app/js/practice-editor.js:304-313`; `app/js/practice-library.js:181`; `app/js/practice-library.js:240-248`; `app/js/llm.js:669`
- **Source:** phrases-practice-08

**What a user notices.** If the user clears the 'Who they are' box while editing a scenario, the app keeps it, and practicing it gives a partner the AI simply invents. Tapping 'Make a copy' on that scenario then does nothing at all, with no message.

**What is wrong.** The create form refuses to add a scenario without a name and a persona, but the edit form saves every change as it happens and only protects the title (updateScenario restores a blank title, not a blank persona). A scenario with empty partnerPersona then: (a) is started by 'Practice this' / its card, and generatePartnerUtterance sends 'The person you are playing: ' with nothing after it; (b) copyScenario returns null because `!source.partnerPersona`, and the editor's `if (id) goTo(...)` silently does nothing.

**Evidence.**

```
practice-editor.js:224 `f.addEventListener('change', () => save({ [prop]: f.value }));`
practice-editor.js:293 `if (!draft.title.trim() || !draft.partnerPersona.trim()) {` (create only)
practice-library.js:245 `if (!str(next.title)) next.title = m.scenarios[i].title;` (no persona guard)
practice-library.js:181 `if (!source || !source.partnerPersona) return null;`
practice-editor.js:139-140 `const id = await library.copyScenario(s); if (id) goTo(...)`
```

**How it happens.** Settings > Practice > Edit one of your scenarios, delete all text in 'Who they are', tap Done. Tap 'Make a copy' on it: nothing happens. Tap the scenario: the AI plays an unspecified person.

**Suggested fix.** In practice-library.updateScenario, treat a blank persona like a blank title: `if (!str(next.partnerPersona)) next.partnerPersona = m.scenarios[i].partnerPersona;`. In practice-editor, show a status note when copyScenario returns null ("This scenario needs a description of who they are before it can be copied.").

**How to verify the fix.** Add a test in tests/ for practice-library (e.g. tests/practice-library.test.mjs, following the existing localStorage shim pattern): updateScenario(id, { partnerPersona: '' }) keeps the old persona. Manual: blank the persona in the edit form, leave, reopen: the old persona is back.

**Do not break.** Keep save-as-you-go in edit mode; do not add a Save button.

**Design reference.** CLAUDE.md 'A LIST THAT SHOWS AN ITEM AS ADDED HAS PROMISED IT IS SAVED' (auto-save must not blank identity fields).

**Verification notes.** The edit form saves every change as it happens (practice-editor.js:224). updateScenario (practice-library.js:240-248) restores only a blank title, not a blank persona. copyScenario returns null when partnerPersona is empty (line 181), and the editor's `if (id) goTo(...)` then does nothing, with no message. generatePartnerUtterance builds 'The person you are playing: ' with nothing after it.
