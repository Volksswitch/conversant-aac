# CR-151: Learned word list: one typo outranks the dictionary forever, the list never stops growing, and non-ASCII words are stored mangled

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/prediction.js:65`
- **Also affects:** `app/js/prediction.js:37`; `app/js/prediction.js:56`; `app/js/keyboard.js:366`
- **Source:** keyboard-07

**What a user notices.** If the person once types a word wrong ("teh") and moves on, the app keeps suggesting the misspelling ahead of the real word from then on. Over months the stored list only grows, and an accented name like "José" is remembered as "jos".

**What is wrong.** predict() puts every personal match ahead of every dictionary match regardless of count, so a single occurrence (count 1) of a typo beats the most common dictionary word with that prefix; accepting the ghost then reinforces it. There is no minimum count, cap, decay or pruning, and each separator re-serializes the whole map to localStorage (shared quota with aac_settings and the error ring). learn() strips everything outside [a-z'] after lowercasing, so 'José' is stored as 'jos'; currentWordPrefix() also stops at a non-ASCII letter.

**Evidence.**

```
prediction.js:71-78 `const personal = Object.keys(uf).filter((w) => w !== p && w.startsWith(p)).sort(...); ... personal.forEach(push);` (all personal before dictionary); prediction.js:56 `const w = String(word || '').toLowerCase().replace(/[^a-z']/g, '');`; prediction.js:37-39 `function saveUserFreq() { try { localStorage.setItem(FREQ_KEY, JSON.stringify(userFreq)); } catch { /* quota/full */ } }`.
```

**How it happens.** Type 'teh ' once in the composer. Next time type 'te' - the ghost offers 'teh' rather than a dictionary word.

> **Verifier correction to the trigger:** The typo case is right. The 'José' example is not reachable today: the app keyboard has no accented keys, and currentWordPrefix() returns nothing when the word ends in a non-ASCII letter, so the word is skipped rather than stored as 'jos'.

**Suggested fix.** In predict(), require a personal word to have count >= 2 to be ranked ahead of dictionary words (personal words with count 1 can still follow dictionary matches, or interleave by comparing count against a threshold). In learn(), cap the map (e.g. keep the 2,000 highest counts: when Object.keys(uf).length > 2500, drop the lowest-count entries). Normalize with `w.normalize('NFKD').replace(/[̀-ͯ]/g, '')` before stripping, or skip learning a word that contained characters outside the allowed set rather than storing a truncated fragment.

> **Verifier correction to the fix (takes precedence):** Treat the non-ASCII normalization as optional hardening rather than a bug fix. The ranking threshold and the size cap are the real fixes.

**How to verify the fix.** tests/prediction.test.mjs: learn('teh') once then assert predict('te',1)[0] is a dictionary word; learn it three times and assert it now ranks first; learn 3,000 distinct words and assert the stored map stays under the cap; learn('José') does not store 'jos'.

**Do not break.** Keep the existing test 'learned words are boosted ahead of the dictionary' meaningful (it learns 5 times). Prediction must stay local and instant (CLAUDE.md word-prediction decision).

**Design reference.** CLAUDE.md 'Word prediction - local tiers' (personalized learning)

**Verification notes.** predict() pushes every personal match (sorted by count) before any dictionary match, so a single learned typo becomes the only ghost shown for its prefix. Accepting it raises its count further. learn() has no cap, minimum count or decay, and re-serializes the whole map on every separator. The non-ASCII half is barely reachable: the app keyboard has no accented keys, and currentWordPrefix() uses /[A-Za-z']+$/, so a word ending in 'é' matches nothing and is never learned. acceptGhost passes only ASCII dictionary words. 'José' therefore is not stored as 'jos' through any current path, though learn() would truncate it if handed one.
