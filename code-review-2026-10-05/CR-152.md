# CR-152: Name respellings also hit names followed or preceded by accented letters (whole-word test is ASCII-only)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/pronunciation.js:81`
- **Also affects:** `app/js/pronunciation.js:77-85`
- **Source:** tts-10

**What a user notices.** If the user sets a pronunciation for a short name like 'Ana', other names that merely start with it and continue with an accented letter (for example 'Anaïs' or 'Renée' for 'Ren') are mispronounced.

**What is wrong.** substitute() defines a word boundary as 'not [A-Za-z0-9]'. Any non-ASCII letter (é, ï, ñ, ö, etc.) is treated as a boundary, so a lexicon entry matches inside a longer word that continues (or begins) with an accented letter. The documented rule is whole-word matching so a name cannot be found inside an unrelated word; names with accents are common in this app's data (CLAUDE.md cites 'José').

**Evidence.**

```
pronunciation.js:80-83 `new RegExp('(?<![A-Za-z0-9])(' + ... + ')(?![A-Za-z0-9])', 'g')`
Scratch run: buildLexicon([{name:'Ana',pronunciation:'Ah-na'}]) then substitute('Anaïs and Ana ...') -> 'Ah-naïs and Ah-na ...'
```

**How it happens.** About Me > People: add 'Ana' with respelling 'Ah-na' and also have a friend 'Anaïs'. Any sentence mentioning Anaïs is spoken as 'Ah-naïs'.

**Suggested fix.** Use Unicode-aware boundaries: change the pattern to `'(?<![\\p{L}\\p{N}])(' + ... + ')(?![\\p{L}\\p{N}])'` and add the 'u' flag (`'gu'`). Note escapeRe output is valid under the u flag for the characters it escapes.

**How to verify the fix.** Add to tests/pronunciation.test.mjs: substitute('Anaïs and Ana', [{from:'Ana',to:'Ah-na'}]) === 'Anaïs and Ah-na', and substitute('Renée met Ren', [{from:'Ren',to:'Wren'}]) === 'Renée met Wren'. Existing case-sensitivity and longest-first tests must still pass.

**Do not break.** Keep matching case-sensitive and single-pass; keep longest-first ordering; the respelling must still never reach the transcript or the LLM.

**Design reference.** CLAUDE.md 'Display text vs. spoken text' (BUILT August 8 2026: 'Matching is case-sensitive and whole-word')

**Verification notes.** substitute() (77-85) uses lookarounds `(?<![A-Za-z0-9])` / `(?![A-Za-z0-9])`, so any non-ASCII letter counts as a boundary; a lexicon entry 'Ana' matches the start of 'Anaïs' and 'Ren' matches inside 'Renée'. This contradicts the stated whole-word rule. The suggested fix with \p{L}\p{N} and the 'u' flag is compatible with escapeRe (line 35), which only escapes syntax characters that are valid identity escapes under 'u'.
