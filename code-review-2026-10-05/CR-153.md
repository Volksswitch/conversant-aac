# CR-153: Undo can take back two actions at once after a previous edit: the word snapshot flag is never reset when editing stops

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:684`
- **Also affects:** `app/js/review-ui.js:623-627 (stopEditing)`; `app/js/review-ui.js:710-713 (afterEdit resets the flag only on a fresh word)`; `app/js/review-ui.js:612-621 (startCardEdit pushes a no-op history entry)`
- **Source:** review-backup-11

**What a user notices.** After correcting one line, starting a correction on another and pressing Undo can remove both the new words and the 'wrong words' mark in one press, instead of one step at a time.

**What is wrong.** wordSnapshotTaken is set true on the first input of a word and reset only by afterEdit when ed.fresh. If editing ends (tap the card body, goTo, Undo) right after typing, the flag stays true. In the next edit session the first typed word skips the history push (ed.fresh && !wordSnapshotTaken is false), so the next Undo returns to the snapshot taken before the session began - e.g. on the partner line that snapshot predates the misheard flag, so one Undo removes the flag and the typing together, contradicting 'No single press can lose more than the last thing the user did'. Related: startCardEdit always calls change() even when the review does not change (choosing the spoken card or re-editing the chosen card), pushing an identical state, so the next Undo press visibly does nothing.

**Evidence.**

```
review-ui.js:679-686
let wordSnapshotTaken = false;
function onWordInput() {
    if (!active || !ed) return;
    if (ed.fresh && !wordSnapshotTaken) { history.push(review, turn().key); wordSnapshotTaken = true; }
review-ui.js:623-627
function stopEditing() {
    editing = null;
    ed = null;
    if (wordInput && document.activeElement === wordInput) wordInput.blur();
}
```

**How it happens.** Edit a card: type 'tea' then tap the card body to finish. Tap the partner line (mark appears), type 'coffee'. Press Undo: both 'coffee' and the misheard mark disappear.

**Suggested fix.** Set `wordSnapshotTaken = false;` inside stopEditing(), and in startCardEdit only call change() when the new review differs (compare JSON of the entry before/after) - otherwise assign `review = model.setCardAnswer(...)` without pushing history.

**How to verify the fix.** Manual reproduction above; after the fix the first Undo removes only 'coffee'.

**Do not break.** Keep 'undo steps back a word rather than a letter' (§6).

**Design reference.** Conversation Review.docx §6 Undo paragraph

**Verification notes.** wordSnapshotTaken is reset only in afterEdit when ed.fresh, and stopEditing() does not reset it. After typing into a fresh word the editor becomes non-fresh, so the flag stays true. Finishing the edit and then tapping the partner line pushes a snapshot through change(setMisheard). createWordEditor starts fresh: true, but onWordInput skips the push because the flag is still true, so one Undo pops the snapshot taken before the misheard flag and removes both the flag and the typing. startCardEdit also always calls change(), pushing an identical state when the card's answer already matches, so the next Undo appears to do nothing.
