# CR-158: Shown transcription seconds leave out the 1.2 seconds of lead-in audio sent with every phrase, and count clicks that were never sent

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/stt-deepgram.js:221`
- **Also affects:** `app/js/stt-deepgram.js:217`; `app/js/stt-azure.js:366`; `app/js/stt-azure.js:381`; `app/js/stt-rest.js:228`; `app/js/stt-rest.js:251`; `app/js/vad.js:60`; `app/js/stt-rest.js:228 (merged duplicate: OpenAI/Google/ElevenLabs hearing counts noise bursts it never sends as billed time)`
- **Source:** stt-11, x-providers-11

**What a user notices.** The cost of paid hearing shown in the app is lower than the bill, by roughly a second per thing the other person says, which for short replies can be a third or more of the real amount.

**What is wrong.** All three sources bill `now - openedAt` (gate-open time). But on the 'open' edge they also upload the pre-roll buffer (up to vad DEFAULTS.preRollMs = 1200 ms; preRollFrames = ceil(1.2 s * rate / 4096) ~ 15 frames ~ 1.28 s), which the services bill as audio submitted. vad.js even documents this cost ('about 0.8s more audio per utterance'). Conversely stt-rest adds openMs to billedMs and reports it BEFORE the 250 ms speech-floor check, so a discarded click is counted although nothing was sent.

**Evidence.**

```
stt-deepgram.js:217 `for (const f of preRoll) send(f);` ... :221 `billedMs += now - openedAt;`
stt-azure.js:381 `span = preRoll.slice();` ... :366 `billedMs += Math.max(0, now - openedAt);`
stt-rest.js:228-229 `billedMs += openMs; if (onBilled) onBilled(billedMs / 1000);` ... :251 `if (openMs - HANG_MS < MIN_SPEECH_MS) { reset(); return; }`
```

**How it happens.** Partner says 'Yes.' (0.4 s): gate open ~1.3 s incl. hang -> 1.3 s counted, ~2.6 s uploaded and billed.

**Suggested fix.** Count what is actually sent. Deepgram: in handleFrame track `sentSamples += FRAME_SAMPLES` for each frame passed to send() (including flushed pre-roll) and report `onBilled(sentSamples / rate)`; Azure/REST: in closeSpan compute seconds from the frames being submitted (`frames.reduce((n,f)=>n+f.length,0) / rate`) and add it only when submit() is actually called (move the billedMs/onBilled lines after the REST speech-floor return).

**How to verify the fix.** tests/stt-rest.test.mjs and tests/stt-azure.test.mjs: drive handleFrame via a fake processor with a known number of loud frames after N quiet frames and assert onBilled equals total submitted samples / rate; a click below the floor must not change billed seconds.

**Do not break.** Keep reporting cumulative totals per session (app.js derives deltas) unless the app.js billing-delta finding is fixed in the same change.

**Design reference.** app/js/vad.js preRollMs comment ('What it costs: about 0.8s more audio per utterance'); CLAUDE.md Deepgram cost-model note

**Verification notes.** Deepgram sends the pre-roll frames on the open edge but bills only `now - openedAt`. Azure seeds the span with the pre-roll, which is submitted but not counted. In stt-rest.closeSpan, billedMs is added and reported before the MIN_SPEECH_MS floor returns without submitting, so a discarded click is counted. So the shown figure undercounts the uploaded audio by about the pre-roll per utterance, and counts clicks that were never sent.

<details><summary>Merged duplicate x-providers-11: OpenAI/Google/ElevenLabs hearing counts noise bursts it never sends as billed time</summary>

closeSpan() adds the span's open time to billedMs and reports it via onBilled before applying the MIN_SPEECH_MS filter that discards short noise spans without submitting them. The services bill only for audio submitted, so every discarded span inflates the estimate.

Fix as proposed by that reviewer: Move the two billing lines below the MIN_SPEECH_MS check so only submitted spans are counted: `if (openMs - HANG_MS < MIN_SPEECH_MS) { reset(); return; } billedMs += openMs; if (onBilled) onBilled(billedMs / 1000); submit(frames, rate, mine);`.

</details>
