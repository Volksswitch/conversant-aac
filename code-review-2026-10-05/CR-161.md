# CR-161: Two-tap mode: the first tap is forgotten whenever the Express Panel redraws between the taps

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/tap-guard.js:86`
- **Also affects:** `app/js/tap-guard.js:60`; `app/js/app.js:3398`; `app/js/app.js:3408`; `app/js/ui.js:536`
- **Source:** ui-shell-05

**What a user notices.** With 'Two taps' on, a person who taps a phrase once and then again can find that nothing was said, because the panel refreshed in between (for example when the other person's offered choices appear) and the second tap only started the count again.

**What is wrong.** tap-guard identifies the armed control by element identity (`armed === m.el`). renderExpressPanel() rebuilds every .ep-btn with epGrid.innerHTML = '' on many events during a conversation - offered choices arriving or clearing (setOfferedChoices / setOfferedRange after each generation), a sound starting/stopping, goal/partner/place toggles, paging. After a redraw the armed element is detached, its ring disappears, and the second tap on the visually identical new button is treated as a first tap. Choice chips arrive at the same moment the user is most likely to reach for a phrase (when suggestions land).

**Evidence.**

```
tap-guard.js:86
        if (armed === m.el) { disarm(); return; }      // the second tap: let it act
tap-guard.js:60  return !!m && armed !== m.el;
ui.js:536   epGrid.innerHTML = '';
app.js:3398 (setOfferedChoices) offeredChoices = next; renderExpressPanel();
```

**How it happens.** Settings > General > One tap or two = Two taps. In a conversation, tap 'Thank you' on the Express Panel once (ring appears); the AI reply with a closed set arrives and the panel redraws; tap 'Thank you' again within the interval: it only re-arms, nothing is spoken.

> **Verifier correction to the trigger:** The panel is not redrawn after every generation. It is redrawn only when the offered choices or range CHANGE, or on a toggle, paging, or sound start/stop. With the default 400 ms interval the window is small, and it grows with a longer user-set interval.

**Suggested fix.** Give addRule an optional `key(el)` returning a stable identity, and use it for the Express Panel rule only: in app.js `tapGuard.addRule('#epGrid .ep-btn', { ..., key: (el) => [...el.parentNode.parentNode.querySelectorAll('.ep-btn')].indexOf(el) + '|' + (el.getAttribute('aria-label') || '') })` (or a data-cell attribute added in ui.js buildItemBtn). In tap-guard store `armedKey` in arm(); define `sameAsArmed(m) = armed === m.el || (armed && !armed.isConnected && m.rule.key && armedKey === m.rule.key(m.el))` and use it in both the click listener and isArmingTap(). Do NOT give the response-card rule a key: a replaced card is new wording and must be re-armed.

> **Verifier correction to the fix (takes precedence):** Rather than computing an index from parentNode.parentNode (fragile against the row/cell structure), add a stable data attribute in ui.js when each Express button is built (for example data-cell=<ordinal> plus the item id or label) and key on that. Keep response cards keyless as the reviewer says.

**How to verify the fix.** Unit test (new tests/tap-guard.test.mjs with a minimal fake document) or manual: two-tap mode, arm a phrase, call renderExpressPanel() from the console, tap the same phrase: it must speak.

**Do not break.** Response cards replaced by a reprompt must still require a fresh first tap (different words). Exemptions (undefined cells, stopping a sound) unchanged.

**Design reference.** CLAUDE.md UI Layout Rule 10 (ONE TAP OR TWO — NOW APP-WIDE)

**Verification notes.** tap-guard.js compares the armed control by element identity (armed === m.el, lines 60 and 86), and renderExpressPanel rebuilds every .ep-btn (epGrid.innerHTML = ''), so after a redraw the second tap on the replacement button arms again instead of acting. The redraw is reachable during a conversation, but less often than the finding implies: setOfferedChoices and setOfferedRange (app.js:3394-3408) return early when nothing changed and redraw only when the offered set actually changes. The default double-tap window is 400 ms (storage.js:1687-1690), so the window is narrow unless the user has lengthened it.
