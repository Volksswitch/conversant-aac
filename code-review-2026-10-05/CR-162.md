# CR-162: Usage summary counts context and other non-turn records as partner turns and as conversations with a person

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/usage-summary.js:254`
- **Also affects:** `app/js/usage-summary.js:422`; `app/js/usage-summary.js:246`; `app/js/usage-summary.js:383`; `app/js/storage.js:2243`
- **Source:** reporting-platform-08

**What a user notices.** The beta figures for 'people talked with', 'people seen in more than one conversation' and 'turns with a partner' are inflated, so a partner tapped but never actually spoken with looks like a returning conversation partner.

**What is wrong.** Since September 2026 a conversation file contains non-turn entries ('context', 'offer', 'placeholder', 'event'). The context entry carries `partner: {id,label}` (storage.pushContext). summarize() reads the partner label from EVERY exchange, not only partner/user turns, so `influencers.turnsWithPartner` and `partners[].turns` include context entries, and a conversation that contains only a context entry (Listen or Start pressed with a partner selected, nothing said) adds that partner to `partners[].conversations` and can make them a 'returning partner'. turnsWithFeeling/turnsWithPlace are counted only on user turns, so the three influencer counts are on different bases. Similarly days/conversation starts come from any timestamped entry, so a conversation consisting only of a 'mic on' event or an unchosen opener set is counted as a conversation in the weekly retention buckets. Measured on the bundled demo data: turnsWithPartner 120 against 105 actual partner+user turns (15 context entries); two context-only conversations with 'Dr. Patel' yield a returning partner with 2 'turns'.

**Evidence.**

```
app/js/usage-summary.js:254-262: `const label = e && e.partner && e.partner.label; if (label) { out.influencers.turnsWithPartner++; ... row.conversations.add(convId); row.turns++; }` (runs for every exchange role)
app/js/storage.js:2241-2248: context entry `role: 'context', trigger, partner: snap.partner || null, ...`
app/js/usage-summary.js:383: `if (convStart !== null) bucketable.push({ t: convStart, kind: 'conversation', ... })` where convStart is set from any entry.
```

**How it happens.** Tester taps 'Dr. Patel' on the Express Panel, presses Listen on two separate days and ends without anyone speaking. The weekly report shows Dr. Patel as a returning partner with 2 turns, and two conversations in the retention buckets.

**Suggested fix.** In summarize(), count partner labels only for partner and user turns: change `if (label)` to `if (label && (isPartner(e) || isUser(e)))`, and apply the same `(isPartner(e) || isUser(e))` condition in the second pass at line ~423. Only push the 'conversation' bucket entry (line 383) when `turns.length > 0` (empty conversations are already counted separately in emptyConversations).

**How to verify the fix.** Add to tests/usage-summary.test.mjs: a log with one context entry carrying a partner and no turns must give partners.length 0 and influencers.turnsWithPartner 0; a log with one context entry plus one partner turn and one user turn stamped with the same partner gives turnsWithPartner 2 and partners[0].turns 2.

**Do not break.** isPractice() must keep reading partner labels from any entry (practice stamps). Keep emptyConversations as is.

**Design reference.** CLAUDE.md 'Beta instrumentation and error reporting' (the headline adoption measure) and 'THE STANDARD FOR THE RECORD IS CAN IT BE RECREATED TO THE SECOND' (non-turn roles)

**Verification notes.** Reproduced with a node script against the real usage-summary.js. Two logs, each holding only a 'context' entry with partner 'Dr. Patel', give partners=[{label:'Dr. Patel', conversations:2, turns:2}], returningPartners 1, turnsWithPartner 2, and a week bucket counting 2 conversations, with 0 partner or user turns. storage.pushContext writes the partner snapshot on context entries, and startConversationLog pushes one at time zero, so a Listen or Start press with a partner selected and nothing said produces this.
