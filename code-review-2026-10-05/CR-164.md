# CR-164: Local-copy guard misses machine names, .local addresses and IPv6 private addresses, so developer copies can still send reports

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/weekly-send.js:84`
- **Also affects:** `app/js/weekly-send.js:474`
- **Source:** reporting-platform-09

**What a user notices.** Test copies run from a developer's computer under its network name can still send anonymous reports, which look like a real tester who has not typed their name.

**What is wrong.** isLocalOrigin only recognizes localhost, loopback, 0.0.0.0, ::1, IPv4 private ranges and link-local IPv4. A local build reached by the machine's hostname (e.g. http://desktop-abc:8000, http://kens-pc.local:8000), or by an IPv6 unique-local/link-local address (fd00::/8, fe80::), returns false. The real app is only ever served over https from conversant.volksswitch.org, so any plain-http origin is necessarily a development copy, yet http is not checked.

**Evidence.**

```
app/js/weekly-send.js:89-96: `if (h === 'localhost' || h.endsWith('.localhost')) return true; ... if (/^169\.254\./.test(h)) return true; return false;`
```

**How it happens.** Ken serves a test build with serve.bat and opens it on the tablet as http://desktop-abc:8000; after the copy is used, a weekly report from an unnamed install arrives in the Sheet.

**Suggested fix.** Add before the final `return false`: `if (loc.protocol === 'http:') return true;` (production is always https), `if (h.endsWith('.local')) return true;`, `if (!h.includes('.') && !h.includes(':')) return true;` (single-label machine names), and `if (/^f[cd][0-9a-f]{2}:/.test(h) || /^fe80:/.test(h)) return true;`.

**How to verify the fix.** Extend the isLocalOrigin cases in tests/weekly-send.test.mjs: {protocol:'http:', hostname:'desktop-abc'}, {protocol:'https:', hostname:'kens-pc.local'}, {hostname:'fe80::1'} return true; {protocol:'https:', hostname:'conversant.volksswitch.org'} still returns false.

**Do not break.** The real origin must never match (that would silence the whole beta, as CLAUDE.md warns); keep the test asserting the production host returns false.

**Design reference.** CLAUDE.md 'A SECOND SOURCE OF DEV NOISE ... A LOCALLY-SERVED COPY REPORTS ANONYMOUSLY'

**Verification notes.** isLocalOrigin (weekly-send.js:84-97) checks only localhost, loopback, 0.0.0.0, ::1, IPv4 private ranges and 169.254. A bare machine name ('desktop-abc'), a '.local' name, an IPv6 ULA or link-local address, or any plain-http origin returns false, so such a copy reports like a real tester. Production is always https on conversant.volksswitch.org, so treating http: as local is safe. Reaching a build by hostname is a plausible thing for Ken to do, but it has not been observed.
