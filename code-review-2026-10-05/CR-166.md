# CR-166: Back from a 'question that came up in a conversation' skips the list it was opened from

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:260`
- **Also affects:** `app/js/worldview-ui.js:236 (renderExtras list rows open renderExtra)`; `app/js/worldview-ui.js:205 (home rows also open renderExtra)`; `app/js/worldview-ui.js:305 (Delete this question -> renderHome)`
- **Source:** g-visual-consistency-05

**What a user notices.** After opening one of the 'questions that came up in conversations' from its list, tapping Back jumps all the way to the start of About Me, so the person has to find the list again to answer the next one.

**What is wrong.** renderExtra(name) is reached from two places: the home screen's 'Questions worth answering' rows (line 205) and the 'Questions that came up in conversations' list (renderExtras, line 236). Its back link is hard-wired to renderHome, and so is the post-Delete navigation, so from the list the user is sent past the list to the home screen. Working through several raised questions therefore costs an extra navigation each time.

**Evidence.**

```
app/js/worldview-ui.js:236  contentEl.append(el('button', { class: 'wv-module-row', onclick: () => renderExtra(e.name) }, [
app/js/worldview-ui.js:253  function renderExtra(name) {
app/js/worldview-ui.js:260  contentEl.append(el('button', { class: 'wv-back', text: '‹ Back', onclick: renderHome }));
app/js/worldview-ui.js:305  await wv.removeExtra(name);
            renderHome();
```

**How it happens.** About Me > Other things about me > 'Questions that came up in conversations' > tap a question > tap '‹ Back': the About Me home appears instead of the list.

**Suggested fix.** Give renderExtra a second parameter for its origin: `function renderExtra(name, back = renderHome)`. Call it as `renderExtra(e.name, renderExtras)` at line 236 and leave line 205 as is. Use `back` for the .wv-back onclick (label '‹ Other things about me' when back === renderExtras, else the common About Me label) and after Delete (line 305). Also pass `back` through the internal re-renders at lines 276 and 293 (`renderExtra(name, back)`) so it is not lost after Undo / Prefer not to say.

**How to verify the fix.** Manual: open a raised question from the list, tap Back -> the list; open one from the home 'Questions worth answering' -> Back returns home; Delete from the list -> the list. Requires at least one raised question (add one via worldview.recordExtraGaps in the console, or the test data folder).

**Do not break.** Keep the confirmDanger on Delete. Do not change renderHome.

**Design reference.** none

**Verification notes.** renderExtras (line 236) opens renderExtra(e.name), but renderExtra's back button (line 260) and its post-Delete navigation (line 305) both go to renderHome, so the list is skipped. The internal re-renders at lines 276 and 293 call renderExtra(name) with no origin, so the fix must carry the origin through them, as the reviewer notes.
