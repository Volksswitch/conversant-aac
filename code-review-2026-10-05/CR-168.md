# CR-168: Picking 'Other…' in the relationship list immediately erases the saved relationship

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:1212`
- **Also affects:** `app/js/worldview-ui.js:1135 (getRelationship returns the empty Other box)`; `app/js/relationships.js:231-245 (empty relationship deletes or blanks the edge)`
- **Source:** worldview-06

**What a user notices.** If a user opens the relationship list on someone they already labeled (say 'Doctor') and picks 'Other…', the old relationship is deleted right away, before they type anything; if they then leave the page, the person has no relationship at all.

**What is wrong.** relSelect's change listener runs commitNow. When the value becomes OTHER, getRelationship() returns otherIn.value.trim(), which is '' because the Other box is hidden/empty for a known relationship. commitNow then calls updatePerson with relationship '', which deletes the me->person edge (or empties its type). The same happens if the user picks 'Other…' by mistake and picks the original again only after leaving.

**Evidence.**

```
app/js/worldview-ui.js:1135: const getRelationship = () => (relSelect.value === OTHER ? otherIn.value.trim() : relSelect.value);
app/js/worldview-ui.js:1212: for (const c of [relSelect, livesCheck, privCheck]) c.addEventListener('change', commitNow);
app/js/relationships.js:241-242: else if (Object.keys(edge.attrs || {}).length) edge.type = '';
            else g.edges = g.edges.filter((e) => e !== edge);
```

**How it happens.** Edit a person whose relationship is 'Doctor'. Choose 'Other…' from the list. Tap '‹ All topics'. Reopen People: the card shows no relationship.

**Suggested fix.** In commitNow, when `relSelect.value === OTHER && !otherIn.value.trim()`, omit `relationship` from the updatePerson payload (pass undefined) so the existing relationship is kept until something is typed. Example: `const relationship = getRelationship(); const relArg = (relSelect.value === OTHER && !relationship) ? undefined : relationship;` and use `relationship: relArg`, adjusting the early-return guard to use `relationship || ''`.

**How to verify the fix.** Manual: the scenario above must leave 'Doctor' in place; typing 'Specialist' into the Other box and leaving the field must then save 'Specialist'.

**Do not break.** Choosing the blank 'Relationship…' option must still clear the relationship deliberately.

**Design reference.** CLAUDE.md Relationship Data section; 'A LIST THAT SHOWS AN ITEM AS ADDED HAS PROMISED IT IS SAVED'.

**Verification notes.** relSelect's change event calls commitNow. getRelationship() returns otherIn.value.trim(), and for a person whose relationship is a known type otherIn is empty. Because the name is non-empty, the guard passes, and updatePerson receives relationship ''. relationships.js:233-243 then deletes the me->person edge, or blanks its type if the edge has attrs. The saved relationship is erased the moment 'Other…' is chosen.
