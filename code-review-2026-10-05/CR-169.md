# CR-169: Pausing and resuming the practice partner throws away the line it already spoke

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2733`
- **Also affects:** `app/js/app.js:2602-2629`; `app/js/app.js:1251-1267`
- **Source:** app-c-04

**What a user notices.** In practice, after the pretend partner speaks and the cards appear, tapping Listen twice (stop, then start) makes the partner say a brand-new line as if the first was never said; the first line vanishes from the saved conversation and the AI partner no longer knows it said it.

**What is wrong.** In practice, advancePracticePartner sets isListening=true and leaves it true until the user responds, so the Listen button stays lit while the user reads the cards. Tapping it takes togglePracticeCue's pause branch; tapping again calls advancePracticePartner(), which asks for a NEW partner line using conversationHistory - which does not yet contain the uncommitted partner line (it lives only in currentPartnerText). handleSilencePeriod(newLine) then overwrites currentPartnerText and calls storage.logPartnerInterim, overwriting the pending partner entry's rawTranscript, so the first spoken line is lost from the record and from the AI's context, and the cards are regenerated against the new line only. This contradicts the decided real-conversation rule that a Listen stop/start mid-turn is a PAUSE that keeps what the partner said.

**How it happens.** 1) Start any practice scenario, tap Start Listening; the partner speaks 'Hi, what can I get you?' and cards appear (Listen still lit). 2) Tap Listen (Paused). 3) Tap Listen again: a different partner line is spoken; open the saved conversation JSON - the pending partner turn's rawTranscript now holds only the second line.

> **Verifier correction to the trigger:** The first line is not entirely gone from the saved JSON: it remains in the pending partner turn's revisions array; rawTranscript holds only the second line, and the AI partner's history never contains the first line.

**Suggested fix.** In advancePracticePartner, when an uncommitted partner line already exists, continue that turn instead of replacing it: before the LLM call capture `const prior = currentPartnerText;` and pass history `prior ? [...conversationHistory, { role: 'partner', text: prior }] : conversationHistory`; after speaking, feed `await handleSilencePeriod(prior ? `${prior} ${line}` : line);` so the pending entry accumulates (mirrors the real pause rule). Alternatively, if Ken prefers, make the resume a no-op that re-shows the existing turn - but do not overwrite.

**How to verify the fix.** Manual steps above: after the fix the pending partner entry contains both lines in order and the second generation request's messages include the first line. A unit test is not practical (app.js); add a source guard in tests/placeholders.test.mjs that advancePracticePartner references currentPartnerText when building history.

**Do not break.** Practice must still never open a real microphone. Do not change the real-mic pause path (resumePartnerCapture).
