# CR-170: Learned word-prediction vocabulary is not in the backup, despite 'everything travels'

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/data-transfer.js:101`
- **Also affects:** `app/js/prediction.js:24 (FREQ_KEY = 'aac_word_freq')`
- **Source:** review-backup-14

**What a user notices.** After moving to a new device, or switching an iPad between the browser and the Home Screen app, word prediction forgets the words the person uses most and starts over.

**What is wrong.** The header says 'WHAT TRAVELS: everything'. The personalized word-frequency store (localStorage 'aac_word_freq', built from the user's own typing) is user-owned data but is not in DATA_FILES, so an export/import loses it. On the iPad the two modes are separate storage silos and Export/Import is the documented bridge, so the learned vocabulary is always lost there.

**Evidence.**

```
data-transfer.js:101-110 DATA_FILES lists worldview, relationships, places, practice-scenarios, control-phrases, placeholders, express-panel, voice - no word frequencies.
prediction.js:24 const FREQ_KEY = 'aac_word_freq';
```

**How it happens.** iPad: type for weeks in a Safari tab, Export, Import into the Home Screen app: completions no longer prefer the user's own words.

**Suggested fix.** Add a top-level `wordFreq` field in buildPackage (read via a new prediction.js export, e.g. `exportFrequencies()` returning the parsed object) and restore it in applyPackage via `importFrequencies(obj)` with a plain-object type check; add a line to summarize() when present. Keep the package version at 3 (absent field = nothing to restore).

**How to verify the fix.** Unit test: buildPackage includes wordFreq when aac_word_freq is set; applyPackage writes it back.

**Do not break.** Counts only - no sentences - so no new privacy exposure; keep it out of any weekly report.

**Design reference.** CLAUDE.md 'Word prediction - local tiers' (aac_word_freq); data-transfer.js header

**Verification notes.** DATA_FILES (data-transfer.js 101-110) and buildPackage include no word frequencies; prediction.js keeps them only in localStorage 'aac_word_freq'. The data-transfer.js header says 'WHAT TRAVELS: everything'. CLAUDE.md records that moving the counts into the data folder is a future extension, but nothing records leaving them out of the backup as a decision, and TODO.md does not track it. On the iPad, Export/Import is the only bridge between the two storage silos, so the learned vocabulary is always lost there.
