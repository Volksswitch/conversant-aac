# CR-171: Cancel on the new-scenario form throws away everything typed without asking

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/practice-editor.js:300`
- **Also affects:** `app/js/confirm-dialog.js`
- **Source:** phrases-practice-11

**What a user notices.** A user who has typed a long description of a practice partner and taps Cancel (perhaps by mistake, next to Add scenario) loses all of it instantly.

**What is wrong.** In create mode the form ends in 'Add scenario' and 'Cancel' side by side; Cancel calls goTo({ mode: 'list' }) unconditionally, discarding the draft. Typing a persona and details on an on-screen keyboard is significant work for this population, and the standing rule requires a confirmation (confirmDanger) before destroying significant work.

**Evidence.**

```
practice-editor.js:300 `button('Cancel', () => goTo({ mode: 'list' })),`
```

**How it happens.** Fill it in yourself > type a persona and details > tap Cancel: the list shows and the typed text is gone.

**Suggested fix.** In the Cancel handler, if any of title/partnerPersona/details/description/behaviorText in the draft is non-blank, `if (!(await confirmDanger({ title: 'Discard this scenario?', body: 'What you have typed will be lost.', confirmLabel: 'Discard', cancelLabel: 'Keep editing' }))) return;` before goTo.

**How to verify the fix.** Manual: type into the create form, tap Cancel, choose Keep editing (text remains), then Discard (returns to list). With an empty form, Cancel goes straight back.

**Do not break.** Use confirmDanger, never window.confirm.

**Design reference.** CLAUDE.md Configurability philosophy: 'Confirm before destroying significant work' and the confirmDanger rule.

**Verification notes.** practice-editor.js:300 is `button('Cancel', () => goTo({ mode: 'list' }))`, with no confirmation, so a typed persona and details are discarded. CLAUDE.md's standing rule 'Confirm before destroying significant work' (use confirmDanger) applies. No recorded decision exempts this form.
