# CR-172: Review saves fail silently - a failed review write is never logged or shown

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:468`
- **Also affects:** `app/js/storage.js:1035-1048 (writeReview returns false, never throws)`
- **Source:** review-backup-08

**What a user notices.** If the device cannot write the review (for example the folder became unavailable), everything the person marked is lost without any sign.

**What is wrong.** writeNow() ignores the boolean that storage.writeReview returns; writeReview swallows every exception and returns false. There is no logError, no red wash and no status. The design promises 'the app stores what they write as they write it, so there is nothing to save', so a silent failure is the one outcome the user has no way to detect.

**Evidence.**

```
review-ui.js:468-472
async function writeNow() {
    if (!conv || !review) return;
    const out = { ...review, updated: new Date().toISOString() };
    await storage.writeReview(conv.id, out);
}
storage.js:1045-1047
    } catch {
        return false;
    }
```

**How it happens.** Windows, data folder on OneDrive, file locked during the write: answers made in review are not saved; nothing is logged.

**Suggested fix.** In writeNow: `const ok = await storage.writeReview(conv.id, out); if (!ok) storage.logError('review save', 'could not write the review for ' + conv.id);` (logError already drives the faint red transcript wash).

**How to verify the fix.** Unit test: shim writeReview to return false and assert logError was called (or a source-level guard test).

**Do not break.** logError must not include the review text (it can contain the user's private sentences and a partner's words).

**Design reference.** Conversant AAC Conversation Review.docx §5; CLAUDE.md error-log rules

**Verification notes.** writeNow() (review-ui.js ~468) awaits storage.writeReview and ignores its boolean; writeReview (storage.js ~1036-1048) returns false on no conversations dir or on any exception and never logs. Nothing else reports the failure, so a failed review save is silent. The suggested fix (logError on false, without the review text) is right.
