# CR-174: 'Change my answer' in How I Sound deletes the answer at once instead of on re-answer

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:527`
- **Also affects:** `app/js/voice.js:140-144 (clearAnswer deletes and saves immediately)`
- **Source:** worldview-09

**What a user notices.** Tapping 'Change my answer' on a How I Sound question erases the earlier choice immediately; if the user then leaves without picking again, their answer is gone.

**What is wrong.** The code comment says 'Re-answering simply overwrites, so there is no destructive step and no confirmation needed', but the button calls voiceProfile.clearAnswer(item.id), which deletes and saves before any new choice is made. Leaving the page, or an accidental tap, loses the answer, and the voice exemplars derived from it.

**Evidence.**

```
app/js/worldview-ui.js:520-528:
    // Answered: show what they picked and let them redo it. Re-answering simply
    // overwrites, so there is no destructive step and no confirmation needed.
    ...
    el('button', { class: 'wv-btn wv-btn-link', text: 'Change my answer',
        onclick: () => { voiceProfile.clearAnswer(item.id); refreshSoundCheckCard(item); } })
app/js/voice.js:140-143: export function clearAnswer(itemId) { const p = current(); delete p.soundCheck[itemId]; return save(); }
```

**How it happens.** Answer a How I Sound item, tap 'Change my answer', then tap '‹ All topics'. The item shows as unanswered and the count drops.

**Suggested fix.** Do not clear on 'Change my answer'. Add a `forceEdit` parameter: `buildSoundCheckCard(item, { editing: true })` renders the candidate list even when an answer is saved (skipping the `if (saved)` early return), with the saved choice highlighted; recordAnswer then overwrites. The button becomes `onclick: () => { const old = document.getElementById('sc-' + item.id); old.replaceWith(buildSoundCheckCard(item, { editing: true })); }`.

**How to verify the fix.** Manual: tap 'Change my answer' then leave; the earlier answer must still be shown when returning. Picking a new candidate must replace it.

**Do not break.** Keep the in-place card replacement (scroll position) behavior.

**Design reference.** CLAUDE.md Sounds Like Me plan (Sound Check forced-choice); standing rule on revertibility.

**Verification notes.** The 'Change my answer' onclick calls voiceProfile.clearAnswer(item.id), and voice.js:140-143 deletes the answer and saves immediately, before any new pick. Leaving the page loses the answer. The code comment ('Re-answering simply overwrites, so there is no destructive step') does not match the code.
