Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** dead-code
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:2962`
- **Also affects:** `app/css/styles.css:2962-3006 (#engineDetails, #enginePanel, .engine-row/.engine-label/.engine-val.*, floor-*)`; `app/css/styles.css:3008-3064 (#overrideControls, .persist-btn, #sessionControls, .session-btn, .session-btn-end) and 5145, 5183-5188 in the hover block`; `app/css/styles.css:3067 (.composer-panel)`; `app/css/styles.css:2105-2122 (.response-card-top, .response-latency, .latency-*)`; `app/css/styles.css:2852-2854, 2870-2882, 2886-2888, 2904-2918, 2929-2938 (.ee-prompt, .ee-card-*, .ee-badge*, .ee-empty-label, .ee-fields, .ee-done, .ee-swatch*)`; `app/css/styles.css:2781, 2812 (#settingsContent .ee-row .ee-swatch, .ee-fields input)`; `app/css/styles.css:4414-4421 (.wv-flash)`; `app/css/styles.css:1546-1560 (.mode-chip/.chip-*; ui.js looks up #modeChip, which is not in index.html)`
- **Source:** css-11

**What a user notices.** None directly; it makes the stylesheet harder to maintain and misleads anyone reasoning about which rules are live (CLAUDE.md still describes the mode chip as a live white-on-slot-colour pair).

**What is wrong.** A scan of every #id and .class selector against index.html and all app/js files (allowing for classes built by string concatenation such as 'ep-band-' + band, 'kbd-' + action, 'review-progress-' + state) found these selectors match nothing: the removed engine diagnostics panel, the pre-Command-Bar override and session rows, the old composer panel, the latency dot, the Express card editor's badges/swatches/fields/prompt, and the wv-flash animation. ui.js also renders a mode chip into #modeChip, which no longer exists, so .mode-chip/.chip-* never apply. Several comments elsewhere (e.g. 'the mode chip puts white on three of the other slot colours', styles.css:42-44) are therefore describing a dead element.

**Evidence.**

```
No match in index.html or app/js/*.js for: engineDetails, enginePanel, engine-row, engine-label, overrideControls, persist-btn, sessionControls, session-btn, composer-panel, response-card-top, response-latency, latency-instant, latency-roundtrip, ee-badge, ee-card-head, ee-card-pos, ee-empty-label, ee-fields, ee-prompt, ee-done, ee-swatch, wv-flash, modeChip (in index.html).
```

**How it happens.** An engineer changes .persist-btn or .chip-standby expecting a visible effect and sees none; a contrast audit counts the mode chip as live.

**Suggested fix.** Delete the listed rule blocks (including their entries inside the @media (hover: hover) block at 5145 and 5183-5188). Before deleting .mode-chip/.chip-*, confirm with the owner whether the mode chip is meant to return; if not, also remove renderModeChip/modeChip from ui.js and correct the 'mode chip' mentions in the --slot-dispreferred comment and in CLAUDE.md Rule on badges.

**How to verify the fix.** After deleting, run npm test (tests/styles.test.mjs, tests/theme.test.mjs) and open the app: conversation screen, every Settings tab, Express editor, About Me - no visual change.

**Do not break.** Do not delete rules for classes built dynamically (ep-band-*, kbd-shift/backspace/enter/page/space/blank, review-progress-*, floor-* only belongs to the dead engine panel). Keep .ep-cell-blank and .ep-undefined.

**Design reference.** none

**Verification notes.** A grep of index.html and app/js/*.js finds no reference to engineDetails, enginePanel, engine-row, engine-label, overrideControls, persist-btn, sessionControls, session-btn, composer-panel, response-card-top, response-latency, latency-*, ee-badge, ee-card-head, ee-card-pos, ee-empty-label, ee-fields, ee-prompt, ee-done, ee-swatch or wv-flash. ui.js still references #modeChip (line 13) and the engineEls diagnostic elements (973+), but neither exists in index.html, so renderModeChip and showEngineState return early and the mode-chip and engine-val/floor-* rules never apply. The CLAUDE.md note that the mode chip is a live white-on-slot pair is therefore stale.
