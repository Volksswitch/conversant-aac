# CR-176: windDownShown is written but never read

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** dead-code
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:2870`
- **Also affects:** `app/js/app.js:3089`; `app/js/app.js:3618`
- **Source:** g-app-flow-overflow-07

**What a user notices.** None. It is leftover bookkeeping that suggests behavior the app no longer has.

**What is wrong.** `windDownShown` ('has Wrap up been shown this conversation?') is declared at 2870, set to false in resetStaticPaging (3089) and true in handleWindDown (3618), and read nowhere in app/, tests/ or scripts/ (verified with grep). It survives from the time a second Wrap up press paged the wind-downs; since the August 26 2026 toggle change that decision is taken by paletteOverlay, so the flag is dead and misleads a reader into thinking first-versus-repeat presses are still distinguished.

**Evidence.**

```
grep for windDownShown across app/, tests/, scripts/ returns only: app/js/app.js:2870 `let windDownShown = false;`, app/js/app.js:3089 `windDownShown = false;`, app/js/app.js:3618 `windDownShown = true;`.
```

**How it happens.** Not a runtime failure; a future change could wire behavior to a flag that no longer reflects the toggle model.

**Suggested fix.** Delete the declaration at app.js:2870 and the two assignments at 3089 and 3618.

**How to verify the fix.** npm test passes; grep -rn windDownShown app/ returns nothing; Wrap up press/cancel still works in the browser.

**Do not break.** none

**Design reference.** CLAUDE.md 'Wrap up and Start conversation are TOGGLES — no Command Bar button is a dead end' (paging moved to New N).

**Verification notes.** grep over app/, tests/ and scripts/ finds only the declaration (app.js:2870) and two writes (3089 in resetStaticPaging, 3618 in handleWindDown); nothing reads it. The toggle decision is taken by paletteOverlay in handleWindDown (3602).
