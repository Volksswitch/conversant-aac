# CR-177: Dead toolbar/Hide code and comments still describe a keyboard Hide button that no longer exists

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** dead-code
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/keyboard.js:279`
- **Also affects:** `app/js/keyboard.js:239`; `app/js/keyboard.js:245`; `app/js/keyboard.js:259`; `app/js/keyboard.js:272`; `app/js/keyboard.js:495`; `app/js/keyboard.js:657`; `app/js/keyboard.js:840`; `app/js/keyboard.js:876`; `app/js/prediction.js:27`; `app/js/app.js:5731`
- **Source:** keyboard-10

**What a user notices.** None directly; the code and comments promise a way to dismiss the keyboard that the person does not actually have, which misleads anyone fixing keyboard problems.

**What is wrong.** The Cut/Copy/Paste/Hide toolbar was removed (keyboard.js build() comment), but handleTool(), dismiss(), suppressNextClick(), selectedText(), deleteSelection(), the `.kbd-tool` branch in the pointerdown handler, the `kbd-no-hide` class toggles, and the unused exports previewHide() and currentPage() remain. prediction.js builds a `rank` Map that nothing reads (and words.json has 13 duplicate entries that make it inconsistent). app.js and keyboard.js comments say 'The keyboard's own Hide icon remains the manual override' / 'the Hide button take it down' - there is no such icon.

**Evidence.**

```
keyboard.js:502-507 'Cut / Copy / Paste toolbar REMOVED (Ken, June 29 2026)'; keyboard.js:494-495 `const tool = e.target.closest('.kbd-tool'); if (tool) { ...handleTool(...) }`; keyboard.js:657 `rootEl.classList.toggle('kbd-no-hide', field.id === 'composerInput');`; app.js:5731 'The keyboard's own Hide icon remains the manual override'; prediction.js:27,47 `let rank = new Map(); ... rank = new Map(words.map((w, i) => [w, i]));` (never read).
```

**How it happens.** A developer investigating 'the keyboard won't go away on the Express tab' trusts the comment that a Hide icon exists and looks for it.

**Suggested fix.** Delete handleTool, dismiss, suppressNextClick, selectedText, deleteSelection, the `.kbd-tool` branch, the two `kbd-no-hide` toggles, previewHide and currentPage (confirm no callers with grep first - none found), and prediction.js `rank`. Correct the app.js:5731 and keyboard.js focusout comments to say the keyboard is dismissed by closing the section/panel or leaving the field. Optionally dedupe app/data/words.json.

> **Verifier correction to the fix (takes precedence):** Before deleting selectedText and deleteSelection, check with grep that nothing other than handleTool calls them. Keep the `.kbd-tool` text in the styles.css :not() selector or remove it at the same time; either is harmless.

**How to verify the fix.** npm test passes; grep for the removed names returns nothing; manual smoke test of composer, About Me and Express tab keyboard behaviour.

**Do not break.** Keep the `.kbd-tool` selector in styles.css if anything else uses it (it is only in a :not() list, harmless). Do not remove hideKeyboard/previewShow/showFor/setEnterAction/setHideOnBlur - they are used.

**Design reference.** keyboard.js build() comment (toolbar removed)

**Verification notes.** build() no longer creates any .kbd-tool element (the toolbar-removed comment), yet the pointerdown branch for '.kbd-tool', handleTool, dismiss and suppressNextClick remain. The kbd-no-hide toggles at 657 and 830 target a Hide button that does not exist. previewHide and currentPage are exported and grep finds no callers outside keyboard.js. prediction.js builds `rank` and never reads it. The app.js comment near 5731 ('The keyboard's own Hide icon remains the manual override') describes a control that is gone.
