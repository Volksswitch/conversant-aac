# CR-179: Dead mode-chip and diagnostic engine-panel code in ui.js targets elements that no longer exist

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** dead-code
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/ui.js:13`
- **Also affects:** `app/js/ui.js:93`; `app/js/ui.js:102`; `app/js/ui.js:973`; `app/js/ui.js:993`; `app/js/ui.js:1116`
- **Source:** ui-shell-12

**What a user notices.** None directly; it makes the code suggest that a 'mode' label is shown to the user when it is not.

**What is wrong.** #modeChip and the #engineMode/#engineFloor/#enginePhase/#engineAction/#engineTurnStatus/#engineRepair/#engineStack/#engineLastUser/#engineCapture elements were removed from index.html in v0.5.13 (git log -S), but ui.js still defines MODE_CHIP, renderModeChip, renderModeCell, the engineEls map and the capture row update, all of which silently no-op. index.html:46-48 still describes 'the mode chip' in the transcript region.

**Evidence.**

```
ui.js:13  const modeChip = document.getElementById('modeChip');   // null
ui.js:103  if (!modeChip || !lastSnap) return;
ui.js:974  mode: document.getElementById('engineMode'),   // null
```

**How it happens.** Read ui.js expecting the mode chip to render; nothing is drawn.

**Suggested fix.** Remove MODE_CHIP, renderModeChip, renderModeCell, engineEls and the #engineCapture block from ui.js (keep lastSnap/capturing only if still used by setListenButtonState's chime edge), drop the related .mode-chip/.engine-val CSS, and update the index.html comment at lines 46-48. Alternatively leave as is if the chip is planned to return.

**How to verify the fix.** npm test passes; the app boots with no console errors.

**Do not break.** setListenButtonState uses `capturing` for the false->true chime edge - keep that variable.

**Design reference.** none

**Verification notes.** There are no #modeChip or #engine* elements in index.html (grep finds them only in ui.js), so modeChip is null and renderModeChip returns early at ui.js:103. engineEls (ui.js:974) and the #engineCapture update (ui.js:1116) resolve to null and no-op. The index.html comment at lines 46-48 still mentions 'the mode chip'. This is dead code only, with no user-facing effect.
