# CR-180: Read-only report views on Troubleshooting use three typefaces and three sizes, contrary to §13

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:1924`
- **Also affects:** `app/css/styles.css:1908-1920 (#errorLogView ui-monospace 0.78rem)`; `app/index.html:1205, 1207 (#weeklyReportContents, #weeklySendLogView — no font rule)`
- **Source:** live-visual-09

**What a user notices.** The five read-only boxes on the Troubleshooting tab look like they belong to different apps: two are in ordinary text, two in one fixed-width font and one in another, all at different sizes.

**What is wrong.** UI-Design §13 'Read-only report view — Monospace, one size for all of them, scrolling.' Measured: #weeklyReportContents and #weeklySendLogView are system-ui 14.6px (no rule); #usageSummaryView and #systemInfoView are Consolas 0.85em (12.4px); #errorLogView is ui-monospace 0.78rem (11.4px).

**Evidence.**

```
app/css/styles.css:1924: #usageSummaryView, #systemInfoView { font-family: Consolas, 'Courier New', monospace; font-size: 0.85em; white-space: pre; }
app/css/styles.css:1910-1911: font-family: ui-monospace, "Cascadia Code", Consolas, monospace; font-size: 0.78rem;
```

**How it happens.** Settings > Troubleshooting: open Weekly reports, How the app is being used, Error log and System information in turn and compare the boxes.

**Suggested fix.** Give all five one shared rule, e.g. a class .report-view (or a selector list #weeklyReportContents, #weeklySendLogView, #usageSummaryView, #systemInfoView, #errorLogView) with font-family: ui-monospace, "Cascadia Code", Consolas, monospace; font-size: 0.85rem; and the same background/color/border as #errorLogView. Keep white-space: pre only on the column-aligned ones (usage summary, system info, error log); pre-wrap on the weekly report description.

**How to verify the fix.** Browser check: the five textareas report identical fontFamily and fontSize. Visually confirm the usage summary columns still align.

**Do not break.** The usage-summary columns rely on a monospace face (recorded Aug 7 2026).

**Design reference.** UI-Design.docx §13 'Read-only report view'.

**Verification notes.** #errorLogView uses ui-monospace at 0.78rem (1910-1911). #usageSummaryView and #systemInfoView use Consolas at 0.85em (1924). #weeklyReportContents and #weeklySendLogView (index.html:1205-1207) have no font rule, so they inherit the dialog's system-ui. UI-Design §13 'Read-only report view' says 'Monospace, one size for all of them, scrolling.'
