# CR-181: Confirmation dialog has no themed background (uses the browser's Canvas color)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:4524`
- **Also affects:** `app/js/confirm-dialog.js:34-38`; `app/js/confirm-dialog.js:118-119`
- **Source:** css-05

**What a user notices.** In the dark, high-contrast dark and yellow-on-black color schemes, the red confirmation card and the progress card are drawn in the browser's own dark grey rather than the scheme's colors, so they look out of place and their contrast is not the one the scheme was tested for.

**What is wrong.** `.danger-dialog` (used for every confirmDanger card and the neutral busy card) sets border, padding, sizes and a shadow but no `background` or `color`, so the dialog takes the UA default `Canvas`/`CanvasText`, which follows `color-scheme` but not the palette (e.g. Chrome's #121212 in the yellow scheme, whose surfaces are #000000). This is the same class of fault Rule 23 records for buttons that declared no background. #settingsDialog sets `background: var(--surface-raised)`; this dialog does not.

**Evidence.**

```
styles.css:4524-4549 `.danger-dialog { position: fixed; inset: var(--app-margin); margin: auto; border: none; border-top: 6px solid var(--danger); border-radius: 10px; padding: 1.5rem; max-width: 26rem; width: fit-content; height: fit-content; ... box-shadow: 0 12px 40px var(--backdrop); font-family: inherit; }` (no background/color)
```

**How it happens.** Settings > Text & Color > Yellow on black. Settings > About > delete a settings profile: the confirmation card body is dark grey, not black, and untinted text inside it is white rather than yellow.

**Suggested fix.** Add `background: var(--surface-raised); color: var(--ink);` to the `.danger-dialog` rule.

**How to verify the fix.** Run scripts/capture-color-schemes.mjs or manually open a confirmation in each of the seven schemes; the card matches the Settings panel's surface. tests/theme.test.mjs continues to pass.

**Do not break.** Do not add a `display` value to this base selector (it would override the UA's dialog:not([open]) rule - see the comment above it).

**Design reference.** CLAUDE.md UI Layout Rule 23 (every colour named for its job; a control that declares no background takes the browser's)

**Verification notes.** .danger-dialog (styles.css:4524-4549) sets no background or color, and the generic dialog rule (3134) sets only border, padding, inset and margin. So the card takes the UA Canvas/CanvasText colors, which follow color-scheme but not the palette. #settingsDialog sets background: var(--surface-raised); this dialog does not. confirm-dialog.js:38 and 119 use the class for both the danger and the neutral busy card.
