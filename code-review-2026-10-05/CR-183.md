# CR-183: Partner resuming does not stop an in-flight generation from restarting the placeholder ladder

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1243`
- **Also affects:** `app/js/app.js:1904-1908`; `app/js/app.js:180-184`; `app/js/placeholders.js:233-243`
- **Source:** app-a-04

**What a user notices.** After the other person starts talking again, the app can still say a 'thinking' phrase a couple of seconds later that is not tied to a real pause, sometimes while they are mid-sentence.

**What is wrong.** handlePartnerResumed calls placeholders.stop() but does not bump placeholderEpoch (abortPlaceholders() does both). The generation started at the previous silence checkpoint keeps running; its generationToken is still current until the next checkpoint. When it returns, `pEpoch === placeholderEpoch` is still true, so it calls placeholders.start(). Because stop() set active=false and armed=false, start() takes its 'defensive' path and schedules a fresh placeholder initialDelay after NOW rather than after a pause. CLAUDE.md requires that the partner resuming 'aborts and resets the ladder' and that a placeholder only speaks after real silence; the next checkpoint is meant to be the only thing that re-arms it. It bites when no further recognizer result arrives within the initial delay while the partner is still speaking or briefly hesitating below the silence threshold (long silence settings, slow-delivering backends).

**Evidence.**

**How it happens.** Silence period set to 3 s. Partner says 'Do you want coffee' and pauses: checkpoint -> arm() + generation. At +1 s the partner resumes with one word ('or...') and then hesitates for 2.5 s (under the 3 s threshold, so no new checkpoint). The generation returns at +3 s -> start() -> defensive path schedules a placeholder at +5 s, which plays during the partner's hesitation, from a ladder no pause armed.

> **Verifier correction to the trigger:** Requires a silence period longer than the placeholder initial delay (defaults 0.5 s and 2 s make it unreachable), the generation returning after the partner resumed and before the next checkpoint, and the partner then producing no recognizer result for at least the initial delay.

**Suggested fix.** In handlePartnerResumed replace `placeholders.stop();` with `abortPlaceholders();` so the in-flight generation sees a changed epoch and calls placeholders.stop() instead of start(). The next silence checkpoint's arm() re-arms the ladder as designed.

**How to verify the fix.** Source-level guard in tests/placeholders.test.mjs (where app.js guards already live): assert the body of handlePartnerResumed calls abortPlaceholders (strip comments first, per CLAUDE.md). Manual: Practice Mode cannot exercise resume; with the mic, set silence to 3 s, reproduce the scenario and confirm no placeholder before the next pause.

**Do not break.** Do not bump generationToken here - the in-flight response options must still be shown. Keep the repair-initiator and user-speaking gates unchanged.

**Design reference.** CLAUDE.md 'No turn-completion gate' (partner resuming aborts and resets the ladder) and 'Placeholders are gated by PARTNER SILENCE'

**Verification notes.** Traced: handlePartnerResumed (app.js:1236-1244) calls placeholders.stop() only, which sets active=false and armed=false but leaves placeholderEpoch unchanged. The generation started at the previous checkpoint still holds the current generationToken until the next checkpoint, so on return pEpoch === placeholderEpoch and it calls placeholders.start() (app.js:1904-1905). start() is not active, so it takes the defensive path (placeholders.js:233-243) with base = Date.now() and schedules a placeholder initialDelay from the generation's return rather than from a pause. Every further non-echo result calls handlePartnerResumed again and cancels it, and a new checkpoint re-arms from its own pause, so at the shipped defaults (0.5 s silence, 2 s initial delay) the stray schedule is always cancelled or superseded. It only speaks when the partner leaves a gap longer than the initial delay but shorter than the silence period, i.e. only with a silence setting above roughly 2 s. Real but narrow; the reviewer's low severity is right.
