# CR-184: With no AI key set, every pause logs an error, keeps the transcript red and shows an error box

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1267`
- **Also affects:** `app/js/app.js:1944 storage.logError('generateOptions', ...)`; `app/js/app.js:1959 ui.showResponseError`; `app/js/llm.js:457`
- **Source:** app-b-11

**What a user notices.** Someone using the app without an AI key (a supported way to use it) sees the transcript tinted red as if something were broken after every sentence the other person says, and their error log fills with the same entry.

**What is wrong.** handleSilencePeriod always calls generateOptions, which always calls llm.generateResponses, which throws 'API key not set' when no key is configured. The catch logs an error (tripping the red wash, which is sticky until a successful render — and with no key there never is one), and shows the 'AI is unavailable' box. The no-key configuration is documented as a legitimate manual-AAC mode, and the codebase elsewhere treats a false alarm on the red wash as worse than none (withTimeout comment).

**Evidence.**

```
app/js/app.js:1267 `await generateOptions(text);` (no key check)
app/js/llm.js:457 `if (!apiKey) throw new Error('API key not set');`
app/js/app.js:1944 `storage.logError('generateOptions', err.message, {...})`
app/js/app.js:1376-1379 comment: 'A false alarm on that signal is worse than no signal'
```

**How it happens.** Skip the API key notice, Start, tap Listen, let the partner speak several sentences: one 'API key not set' error per pause, permanent red wash, error box in the response region.

**Suggested fix.** At the top of generateOptions (after the closing fast path), if `!(storage.loadApiKey() || '').trim()`, skip the AI: set `ui.setPaletteBusy(false)`, `ui.setTranscriptState('uncleaned')` (raw words shown), leave the reserved empty cards, set a status like 'No AI key — reply with the Express Panel or In my own words', do NOT log an error, and return. Leave placeholders running (see the placeholder finding).

**How to verify the fix.** Manual: clear the key, run a short conversation, confirm no red wash, no new error log entries, Express replies still commit and save.

**Do not break.** This overlaps the open CLAUDE.md question on the amber error box; do not remove showResponseError for real failures, only stop treating the no-key configuration as a failure.

**Design reference.** CLAUDE.md 'AI is an enhancement layer, not a hard dependency'; 'API-key feedback' (the pre-start prompt is informational, not blocking).

**Verification notes.** No key check exists before generation: handleSilencePeriod always calls generateOptions, llm.generateResponses throws 'API key not set' (llm.js:457), and the catch logs via storage.logError (red wash, sticky until a successful showResponses, which never happens without a key) and calls ui.showResponseError. No-key use is documented as a supported manual-AAC mode. Not in TODO.md; the related CLAUDE.md open question on the amber box is about removing it for real failures, not about the no-key configuration.
