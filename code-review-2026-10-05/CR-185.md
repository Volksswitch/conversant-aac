# CR-185: A switched-on partner, place or feeling disappears while its band is paged

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:4101`
- **Also affects:** `app/js/express-bands.js:244 (litFirst puts lit items at index 0)`; `app/js/express-bands.js:308-309 (band page shows L[page*per ...])`; `app/js/express-bands.js:319-330 (whole-panel scope overwrites every cell)`
- **Source:** app-d-11

**What a user notices.** While the person is looking at the second set of a band through More, the button that is currently switched on is not on screen, so nothing shows that it is still steering the suggestions.

**What is wrong.** composedPanel passes litIds so lit buttons go to the front of their band, which keeps them on page 0 only. On page >= 1 of the same band (band scope) the window starts at page*per, so the lit item is hidden; with the whole-panel scope every cell except More is replaced by the paged band, hiding lit Context buttons and goals in other bands too. The recorded decision is that a switched-on button ALWAYS shows, because otherwise it steers the AI with nothing on screen saying so.

**Evidence.**

```
app/js/app.js:4099-4106 (litIds passed)
app/js/express-bands.js:308-309
  const start = scope === 'band' ? page * per : 0;
  for (let k = 0; k < per; k++) items[P[k]] = L[start + k];
```

**How it happens.** Context band overflows. Tap Mom (lit, moves to the front). Tap the Context band's More: page 2 shows other entries; Mom is no longer visible though still active.

**Suggested fix.** In express-bands.composePanel, when paging a band (band scope), keep the lit entries pinned in the first positions of every page: split L into lit and rest, show the lit ones first on each page and page only through the rest (per = n - 1 - lit.length, minimum 1). For the whole-panel scope, exclude cells holding lit items from the takeover. Add tests in tests/express-bands.test.mjs.

**How to verify the fix.** Unit test in tests/express-bands.test.mjs: composePanel with an overflowing context list, litIds containing one id, paging {band:'context', page:1} - assert the lit id is in items on page 1.

**Do not break.** Cell positions/geometry must not change (paint/content only). The More button must keep its fixed cell.

**Design reference.** CLAUDE.md 'A band that overflows gets a MORE button' - 'A SWITCHED-ON button always shows (Ken)'

**Verification notes.** In express-bands.composePanel, litFirst puts lit items at the front of their band, so they show only on page 0. Under the band scope, page >= 1 shows L[page*per...], so the lit item is off screen. The whole-panel scope overwrites every cell except More. The recorded rule (a switched-on button always shows) is implemented as 'front of band', so it holds only on the first page. The exposure is transient: any button tap resets paging, so the lit item is hidden only while the user deliberately pages that band.
