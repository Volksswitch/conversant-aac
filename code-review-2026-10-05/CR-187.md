# CR-187: In 'rows' mode a large Flex band can shrink the Context band below its floor of four

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-bands.js:122`
- **Also affects:** `app/js/express-bands.js:131-136`; `app/js/express-bands.js:167-176`; `app/js/express-bands.js:39-45`
- **Source:** express-12

**What a user notices.** On a narrow side layout, if the user gives the Flex band nearly all the rows, the Context band can end up with only three spots, so a four-way choice from the other person cannot all appear as buttons.

**What is wrong.** In ROWS mode flexRows is clamped only to nRows - ctxRows, and the floor top-up borrows rows/cells only from the Always band ('Rows come from ALWAYS above, never from Flex below'). When Flex takes every remaining row, alwaysRows is 0 and nothing can be borrowed, so contextN stays below CONTEXT_FLOOR. Measured: Side Layout 6 (3 positions per row) with contextRows 1 and flexRows 10 or 11 gives context 3, always 0. The header calls the floor 'UNCONDITIONAL'. In COUNTS mode Context is sized before Flex so the floor holds.

**Evidence.**

```
express-bands.js:121-123 `let ctxRows = clamp(sizes.contextRows ?? 1, 0, nRows); const flexRows = clamp(sizes.flexRows ?? 0, 0, nRows - ctxRows); let alwaysRows = nRows - ctxRows - flexRows;`
:133 `while (ctxPositions() < Math.min(CONTEXT_FLOOR, total) && alwaysRows > 0) {`
node experiment: S6 flexRows 10 -> context 3 always 0 flex 29.
```

**How it happens.** Settings > Express Panel: side dock, Side Layout 6, band shape 'rows', Flex band 10. The Context band has 3 positions; a partner offering four options shows only three choice buttons.

**Suggested fix.** In bandPlan ROWS branch, compute flexRows after reserving enough rows for the floor: first determine the minimum context rows needed (walk filled rows from the end of the Always region), then clamp flexRows to `nRows - ctxRowsNeeded`. Simplest: after the existing loop, if ctxPositions() is still below the floor and flexRows > 0, move rows from Flex to Context (decrement flexRows, increment ctxRows, recomputing bandOfRow) until the floor is met or flexRows is 0.

**How to verify the fix.** Add to tests/express-bands.test.mjs: for every layout in LAYOUTS and every flexRows 0..nRows, bandPlan(rows, {shape:'rows', contextRows:1, flexRows}).contextN >= Math.min(4, total).

**Do not break.** Do not change COUNTS mode, and do not change results for any layout/size combination that already meets the floor (existing tests encode those).

**Design reference.** express-bands.js header 'THE CONTEXT BAND'S FLOOR OF FOUR IS UNCONDITIONAL'

**Verification notes.** Ran bandPlan over every layout in LAYOUTS with shape rows: S6 with contextRows 1 and flexRows 10 or more gives contextN 3, alwaysN 0 and flexN 29, which breaks the 'unconditional' floor of four. The floor top-up borrows only from Always, and both the cell-level fallback and the row loop stop when Always is empty. bandFlexInput allows up to 60, so the setting is reachable.
