# CR-190: Speakability and no-empty-interjection rules are missing from the other prompts that write the user's words

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/llm.js:773`
- **Also affects:** `app/js/llm.js:738-749 (generatePracticeOpeners)`; `app/js/llm.js:830-836 (repairSelf)`; `app/js/llm.js:859-869 (repairOptions)`; `app/js/llm.js:594-598 (rules present only in generateResponses)`; `app/js/llm.js:773 (merged duplicate: User-voice prompts other than generateResponses lack the 'everything is spoken aloud' speakability rule)`
- **Source:** llm-engine-07, x-rules-08

**What a user notices.** Statements, practice openers and rephrased repeats can come back with texting shorthand, symbols or emoji, or begin with an empty "Well," or "Oh," which the voice then reads out awkwardly in the user's name.

**What is wrong.** The 'EVERYTHING YOU WRITE WILL BE SPOKEN ALOUD' rule (no 'idk', '&', '%', emoji, stage directions) and the standing v0.3.9 'No response may begin with an empty interjection' rule are only in generateResponses. generateStatements has the interjection rule but not speakability; generatePracticeOpeners, repairSelf and repairOptions have neither, although all of them produce text that is spoken as the user. NO_VULGARITY is correctly present in all of them.

**Evidence.**

```
llm.js:594: 'EVERYTHING YOU WRITE WILL BE SPOKEN ALOUD by a speech synthesizer ...' appears only inside cachedPrompt of generateResponses. llm.js:830-836 (repairSelf system prompt) contains instruction + REWORD_ONLY + NO_VULGARITY + 'Return ONLY the new utterance text' and nothing about speakability or interjections; llm.js:745-749 (practice openers) likewise.
```

**How it happens.** User typed "idk if i can make it tmrw"; partner says "What?"; Rephrase card returns "Idk if I can make it tmrw, sorry" and is spoken letter by letter.

**Suggested fix.** Extract the speakability paragraph and the interjection sentence from generateResponses into a constant (e.g. `const SPEAKABLE = `...``), use it in generateResponses' cached prompt unchanged (byte-identical, so the cache is unaffected), and append `${SPEAKABLE}` next to `${NO_VULGARITY}` in generateStatements, generatePracticeOpeners, repairSelf and repairOptions.

**How to verify the fix.** tests/llm.test.mjs: for each of generateStatements, generatePracticeOpeners, repairSelf, repairOptions, capture the system text via the existing sysText() helper and assert it contains 'SPOKEN ALOUD' and 'empty interjection'.

**Do not break.** Keep the cached prompt of generateResponses byte-for-byte identical in content (only move text into a constant). Do not add these rules to generatePartnerUtterance's honesty block beyond what it has; the practice partner is a different person.

**Design reference.** CLAUDE.md 'Standing findings from the archived build logs' (no response may begin with an empty interjection, v0.3.9) and NO_VULGARITY note (speakability is separate).

**Verification notes.** grep shows 'SPOKEN ALOUD' only at llm.js:594, in generateResponses. The empty-interjection rule is at 598 (generateResponses) and 783 (generateStatements) only. repairSelf, repairOptions and generatePracticeOpeners carry NO_VULGARITY and REWORD_ONLY but neither rule. Practice openers do ask for a 'short, speakable sentence', which is partial coverage. All of these produce words spoken as the user. Impact is minor.

The speakability rule ('EVERYTHING YOU WRITE WILL BE SPOKEN ALOUD ... no texting abbreviations or initialisms, no &, @, emoji, stage directions') appears only inside generateResponses' cached prompt. CLAUDE.md records it as the fix for the unsayable 'fw' card, kept separate from the vulgarity rule. generateStatements (Reframe-to-lead), repairSelf, repairOptions and generatePracticeOpeners also produce text the app speaks in the user's voice. Each carries NO_VULGARITY but not the speakability instruction. NO_VULGARITY forbids initialized vulgarity only, so harmless written-only forms ('idk', 'tbh', 'w/') are not covered.

Fix as proposed by that reviewer: Lift the speakability paragraph at llm.js:594 into a module constant (for example const SPOKEN_ALOUD = `EVERYTHING YOU WRITE WILL BE SPOKEN ALOUD ...`) next to NO_VULGARITY. Use it in generateResponses (unchanged position, still inside the cached prefix) and append it beside ${NO_VULGARITY} in generateStatements, repairSelf, repairOptions and generatePracticeOpeners. Do not add it to generatePartnerUtterance (already told 'spoken aloud'), draftScenario or anything that does not produce user speech.
