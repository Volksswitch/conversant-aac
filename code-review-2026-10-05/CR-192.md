# CR-192: Android hearing default switches to a paid service only for a Deepgram key, not the recommended Azure key

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/storage.js:1081`
- **Also affects:** `app/js/storage.js:1063-1083`; `Documents/Conversant AAC User Manual (Android).docx paragraph 111`
- **Source:** x-defaults-08

**What a user notices.** On an Android phone or tablet, someone who pastes the recommended Azure key but never changes the hearing choice keeps the built-in recognizer, which on Android drops words and beeps at every restart, even though the app would have switched them automatically had they used Deepgram.

**What is wrong.** loadSttProvider() defaults Android to a paid recognizer when no choice is stored, because the built-in one is recorded as not good enough there (Ken, Aug 31 2026). The shortcut only checks for a Deepgram key. Since Sept 21 2026 Azure is the recommended service everywhere (CLAUDE.md, Settings label '(Recommended)'), so the automatic default now favors the non-recommended service and ignores the recommended one.

**Evidence.**

```
app/js/storage.js:1081  if (platform.isAndroid() && (loadDeepgramKey() || '').trim()) return 'deepgram';
app/js/storage.js:1082  return 'builtin';
```

**How it happens.** Fresh Android install; user follows the Speech Provider Guide, pastes an Azure key and region on the Speech tab, and does not touch 'Hearing the other person'. No sttProvider is stored, so loadSttProvider returns 'builtin'.

**Suggested fix.** In loadSttProvider, before the Deepgram check, add: `if (platform.isAndroid() && (loadAzureKey() || '').trim() && (loadAzureRegionSetting() || '').trim()) return 'azure';` keeping the Deepgram line as the second fallback. Require BOTH key and region, for the same reason the existing comment requires a key: a source that cannot start is treated as fatal and switches listening off.

> **Verifier correction to the fix (takes precedence):** Use loadAzureRegionSetting() (no eastus fallback) for the region check, as suggested; loadAzureRegion() falls back to 'eastus' and would make the region check always pass. Decide with Ken which of Azure/Deepgram wins when both keys exist (suggested order puts Azure first).

**How to verify the fix.** Add a case to the storage tests (tests/storage-*.test.mjs) that stubs platform.isAndroid() true, sets azureKey + azureRegion with no sttProvider, and expects 'azure'; and one with azureKey but no region expecting 'builtin'.

**Do not break.** A stored choice must still always win. Do not default to azure without a region (the comment above this line explains the 'no-key' fatal path). Check stt-azure handles a region read through loadAzureRegionSetting vs loadAzureRegion consistently.

**Design reference.** CLAUDE.md 'Azure is the RECOMMENDED speech service' and 'Android needs a paid service to HEAR'

**Verification notes.** storage.js:1081 defaults Android to a paid recognizer only when a Deepgram key exists; an Azure key+region with no stored sttProvider returns 'builtin'. No code path saves sttProvider when an Azure key is pasted (saveSttProvider is only called from the radio handler, app.js:7358). Azure is recorded as the recommended service since 2026-09-21. It is a stale default rather than a crash, and the Aug 31 decision was written when Deepgram was the only paid option, so Ken should confirm the preference.
