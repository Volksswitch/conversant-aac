# CR-194: The voice crossover guard does not know Azure's voices

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/tts.js:133`
- **Also affects:** `app/js/tts.js:138`; `app/js/tts-azure.js:78-95`
- **Source:** tts-14

**What a user notices.** If a future mistake hands an Azure voice name to another service, the app will not catch it, and that service will refuse every sentence and drop to the device voice.

**What is wrong.** belongsToAnotherService() builds each service's known list from aura.VOICES or TTS_PROVIDERS[id].voices. Azure is neither, so listFor('azure') is [] and the owner loop iterates only ['deepgram', ...TTS_PROVIDERS keys]. An Azure id (e.g. 'en-US-JennyNeural') given to OpenAI/Google/ElevenLabs/Deepgram is never refused, although it is demonstrably Azure's (it is in tts-azure.js VOICES). The guard was added specifically to stop exactly this class of crossover.

**Evidence.**

```
tts.js:133-135 `const listFor = (id) => (id === 'deepgram' ? aura.VOICES.map((v) => v.id) : (TTS_PROVIDERS[id] && TTS_PROVIDERS[id].voices || []).map((v) => v.id));`
tts.js:138 `for (const id of ['deepgram', ...Object.keys(TTS_PROVIDERS)]) {`
```

**How it happens.** tts.setPaidVoice('google', 'en-US-JennyNeural') is accepted silently; every Google utterance is then refused and falls back.

**Suggested fix.** Include Azure: `const listFor = (id) => id === 'deepgram' ? aura.VOICES.map(v => v.id) : id === 'azure' ? azure.VOICES.map(v => v.id) : (TTS_PROVIDERS[id]?.voices || []).map(v => v.id);` and iterate `['deepgram', 'azure', ...Object.keys(TTS_PROVIDERS)]`. Because Azure's real catalog is fetched, keep the rule that an id nobody lists is allowed.

**How to verify the fix.** Add to tests/tts.test.mjs: setPaidVoice('google', 'en-US-JennyNeural') leaves getPaidVoice('google') unchanged; setPaidVoice('azure', 'en-US-JennyNeural') is accepted.

**Do not break.** Do not refuse ids that no list claims (fetched catalogs).

**Design reference.** CLAUDE.md 'A TWO-SERVICE if/else MET FIVE SERVICES' ('THE CROSSOVER IS NOW STRUCTURALLY REFUSED')

**Verification notes.** belongsToAnotherService() (tts.js:132-142) builds known lists only for 'deepgram' (aura.VOICES) and TTS_PROVIDERS entries; Azure is not in TTS_PROVIDERS, so listFor('azure') is [] and the owner loop never checks Azure. tts-azure.js exports VOICES (78-95) and is already imported as `azure` in tts.js, so an Azure id such as 'en-US-JennyNeural' handed to Google/OpenAI/ElevenLabs/Deepgram is accepted. No current caller is shown to do this, so it is a gap in the guard rather than a live failure; low.
