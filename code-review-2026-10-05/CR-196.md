# CR-196: The 'Try again' button in the response area is not covered by the two-tap safeguard

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** design-violation
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/ui.js:424`
- **Also affects:** `app/js/app.js:863`
- **Source:** ui-shell-09

**What a user notices.** With 'Two taps' turned on, a single stray touch on 'Try again' still fires a new request and replaces what is in the response area, unlike every other control on that screen.

**What is wrong.** UI Layout Rule 10 says any tap that replaces what is on screen needs two taps when the setting asks. The only tap-guard rule for the response region is '#responseOptions .response-card[data-index]'; the error box's .response-error-retry button (built by showResponseError) matches no rule, so it always acts on one tap.

**Evidence.**

```
ui.js:424-428
        const btn = document.createElement('button');
        btn.type = 'button';
        btn.className = 'response-error-retry';
        btn.textContent = 'Try again';
        btn.addEventListener('click', onRetry);
app.js:863  tapGuard.addRule('#responseOptions .response-card[data-index]', {...});
```

**How it happens.** Two-tap mode on; make generation fail (e.g. a bad API key) so the error box shows; one tap on 'Try again' immediately re-requests.

**Suggested fix.** In app.js next to the other rules add `tapGuard.addRule('#responseOptions .response-error-retry');` (before tapGuard.install()).

**How to verify the fix.** Manual: two-tap mode, trigger the error box, a single tap only shows the arm ring; a second tap retries.

**Do not break.** CLAUDE.md has an open TODO to possibly remove the error box before public release; this is still worth a one-line fix while it exists.

**Design reference.** CLAUDE.md UI Layout Rule 10 (ONE TAP OR TWO — NOW APP-WIDE)

**Verification notes.** The only tap-guard rule for the response region is '#responseOptions .response-card[data-index]' (app.js:863). showResponseError (ui.js:413-432) builds a .response-error-retry button that is not inside a response card, so match() returns null and a single tap fires the retry. The retry re-requests and replaces what is on screen, which UI Layout Rule 10 says needs two taps when the setting is on. This is separate from the open TODO about removing the amber box, though removing the box would make it moot.
