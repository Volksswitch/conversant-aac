# CR-200: Inline completion acceptance is described differently in CLAUDE.md than it is built

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** doc-mismatch
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/keyboard.js:312`
- **Also affects:** `app/js/keyboard.js:57`; `app/js/keyboard.js:725`
- **Source:** keyboard-09

**What a user notices.** None today; the design record tells a future developer that typing a space accepts the suggested word, which would make the app silently replace words if someone 'fixed' the code to match.

**What is wrong.** CLAUDE.md ('Word prediction - local tiers', v0.5.42 note) says the ghost is 'accepted by typing the separator you were going to type anyway' and lists that as its key advantage. The code (Ken, July 2026) and all three User Manuals say the opposite: a separator never accepts; only a tap in the field accepts. CLAUDE.md is the stale side.

**Evidence.**

```
keyboard.js:306-311 'Space / Enter close a word. They do NOT accept the inline ghost — a separator must never silently swap the typed word for a prediction ... Acceptance is an explicit tap in the field'; User Manual: 'To accept it, tap anywhere in the text box ... Typing a space, comma, period, or enter doesn't accept'. CLAUDE.md: 'accepted by typing the separator you were going to type anyway'.
```

**How it happens.** A future session reads CLAUDE.md, sees separators should accept, and changes handleKey accordingly - 'Yes' + space would become 'Yesterday'.

**Suggested fix.** Update the CLAUDE.md 'Word prediction - local tiers' paragraph to say the ghost is accepted by tapping anywhere in the field, separators never accept (Ken, July 2026), and give the reason. No code change.

**How to verify the fix.** Read the updated CLAUDE.md paragraph against keyboard.js handleKey and the manual tip.

**Do not break.** Do not change the code.

**Design reference.** CLAUDE.md 'Word prediction — local tiers'

**Verification notes.** CLAUDE.md ('Word prediction — local tiers' and the v0.5.42 DONE note) says the ghost is 'accepted by typing the separator you were going to type anyway' / 'by typing any word-separator'. keyboard.js handleKey says separators never accept the ghost and acceptance is an explicit tap in the field (Ken, July 2026), and acceptGhost is reached only from the field pointerdown and acceptPendingGhost. CLAUDE.md is the stale record.
