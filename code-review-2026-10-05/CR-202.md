# CR-202: User Manual says tapping outside the Settings Panel closes it; nothing does that

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** doc-mismatch
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `Documents/Conversant AAC User Manual (Windows Chromebook Mac).docx:318`
- **Also affects:** `Windows manual paragraph 134 ('Tap elsewhere, or tap the X...')`; `Documents/Conversant AAC User Manual (iPad).docx paragraphs 152, 336`; `Documents/Conversant AAC User Manual (Android).docx paragraphs 134, 319`; `app/js/app.js:760`; `app/js/app.js:6994`
- **Source:** x-defaults-03

**What a user notices.** The manual tells people they can close Settings by tapping outside it. Tapping outside does nothing (and on the Express Panel tab it selects a panel button for editing), so a user following the manual thinks the app is stuck. Only the X (or Esc) closes it.

**What is wrong.** The CODE is right and the DOCUMENT is wrong. Settings is opened with dialog.showModal() and there is no backdrop-click handler on #settingsDialog anywhere (the only backdrop handlers are in confirm-dialog.js for the red confirmation card). The only close routes are #closeSettingsBtn and the dialog 'cancel' event (Escape). The area outside the panel is the dock, which is inert under a modal except on the Express tab, where it is the live panel and a tap edits a button.

**Evidence.**

```
Windows manual para 318: "Tap the X at the right of the Settings title bar, or tap outside the panel, to dismiss it."
Windows manual para 134: "Tap elsewhere, or tap the X at the right of the Settings Panel title bar. The key is saved immediately."
app/js/app.js:6994  dialog.showModal();
app/js/app.js:760  settingsDialog.addEventListener('cancel', () => { ... })   // Escape only
grep for 'target === dialog' / closedby in app/js and index.html finds no Settings backdrop handler.
```

**How it happens.** Open Settings, tap the Express Panel or the area beside the panel: the panel stays open (on the Express tab the tapped panel button is selected for editing instead).

**Suggested fix.** Edit the documents, not the code. In all three User Manuals: para 318 (Windows; iPad 336; Android 319) change to "Tap the X at the right of the Settings title bar to dismiss it." Para 134 (Windows; iPad 152; Android 134) change to "Tap the X at the right of the Settings Panel title bar. The key is saved as soon as you paste it." Follow the sync-docs rules (backup first, no edits to a document under review).

> **Verifier correction to the fix (takes precedence):** Fix para 318/336/319 as suggested. Para 134/152/134 ('Tap elsewhere, or tap the X ... The key is saved immediately') is in the API-key paste context and 'tap elsewhere' may only mean leaving the field; check its context before rewriting and only remove the dismiss claim if it implies closing the panel.

**How to verify the fix.** Manual check in the app: tap outside the Settings Panel on several tabs and confirm it stays open. python scripts/doc-tests/check-docs.py on the edited manuals.

**Do not break.** Do not add a backdrop-close to make the manual true: the dock beside Settings is a live editing surface on the Express tab and a keyguard-backed area, so a backdrop dismiss would turn imprecise taps into lost places.
