# CR-205: Manual's Conversation tab names four controls by labels that are not on screen

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** doc-mismatch
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `Documents/Conversant AAC User Manual (Windows Chromebook Mac).docx:381`
- **Also affects:** `Windows manual paragraphs 210, 385, 389, 391`; `Documents/Conversant AAC User Manual (iPad).docx paragraphs 227, 395, 399, 403, 405`; `Documents/Conversant AAC User Manual (Android).docx paragraphs 210, 382, 386, 390, 392`; `app/index.html:814`; `app/index.html:821`; `app/index.html:828`; `app/index.html:866`; `settings-help.json:78`; `settings-help.json:128`; `settings-help.json:152`
- **Source:** x-defaults-04

**What a user notices.** The manual tells the reader to turn on "Don't save conversations to my data folder", "Auto-resume listening", "Response options per category" and "What a response option shows", but the Settings screen labels them differently, so a reader scanning for those words cannot find the control.

**What is wrong.** Labels quoted in the manual (which the house convention requires to match the screen) differ from index.html: (1) "Don't save conversations to my data folder" vs on-screen "Do not save my conversations" (the markup comment says the folder wording was deliberately removed because tablets have no folder); (2) "Auto-resume listening" vs "Resume listening automatically after speaking a response" (the manual's own chime row a few lines later quotes "Resume listening automatically"); (3) "Response options per category" vs "Suggestions per category"; (4) "What a response option shows" vs "What a response card shows". Items 1-2: the code is right and the documents are wrong. Items 3-4: the manual applies writing-conventions.json, which bans "response card" as a development word in user-facing text - but the on-screen labels, the text-size labels ("Response cards - the full response") and the spoken help (suggestions, cardTextModeInput, responseFontSelect, openers, windDowns) still use "card". Either the labels change or the manual quotes them as they are; that choice is Ken's.

**Evidence.**

```
app/index.html:814  Do not save my conversations
app/index.html:866  Resume listening automatically after speaking a response
app/index.html:821  <label for="responsesPerCategoryInput">Suggestions per category</label>
app/index.html:828  <label for="cardTextModeInput">What a response card shows</label>
Windows manual para 381: "Don’t save conversations to my data folder"; para 385: "Auto-resume listening"; para 389: "Response options per category"; para 391: "What a response option shows"
writing-conventions.json:643  "term": "response card" ... "'card' is a development concept, not a user's word"
```

**How it happens.** A tester reads section 4.5 or 6.5, opens Settings > Conversation and looks for "Don't save conversations to my data folder"; the checkbox reads "Do not save my conversations", so they are unsure it is the same control.

**Suggested fix.** Documents (all three manuals): paragraph 210 note and the 6.5 row 381 -> "Do not save my conversations"; row 385 -> "Resume listening automatically after speaking a response". For rows 389/391 ask Ken which side moves: EITHER change index.html line 821 to "Response options per category" and line 828 to "What a response option shows" (and the text-size labels at 403/412 to "Response options - the full response" / "Response options - the short version", and the settings-help.json entries that say 'card'), then regenerate settings-help.js; OR change the manual rows to quote the screen labels exactly.

**How to verify the fix.** python scripts/doc-tests/check-docs.py (the quotes rule harvests names from app/index.html). npm test if index.html or settings-help.json changes (tests/ui-standards and settings-help tests).

**Do not break.** Changing index.html labels must keep the element ids and data-help keys. Do not change the 'Don't save' Command Bar button; it is a different control.

**Design reference.** CLAUDE.md 'A test suite for the documents' (quotes rule harvests app names); writing-conventions.json 'response card' entry

**Verification notes.** Verified: manual rows 381/385/389/391 (Windows; iPad 399/403/405; Android 386/390/392) and note 210 quote 'Don't save conversations to my data folder', 'Auto-resume listening', 'Response options per category', 'What a response option shows', while index.html:814/866/821/828 read 'Do not save my conversations', 'Resume listening automatically after speaking a response', 'Suggestions per category', 'What a response card shows'. writing-conventions.json:643 bans 'response card' as an error, so the screen labels themselves conflict with the house vocabulary; which side moves is Ken's call.
