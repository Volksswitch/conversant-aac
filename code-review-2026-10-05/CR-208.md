# CR-208: No drift test between CHANGELOG.md and the bundled What's-new notes, unlike settings-help

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** other
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/whats-new.js:23`
- **Also affects:** `scripts/apply-release-notes.mjs:122`; `tests/whats-new.test.mjs:13`; `tests/settings-help.test.mjs:192`
- **Source:** g-test-suite-07

**What a user notices.** If the release notes are edited and the regeneration step is forgotten, users would see old or missing notes after an update, and no test would warn.

**What is wrong.** settings-help has a test that fails when settings-help.json and the generated settings-help.js disagree ('the bundled copy matches settings-help.json (generator was run)'). The release notes use the identical arrangement (CHANGELOG.md -> apply-release-notes.mjs -> RELEASE_NOTES block in whats-new.js) but tests/whats-new.test.mjs only tests the selection logic, never that the bundled block matches CHANGELOG.md. Running the generator logic in scratch against today's tree shows no drift, so this is a missing guard, not a current defect. CLAUDE.md calls this same staleness trap out for both generators.

**Evidence.**

```
tests/settings-help.test.mjs:192: test('the bundled copy matches settings-help.json (generator was run)', ...)
tests/whats-new.test.mjs: tests compareVersions / collectWhatsNew / pending / scoped notes only.
Scratch notesdrift.mjs (the generator with its write replaced by a compare): DRIFT: false.
```

**How it happens.** 1) Edit a bullet under '## Unreleased' in CHANGELOG.md. 2) Forget scripts/apply-release-notes.mjs. 3) npm test passes. 4) Release: the What's-new panel shows the old wording.

**Suggested fix.** Refactor scripts/apply-release-notes.mjs so the parse step is an exported pure function (e.g. buildReleaseNotes(changelogText, appVersion) returning the notes object) and the file write only happens when run as a script (guard with import.meta.url === pathToFileURL(process.argv[1]).href). Add a test to tests/whats-new.test.mjs that reads CHANGELOG.md and APP_VERSION, calls buildReleaseNotes, extracts the JSON between the @@RELEASE_NOTES_START@@/END@@ markers in whats-new.js, and deepEqual-compares, with the message 'run: node scripts/apply-release-notes.mjs'.

> **Verifier correction to the fix (takes precedence):** Do not compare the whole CHANGELOG, Unreleased included. CLAUDE.md's changelog-as-you-go rule adds bullets under '## Unreleased' during the dev cycle, and the generator is run only at release (RELEASING.md step). An exact-match test would therefore fail on every dev commit that adds a note. Restrict the comparison to the released '## Version X.Y.Z' sections: skip the APP_VERSION key that Unreleased maps to, or treat it as allowed to be missing or stale. Alternatively, make it a check inside the release ritual rather than part of npm test.

**How to verify the fix.** Change one character in a CHANGELOG.md bullet without regenerating: the new test fails. Run the generator: it passes.

**Do not break.** The '## Unreleased' section maps to APP_VERSION, so the test must read APP_VERSION from app.js exactly as the script does. Do not let the test write any file.

**Design reference.** CLAUDE.md '"What's new" notes are BUNDLED, never fetched (v0.5.62)' and Rule 17 note on the settings-help drift guard.

**Verification notes.** tests/whats-new.test.mjs tests only the selection logic. Nothing compares the RELEASE_NOTES block with CHANGELOG.md, though settings-help.json does have such a guard. Today '## Unreleased' is empty and the bundle holds 0.13.4, so nothing has drifted. The guard is simply missing.
