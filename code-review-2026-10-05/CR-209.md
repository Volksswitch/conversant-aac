# CR-209: American-spelling test does not scan the shipped data files the user sees

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** other
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `tests/american-spelling.test.mjs:177`
- **Also affects:** `app/data/worldview-questions.json:1`; `app/data/words.json:1`; `app/manifest.webmanifest:4`
- **Source:** g-test-suite-06

**What a user notices.** Question wording in About Me and the word-completion list could gain British spellings without any check, so the app could suggest or show "colour" to a user.

**What is wrong.** The on-screen-text test scans app/index.html and string literals in app/js/*.js, but not app/data/*.json. worldview-questions.json holds every About Me question and answer option shown on screen (and sent to the AI as profile labels), words.json is the word-prediction dictionary whose entries are offered as inline completions, and manifest.webmanifest's description is shown at install. All three are clean today (detector run in scratch: 0 hits each), so this is a scope gap, not a current defect — the same 'scope was too narrow' failure CLAUDE.md records for the prototypes and generators.

**Evidence.**

```
tests/american-spelling.test.mjs:177-188: const html = readFileSync(join(root, 'app', 'index.html'), 'utf8'); ... const dir = join(root, 'app', 'js'); for (const f of readdirSync(dir).filter((n) => n.endsWith('.js') && !GENERATED.has(n))) ...  (no app/data, no manifest)
Scratch run brit.mjs: app/data/words.json 0, app/data/worldview-questions.json 0, app/manifest.webmanifest 0.
```

**How it happens.** 1) Add an answer option 'Favourite colour' to worldview-questions.json. 2) npm test passes. 3) The About Me screen shows the British spelling and the AI receives it as a label.

**Suggested fix.** In the 'the app's on-screen text is in American English' test, also run findBritish over the string values of app/data/worldview-questions.json (walk the parsed JSON and join all string values), over app/data/words.json (join the word list), and over the name/description fields of app/manifest.webmanifest. Keep pricing.json out (no prose).

**How to verify the fix.** Temporarily add 'colour' to words.json in a scratch copy of the check (or a unit case calling the same helper on a fixture) and confirm the test reports it; with the real files the test stays green.

**Do not break.** Do not scan JSON keys or ids, only displayed string values; keys like fav_screen are not prose.

**Design reference.** CLAUDE.md 'Document convention: AMERICAN ENGLISH SPELLING ONLY' ('Scope is everything a user reads or hears').

**Verification notes.** tests/american-spelling.test.mjs reads these sources: CHANGELOG.md, settings-help.json, app/index.html, string literals in app/js, doc-generators, prototypes, CLAUDE.md and TODO.md. It never reads app/data/worldview-questions.json, app/data/words.json or app/manifest.webmanifest, and all three are text a user sees. Nothing is wrong today; the scope gap is real.
