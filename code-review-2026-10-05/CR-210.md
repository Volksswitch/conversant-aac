# CR-210: Spoken-help coverage test misses sections built at runtime by the Express Panel editor

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** other
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `tests/settings-help.test.mjs:61`
- **Also affects:** `app/js/express-editor.js:489`; `tests/settings-help.test.mjs:169`; `tests/ui-standards.test.mjs:173`; `app/js/help-mode.js:93`
- **Source:** g-test-suite-04

**What a user notices.** A Settings section can go silent under the "?" help button without any test noticing; three Express Panel sections already have.

**What is wrong.** runtimeSectionKeys() hard-codes three runtime editors (control-phrases-editor, placeholder-editor, practice-editor) and 'every collapsible section heading resolves to a spoken phrase' only reads index.html. express-editor.js builds its Always/Context/Flex sections via section() with class setting-group and no data-help, so they are outside both checks (the silent headings themselves are already reported). The structural hole is that any runtime-built section is uncovered unless someone remembers to add a regex for its builder, which the test's own comment warns about. A browser walk asking help-mode.resolveTap for each visible section heading finds exactly the three silent Express headings and nothing else, so it is an accurate, low-noise guard.

**Evidence.**

```
tests/settings-help.test.mjs:62-66: const sources = [ ['control-phrases-editor.js', ...], ['placeholder-editor.js', ...], ['practice-editor.js', ...] ];
app/js/express-editor.js:489-493: const wrap = el('div', 'setting-group ee-section'); wrap.dataset.band = key; wrap.appendChild(el('label', null, title));  (no dataset.help)
Experiment silent-sections.mjs (puppeteer, every Settings tab, resolveTap(summary).key then settings-help lookup): express: "Always — the words that never move" -> key=null; "Context — describing the conversation c..." -> key=null; "Flex — phrases that suit who you are wi..." -> key=null; no other heading silent.
```

**How it happens.** 1) Add a new runtime editor that emits .setting-group sections without data-help. 2) npm test stays green. 3) In Settings, tap "?" then a section heading: nothing is said.

**Suggested fix.** In tests/ui-standards.test.mjs (which already starts the app, opens Settings and walks every tab), add a test that, for each tab, clicks it, opens all details, and for every visible '#settingsDialog .setting-group summary' calls (await import('./js/help-mode.js')).resolveTap(summary).key and (await import('./js/settings-help.js')).lookup(key), collecting headings where either is falsy; assert the list is empty. Keep the source-regex test as the fast path. (The Express sections themselves are fixed by giving section() a dataset.help and adding entries to settings-help.json — the separately reported bug.)

**How to verify the fix.** Before fixing the Express sections the new browser test must fail listing exactly the three Express headings; after adding data-help keys and settings-help.json entries (and running scripts/apply-settings-help.mjs) it passes.

**Do not break.** Skip the test the same way the file already does when puppeteer cannot launch. Wait for the Express editor to render before reading its headings (it renders on tab show).

**Design reference.** CLAUDE.md UI Layout Rule 17 (spoken help; 'a coverage test that reads one file only covers what that file declares') and Rule 18.

**Verification notes.** runtimeSectionKeys() lists only control-phrases-editor, placeholder-editor and practice-editor. express-editor.js section() builds a .setting-group with a label and no dataset.help. Its toolbar buttons (mkBtn) carry no id, so help-mode.resolveTap's group fallback marks the group unnameable and returns no key. The three Express band headings are therefore silent under the '?' and no test covers them. Not tracked in TODO.md.
