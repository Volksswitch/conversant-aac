# CR-211: Typing a key for OpenAI, Google Cloud or ElevenLabs fires a voice-list request on every keystroke and keeps the old account's list

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** performance
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:7924`
- **Also affects:** `app/js/app.js:7898`; `app/js/app.js:7437`; `app/js/storage.js:1303`
- **Source:** x-providers-13

**What a user notices.** Typing a speech-service key by hand sends dozens of failed requests to that company, and after changing to a different account's key the partner voice may still be chosen from the previous account's voices.

**What is wrong.** wireKeyField's onChange runs on every input event; for catalog services it calls refreshVoices(), which has no in-flight guard (Azure has azureFetchInFlight) and does not clear the cached catalog first (Azure calls clearAzureVoiceCatalog). Each partial key produces a request that fails with 401; if the final key's fetch fails, the previous account's cached catalog remains and pickRestPartnerVoice keeps drawing from it (for ElevenLabs those can be another account's private voice ids, which then 404).

**Evidence.**

```
app/js/app.js:7924: onChange: () => { showStatus(null, ''); refreshVoices(); },
app/js/app.js:7898-7903: const refreshVoices = async () => { ... const voices = await ttsRest.fetchVoices(provider, key); ...
app/js/app.js:7437 (Azure, for contrast): storage.clearAzureVoiceCatalog();
```

**How it happens.** Type a 40-character ElevenLabs key by hand: ~40 GET /v1/voices requests are sent with partial keys. Replace account A's key with account B's key while offline: account A's catalog stays cached and the partner Auto voice is one of account A's voices.

**Suggested fix.** In the catalog loop, add a per-service `let fetchInFlight = false;` guard and debounce onChange (e.g. setTimeout 600 ms, cleared on each input). On key change, remove the cached catalog first: add `storage.clearServiceVoiceCatalog(id)` in storage.js (localStorage.removeItem(`aac_${id}_voices`)) and call it in onChange before refreshVoices.

**How to verify the fix.** Manual with the network panel open: type a key character by character and confirm at most one catalog request after typing stops.

**Do not break.** The key Test button still needs to fetch the catalog as its second step (Ken's Sept 8 2026 decision).

**Design reference.** CLAUDE.md 'Five paid speech services' (catalog fetch is a step of the key test)

**Verification notes.** wireKeyField calls onChange on every 'input' event (app.js:982-987). The catalog loop's onChange (7924) calls refreshVoices(), which has no in-flight guard or debounce and does not clear the cached catalog (7898-7913). The Azure handler, by contrast, clears its cache (7437). Typing a key character by character therefore fires one request per keystroke. If the final fetch fails, the previous account's catalog stays cached and pickRestPartnerVoice keeps drawing from it.
