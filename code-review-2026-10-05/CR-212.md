# CR-212: The cached prompt prefix changes mid-conversation (new extra fact names, and the active place)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** performance
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/llm.js:606`
- **Also affects:** `app/js/llm.js:296-299 (setExtraNames, 'Refreshed each turn')`; `app/js/llm.js:358 (placesBlock in buildProfileBlock)`; `app/js/app.js:1807 and 1811 (setExtraNames / places.buildBlock(activePlace.placeId))`
- **Source:** llm-engine-08

**What a user notices.** None visible; each time it happens the user's AI bill for that request is higher than it needs to be.

**What is wrong.** Content in the cached half of generateResponses' system prompt varies within a conversation: (a) extraNames is appended inside cachedPrompt and grows whenever the model returns a new missing_other (up to two per turn), so the next request writes a new ~3,500-token cache entry at 1.25x instead of reading at 0.1x; (b) placesBlock is built with the active place EXCLUDED (places.buildBlock(activePlace.placeId)), so tapping a Place mid-conversation (which also fires a context refresh) changes the cached prefix. CLAUDE.md's caching section requires per-conversation-volatile content to sit after the breakpoint.

**Evidence.**

```
llm.js:605-607:
  ...${worldviewKeys.length ? `\n  The keys: ${worldviewKeys.join(', ')}.` : ''}${extraNames.length ? `\n  Names already added from earlier conversations, reuse one if it fits: ${extraNames.join(', ')}.` : ''}
llm.js:614: `${perCatBlock}${buildProfileBlock()}` (placesBlock inside). app.js:1811: `llm.setPlacesBlock(places.buildBlock(activePlace && activePlace.placeId));`
```

**How it happens.** A medical practice or clinic conversation where several turns each report a new missing_other: every one of those turns pays a cache write; the 'share of prompt from cache' figure in Settings > About drops.

**Suggested fix.** Move the extraNames sentence out of cachedPrompt into turnPrompt (e.g. append `${extraNames.length ? `\n\nNames already added from earlier conversations for "missing_other", reuse one if it fits: ${extraNames.join(', ')}.` : ''}` after the context JSON). For places, either pass the full list to setPlacesBlock (always places.buildBlock()) and let buildHereBlock in the situation block carry the 'you are here' framing, or move setPlacesBlock's output to the tail; the first keeps the prefix stable.

> **Verifier correction to the fix (takes precedence):** The extraNames move to the tail is correct. For places, do NOT simply pass the full list to setPlacesBlock. The exclusion is deliberate (comment at app.js:1808-1810: the active place gets the 'you are here' framing from buildHereBlock, not 'places I go'), so including it would put the same place in front of the model under two framings. Either accept this cost (a place changes rarely within a conversation), or keep the full list cached and have buildHereBlock say explicitly that the listed place is the one the user is at now.

**How to verify the fix.** tests/llm.test.mjs: following the existing head/tail split test, set extraNames to a sentinel and assert it appears in the tail block and not in the head; assert the head is byte-identical across two calls that differ only in extraNames.

**Do not break.** worldviewKeys can stay cached (set once at startup). Keep the instruction text that tells the model the second list is for missing_other only. Do not change places.buildHereBlock privacy wording.

**Design reference.** CLAUDE.md 'Prompt caching - BUILT August 8 2026' (caching breaks silently; per-turn content must be after the breakpoint).

**Verification notes.** extraNames is interpolated into cachedPrompt (llm.js:606-607). It comes from worldview.extraNames(), which grows when recordExtraGaps adds a new missing_other name during a conversation (generateOptions records them every turn). The next request therefore rewrites the cache. placesBlock sits inside buildProfileBlock in the cached head, and it is built with the active place excluded (places.buildBlock(excludeId), app.js:1811), so tapping a Place mid-conversation changes the cached prefix.
