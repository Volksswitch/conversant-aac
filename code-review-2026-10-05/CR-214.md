# CR-214: Turning saving back on mid-turn writes the other person's words that were spoken while the conversation was private

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** privacy
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/storage.js:2167`
- **Also affects:** `app/js/storage.js:2006 (setConversationSaving)`; `app/js/app.js:1259 (logPartnerInterim receives the whole turn's accumulated text)`; `app/js/transcript-log.js:58-66 (upsert overwrites the pending turn with the full text)`
- **Source:** storage-04

**What a user notices.** If a person makes a conversation private while the other person is talking and then turns saving back on before that person finishes, the saved file can include what the other person said during the private stretch.

**What is wrong.** app.js handleSilencePeriod passes the cumulative text of the partner's whole turn to logPartnerInterim at every pause. storage keeps pendingPartnerTurn across a privacy toggle. While private, logPartnerInterim no-ops; when saving resumes and the partner pauses again, the full accumulated turn - including words heard while private - is written (overwriting the pending entry or creating a new one). The User Manual says saving 'resumes from that point'.

**Evidence.**

```
app/js/app.js:1259: if (text) storage.logPartnerInterim({ rawTranscript: text, partner: partnerStamp() });
app/js/storage.js:2168: if (!conversationSaving) return;
app/js/storage.js:2173: pendingPartnerTurn = tlog.upsertPartnerInterim(currentLogData.exchanges, pendingPartnerTurn, { rawTranscript, ...
```

**How it happens.** Partner says 'my test results came back' (pause, written), user taps Don't save, partner continues 'and it is cancer' (pause, not written), user taps Don't save again, partner adds 'but treatable' (pause): the pending entry's rawTranscript becomes the whole sentence including 'and it is cancer'.

> **Verifier correction to the trigger:** A second pause is not needed: if saving is turned back on and the user then responds, commitExchange finalizes the pending partner entry with the whole raw turn (app.js:2359), which also writes the words heard while private.

**Suggested fix.** In storage.js add `let partnerTurnTainted = false;`. In setConversationSaving: when `on` is false set `partnerTurnTainted = true`. In logPartnerInterim and finalizePartnerTurn return early while partnerTurnTainted is true. In detachPendingPartnerTurn (called at every turn boundary) and resetConversationId set `partnerTurnTainted = false`. The partner turn in progress when privacy was used is therefore never written; the next turn records normally.

> **Verifier correction to the fix (takes precedence):** Clearing the taint flag in detachPendingPartnerTurn would defeat the fix: commitExchange calls detachPendingPartnerTurn first and only then finalizePartnerTurn(handle, full raw), so the tainted turn would be written at exactly the boundary the fix relies on. Instead mark the tainted turn itself (e.g. a module WeakSet of tainted handles plus a flag that taints the next turn created while the same partner turn continues) and have finalizePartnerTurn skip any tainted handle; clear the 'taint the next turn' flag only when a new partner turn begins after a user turn (or at resetConversationId).

**How to verify the fix.** Add to tests/storage-transcript.test.mjs: logPartnerInterim('a'), setConversationSaving(false), logPartnerInterim('a b'), setConversationSaving(true), logPartnerInterim('a b c'); assert the file's partner entry still reads 'a'. Then detachPendingPartnerTurn(); logPartnerInterim('next'); assert a new entry 'next' is written.

**Do not break.** Must not drop partner turns in ordinary saved conversations; make sure terminateConversation's finalize path (app.js:2821) still works when no privacy toggle happened.

**Design reference.** User Manual section 4.5; CLAUDE.md 'Conversation privacy'

**Verification notes.** handleSilencePeriod passes the cumulative turn text (currentPartnerText = text) to logPartnerInterim at every pause (app.js:1259); storage keeps pendingPartnerTurn across the privacy toggle, and upsertPartnerInterim (transcript-log.js:58) overwrites rawTranscript with the whole text. While private the call no-ops; once saving is back on the next pause writes the full accumulated text including words heard while private. The same happens without another pause: commitExchange's finalizePartnerTurn writes the full raw turn when the user responds after re-enabling saving. Trigger is narrow (toggle off and back on within one partner turn).
