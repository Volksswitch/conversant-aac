# CR-219: Resetting the Always band or deleting a situation orphans sound files, and every backup carries them

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** resource-leak
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:667`
- **Also affects:** `app/js/express-editor.js:682`; `app/js/express-editor.js:194`; `app/js/express-panel.js:106`; `app/js/data-transfer.js:166-170`; `app/js/express-editor.js:661-665`
- **Source:** express-08

**What a user notices.** Sound clips belonging to buttons removed by 'Reset to the app's phrases' or by deleting a Flex situation stay in the data folder. Each can be up to 10 MB and is copied into every backup, so backups grow and slow down for sounds the user can no longer play.

**What is wrong.** Only removePicked() deletes a sound button's clip. resetAlways() (resetBand('always')) and deleteSituation() (removeFlexList) drop whole lists that may contain type 'audio' items, but never call storage.deleteAudioFile for their `file`. A future SEED_REVISION bump has the same effect in normalize() (stale -> Always replaced with defaults). Backups export every file in the audio folder (listAudioFiles), not only the ones referenced by buttons, so orphans are carried forever. Also the Reset confirmation text counts sound buttons as 'phrases' and does not mention that sounds will be deleted.

**Evidence.**

```
express-editor.js:194 (only path that cleans up) `if (gone && gone.type === 'audio' && gone.file) storage.deleteAudioFile(gone.file).catch(() => {});`
express-editor.js:667 `expressPanel.resetBand('always');` (no clip cleanup)
express-editor.js:682 `expressPanel.removeFlexList(key);` (no clip cleanup)
data-transfer.js:166-168 `for (const { name, file } of await storage.listAudioFiles()) { if (!isSafeAudioName(name)) continue; audio.push({ ... data: await blobToBase64(file) }); }`
```

**How it happens.** Add a 9 MB song as a sound button in the Always band, then 'Reset to the app's phrases'. The button is gone but audio/<id>-<stamp>.mp3 remains, and the next Export includes ~12 MB of base64 for it.

**Suggested fix.** Add a helper in express-editor.js `function deleteClipsOf(list) { for (const x of list || []) if (x && x.type === 'audio' && x.file) storage.deleteAudioFile(x.file).catch(() => {}); }`. In resetAlways capture `const before = bandList('always')` before resetBand and call deleteClipsOf(before) after it; in deleteSituation call deleteClipsOf(list) after removeFlexList. Mention sounds in the reset warning when any exist. Optionally, in data-transfer export, include only clips referenced by expressPanel.allItems() (filter by `file`), which also cleans up historic orphans.

**How to verify the fix.** Add a test in tests/express-panel-store.test.mjs or a manual check: create an audio item with a written file, reset the band, confirm storage.listAudioFiles() no longer lists it.

**Do not break.** Never delete a clip still referenced by another list (clips are named per button id, so this should not happen, but filter against allItems() before deleting to be safe).

**Design reference.** CLAUDE.md 'SOUND buttons on the Express Panel' (deleting the button deletes its file; clips travel in the backup)

**Verification notes.** Only removePicked deletes a sound file. resetAlways (resetBand) and deleteSituation (removeFlexList) drop whole lists without calling storage.deleteAudioFile. data-transfer export iterates storage.listAudioFiles() (every file in the audio folder), not only referenced clips, so orphans ride in every backup.
