# CR-220: settleRestore leaves its grace timer running after the restore settles

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** resource-leak
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/storage.js:223`
- **Also affects:** `app/js/app.js:1600`
- **Source:** g-app-flow-overflow-08

**What a user notices.** None noticeable; a timer keeps running for a few seconds after start-up for nothing.

**What is wrong.** settleRestore races the in-flight restore against `new Promise((res) => setTimeout(res, graceMs))` but never clears the timeout when the restore wins. The timer then fires later and resolves a promise nobody holds. Harmless today (one call per Start), but it is the same Promise.race-does-not-cancel-the-loser shape that caused the recorded false 'storage warm-up did not finish' error, and it keeps a pending timer that test harnesses and future callers can trip over.

**Evidence.**

```
app/js/storage.js:219-225: `export function settleRestore(graceMs) { if (!restoreInFlight) return Promise.resolve(); return Promise.race([ restoreInFlight.catch(() => {}), new Promise((res) => setTimeout(res, graceMs)), ]); }`
```

**How it happens.** Start pressed; the restore completes in a few ms; the FOLDER_ANSWER_GRACE_MS timer still fires later. A node test that awaits settleRestore with a long grace keeps the process alive until the timer expires.

**Suggested fix.** Keep the timer id and clear it in a finally: `let t; return Promise.race([restoreInFlight.catch(() => {}), new Promise((res) => { t = setTimeout(res, graceMs); })]).finally(() => clearTimeout(t));`

**How to verify the fix.** Add to tests/storage-transcript.test.mjs (or a storage test): with a resolved restoreInFlight, call settleRestore(60000) and confirm the test process exits promptly (no lingering timer), e.g. by asserting via a fake setTimeout/clearTimeout spy that clearTimeout was called.

**Do not break.** It must still never reject.

**Design reference.** CLAUDE.md 'Logs are ASCII, and a permission prompt is not a hang' (Promise.race does not cancel the loser; clear the timer in a finally).

**Verification notes.** settleRestore (storage.js:219-225) races restoreInFlight against a setTimeout it never clears, so the timer fires after the race settles. Its only caller is app.js:1600 (once per Start) and the resolver is a no-op, so nothing is logged and the user sees nothing; no test currently calls it. Real mechanism, negligible impact.
