# CR-225: Conversation-surface buttons render in the browser's default font (Arial), and the Express Panel preview in Settings switches to the app font

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:981`
- **Also affects:** `app/css/styles.css:986-987 (body font-family system-ui)`; `app/css/styles.css:5063 (keyboard keys font-family: inherit)`; `app/css/styles.css:2351 (.ep-btn sets font-size but not family)`
- **Source:** live-visual-06

**What a user notices.** The words on the Express Panel, the response suggestions and the Command Bar are in a different typeface from the keyboard, the conversation pane and Settings; and when you edit the Express Panel in Settings it is shown in yet another typeface, so the line breaks you see while editing are not the ones you get in a conversation.

**What is wrong.** The house font is set on body (system-ui), but <button> does not inherit font-family by default, so every button that does not set one uses the UA button font (Arial on Windows Chrome). The fix applied for Settings (:where(#settingsDialog) :where(button,input,select,textarea){font-family:inherit}) is scoped to the dialog, so on the conversation surface .ep-btn, .response-card text, .cmd-btn and #cancelComposerBtn are Arial while .kbd-key (font-family: inherit), the transcript and the composer textarea are system-ui (Segoe UI). When the Express Panel is reparented into #settingsDialog for editing, the dialog rule now applies and the same cells switch to system-ui, so wrapping differs (e.g. 'Do not finish / my sentence' docked vs 'Do not finish my / sentence' in Settings) — the editor preview is not the panel 'as it will actually appear'.

**Evidence.**

```
app/css/styles.css:981-984:
:where(#settingsDialog) :where(button, input, select, textarea) {
    font-family: inherit;
    font-size: inherit;
}
Measured: docked #expressPanel .ep-text fontFamily 'Arial'; hosted in Settings 'system-ui, -apple-system…'; .response-text 'Arial'; .cmd-btn 'Arial'; #appKeyboard .kbd-key 'system-ui'; #composerInput 'system-ui'.
```

**How it happens.** Start the app at 1280x800. Compare the Express Panel cell 'Do not finish my sentence' on the conversation screen with the same cell after opening Settings > Express Panel and Keyboard: the font and line breaks change.

**Suggested fix.** Make buttons inherit the house font everywhere with a zero-specificity rule near the body rule:
:where(button, input, select, textarea) { font-family: inherit; }
(leave font-size alone outside the dialog — conversation-surface controls set their own sizes). Then the dialog-scoped rule's font-family line becomes redundant but harmless.

**How to verify the fix.** Browser check: on the conversation screen, getComputedStyle of #expressPanel .ep-btn, .response-card, .cmd-btn, .kbd-key all report the same font-family; with Settings open on the Express tab, the hosted .ep-btn font-family equals the docked value. Re-run tests/ui-standards.test.mjs and tests/styles.test.mjs.

**Do not break.** Changing the face can change text wrapping in fixed-size cells; box sizes must not change (geometry is set by the grid, not content). Re-check the 'Choice button #N' and Command Bar word labels still fit (Rule 21).

**Design reference.** CLAUDE.md 'AS BUILT (August 8 2026)' (the Settings Express tab is 'a view of the panel as it will actually appear, edited in place'); UI-Design.docx §13.

**Verification notes.** The only font-family rule that reaches buttons is :where(#settingsDialog) :where(button,input,select,textarea){font-family:inherit} (styles.css:981). body sets system-ui (987), and .ep-btn, .response-card/.response-text and .cmd-btn set no font-family. A button does not inherit font-family by default; I measured Chrome's default as Arial in a test page. When the panel is reparented into #settingsDialog, the dialog rule applies, so the same cells change typeface. That contradicts the recorded intent that the Settings Express tab shows the panel 'as it will actually appear'.
