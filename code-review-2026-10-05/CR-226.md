# CR-226: Response cells inherit the slot tint, showing tinted corners and gaps around the cards

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:2291`
- **Also affects:** `app/js/ui.js:306 and 392 (cell.className includes the slot class)`; `app/css/styles.css:1963-1968 (.response-cell)`
- **Source:** css-08

**What a user notices.** In the Bold outlines and color-blind schemes, small square colored patches show at the rounded corners of the response cards, and with two cards per category a colored strip appears between the stacked cards.

**What is wrong.** ui.js puts the slot class (slot-preferred etc.) on the .response-cell wrapper as well as on the card. `.slot-*` rules set `background: var(--slot-*-tint)`, so the cell is painted with the tint. The card has a 10px border radius and a 2px --edge-strong border, so the cell's square tint is visible outside the rounded corners, and in split cells (two cards) the tint fills the --grid-gap between the cards while the gaps between categories show the page. The comment at styles.css:2313 already notes the slot class sits on the cell and caused one bug.

**Evidence.**

```
styles.css:2291 `.slot-preferred    { border-left-color: var(--slot-preferred);    background: var(--slot-preferred-tint); }`
ui.js:306 `cell.className = `response-cell ${slotCls}${split ? ' response-cell-split' : ''}`;`
```

**How it happens.** Settings > Text & Color > Bold outlines; look at the corners of the four response cards: square tinted corners behind the rounded outline. Set two responses per category and a non-zero gap: a tinted strip between the two cards of each category.

**Suggested fix.** After the slot rules (after line 2295) add `.palette-grid > .response-cell { background: transparent; }` (0,2,0 beats the 0,1,0 slot rule).

**How to verify the fix.** Visual check in Bold and Color-blind schemes; card rects unchanged.

**Do not break.** Do not remove the slot class from the cell in JS without checking the cb-scheme selector note at styles.css:2313; empty reserved cards keep their own tint because they are .response-card.

**Design reference.** CLAUDE.md UI Layout Rule 22/23 and the comment at styles.css:2313

**Verification notes.** ui.js:306 and 392 put the slot class on the .response-cell as well as the card, and .slot-* (styles.css:2291-2294) sets background to the slot tint, so the cell is painted. The card has a 10px radius and 2px border, so the cell's square tint shows outside the rounded corners, and with two cards per category and a non-zero gap the cell tint fills the gap between them. No rule clears the cell background. Visibility depends on how far the tint is from the page (faint in Default, clearer in Bold where the tint is #d9ead9).
