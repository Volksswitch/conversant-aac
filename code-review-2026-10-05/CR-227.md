# CR-227: Express Panel phrases with a word wider than the cell are cut off mid-letter with no ellipsis (side dock)

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:2498`
- **Also affects:** `app/css/styles.css:2351-2357 (.ep-btn overflow:hidden, font-size)`
- **Source:** live-visual-05

**What a user notices.** On a narrower screen with the panel at the side, some phrases show chopped-off words like "Awesom" and "somethin", so the user cannot be sure what the button says.

**What is wrong.** .ep-text wraps at spaces and line-clamps to 3 lines (ellipsis only for vertical overflow), but sets no overflow-wrap/word-break/hyphens. A single word longer than the cell's content width overflows horizontally and is silently clipped by .ep-btn's overflow:hidden — no ellipsis — contradicting the §13/Rule 9 contract 'the phrase, truncated with an ellipsis'. At 1180x820 with the side dock the cell content box is about 53px wide, so 'Awesome' and 'something' are cut.

**Evidence.**

```
app/css/styles.css:2498-2506:
.ep-text {
    white-space: normal;
    overflow: hidden;
    text-align: center;
    line-height: 1.12;
    display: -webkit-box;
    -webkit-line-clamp: 3;
    -webkit-box-orient: vertical;
}
Audit at 1180x820 side dock (light/dark/yellow): span.ep-text "I need something for my care" scrollWidth 58-60 vs clientWidth 53; screenshot shows 'Awesome' rendered as 'Awesom' and 'I need somethin / for my / care'.
```

**How it happens.** Viewport 1180x820 (iPad-class), Settings > Express Panel and Keyboard > Side of the screen, default Always phrases. Look at the 'Awesome' and 'I need something for my care' cells.

**Suggested fix.** Add to .ep-text: overflow-wrap: anywhere; (optionally hyphens: auto; — <html lang="en"> is already set) so an over-long word breaks onto the next line and the existing 3-line clamp supplies the ellipsis when needed.

**How to verify the fix.** Browser check: at 1180x820 side dock, for every #expressPanel .ep-text assert scrollWidth <= clientWidth + 1. Visually confirm 'Awesome' and 'something' are fully readable (broken or hyphenated).

**Do not break.** Text-only change; must not alter .ep-btn box properties (keyguard geometry, tests/styles.test.mjs guards). Check the response cards (.response-text) for the same issue if a long single word is generated.

**Design reference.** UI-Design.docx §13 'Express Panel button — The phrase, truncated with an ellipsis'; CLAUDE.md UI Layout Rule 9.

**Verification notes.** .ep-text (styles.css:2498-2506) wraps at spaces and line-clamps to 3 lines but sets no overflow-wrap, word-break or hyphens. .ep-btn has overflow:hidden (2354), so a single word wider than the cell is clipped horizontally with no ellipsis, because -webkit-line-clamp only adds an ellipsis for vertical overflow. 'Awesome' and 'I need something for my care' are shipped defaults (express-items.js:178-182). The narrow side-dock cell width is the reviewer's measurement, but the mechanism is unambiguous. Adding overflow-wrap: anywhere is a text-only fix and does not touch the box.
