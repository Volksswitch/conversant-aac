# CR-230: Hovering a Context-band partner or feeling makes it look switched on; More button loses its label on keyboard focus

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/css/styles.css:5176`
- **Also affects:** `app/css/styles.css:2578-2593 (Context band neutral fill and its focus rule)`; `app/css/styles.css:2463-2467 (.ep-btn.ep-more white text on band fill)`; `app/css/styles.css:2507-2511 (.ep-btn:focus-visible sets background only)`
- **Source:** css-03

**What a user notices.** On a Surface with the keyboard cover or a mouse, resting the pointer on (or tapping) a person or feeling button in the Context band makes it look exactly like it is switched on, while a place button beside it turns white. A keyboard user tabbing to the More button sees a blank button.

**What is wrong.** Inside @media (hover: hover), `.ep-btn.ep-choice:hover, .ep-btn.ep-partner:hover, .ep-btn.ep-feeling:hover` (0,3,0, declared last) paints a dark fill of the kind's own colour with white text. That was written for the old solid influencer fill; since August 23 2026 Context-band partner/place/feeling buttons use the band tint and only the ON state is a solid fill (`.ep-btn.ep-band-context.ep-on`). Because the hover rule is later with equal specificity, an un-lit partner/feeling under the pointer computes the same dark fill + white text as a lit one (measured: hovered OFF partner = dark brown, white text). Place buttons are not in that list, so they fall to `.ep-btn:hover` (white fill) - two kinds in one band hover differently. Separately, `.ep-btn:focus-visible` (line 2507, later than `.ep-btn.ep-more` at 2463, same specificity) sets background --surface-raised but not color, so a focused More/Close button shows its white label on white.

**Evidence.**

```
styles.css:5176-5182 `.ep-btn.ep-choice:hover, .ep-btn.ep-partner:hover, .ep-btn.ep-feeling:hover { background: color-mix(in srgb, var(--ep-color) 82%, var(--shade)); color: var(--ink-inverse); outline-color: var(--ep-color); }`
styles.css:2578-2584 `.ep-btn.ep-band-context.ep-partner, ... { background: var(--band-tint); color: var(--ink); ... }`
styles.css:2463-2467 `.ep-btn.ep-more { background: var(--band-color, var(--edge-strong)); ... color: var(--ink-inverse); }`
styles.css:2507 `.ep-btn:focus-visible { background: var(--surface-raised); outline: 2px solid var(--ep-color); outline-offset: -1px; }`
```

**How it happens.** Surface with type cover, Context band showing an un-lit person button: move the pointer over it (or tap it in two-tap mode and leave the finger-hover stuck) - it renders with the solid fill and white text of a lit button. Tab with a physical keyboard to the More button - its label disappears.

> **Verifier correction to the trigger:** Two details are wrong. A hovered un-lit partner or feeling is not identical to a lit one: the lit one also has the .ep-on ring and the check mark, so it looks filled like a lit button but without the ring and check. A hovered place button does NOT turn white: .ep-btn:hover is 0,2,0 and loses to .ep-btn.ep-band-context.ep-place (0,3,0), so the place keeps its band tint and only gains an outline. The inconsistency is real (partner/feeling go solid, place stays tinted) but the description should say that.

**Suggested fix.** In the @media (hover: hover) block, after the existing partner/feeling hover rule, add band-aware overrides:
.ep-btn.ep-band-context.ep-partner:hover,
.ep-btn.ep-band-context.ep-place:hover,
.ep-btn.ep-band-context.ep-feeling:hover { background: var(--surface-raised); color: var(--ink); outline-color: var(--band-color); }
.ep-btn.ep-band-context.ep-on:hover { background: color-mix(in srgb, var(--band-color) 82%, var(--shade)); color: var(--ink-inverse); }
(0,4,0 beats 0,3,0). Outside the media block, after line 2511, add:
.ep-btn.ep-more:focus-visible { background: color-mix(in srgb, var(--band-color, var(--edge-strong)) 82%, var(--shade)); color: var(--ink-inverse); outline-color: var(--band-color, var(--edge-strong)); }

**How to verify the fix.** Manual on a device with a mouse: hover an un-lit and a lit partner, place and feeling in the Context band - un-lit ones stay light, lit ones stay filled. Tab to More with a physical keyboard - label readable. Check getBoundingClientRect of the cells is unchanged.

**Do not break.** Paint only; no box properties. Keep :focus-visible outside the hover media query (Rule 20). Partner/feeling buttons that are NOT in a band (none today) should keep the existing rule.

**Design reference.** CLAUDE.md UI Layout Rule 20 (hover is decoration, never information) and the August 23 2026 band design (styles.css comment at 2569)

**Verification notes.** Inside @media (hover: hover), .ep-btn.ep-choice:hover, .ep-btn.ep-partner:hover, .ep-btn.ep-feeling:hover (0,3,0, styles.css:5176) comes after the Context-band neutral rule .ep-btn.ep-band-context.ep-partner/... (0,3,0, 2578), so an un-lit partner or feeling in the Context band takes a dark solid fill with white text under the pointer. Separately .ep-btn:focus-visible (2507, 0,2,0) is later than .ep-btn.ep-more (2463, 0,2,0) and sets background --surface-raised without color, leaving the More label white on white when focused from the keyboard.
