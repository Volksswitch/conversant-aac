# CR-232: 'Let me drag the borders to resize' checkbox uses an unstyled class and renders bold, unlike every other checkbox

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/index.html:767`
- **Also affects:** `app/css/styles.css:3437-3442 (dialog label bold block)`; `app/css/styles.css:3828-3835 (.checkbox-label)`
- **Source:** live-visual-11

**What a user notices.** On Settings > Screen Layout, this one on/off option is in bold heading-style text with no gap, so it reads like a title rather than a choice, unlike all the other checkboxes.

**What is wrong.** The label is class="checkbox-row", which has no CSS rule, so it falls back to 'dialog label' (display:block; font-weight:600). All other checkbox labels use class "checkbox-label" (flex row, weight 400).

**Evidence.**

```
app/index.html:767-770:
                        <label class="checkbox-row">
                            <input type="checkbox" id="layoutUnlockToggle">
                            Let me drag the borders to resize
                        </label>
Measured: layoutUnlockToggle label font-weight 600; every other checkbox label 400.
```

**How it happens.** Settings > Screen Layout > Resizing the screen areas.

**Suggested fix.** Change class="checkbox-row" to class="checkbox-label" in app/index.html:767.

**How to verify the fix.** Browser check that the label's computed font-weight is 400 and display is flex.

**Do not break.** none

**Design reference.** UI-Design.docx §13.

**Verification notes.** index.html:767 uses class 'checkbox-row', which has no CSS rule; the only similar rule is .wv-person-checkbox-row. The label therefore takes 'dialog label' (display:block, font-weight:600). Changing it to checkbox-label is safe: sections.js picks the first non-checkbox label as the section heading, and that is 'Resizing the screen areas', which comes first.
