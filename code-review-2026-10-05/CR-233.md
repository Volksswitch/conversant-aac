# CR-233: "Button size" was removed but the section, its spoken help, its Reset help and the manuals still describe it

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/index.html:779`
- **Also affects:** `settings-help.json:58`; `settings-help.json:146`; `app/index.html:788`; `Documents/Conversant AAC User Manual (Windows Chromebook Mac).docx (paragraph 333, 'button and gap sizes')`; `Documents/Conversant AAC User Manual (iPad).docx (paragraph 349)`; `Documents/Conversant AAC User Manual (Android).docx (paragraph 334)`; `app/index.html:779 (merged duplicate: 'Button sizes and gaps' section and its spoken help describe a button-size control that no longer exists)`
- **Source:** x-defaults-02, live-visual-12

**What a user notices.** The Screen Layout tab has a section called "Button sizes and gaps" that contains only a spacing slider, and the spoken help says it sets "how big every button in the app is". A user looking for a button-size control will not find one and may think it is broken or hidden.

**What is wrong.** The 'Button size' slider was removed in September 2026 (storage.js migrateBundle comment; app.js applyButtonSizing 'WARNING: Button size USED TO LIVE HERE AND IS GONE'). The section heading still reads "Button sizes and gaps", the section's spoken help still describes button size, and the spoken help for the reset button says it puts 'button size and spacing back'. The visible reset button itself was correctly renamed "Reset spacing to default". The three user manuals still say a settings profile holds 'button and gap sizes'.

**Evidence.**

```
app/index.html:779  <label>Button sizes and gaps</label>
app/index.html:788  <button id="resetSizingBtn" ...>Reset spacing to default</button>
settings-help.json:58  "buttonSizing": "How big every button in the app is and how much space sits between them. Changing these moves the holes in a keyguard."
settings-help.json:146  "resetSizingBtn": "Puts button size and spacing back to how they started. Screen edge margin is left alone."
app/js/app.js:4756  // WARNING: "Button size" USED TO LIVE HERE AND IS GONE (Ken, September 2026).
Windows manual para 333: "A profile holds your voice, dock and layout, button and gap sizes, timings..."
```

**How it happens.** Settings > Screen Layout > open "Button sizes and gaps": only "Button spacing" is inside. Tap ? then the heading: the app says it controls how big every button is. Tap ? then "Reset spacing to default": it says it resets button size.

> **Verifier correction to the trigger:** The Windows manual's profile row (para 333) also carries the stale 'button and gap sizes' wording, not only iPad/Android; fix all three.

**Suggested fix.** index.html line 779: rename the heading to "Button spacing" is not possible (it would duplicate the slider label), so use "Spacing between buttons" or "Gaps between buttons" (Ken's call on wording; keep data-help="buttonSizing"). settings-help.json: buttonSizing -> "How much space sits between the buttons. Changing it moves the holes in a keyguard."; resetSizingBtn -> "Puts the spacing between buttons back to how it started. The screen areas and the screen edge margin are left alone." Run `node scripts/apply-settings-help.mjs`. In all three User Manuals, in the Settings profiles row, replace "button and gap sizes" with "button spacing" (documents: follow the sync-docs backup rule and do not edit a document carrying tracked changes or comments).

**How to verify the fix.** npm test (settings-help drift + coverage test). Open Settings > Screen Layout, arm ?, tap the heading and the reset button and listen. python scripts/doc-tests/check-docs.py after the manual edits.

**Do not break.** Keep data-help="buttonSizing" and the resetSizingBtn id (tests/settings-help.test.mjs keys on them). Do not touch the convLayout reset, which is a separate button.

**Design reference.** CLAUDE.md UI Layout Rule 18 (the 'Button sizes and gaps' example is itself now stale); storage.js 'CARRYING A REMOVED SETTING FORWARD'
