# CR-235: Azure practice-partner 'Auto' and the scenario voice list ignore the account's own Azure voice list

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:1121`
- **Also affects:** `app/js/app.js:1183`; `app/js/app.js:7666`; `app/js/app.js:7706`
- **Source:** x-providers-12

**What a user notices.** With an Azure voice, the practice partner's automatic voice and the per-scenario voice list come from a short built-in list, which may include voices the account's region does not offer, so the partner can fall back to the device voice.

**What is wrong.** pickAzurePartnerVoice and practiceVoiceChoices read ttsAzure.VOICES (16 shipped voices), while the Settings pickers use the fetched account catalog (storage.loadAzureVoiceCatalog), and refreshAzureVoices explicitly handles the shipped default being absent from the account's region. The catalog services already use the cached catalog in pickRestPartnerVoice and practiceVoiceChoices, so Azure is the odd one out.

**Evidence.**

```
app/js/app.js:1123-1125:
    const own = storage.loadAzureVoice() || ttsAzure.DEFAULT_VOICE;
    const other = ttsAzure.VOICES.find((v) => v.id !== own);
app/js/app.js:1183: if (service === 'azure') return { service, options: ttsAzure.VOICES.map(named) };
app/js/app.js:7666-7668: partnerRedraw.azure = () => fillVoiceSelect(azurePartnerVoiceSelect, (storage.loadAzureVoiceCatalog() || {}).voices || ttsAzure.VOICES, ...
```

**How it happens.** Azure account in a region whose catalog lacks en-US-JennyNeural; the user's voice is Ava. Practice partner on Auto picks Jenny from the shipped list; Azure refuses it and every partner line falls back to the device voice with an error logged.

> **Verifier correction to the trigger:** The concrete failure (a region whose catalog lacks the voice Auto picks) is hypothetical. Most en-US neural voices are widely available, so the likelier visible effect is that the per-scenario voice list differs from the Settings list, rather than a fallback to the device voice.

**Suggested fix.** In pickAzurePartnerVoice use `const list = ((storage.loadAzureVoiceCatalog() || {}).voices) || ttsAzure.VOICES;` and find in that list; in practiceVoiceChoices use the same list for 'azure'.

**How to verify the fix.** Manual: with a cached Azure catalog, start practice on Auto and confirm the Azure partner Test plays a voice from the account's list.

**Do not break.** Keep the shipped list as the fallback when no catalog is cached.

**Design reference.** CLAUDE.md UI Layout Rule 17 (partner voice must be usable and distinct)

**Verification notes.** pickAzurePartnerVoice (app.js:1121-1126) and the azure branch of practiceVoiceChoices (1183) read the 16 shipped ttsAzure.VOICES. The Settings pickers and the catalog-service paths read the cached account catalog. The inconsistency is real. Whether a shipped voice is actually missing in a given region was not verified.
