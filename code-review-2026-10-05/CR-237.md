# CR-237: Opener cards are not refreshed when the partner is chosen after pressing Start conversation

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:4577`
- **Also affects:** `app/js/app.js:4511 (refreshForContextChange skips static palettes)`; `app/js/app.js:3144-3146 (handleInitiate personalizes openers once, at press time)`
- **Source:** app-d-09

**What a user notices.** If the person presses Start conversation and then taps who they are talking to, the openers still show the generic greetings (or the previous person's name) instead of that person's own openers and name.

**What is wrong.** handleTogglePartner calls applyControlPhrases(), which updates the engine's opener list, but the opener palette already on screen was built by engine.initiate({partnerName}) at press time and is never redrawn; refreshForContextChange deliberately returns false for static palettes. So the visible openers do not include the new partner's own openers and use the old name substitution, while the comment says partner-specific starters come first.

**Evidence.**

```
app/js/app.js:4574-4577
  // Re-merge their own starters and closings into the engine's static palettes.
  // Switching partner has to re-run this in both directions ...
  applyControlPhrases();
app/js/app.js:4511  if (currentStatic.kind) return false;
```

**How it happens.** No partner active. Press Start conversation (generic openers appear). Tap the 'Mom' partner button, who has her own openers. The cards still show the generic list without Mom's openers or her name.

**Suggested fix.** In handleTogglePartner, after applyControlPhrases(), if `currentStatic.kind === 'opener'` re-run the opener render without toggling the overlay: `const snap = engine.initiate({ partnerName: partnerLabel(activePartner) }); ui.showEngineState(snap); renderStaticPalette('opener', snap.palette, 'Pick an opener');`. Do not call handleInitiate (it is a toggle and would cancel).

**How to verify the fix.** Manual as in the failure scenario: after tapping Mom, the opener cards must show her openers first and her name.

**Do not break.** Must not disturb the Start-conversation overlay backout (overlayEnter/overlayCancel captured palette) - only re-render the static palette contents.

**Design reference.** CLAUDE.md 'Per-partner profile' (openers ADD to the global list, theirs first, re-merged on every partner change)

**Verification notes.** Traced. handleInitiate renders the openers once, from engine.initiate({partnerName}). handleTogglePartner calls applyControlPhrases(), which updates the engine's opener list, but nothing redraws the opener palette already on screen, and refreshForContextChange returns false for static palettes. The visible openers keep the old list and the old name until Start conversation is pressed again.
