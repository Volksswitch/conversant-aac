# CR-240: Cost breakdown labels a token count as 'words in and out', and the count includes cached tokens re-read on every request

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6143`
- **Also affects:** `app/js/app.js:6137`
- **Source:** g-misc-overflow-05

**What a user notices.** The cost breakdown says the AI handled a number of 'words' that is several times larger than anything the user actually said or read, which makes the figure look alarming and impossible to check against the Anthropic bill.

**What is wrong.** `words` is the sum of input + cache-write + cache-read + output TOKENS. Tokens are not words (roughly 0.75 words per token), and, more importantly, cacheReadTokens counts the ~3,570-token cached prompt prefix again on EVERY suggestion request (several per partner turn at the 0.5 s silence period), so the number is dominated by the same instructions being re-read, not by words exchanged. Labelled 'words in and out', it reads as a count of conversation words and can be an order of magnitude higher than the conversation. Anthropic's statement reports tokens, so the label also prevents the user checking the figure against the bill, which is the stated purpose of naming the company on this line (comment at 6125-6131).

**Evidence.**

```
app.js:6137-6138  const words = usage.inputTokens + usage.cacheWriteTokens + usage.cacheReadTokens + usage.outputTokens;
app.js:6143  line('Anthropic Claude', `${words.toLocaleString()} words in and out`, aiCost);
```

**How it happens.** Use a paid speech service so the breakdown appears, hold a ten-minute conversation, open Settings > About. The Anthropic line shows e.g. '250,000 words in and out' for a conversation of a few hundred spoken words.

**Suggested fix.** Rename the variable to `tokens` and relabel the amount so it is honest and still plain: e.g. `${tokens.toLocaleString()} tokens (Anthropic's billing unit)`. If Ken prefers no technical term on this surface, show no amount at all for this line (pass '' like the company total lines do) rather than a mislabeled one. Do not attempt a tokens-to-words conversion: cache reads make any such figure meaningless.

**How to verify the fix.** Manual: with stored usage set (e.g. via storage.addUsageTokens({input:1000, output:500, cacheRead:90000})) and sttSeconds > 0, open Settings > About; the Anthropic line must not use the word 'words'. Check the manuals' 'Estimated cost' paragraph still matches.

**Do not break.** Ken's plain-language rule: avoid jargon in user-facing text; if 'tokens' is used, give it a plain gloss. Do not change the cost arithmetic or the '% reused rather than re-sent' line, whose wording is deliberate.

**Design reference.** CLAUDE.md 'Prompt caching — BUILT August 8 2026' (input_tokens vs cache buckets) and the PLAIN LANGUAGE rule

**Verification notes.** app.js:6137-6143 sums input + cacheWrite + cacheRead + output tokens and labels the total '<n> words in and out'. Introduced in commit e1e6bff with no recorded decision about the wording, and nothing in CLAUDE.md or the manuals settles it. The cache reads re-count the cached prefix on every request, so the figure overstates conversation volume many times over and does not match the unit on the Anthropic statement. Cosmetic: it does not affect the cost arithmetic.
