# CR-241: Cost breakdown shows the internal word 'builtin' as a company name

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6153`
- **Also affects:** `app/js/app.js:52-56 (SPEECH_COMPANY has no builtin entry)`; `app/js/storage.js:1344-1346 (loadTtsProvider defaults to 'builtin')`; `app/js/app.js:6068-6069 (rate lookup)`; `app/js/app.js:52 (merged duplicate: The cost breakdown shows the internal word 'builtin' as a company name)`
- **Source:** app-e-09, x-providers-09

**What a user notices.** Someone who hears through the free built-in recognizer and pays only for a better voice sees a line in the cost breakdown labeled 'builtin' with $0.00, which looks like a mistake or an unknown company.

**What is wrong.** The breakdown names each speech line with SPEECH_COMPANY[p] || p. SPEECH_COMPANY covers deepgram, azure and the catalog providers but not 'builtin' (the free device recognizer / voice). The breakdown is shown whenever sttSeconds > 0 OR ttsCharacters > 0, so the recommended configuration 'free browser hearing + paid voice' (CLAUDE.md) always prints a 'builtin' company line followed by 'Hearing  not used  $0.00'. The same happens with a paid recognizer and the device voice. The fallback-to-id was meant to expose a FORGOTTEN paid service, not the deliberate free one.

**Evidence.**

```

const SPEECH_COMPANY = {

app/js/app.js:6160-6164
                line(nameOf(sttProviderNow), '', sttCost);
                line('Hearing', heard, sttCost, 'usage-sub');
```

**How it happens.** Settings > Speech: hearing = This device, voice = Deepgram. Have a conversation, then open Settings > About. The breakdown reads 'Anthropic Claude ...', 'builtin $0.00', 'Hearing not used $0.00', 'Deepgram $0.02', 'Speaking ...'.

**Suggested fix.** In updateUsageDisplay, skip the company line and its sub-line for a side whose provider is 'builtin' (it costs nothing and has no bill to check): e.g. `const paidStt = sttProviderNow !== 'builtin'; const paidTts = ttsProviderNow !== 'builtin';` and only emit the hearing pair when paidStt (or sttSeconds > 0) and the speaking pair when paidTts (or ttsCharacters > 0). If a builtin line must remain, label it 'This device (free)' via a `builtin` entry in SPEECH_COMPANY.

**How to verify the fix.** Manual: set hearing to This device and voice to a paid service, speak something, open About: no 'builtin' text. Add a source-level check in tests/settings-help.test.mjs or a new test that SPEECH_COMPANY or the breakdown handles 'builtin'.

**Do not break.** Keep the rule that an unknown PAID service shows its own id rather than borrowing another company's name.

**Design reference.** CLAUDE.md 'Five paid speech services' / pricing comments in updateUsageDisplay (three separate estimates, named by company).

**Verification notes.** SPEECH_COMPANY (app.js:52-56) contains deepgram, azure, and the catalog ids openai/google/elevenlabs (verified by importing speech-catalog.js). It has no 'builtin' entry. loadTtsProvider defaults to 'builtin', and loadSttProvider returns 'builtin' on most platforms. The breakdown is shown whenever sttSeconds > 0 or ttsCharacters > 0. With free hearing and a paid voice, the names differ, so the else branch prints line(nameOf('builtin'), ...), which renders the literal 'builtin' followed by 'Hearing not used $0.00'.

<details><summary>Merged duplicate x-providers-09: The cost breakdown shows the internal word 'builtin' as a company name</summary>

SPEECH_COMPANY maps only the paid services. nameOf(p) falls back to the raw id, so when either hearing or speaking is the free option the breakdown prints a heading 'builtin'. The breakdown is shown whenever any paid usage exists, so the mixed free-hearing + paid-voice configuration (recorded in CLAUDE.md as the valuable steady state on Chromium) always shows it.

Fix as proposed by that reviewer: When a side is 'builtin', skip its company and sub-lines entirely: in the breakdown, `if (sttProviderNow !== 'builtin') { line(nameOf(sttProviderNow), '', sttCost); line('Hearing', heard, sttCost, 'usage-sub'); }` and likewise for speaking; keep the combined branch only when both are the same paid company. Alternatively add `builtin: 'This device (free)'` to SPEECH_COMPANY.
