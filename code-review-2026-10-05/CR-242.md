# CR-242: Cost breakdown shows '0 min heard' for paid hearing under 30 seconds

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:6154`
- **Also affects:** `app/js/app.js:6112`
- **Source:** g-misc-overflow-06

**What a user notices.** Right after trying a paid hearing service briefly, the breakdown appears (because something was billed) but says '0 min heard', which looks like a counting error.

**What is wrong.** The breakdown is shown as soon as sttSeconds > 0, but the hearing amount is Math.round(sttSeconds / 60), so any total below 30 seconds prints '0 min heard' next to a non-zero (or $0.00) cost; 31-89 seconds prints '1 min'. The gate and the label disagree about whether anything was heard.

**Evidence.**

```
app.js:6112  const paidUsed = sttSeconds > 0 || ttsCharacters > 0;
app.js:6154  const heard = sttSeconds > 0 ? `${Math.round(sttSeconds / 60)} min heard` : 'not used';
```

**How it happens.** Choose Deepgram (or Azure) for hearing, listen for 20 seconds of speech, open Settings > About: the Hearing line reads '0 min heard'.

**Suggested fix.** Show seconds under a minute: `const heard = sttSeconds <= 0 ? 'not used' : sttSeconds < 60 ? `${Math.round(sttSeconds)} sec heard` : `${Math.round(sttSeconds / 60)} min heard`;`.

**How to verify the fix.** Manual: set storage settings usageSttSeconds to 20 and open Settings > About; line reads '20 sec heard'. At 600 it reads '10 min heard'.

**Do not break.** none

**Design reference.** none

**Verification notes.** app.js:6111 shows the breakdown when sttSeconds > 0, and 6154 prints Math.round(sttSeconds/60) min, so 1-29 seconds reads '0 min heard'. Cosmetic.
