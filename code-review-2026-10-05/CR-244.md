# CR-244: A failure while choosing a data folder is reported only in the hidden status bar

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/app.js:7010`
- **Also affects:** `app/css/styles.css:3108-3121 (#statusBar is visually hidden)`; `app/js/app.js:7026 (Reload message also goes to the hidden status bar)`
- **Source:** app-f-10

**What a user notices.** If choosing a data folder fails (for example the browser's permission prompt is declined), nothing on screen says so; the user just sees 'No folder selected' and may think conversations are being saved.

**What is wrong.** The Choose Folder handler reports any non-cancel error with ui.setStatus, which writes to #statusBar - removed from view in v0.5.2 and kept only as a screen-reader live region. CLAUDE.md already notes this pattern makes messages invisible. Settings has visible live-status elements for exactly this.

**Evidence.**

```
app/js/app.js:7004-7013
  } catch (err) { if (err.name !== 'AbortError') { ui.setStatus(`Folder error: ${err.message}`); } }
app/css/styles.css:3108 /* Status bar removed from view (Ken) — kept as a visually-hidden aria-live region */
```

**How it happens.** Settings > General > Choose Folder, pick a folder, then decline the 'allow edit' permission prompt (NotAllowedError) - no visible message.

> **Verifier correction to the trigger:** It is not verified that declining Chrome's write-permission prompt raises a non-Abort error (it may raise AbortError, which is deliberately silent). The confirmed point is that EVERY non-AbortError on this path is invisible, for example a failure in ensureDataSubfolders or adoptDataFolder after the folder was picked.

**Suggested fix.** Add a live status element next to the folder name in index.html (e.g. <p class="api-key-status" id="dataFolderStatus" role="status" hidden>) and report with setStatusLine('dataFolderStatus', 'warn', `Could not use that folder: ${err.message}`); clear it on success.

**How to verify the fix.** Manual as in failure_scenario; message appears beside the folder name.

**Do not break.** Live status is permitted by Rule 14; add a spoken-help entry only if the coverage test requires one for a new element (status lines are not controls).

**Design reference.** CLAUDE.md iPad section ('routes through ui.setStatus, which has been visually hidden since v0.5.2'); UI Layout Rule 14.

**Verification notes.** Any non-AbortError from the Choose Folder handler (app.js:7004-7013) goes to ui.setStatus, which writes to #statusBar (ui.js:1095-1097). styles.css:3108-3120 hides #statusBar visually (clip and 1px size). So the failure message never appears on screen. Failure sources include ensureDataSubfolders or adoptDataFolder throwing after showDirectoryPicker succeeded (storage.js:295-302). In that case the folder may already be set while the display never updates, because updateFolderDisplay is not reached.
