# CR-247: Commands tab reset warning does not mention the "one more thing" phrases it also resets

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/control-phrases-editor.js:122`
- **Also affects:** `app/js/control-phrases.js:308-317`
- **Source:** phrases-practice-13

**What a user notices.** The reset warning lists what will be lost but leaves out the 'one more thing' phrases, so a user who customized those is not told they will be replaced.

**What is wrong.** resetPhrases() replaces every list including declineClosing, but the confirmDanger body enumerates only asking them to repeat, trying again, the openers, the wind-down statements and the goodbyes.

**Evidence.**

```
control-phrases-editor.js:122 `body: 'This restores the default wording for every command phrase — asking them to repeat, trying again, the openers, the wind-down statements and the goodbyes. Your edits will be lost.'`
control-phrases.js:309 `phrases = normalize(DEFAULTS);`
```

**How it happens.** Edit a 'One more thing' phrase, tap Reset to default, read the warning (no mention), confirm: the edited phrase is replaced.

**Suggested fix.** Change the body to '...the openers, the wrap-up statements, the goodbyes and the "one more thing" phrases. Your edits will be lost.' (also aligns 'wind-down' with the 'Wrap up' button name).

**How to verify the fix.** Manual: open the reset dialog and read the text.

**Do not break.** Keep American English and plain style.

**Design reference.** CLAUDE.md Configurability philosophy: confirm before destroying significant work.

**Verification notes.** resetPhrases() restores normalize(DEFAULTS), which includes declineClosing (in LIST_KEYS), but the confirmDanger body at control-phrases-editor.js:122 lists only repeat, retry, openers, wind-downs and goodbyes. The 'one more thing' phrases are reset without being mentioned.
