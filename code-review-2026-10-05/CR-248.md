# CR-248: Place buttons keep their old name after the place is renamed in My Places, unlike partner buttons

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:218`
- **Also affects:** `app/js/express-editor.js:441-443`; `app/js/ui.js:573`; `app/js/app.js:4114-4120`; `app/js/app.js:4633`; `app/js/app.js:4469-4472`
- **Source:** express-10

**What a user notices.** If the user renames a place in My Places, the place's button on the Express Panel still shows the old name (and the status and saved conversations use it), while a renamed person's button updates straight away. In the editor the place picker shows the new name next to a button showing the old one.

**What is wrong.** Partner faces are resolved live from About Me (composedPanel maps partner items through partnerLabel / relationships.displayName, and the editor's labelOf does the same). Place items store a copy of the name at pick time (save({ placeId: id, name })) and every consumer reads item.name: ui.renderExpressPanel label, labelOf in the editor, the 'At X' status, and placeStamp. places.js has no live lookup in this path, so a rename in My Places never reaches the button. The editor's picker selects by id (showing the new name) beside the stale face.

**Evidence.**

```
express-editor.js:218 `return String(item.text || item.name || '').trim();` (place uses stored name) vs :217 partner uses `relationships.displayName(item.personId, item.name)`
express-editor.js:443 `(id, name) => save({ placeId: id, name })`
ui.js:573 `const label = item.name || 'Place';`
app.js:4118-4120 only partner items get a resolved `label`.
```

**How it happens.** Add place 'Starbucks', put it on the panel, then rename it in My Places to 'Starbucks on Main'. The panel button still reads 'Starbucks'.

**Suggested fix.** Mirror the partner approach. In app.js composedPanel, also map place items: `item.type === 'place' ? { ...item, name: (item.placeId && places.getPlace(item.placeId)?.name) || item.name } : ...`. In express-editor labelOf, for type 'place' return `(item.placeId && places.getPlace(item.placeId)?.name) || item.name || ''`. In handleTogglePlace/placeStamp read the live name the same way (or rely on the composed item, which now carries it).

**How to verify the fix.** Manual: rename a place in My Places and confirm the panel button, the editor row, and the 'At ...' status show the new name. Unit: none needed beyond existing places tests.

**Do not break.** Keep the stored name as the fallback for a place that has since been deleted (same reasoning as partnerLabel). Do not send a respelling to the AI (places.js pronunciation is speak-time only).

**Design reference.** app.js partnerLabel comment (names answered from About Me every time, Ken August 25 2026)

**Verification notes.** composedPanel (app.js:4114-4120) resolves a live label only for partner items. Place items keep the name stored at pick time (express-editor.js:443), which ui.js:573, labelOf, the status line and placeStamp all read. Nothing in places.js propagates a rename to the Express model.
