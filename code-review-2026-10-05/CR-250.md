# CR-250: Move and delete buttons do nothing, with no feedback, when no row is selected

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:498`
- **Also affects:** `app/js/express-editor.js:164-168`; `app/js/express-editor.js:177-180`
- **Source:** express-14

**What a user notices.** The up, down and delete buttons above each list look active all the time, but if no phrase is selected (or the selected one is in a different band) tapping them does nothing and nothing explains why.

**What is wrong.** toolbar() always renders ▲ ▼ ✕ enabled. move() and removePicked() return silently when pickedId is null or not in this band's list (e.g. after a delete, which clears pickedId; or after Settings reopens). For a population that taps imprecisely, a control that silently ignores a tap reads as broken.

**Evidence.**

```
express-editor.js:166-168 `const i = list.findIndex((x) => x.id === pickedId); const j = i + dir; if (i < 0 || j < 0 || j >= list.length) return;`
express-editor.js:179-180 `const i = list.findIndex((x) => x.id === pickedId); if (i < 0) return;`
```

**How it happens.** Delete a phrase (pickedId becomes null), then tap ✕ again expecting to delete the next one: nothing happens.

**Suggested fix.** In toolbar(band), after building, set `disabled` on the three tool buttons when `bandList(band).findIndex((x) => x.id === pickedId) < 0`, and also disable ▲ on the first row and ▼ on the last. Since markPicked deliberately does not re-render, update the disabled state in markPicked by querying `.ee-toolbar .ee-tool` within the picked row's section.

**How to verify the fix.** Manual: open the tab with nothing selected - the three tools are greyed; tap a row - they enable.

**Do not break.** markPicked must still not re-render the editor (that loses focus on the tapped field).

**Design reference.** none

**Verification notes.** toolbar() always renders the up, down and delete buttons enabled, and move() and removePicked() return silently when pickedId is not in that band's list (for example right after a delete, which sets pickedId null). No decision recording this as intended was found in CLAUDE.md.
