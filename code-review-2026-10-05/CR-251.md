# CR-251: One 'move up/down' action wears three glyph sets across the editors

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:500`
- **Also affects:** `app/js/express-editor.js:501 ('▼')`; `app/js/control-phrases-editor.js:80 ('↑')`; `app/js/control-phrases-editor.js:82 ('↓')`; `app/js/worldview-ui.js:843 ('↑', aria-label 'Move up') and :845 ('↓') - People / Places / general goals lists`; `app/js/placeholder-editor.js:13-20 (deliberately no reorder - see cautions)`; `app/js/icons.js:66-67 (prevTurn/nextTurn chevrons)`
- **Source:** g-visual-consistency-03

**What a user notices.** Moving an item up or down looks different depending on which screen you are on: thin arrows in Commands and About Me goals, solid triangles in the Express Panel editor. It reads as different controls when it is the same action.

**What is wrong.** Reordering is drawn with text characters, not icons, and with two different character sets: the Commands editor and About Me's goal list use U+2191/U+2193 (thin arrows), the Express Panel editor's toolbar uses U+25B2/U+25BC (solid triangles). Measured rendering: the thin arrows are hairline glyphs at ~1em while the triangles are filled blocks, so the two read as different controls. icons.js is the app's icon vocabulary and has no move-up/move-down entry, which is why each editor improvised. (The Commands editor's arrows also have no accessible name - already reported separately; the fix below also cures that.) The placeholder editor has no reorder at all, and that is a recorded decision (Ken, Sep 9 2026: order does not affect what is said there, so reorder buttons would contradict the tab text) - it should NOT gain reorder.

**Evidence.**

app/js/express-editor.js:501  bar.appendChild(mkBtn('▼', 'ee-tool', () => move(band, 1), 'Move the selected button down'));

**How it happens.** Open Settings > Commands (rows with ↑ ↓ ✕), then Settings > Express Panel and Keyboard (toolbar ▲ ▼ ✕), then About Me > People > a person's goals (↑ ↓ ✕). Same action, different glyphs.

**Suggested fix.** Add two entries to ICONS in app/js/icons.js, reusing the chevron paths already there: `moveUp: SVG('<path d="M6 15l6-6 6 6"/>')` and `moveDown: SVG('<path d="M6 9l6 6 6-6"/>')` (or alias prevTurn/nextTurn). Then: control-phrases-editor.js:80/82 - create with mkBtn('') and call setIconButton(up, 'moveUp', 'Move up') / setIconButton(down, 'moveDown', 'Move down'); also give the ✕ an aria-label 'Delete' (mkBtn there takes no title). express-editor.js:500/501 - setIconButton(btn, 'moveUp', 'Move the selected button up') / ('moveDown', ...). worldview-ui.js:843/845 - create the button without text and call setIconButton(up, 'moveUp', 'Move up') etc. Consider the same treatment for the ✕ delete glyph (ICONS.close) so all row tools share one vocabulary. Leave placeholder-editor.js without reorder.

**How to verify the fix.** In tests/ui-standards.test.mjs, assert that every Settings button whose aria-label starts with 'Move' contains an svg.icon and no text, and has an accessible name. Manually: the three screens above show the same chevron shape, in the scheme ink color, with tooltips; reorder still works and the first row's up / last row's down are disabled.

**Do not break.** Do not add reorder to the placeholder editor (recorded decision in placeholder-editor.js header, Ken Sep 9 2026). Keep button sizes (#controlEditor .ee-tools button is fixed square at --btn-min-dim; #expressEditor .ee-toolbar .ee-tool likewise) - setIconButton adds class icon-btn, so confirm no icon-btn rule changes those boxes. Keep the Express editor's toolbar model (acts on the selected row) - only the glyph changes.

**Design reference.** Conversant AAC UI-Design.docx §13 (fixed-function controls show an icon and carry an accessible name; one appearance per kind of control); icons.js; CLAUDE.md UI Layout Rule 4/12.

**Verification notes.** Verified in the code: control-phrases-editor.js:80/82 use mkBtn('↑')/('↓'), and that mkBtn (line 37) sets no title or aria-label, so those buttons have no accessible name beyond the arrow glyph. express-editor.js:500/501 use '▲'/'▼' with titles. worldview-ui.js:843/845 use '↑'/'↓' with aria-labels. icons.js has no move-up or move-down icon. The placeholder editor deliberately has no reorder, as its header records.
