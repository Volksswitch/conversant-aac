# CR-252: The 'Already set up' situation list shows the wrong situation, cannot select its first entry, and its delete X silently does nothing

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/express-editor.js:568`
- **Also affects:** `app/js/express-editor.js:574-597`; `app/js/express-editor.js:673-686`
- **Source:** express-06

**What a user notices.** In the Flex section, if the situation being edited has no phrases yet (for example 'Anyone at Anyplace' when only Mom's list exists), the 'Already set up' list displays Mom's situation as if it were current. Picking that entry does nothing, and the X beside it - labelled as deleting the situation shown - does nothing either.

**What is wrong.** The dropdown only marks an option selected when it equals the current flexPartner/flexPlace. When the current situation is not in flexSituations(), no option is selected, so the browser shows (and reports selectedIndex 0 for) the first entry. Choosing that already-'selected' first entry fires no change event, so the user cannot jump to it. The adjacent X is titled 'Delete every phrase for the situation shown', but deleteSituation() acts on flexPartner/flexPlace (the edited situation), not on the dropdown's displayed value; with an empty list it returns silently. This directly undermines the file's own rule that 'THE SITUATION BEING EDITED MUST NEVER BE AMBIGUOUS'. The default editor state (Anyone/Anyplace) hits this whenever the user has made a partner or place list but no general list.

**Evidence.**

```
express-editor.js:577-582 `entries.forEach(({ key, partnerId, placeId }) => { ... if (partnerId === flexPartner && placeId === flexPlace) o.selected = true; sel.appendChild(o); });`
express-editor.js:595-596 `mkBtn('✕', 'ee-situation-del', deleteSituation, 'Delete every phrase for the situation shown')`
express-editor.js:674-676 `const key = flexKey(flexPartner, flexPlace); const list = bandList('flex'); if (!list.length) return;`
```

**How it happens.** Settings > Express Panel > Flex. Set the scope to Mom / Anyplace, add a phrase. Switch the scope back to Anyone / Anyplace. 'Already set up' now shows 'Mom at Anyplace'. Selecting 'Mom at Anyplace' in it does nothing; pressing the X does nothing and shows no message.

**Suggested fix.** In flexSection, insert a first placeholder option `{ value: '', text: '— choose —' }` that is selected whenever the current situation is not in `made` (i.e. no other option matched). In the change handler, ignore value ''. Make the X act on what the dropdown shows: either disable it (`btn.disabled = true`) when the placeholder is selected, or have deleteSituation take the key from the select's value. Keeping it bound to flexPartner/flexPlace is fine once the placeholder guarantees the dropdown and the edited situation agree.

**How to verify the fix.** Manual: reproduce the scenario; the dropdown must read '— choose —', choosing 'Mom at Anyplace' must switch the scope selects to Mom / Anyplace, and the X must be disabled while '— choose —' is shown.

**Do not break.** Keep it a dropdown (Ken, August 26 2026 decision). Keep the delete confirmed through confirmDanger.

**Design reference.** express-editor.js header 'THE SITUATION BEING EDITED MUST NEVER BE AMBIGUOUS'; Express Panel Design 7.3

**Verification notes.** In flexSection the 'Already set up' select marks an option selected only when it equals flexPartner/flexPlace; when the edited situation has no list, no option is selected, so the browser shows the first one and choosing it fires no change event. deleteSituation acts on flexPartner/flexPlace and returns silently when that list is empty, so the X labelled 'the situation shown' does nothing. Confusing but not destructive, and the scope selects still work, so low rather than medium.
