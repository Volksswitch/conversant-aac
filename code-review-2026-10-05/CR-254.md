# CR-254: Generated symbols page drops comma and period, so the number page has no decimal point; code comment claims only letters are replaced

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/keyboard-layouts.js:201`
- **Also affects:** `app/js/keyboard-layouts.js:181`; `app/js/keyboard.js:871`; `tests/keyboard-layouts.test.mjs:7`
- **Source:** keyboard-08

**What a user notices.** When the number button opens the keyboard on its number page, there is no decimal point or comma, so answering "98.6" or "2.5" means switching back to the letters page mid-number.

**What is wrong.** buildSymbolsPage() replaces every 'char' cell, including the ',' and '.' cells of the letters page, with pool symbols. On the 28-character layouts the pool's '.' and ',' are entries 31-32, beyond the 28 cells, so neither appears on the symbols page. The header comment (and the test header) say only LETTER cells become symbols. The number chip opens the composer on this page specifically for numeric answers.

**Evidence.**

```
keyboard-layouts.js:200-204 `return (letterRows || []).map((row) => (row || []).map((cell) => { if (cell.kind === 'char') { const sym = SYMBOL_POOL[i++]; ...` ; keyboard-layouts.js:181-183 'only each LETTER cell becomes a symbol (in pool order)'; SYMBOL_POOL:194 `'.', ',', '<', ...` (positions 31-32). Scripted check: on all 28-char layouts the symbols page contains neither ',' nor '.'.
```

**How it happens.** Bottom Layout 11 (default). Partner asks 'What's your temperature?' Tap the number button; type 98 then look for '.' - it is not there.

**Suggested fix.** In buildSymbolsPage, leave non-letter character cells unchanged: `if (cell.kind === 'char' && /[a-z]/i.test(cell.char)) { const sym = SYMBOL_POOL[i++]; ... }` and `if (cell.kind === 'char') return cell;` for punctuation/digit cells. Then remove '.' and ',' from SYMBOL_POOL (and, for S10/B9 whose digit cells would now stay digits, drop leading digits from the pool when the layout already has them, or accept the duplicate).

> **Verifier correction to the fix (takes precedence):** Correct the keyboard-layouts.js comment in any case. Before changing which cells get symbols, ask Ken: keyboard.js:103-105 records that comma and period stay on the letters page per his spec. If he agrees the number page needs '.', the smaller change is to give the number page a decimal point rather than restructure the pool, and the cell geometry must stay unchanged either way.

**How to verify the fix.** tests/keyboard-layouts.test.mjs: for every layout whose letters page has ',' and '.', assert the symbols page keeps them in the same cells; keep the congruence test (spans and positions unchanged).

**Do not break.** Geometry must not change (one keyguard covers both pages) - this only changes which symbol sits in which existing cell. The existing congruence test asserts char cells become char|blank, which still holds.

**Design reference.** keyboard-layouts.js symbols-page comment; keyboard.js comment at page state ('Comma, period, space and backspace stay on the letters page')

**Verification notes.** Ran buildSymbolsPage over every layout: on all 28-character layouts (every layout except S10 and B9) the symbols page contains neither ',' nor '.'. Every 'char' cell, including the letters page's comma and period, is replaced from the pool, and '.' and ',' sit at pool positions 30-31, past the 28 cells. That contradicts the keyboard-layouts.js comment 'only each LETTER cell becomes a symbol'. However, keyboard.js:103-105 says 'Comma, period, space and backspace stay on the letters page per Ken's spec; space, backspace and enter are repeated on the symbols page', which reads as though comma and period were deliberately not repeated. That was decided before the number button (August 2026) began opening the composer on the symbols page. The comment mismatch is certain; whether the number page should carry a decimal point is a design call.
