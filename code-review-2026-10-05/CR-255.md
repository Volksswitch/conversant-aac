# CR-255: One-shot capital is armed on every keyboard show, so mid-sentence words in Conversation Review and appended text get capitalized

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/keyboard.js:653`
- **Also affects:** `app/js/review-ui.js:670`; `app/js/review-ui.js:495`; `app/js/review-ui.js:647`
- **Source:** keyboard-06

**What a user notices.** When correcting a word in the middle of a sentence in Conversation Review, the first letter typed comes out as a capital ("I went to the Store"). The same happens when you tap back into a box to finish a word you already started.

**What is wrong.** show() unconditionally sets shiftState='shift' (except apiKeyInput). Conversation Review calls keyboard.showFor(wordInput) once, when editing starts (highlight on word 0). The one-shot shift then stays pending while the user presses Next Word / taps a later word (focus is held, so show() is not re-run and nothing consumes the shift), so the first letter of whichever word they replace is uppercase. Likewise any focusin into a field that already has text arms the capital even when the caret is mid-word.

**Evidence.**

```
keyboard.js:649-653 `// Start each field in one-shot Shift so the first letter is capitalized ... shiftState = field.id === 'apiKeyInput' ? 'off' : 'shift';`; review-ui.js:670-673 `if (document.activeElement !== wordInput) { ... wordInput.focus(...); keyboard.showFor(wordInput); }`; review-ui.js:496 `case 'nextWord': if (ed) { ed = wed.moveWord(ed, 1); afterEdit(false); } break;` (no shift reset).
```

**How it happens.** Conversation Review, on-screen keyboard. Tap a card twice to edit 'I need to go to the store'. Press Next Word six times to highlight 'store', type 'shop' - the sentence becomes '... to the Shop'.

**Suggested fix.** Arm the capital only where it is wanted: in show(), set shift only if the field is empty or the text before the caret is empty or ends with sentence punctuation plus whitespace: `const before = (field.value || '').slice(0, field.selectionStart ?? field.value.length); shiftState = noAutocap ? 'off' : (/^\s*$/.test(before) || /[.!?]\s+$/.test(before)) ? 'shift' : 'off';`. For review, also export `setShift(on)` from keyboard.js and call it from review-ui syncWordInput with `ed.sel === 0` (or the previous word ends in . ! ?) whenever the highlight moves.

**How to verify the fix.** Manual: the failure scenario yields 'shop'; editing word 0 still yields a capital; About Me empty fields still start capitalized.

**Do not break.** Keep the capital for the start of empty About Me fields (proper nouns, Ken's June 2026 decision) and for the composer's first word.

**Design reference.** keyboard.js show() comment (one-shot shift for proper nouns/sentence starts); Conversation Review design §6.3

**Verification notes.** show() sets `shiftState = field.id === 'apiKeyInput' ? 'off' : 'shift'` on every call, whatever the field holds or where the caret sits. In review-ui syncWordInput(), showFor(wordInput) runs only when wordInput is not already focused, i.e. once when editing starts. Pointer-downs on the pane and bar are prevented, so focus is held, show() is not re-run, and nothing consumes the pending shift when the user presses Next Word or taps another word. The first letter typed into whichever word they replace is therefore uppercase. Tapping back into an About Me field that already holds a partial word likewise arms the capital mid-word.
