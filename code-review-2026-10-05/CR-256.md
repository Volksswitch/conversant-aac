# CR-256: 'Hear it' speaker buttons are a color emoji, not the app's SVG icon, so they ignore the color scheme

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/placeholder-editor.js:96`
- **Also affects:** `app/js/express-editor.js:284 (phrase row 🔊)`; `app/js/express-editor.js:394 (sound row 🔊)`; `app/js/worldview-ui.js:288 ('🔊 Speak my answer', conversation-raised question)`; `app/js/worldview-ui.js:541 (Sound Check candidate 🔊)`; `app/js/worldview-ui.js:1094 (respelling 'Hear it said' 🔊)`; `app/js/worldview-ui.js:1413 (place respelling 'Hear it said' 🔊)`; `app/js/worldview-ui.js:1633 ('🔊 Speak my answer', questionnaire card)`; `app/js/icons.js:37 (ICONS.speak - the speaker SVG already used by composer Speak and review 'Hear it')`; `app/js/review-ui.js:57 (review Hear it uses icon 'speak')`; `Documents/Conversant AAC User Manual (Windows Chromebook Mac).docx para 273 ('“Speak” button (🔊)')`
- **Source:** g-visual-consistency-02

**What a user notices.** The little speaker buttons used to hear a phrase stay gray-and-blue in every color scheme, so in Yellow on black they do not match anything around them and are dimmer than the other buttons; they also look different on an iPad than on Windows.

**What is wrong.** Every 'hear this' control in the Settings editors and About Me renders the text character U+1F50A (🔊). Browsers draw it from the platform's color emoji font, which ignores CSS `color`, so it does not take the scheme's ink color (computed `color` is rgb(255,212,0) in Yellow on black while the glyph paints gray and blue). Its size and artwork also vary by platform (Segoe UI Emoji vs Apple Color Emoji). Meanwhile the app has a speaker SVG, ICONS.speak, drawn with stroke=currentColor, that the composer's Speak button and Conversation Review's 'Hear it' already use - so the same meaning has two appearances. UI-Design §13 says a fixed-function control 'shows an icon and carries its explanation in its accessible name'; icons.js says icons are inline SVG precisely so they inherit the button color. Accessible names are present on most of these sites (aria-label 'Hear this phrase'/'Hear it said'), but worldview-ui.js:541 has only a title, so its accessible name is the emoji itself.

**How it happens.** Settings > Text & Color > Color scheme 'Yellow on black'. Open Settings > Placeholders (or the Express Panel editor, or About Me > a place's 'How to say it'). The speaker buttons are gray and blue while every other button glyph is yellow/white.

**Suggested fix.** Use the existing icon everywhere. (1) placeholder-editor.js:96: after `const hear = mkBtn('', 'ee-hear')` call `setIconButton(hear, 'speak', 'Hear this phrase')` (import { setIconButton } from './icons.js'). (2) express-editor.js:284 and :394: build the button with mkBtn('', 'ee-hear', handler) then `setIconButton(b, 'speak', 'Hear this phrase')` / `'Hear this sound'`. (3) worldview-ui.js:541, :1094, :1413: create the button with no text, then setIconButton(btn, 'speak', 'Hear this' / 'Hear it said') - el() no longer accepts raw HTML (SEC-8 removed it), so set the icon after creation via setIconButton, which uses the trusted ICONS string. (4) worldview-ui.js:288 and :1633 ('🔊 Speak my answer'): these are TEXT Settings action buttons (§13); drop the emoji and leave the label 'Speak my answer', or prepend ICONS.speak + a text span if Ken wants the glyph kept - do not leave a color emoji. Check that `.icon` sizing inside #settingsContent buttons gives the same visual size as the old emoji (about 1em). Update the three User Manuals where they show '(🔊)' (e.g. Windows manual para 273) via a docs sync.

> **Verifier correction to the fix (takes precedence):** The fix is right. Do not change the bundled release notes in whats-new.js or CHANGELOG.md, which quote the 🔊 as history; only the User Manuals need updating at the next docs sync.

**How to verify the fix.** Extend tests/ui-standards.test.mjs: assert no visible button in #settingsContent has textContent matching /\p{Extended_Pictographic}/u (emoji), and that every .ee-hear / .wv-say-as-hear / .sc-speak has an aria-label. Manually: switch to Yellow on black and Dark, open Placeholders, Express Panel editor, About Me > How I Sound and a place's respelling; every speaker is drawn in the scheme ink and is the same shape as the composer's Speak button.

**Do not break.** Keep the accessible names ('Hear this phrase', 'Hear it said') - the icon is aria-hidden. Keep Sound Check's speaker beside each candidate (CLAUDE.md: hearing it is the test). Do not touch the conversation-surface composer Speak, which already uses ICONS.speak. Manuals quote the emoji, so they need the same change.

**Design reference.** Conversant AAC UI-Design.docx §13 (fixed-function control shows an icon with an accessible name; consistency checked by tests/ui-standards.test.mjs); icons.js header; CLAUDE.md UI Layout Rule 23 (colors follow the scheme).

**Verification notes.** The cited sites render the literal U+1F50A: placeholder-editor.js:96, express-editor.js:284/394, worldview-ui.js:288/541/1094/1413/1633. U+1F50A has default emoji presentation, and the stylesheet has no font-variant-emoji or text-presentation rule (grep finds none), so it is drawn from the color emoji font, which ignores CSS `color`. ICONS.speak (icons.js:37, stroke=currentColor) exists and is used by the composer Speak button and the review 'Hear it' button, so the same action has two appearances. worldview-ui.js:541 has only `title: 'Hear this'` and no aria-label, so the button's accessible name comes from its content (the emoji), as stated. The whats-new.js release notes also quote the emoji. Those are historical notes and should not be edited.
