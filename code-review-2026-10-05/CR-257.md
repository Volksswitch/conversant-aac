# CR-257: Button tour still calls the Wrap up button "Wind down" and describes icons the user may not see

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/practice-tour.js:132`
- **Also affects:** `app/index.html:148`; `app/js/practice-tour.js:66`; `app/js/practice-tour.js:74`; `app/js/practice-tour.js:130`; `settings-help.json:62 (merged duplicate: Spoken help and the button tour still call the "Wrap up" button "Wind down")`; `app/js/practice-tour.js:132 (merged duplicate: In the controls tour and spoken Settings help the button is still called "Wind down"; it was renamed "Wrap up")`; `app/js/practice-tour.js:130 (merged duplicate: Button tour describes icons even when the Command Bar is set to show words)`
- **Source:** phrases-practice-07, x-defaults-01, live-runtime-06, x-defaults-06

**What a user notices.** The tour tells the user to tap 'Wind down', but the button is called 'Wrap up' everywhere else, so the coach and the screen disagree. If the user has chosen word labels on the command buttons, the tour's 'it shows a microphone' style hints describe pictures that aren't there.

**What is wrong.** The button was renamed 'Wrap up' on August 26 2026 (index.html carries a comment about the stale 'Wind down' text it previously showed). The tour step 'wind-down' still says "Wind down is how you signal you would like to finish...". Separately, every `where` hint describes the button's icon, but Settings > Commands > 'What the command buttons show' can show one/two-word labels instead of icons, in which case 'shows a microphone' or 'shows two upright bars' is wrong.

**Evidence.**

```
practice-tour.js:132-133 `say: "Wind down is how you signal you would like to finish, without saying " + "goodbye yet...`
index.html:148 `<button id="windDownBtn" type="button" class="cmd-btn">Wrap up</button>`
practice-tour.js:66 `where: "The one I mean shows a microphone...`
```

**How it happens.** Run the tour; at the wind-down step the coach says 'Wind down...' while the button's label and accessible name say 'Wrap up'. With command labels turned on, mis-tap any step and hear an icon description that does not match the labelled button.

**Suggested fix.** Change the step's say text to use 'Wrap up' (e.g. "Wrap up is how you signal you would like to finish, without saying goodbye yet..."). For the label mode, either add a `whereLabel` per step naming the button's word label and have hintWhere pick it when storage.loadCommandLabels() !== 'icon', or reword each `where` to lead with the position and name ('the fourth button from the left, Repeat what I said').

**How to verify the fix.** Run the tour with icons and with labels; confirm every spoken instruction names the button the way the screen shows it. Optionally add a test in tests/ asserting no TOUR_STEPS say/where string contains 'Wind down'.

**Do not break.** Keep the button ids/targets unchanged; keep the plain-language and American English rules for any new wording.

**Design reference.** CLAUDE.md UI Layout Rule 21 (Wrap up rename, command labels); practice-tour.js note 'EVERY `where` DESCRIBES A REAL BUTTON AND WILL GO STALE SILENTLY'.

**Verification notes.** practice-tour.js:132 still says 'Wind down is how you signal...', while index.html:148 labels the button 'Wrap up', matching the August 26 2026 rename. The `where` hints describe icons only, and Rule 21 lets the command buttons show word labels instead (storage.loadCommandLabels), in which case the icon descriptions do not match the screen.

<details><summary>Merged duplicate x-defaults-06: Button tour describes icons even when the Command Bar is set to show words</summary>

The 'where' hints spoken when the user presses the wrong button are fixed strings describing each button's ICON. The Commands-tab setting 'What the command buttons show' (storage.loadCommandLabels: 'icon' | 'words') replaces the icon with a one/two-word face (ui.js COMMAND_FACES). The tour does not consult that setting, so in 'words' mode every hint describes something that is not drawn.

Fix as proposed by that reviewer: In practice-tour.js give each Command Bar step an additional field, e.g. `whereWords: "The one I mean says Wrap up. It is seventh from the left in the middle row."`, using the faces from ui.js COMMAND_FACES ('Listen', 'Start', 'End', 'Say again', 'Hold on', 'Pardon?', 'Wrap up', "Don't save", 'Settings'). Where the hint is spoken, use `storage.loadCommandLabels() === 'words' && step.whereWords ? step.whereWords : step.where`. Steps not on the Command Bar (cards, New 4, In my own words, Cancel) keep their single 'where'.

</details>
