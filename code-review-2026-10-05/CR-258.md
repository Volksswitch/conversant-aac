# CR-258: 'Hear it' does not reproduce what the answer would have sounded like: a sound plays its label as speech, a phrase ignores its respelling, and a corrected partner line is spoken in the user's own voice

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:532`
- **Also affects:** `app/js/review-ui.js:238-242 (answerText)`; `app/js/review-ui.js:742-747 (sound answer text = item.label)`; `app/js/review-ui.js:216 (hear enabled while editing the partner line)`; `app/js/app.js:889 (deps.speak = tts.speak)`
- **Source:** review-backup-10

**What a user notices.** Pressing Hear it after choosing a sound button reads out the button's name instead of playing the sound; for a phrase with a custom pronunciation it says the word the wrong way; while correcting what the other person said, it speaks the other person's words as if the user said them.

**What is wrong.** hear() speaks answerText(entry()) or the editor text. For answer kind 'sound', text is the button label ('Sound' by default). For 'phrase', text is item.text while the live panel speaks `phrase.speak || phrase.text` (the per-item respelling). When editing target 'heard', hear is enabled and speaks the partner's corrected words through tts.speak in the user's own voice, which the design reserves for judging the user's own sentences.

**Evidence.**

```
review-ui.js:532-535
function hear() {
    const text = editing ? wed.editorText(ed) : answerText(entry());
    if (text) deps.speak(text);
}
review-ui.js:744
            text: sound ? (item.label || 'Sound') : (item.text || ''),
review-ui.js:216
    const hearable = editing ? !!wed.editorText(ed) : !!answerText(e);
```

**How it happens.** Review a turn, tap a sound button on the panel, press Hear it: the app says 'Happy birthday song' instead of playing it.

**Suggested fix.** Store `speak: item.speak || null` in setPhraseAnswer (review-model) and have hear() speak `a.speak || a.text` for phrases; for kind 'sound' either disable Hear it (set hearable false when answer.kind === 'sound') or play the clip through the app's existing audio playback; set hearable false when editing.target === 'heard'.

**How to verify the fix.** Unit test in tests/review.test.mjs: setPhraseAnswer keeps `speak`. Manual: the three cases above.

**Do not break.** Any new answer field must be accepted by cleanEntry and must not break REVIEW_LESSONS (voice-harvest tests read answer kinds). Never speak a sound label as the user.

**Design reference.** Conversation Review.docx §6.2 ('Hear it speaks the sentence back, so the user can judge whether it sounds right coming out of this device in this voice')

**Verification notes.** answerWithPhrase stores text = item.label || 'Sound' for a sound answer, and hear() speaks answerText(entry()) through deps.speak (tts.speak), so the label is read aloud as the user's own speech. A phrase answer stores item.text only; the per-item respelling (item.speak) used by the live panel is not stored, so Hear it ignores it (the name lexicon still applies via tts.setPronouncer). renderBar enables Hear it whenever editing has text, including target 'heard', so the corrected partner words are spoken in the user's voice.
