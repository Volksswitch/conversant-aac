# CR-259: A 'the app wrote down the wrong words' mark is recorded by a single tap and cannot be removed after leaving review

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:656`
- **Also affects:** `app/js/review-model.js:410-420 (setMisheard / clearMisheard - clearMisheard is never called)`; `app/js/review-ui.js:274-283`
- **Source:** review-backup-06

**What a user notices.** Tapping the other person's line once marks it as misheard. A stray tap leaves a permanent note saying the app got the words wrong, and there is no way to take it back except Undo before leaving.

**What is wrong.** onPaneClick on the partner line of the current turn immediately calls change(model.setMisheard(...)), which creates `misheard: { heard, said: null }` - a full mark - before the user has typed anything. Unlike a response card (where editing the spoken card and leaving it unchanged records nothing, cleanEntry drops unchangedSpoken), there is no equivalent for the misheard mark: deleting all words keeps the flag (setMisheard with '' keeps misheard), and model.clearMisheard is exported but no UI calls it. Undo is the only remedy and the history is discarded on leave/enter. On turn 0, which is outlined on entry, one tap is enough. This population taps imprecisely, and the mark feeds the misheard notes the design says tell us where transcription struggles.

**Evidence.**

```
review-ui.js:652-658
    const t = turn();
    const prior = entry().misheard;
    change(model.setMisheard(review, t, prior && prior.said ? prior.said : t.partnerText));
    editing = { target: 'heard' };
review-model.js:418-420
export function clearMisheard(review, turn) {
    return withEntry(review, turn.key, (e) => { e.misheard = null; });
}
(grep: clearMisheard has no caller in app/js)
```

**How it happens.** Open a conversation in review; accidentally tap the first partner line; tap elsewhere / Settings to leave. Reopen: 'Your note: the app wrote down the wrong words.' remains and cannot be removed.

> **Verifier correction to the trigger:** Recording the flag on one tap of the current turn's partner line is the design (Conversation Review.docx §6.4: 'A tap on the line of the exchange already showing opens it for correction'), and with 'One tap or two' set to two the first tap is held back by tap-guard. The defect is only that the flag cannot be removed after leaving review, not that one tap sets it.

**Suggested fix.** Give the mark a way out consistent with cards: when the user finishes editing the heard line (stopEditing for target 'heard') and the misheard note's `said` is null AND it was created in this edit session, offer removal - simplest: tapping the user's 'Your note' line (`.review-note-left`) for the current turn calls change(model.clearMisheard(review, turn())) and render(). Give that note `data-part="misheard"` and handle it in onPaneClick. Add a spoken-help/title 'Tap to remove this note'.

**How to verify the fix.** Manual: flag a line, leave review, re-enter, tap the note - it disappears and the review file no longer has misheard for that key. Unit test in tests/review.test.mjs for clearMisheard dropping the entry when nothing else is set.

**Do not break.** The design says the flag comes first and stands on its own (§6.4) - keep recording it on the first tap; only add removal. Keep practice conversations excluded.

**Design reference.** Conversant AAC Conversation Review.docx §6.4 ('Nothing carries a mark until the user marks it'), §6 (Undo)

**Verification notes.** model.clearMisheard is exported and has no caller anywhere in app/js or tests. Once a review is left the history is discarded, and setMisheard with the original text still keeps `misheard` (said becomes null, the flag stays). Every other kind of mark can be taken back after re-entering (toggle a phrase, New 4, a reframer, choose the spoken card); the misheard flag cannot.
