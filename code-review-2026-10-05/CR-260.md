# CR-260: Practice filter shows 'No practice conversations in this time' above 'Older conversations are hidden (13, real and practice together)'

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/review-ui.js:859`
- **Also affects:** `app/js/review-ui.js:871-874 (empty-state strings 'in this time')`; `app/js/review-ui.js:841-846 (status placed before olderNote)`; `app/js/storage.js:983-986 (older counted by file name for every conversation, practice or not)`; `app/index.html:938-944 (reviewListRange options: The last week / month / three months / Any time)`
- **Source:** g-visual-consistency-06

**What a user notices.** With 'Practice conversations' chosen, the list says there are none, then says 13 older conversations are hidden - which reads as if 13 practice conversations exist when most of them may be real ones. 'In this time' is also an odd phrase.

**What is wrong.** storage.listConversationLogs counts every conversation file older than the cutoff by its file name, without opening it, so it cannot tell practice from real (practice is only marked inside the file, review-model.js:34). renderList prints that one count under whichever filter is active. When the filter yields no rows, the status line 'No practice conversations in this time.' is drawn directly above 'Older conversations are hidden (13, real and practice together).', so the number sits under a practice-only heading. The parenthetical explains an implementation detail rather than answering the reader's question (are there older PRACTICE conversations?). The status wording 'in this time' does not name the period the user picked.

**How it happens.** Data folder with 13 conversations older than a week and none in the last week. Settings > Conversation Review > 'Practice conversations', 'The last week'. Screen: 'No practice conversations in this time.' then 'Older conversations are hidden (13, real and practice together). [Show conversations from any time]'.

> **Verifier correction to the trigger:** The note already says the count is 'real and practice together', so the defect is the awkward juxtaposition and the vague 'in this time', not an outright false implication.

**Suggested fix.** Counting per filter would require opening every old file, which the date range exists to avoid (TODO.md 2026-10-03 entry), so reword instead. In renderList: read the chosen range's label (`const rangeText = range ? range.options[range.selectedIndex].text.toLowerCase() : 'this period'`, e.g. 'the last week'). Empty status: `listShowsPractice ? `No practice conversations from ${rangeText}.` : `No conversations from ${rangeText}.``. Older note without the misleading count: `Conversations from before ${rangeText} are not shown.` followed by the existing 'Show conversations from any time' button. If Ken wants the number kept, phrase it so it is not tied to the filter: `${n} older saved conversation(s) are not shown. Some may be real and some practice.` Keep the button.

**How to verify the fix.** Unit-level: none (renderList needs a data folder). Manual with the test data folder (`reset test data`, then age it or pick 'The last week' after moving dates): switch to Practice with no recent practice conversations and confirm the two lines read consistently and name the period; switch to Real and confirm the same note.

**Do not break.** Do not open old files to count them (defeats the range). Keep the status element's role=status. Plain American English per CLAUDE.md writing rules.

**Design reference.** Conversant AAC Conversation Review.docx §4 (real or practice, never both); TODO.md 'DONE 2026-10-03: the list can be cut by date'; CLAUDE.md PLAIN STYLE.
