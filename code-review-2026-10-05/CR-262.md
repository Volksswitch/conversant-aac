# CR-262: Command Bar buttons keep their text-trimming styles after switching back to icons

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/ui.js:917`
- **Also affects:** `app/js/ui.js:1156`; `app/js/ui.js:1182`
- **Source:** ui-shell-07

**What a user notices.** After trying 'A short label' on the command buttons and switching back to icons, some icons can sit off-center (pushed to the top-left of their button) until the app is reloaded.

**What is wrong.** fitCardsAndCommands() clamps worded Command Bar faces by writing inline display:-webkit-box, -webkit-box-orient, align-items and -webkit-line-clamp on the BUTTON itself, but only for buttons matching `button.cmd-worded`. setCommandLabelMode('icon') -> applyControlIcons() -> setCommandFace removes the cmd-worded class first, so the following fitCardsAndCommands() never visits those buttons and the inline styles written while they were worded remain on the icon buttons permanently (later resizes use the same selector). The comment at ui.js:1185 says switching back to icons needs the clamps taken off, but the code cannot reach them.

**Evidence.**

```
ui.js:917-921
    document.querySelectorAll('#listenControls > button.cmd-worded').forEach((btn) => {
        ...fitText(btn, ...)
ui.js:1158-1161 (icon branch of setCommandFace)
        setIconButton(btn, iconName, label);
        btn.classList.remove('cmd-worded');
        return;
```

**How it happens.** Side dock with a narrow Command Bar. Settings > Commands > On each command button = 'A short label' (a long face such as "Don't save" overflows and is clamped). Switch it back to 'Its icon': that button keeps display:-webkit-box inline and its icon is no longer centered.

**Suggested fix.** In setCommandFace's icon branch (ui.js ~1158), before returning, clear the four properties: `['-webkit-line-clamp', 'display', '-webkit-box-orient', 'align-items'].forEach((p) => btn.style.removeProperty(p));` (or export/reuse a small clearFit(el) helper that fitText already performs at its top).

**How to verify the fix.** Manual: reproduce, then inspect the button in devtools - no inline style after switching to icons. Browser check in tests/ui-standards.test.mjs: after setCommandLabelMode('words') then ('icon'), assert every #listenControls > button has an empty style.display.

**Do not break.** Must not add padding/border/margin to Command Bar buttons (Rule 21: cell width floors at padding+border and moves keyguard holes).

**Design reference.** CLAUDE.md UI Layout Rule 21 (Command Bar icon or label)

**Verification notes.** fitCardsAndCommands only visits '#listenControls > button.cmd-worded' (ui.js:917). setCommandFace's icon branch calls setIconButton (icons.js:81-89, which does not touch inline style) and removes cmd-worded, so the inline display/-webkit-box-orient/align-items/-webkit-line-clamp written while the face was worded and overflowing remain. The comment in setCommandLabelMode says switching back needs the clamps taken off, but the selector can no longer reach those buttons. The trigger is narrow: only a worded face that actually overflowed was ever clamped.
