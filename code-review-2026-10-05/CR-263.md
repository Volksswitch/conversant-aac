# CR-263: The Speak button on a conversation-raised question stays disabled after the user answers it

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:290`
- **Also affects:** `app/js/worldview-ui.js:283-284 (setExtra on change/blur without re-render)`; `app/js/worldview-ui.js:1657-1659 (built-in cards refresh after saving, which re-enables Speak)`
- **Source:** worldview-12

**What a user notices.** After typing an answer to a question that came up in a conversation, the 'Speak my answer' button stays greyed out until the user leaves the page and comes back, unlike the built-in questions.

**What is wrong.** renderExtra computes the Speak button's disabled state once from e.value at render time. Answers are saved by setExtra on change/blur, but nothing re-renders the card or re-evaluates the disabled attribute, so a newly answered extra cannot be spoken. Built-in cards call refreshCard after Save, so their Speak button enables.

**Evidence.**

```
app/js/worldview-ui.js:283-290:
    input.addEventListener('change', () => wv.setExtra(name, input.value.trim()));
    input.addEventListener('blur', () => wv.setExtra(name, input.value.trim()));
    ...
    if (!(e.value || '').trim()) speakBtn.setAttribute('disabled', 'true');
```

**How it happens.** Open a 'from a conversation' question that has no answer, type an answer, tap outside the box: the Speak button remains disabled.

**Suggested fix.** Add `input.addEventListener('input', () => { if (input.value.trim()) speakBtn.removeAttribute('disabled'); else speakBtn.setAttribute('disabled', 'true'); });` after speakBtn is created (move the listener below the speakBtn declaration).

**How to verify the fix.** Manual: typing into the box enables Speak; clearing it disables it.

**Do not break.** none

**Design reference.** CLAUDE.md Build Step 2 'Speak my answer' control.

**Verification notes.** renderExtra sets the Speak button's disabled attribute once, from e.value at render time. The input's change and blur handlers call wv.setExtra without re-rendering or touching the button, so after a first answer Speak stays disabled until the page is redrawn. Built-in cards call refreshCard after saving, so their Speak button does enable.
