# CR-265: About Me back links say '‹ Back' on two screens and '‹ All topics' on six, including screens that are not topics

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:472`
- **Also affects:** `app/js/worldview-ui.js:223 renderExtras - '‹ Back'`; `app/js/worldview-ui.js:260 renderExtra - '‹ Back'`; `app/js/worldview-ui.js:472 renderSoundCheck - '‹ All topics'`; `app/js/worldview-ui.js:684 renderPeople - '‹ All topics'`; `app/js/worldview-ui.js:1289 renderGeneralGoals - '‹ All topics'`; `app/js/worldview-ui.js:1317 renderPlaces - '‹ All topics'`; `app/js/worldview-ui.js:1561 renderModule - '‹ All topics'`; `app/js/worldview-ui.js:700 and :1572 (comments naming the '‹ All topics' link)`
- **Source:** g-visual-consistency-04

**What a user notices.** The link that returns to the About Me list is worded differently from screen to screen, and on People, Places, Goals and How I Sound it says 'All topics' even though those are not under the Topics heading.

**What is wrong.** Every About Me sub-screen returns to renderHome() with a .wv-back button, but the label varies: '‹ Back' on the two 'questions that came up in conversations' screens, '‹ All topics' on the other six. The home screen groups its rows under separate headings - 'Topics', 'People & relationships', 'Places', 'Goals', 'Other things about me', 'How I sound' - so 'All topics' is accurate only for the questionnaire modules (renderModule) and misnames the destination for People, Places, Goals and How I Sound. All eight go to the same place, so they should carry the same words.

**Evidence.**

```
app/js/worldview-ui.js:223  contentEl.append(el('button', { class: 'wv-back', text: '‹ Back', onclick: renderHome }));
app/js/worldview-ui.js:260  contentEl.append(el('button', { class: 'wv-back', text: '‹ Back', onclick: renderHome }));
app/js/worldview-ui.js:472  contentEl.append(el('button', { class: 'wv-back', text: '‹ All topics', onclick: renderHome }));
app/js/worldview-ui.js:684  ... text: '‹ All topics', onclick: renderHome ... (People in Your Life)
app/js/worldview-ui.js:1289 ... '‹ All topics' ... (Goals For Any Conversation)
app/js/worldview-ui.js:1317 ... '‹ All topics' ... (My Places)
app/js/worldview-ui.js:1561 ... '‹ All topics' ... (a questionnaire module)
Home headings (worldview-ui.js renderHome): 'Topics', 'People & relationships', 'Places', 'Goals', 'Other things about me', 'How I sound'. Measured: opening People shows '‹ All topics'.
```

**How it happens.** Settings > About Me > People in Your Life: link reads '‹ All topics'. Back, then 'Questions that came up in conversations': link reads '‹ Back'.

**Suggested fix.** Use one label that names the destination: '‹ About Me' (the tab and screen name) at all eight sites (223, 260, 472, 684, 1289, 1317, 1561). Simplest: add a helper in worldview-ui.js, `function backLink(onclick = renderHome, label = 'About Me') { return el('button', { class: 'wv-back', text: '‹ ' + label, onclick }); }`, and call it from each renderer. Update the comments at 700 and 1572. (See the separate finding about renderExtra, whose back link should return to the list it came from.)

**How to verify the fix.** Grep app/js/worldview-ui.js for "class: 'wv-back'" - only the helper should remain. Manually open each About Me sub-screen (a topic, People, Places, Goals, How I Sound, Other things about me, one raised question) and confirm the same link text. Update the User Manuals if they quote 'All topics' (current manuals do not).

**Do not break.** Keep the .wv-back class (tests/ui-standards.test.mjs lists '.wv-btn-link, .wv-back' as a deliberate transparent-fill exception). Spoken help resolves by data-help/ids, not by this label, so nothing there changes.

**Design reference.** Conversant AAC UI-Design.docx §13 ('Everywhere else, a button that reads the same does the same' - the converse: one action, one label).

**Verification notes.** Verified: worldview-ui.js lines 223 and 260 read '‹ Back', and lines 472, 684, 1289, 1317 and 1561 read '‹ All topics'. All seven call renderHome (the reviewer's 'eight' counts the comment sites; there are seven buttons). No design record makes the label difference deliberate.
