# CR-267: A multiple-choice About Me answer can never be removed, only hidden

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** confirmed (skeptic: confirmed)
- **Location:** `app/js/worldview-ui.js:1662`
- **Also affects:** `app/js/worldview-ui.js:1678-1679 (own-words Save ignores a blank box)`; `app/js/worldview-ui.js:1618-1622 (Undo after 'Prefer not to say' restores the stashed answer)`; `app/js/worldview-ui.js:323-324 (intro promises any answer can be removed)`; `app/js/worldview-ui.js:1737-1738 (text fields DO reset on blank Save)`
- **Source:** worldview-08

**What a user notices.** Once the user taps an answer on a pick-one question (for example a personality statement or 'Is faith part of your life?'), there is no way to go back to having no answer; 'Prefer not to say' and its Undo bring the old answer back, even though the page says any answer can be removed.

**What is wrong.** buildChoice offers chips (no deselect) and an 'In my own words' box whose Save does nothing on blank. Text and free-multi fields reset to unanswered on a blank Save, and multi chips reset when the last chip is deselected, but choice fields have no route to resetField. declineField stashes the value as prevValue and undeclineField restores it, so decline-then-undo returns the original answer. The only alternative is the declined state, which puts the label into the AI's 'chose not to share' list, a different meaning from 'no answer'.

**How it happens.** About Me > What I'm Like > tap 'Very much like me' on 'I worry about things.' Try to clear it: tapping the chip again re-saves it; blank own-words Save does nothing; Prefer not to say then Undo restores 'Very much like me'.

**Suggested fix.** Make tapping the currently selected chip clear the answer, mirroring buildMultiChips: in buildChoice change the chip onclick to `() => (current === opt ? wv.resetField(field.key).then(() => refreshCard(field)) : saveAndRefresh(field, opt))`, and have a blank own-words Save reset when the current value is custom: `if (v) saveAndRefresh(field, v); else if (isCustom) wv.resetField(field.key).then(() => refreshCard(field));`.

**How to verify the fix.** Manual: tap a selected chip; the card shows no '✓ Answered' badge and the module count drops by one. Add a buildBlock check in tests/worldview.test.mjs that a reset trait field contributes nothing.

**Do not break.** Do not change declineField's stash behavior (deliberate, Ken July 2026).

**Design reference.** CLAUDE.md Worldview Questionnaire: three field states; 'every answer optional and revisable'.

**Verification notes.** In buildChoice, tapping a chip always saves that option, and the own-words Save ignores a blank box. Nothing on a choice card calls wv.resetField. By contrast, buildMultiChips resets when the last chip is deselected, and buildTextish and buildFreeMulti reset on a blank Save. Decline followed by Undo restores the stashed prevValue. A single-choice answer therefore cannot be returned to 'unanswered', even though the intro says any answer can be removed.
