# CR-277: On Android the live text and a checkpoint can repeat words while a re-sent sentence is still in progress

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/stt.js:368`
- **Also affects:** `app/js/stt.js:646`; `app/js/stt.js:745`; `app/js/stt.js:302`
- **Source:** stt-16

**What a user notices.** On Android, the other person's words can briefly show doubled ('this this is a'), and if the pause timer fires at that moment the doubled text is what the AI is asked about.

**What is wrong.** The Android 'ladder' fix (resendsLastStatement) is applied only when a FINAL segment is committed. The displayed text, the checkpoint text and getCurrentTranscript() all use `joinParts([accumulatedText, currentInterim])`; if the recognizer's in-progress interim re-sends the last finalized rung (the measured Android behavior), the rung appears twice until the next final collapses it.

**Evidence.**

```
stt.js:368 `if (onTranscript) onTranscript(joinParts([accumulatedText, currentInterim]));`
stt.js:646 `const text = joinParts([accumulatedText, currentInterim]);`
stt.js:307 `return next === prev || next.startsWith(prev + ' ');` (only consulted from commitSegment)
```

**How it happens.** Android: final 'this is' committed; interim 'this is a' arrives; live text reads 'this is this is a'; a 0.5 s checkpoint firing then sends that to the AI.

**Suggested fix.** Add a helper `function currentText() { return resendsLastStatement(currentInterim) ? joinParts([...segments.slice(0, -1), currentInterim]) : joinParts([accumulatedText, currentInterim]); }` and use it at lines 368, 646 and 745.

**How to verify the fix.** tests/stt.test.mjs: emitFinal('this is'); emitInterim('this is a'); assert getCurrentTranscript() === 'this is a'.

**Do not break.** Unconditional by design (no Android detection); it must remain a no-op where interims carry only new words.

**Design reference.** stt.js resendsLastStatement comment; CLAUDE.md 'Android — MEASURED'

**Verification notes.** The display and the checkpoint text both use joinParts([accumulatedText, currentInterim]), and resendsLastStatement is consulted only from commitSegment. If an Android interim re-sends the last finalized rung plus more, the rung appears twice until the next final collapses it. CLAUDE.md records that two mechanisms fit the measured Android data (every rung final, or a session restart between rungs), and neither has been shown to produce an interim that re-sends an already-final rung. So whether this window actually occurs is unconfirmed.
