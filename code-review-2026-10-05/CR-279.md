# CR-279: A reply with no text block (e.g. a refusal) loses both its token usage and its stop reason

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** bug
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/suggest-anthropic.js:234`
- **Also affects:** `app/js/suggest-anthropic.js:335-338 (complete)`; `app/js/llm.js:38-42 (askDetailed)`; `app/js/llm.js:643-654 (parse-error enrichment)`
- **Source:** llm-engine-05

**What a user notices.** If the AI declines to answer, the cost shown in Settings leaves out what that request was charged, and the error recorded only says there was no text, not that the AI declined, so it reads like any other failure.

**What is wrong.** complete() calls textFrom(data) inside the return expression, before usageFrom(data) and data.stop_reason are returned. textFrom throws 'no text in the reply' when there is no text block - which is what a stop_reason 'refusal' (or a reply that is only thinking) can produce. The throw propagates out of provider.complete, so askDetailed never calls onUsageUpdate (the request was billed but is not counted) and generateResponses' catch block that appends `(stop: <reason>)` and attaches the reply is never reached (it only wraps parseGeneration). CLAUDE.md states 'A reply that still cannot be read now says why (stop: end_turn|max_tokens|refusal)'; this path does not.

**Evidence.**

```
suggest-anthropic.js:296-298:
    const block = blocks.find((b) => b && b.type === 'text') || ...;
    if (!block || typeof block.text !== 'string') throw new Error('no text in the reply');
suggest-anthropic.js:338:
    return { text: textFrom(data), usage: usageFrom(data), stopReason: data.stop_reason || null };
llm.js:39-40:
    const { text, usage, stopReason } = await provider.complete({ ... });
    if (usage && onUsageUpdate) onUsageUpdate(usage);
```

**How it happens.** Sonnet 5.5 returns HTTP 200 with stop_reason 'refusal' and empty content. Error logged: 'no text in the reply'; Settings > About spend does not include that request's input tokens.

**Suggested fix.** In complete(): compute `const usage = usageFrom(data); const stopReason = data.stop_reason || null;` first; then `let text; try { text = textFrom(data); } catch { text = ''; }` and return `{ text, usage, stopReason }`. In llm.askDetailed, after reporting usage, if `!text` throw `Object.assign(new Error(`no text in the reply (stop: ${stopReason || 'unknown'})`), { stopReason })`. This keeps usage counted and puts the stop reason in the message.

**How to verify the fix.** tests/suggest-provider.test.mjs: stub fetch to return {content:[], stop_reason:'refusal', usage:{input_tokens:100,output_tokens:0}}; register an onUsage spy via llm.onUsage; call llm.generateResponses and assert the spy received input 100 and the rejection message contains 'refusal'.

**Do not break.** This overlaps the CLAUDE.md open TO DO 'tell an AI REFUSAL apart from a network failure' - this fix only preserves the data; it must not add a worded error box to the conversation screen (Ken's standing position). Do not log the reply text in any report path.

**Design reference.** CLAUDE.md 'THE SERVICE ENFORCES THE SHAPE OF A SET OF SUGGESTIONS' (stop reason in the message) and 'Prompt caching - the cost display had to change or it would have lied'.

**Verification notes.** The mechanism is real. In suggest-anthropic.js, complete() returns `{ text: textFrom(data), usage: usageFrom(data), ... }` at line 234. textFrom (line 194) throws 'no text in the reply' when no text block exists. The usage and stop reason are therefore lost: askDetailed never calls onUsageUpdate, and the `(stop: ...)` enrichment in generateResponses only wraps parseGeneration. I could not confirm how often the service returns HTTP 200 with no text block for a refusal under structured output, so the trigger's reachability is unverified. This is not in TODO.md. The related 'tell an AI REFUSAL apart' item is an Open Questions TO DO in CLAUDE.md, not TODO.md.
