# CR-283: Key fields discard text that arrived without an input event when focus leaves, and Close/Escape only re-check the Claude key

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/app.js:981`
- **Also affects:** `app/js/app.js:760`; `app/js/app.js:8418`; `app/js/app.js:7346`; `app/js/app.js:7429`; `app/js/app.js:7462`; `app/js/app.js:7473`; `app/js/app.js:7917`
- **Source:** g-app-flow-overflow-06

**What a user notices.** If a password manager or other filler puts a key into one of the key boxes without the app noticing, the key is thrown away as soon as the user taps anywhere else or closes Settings: the box goes back to the old key or goes blank, and the service keeps failing. For every service except Claude, closing Settings does not even try to save it.

**What is wrong.** Every key field is saved from its 'input' listener. The Close button and the dialog's 'cancel' (Escape) handler were added as a 'belt-and-suspenders' for paste/fill paths that set the value without an input event (their own comments cite 'Ken's bug 1'), but (a) they read only apiKeyInput - the Deepgram, Azure key, Azure region, OpenAI, Google Cloud and ElevenLabs fields have no such save; and (b) the 'blur' listener in wireKeyField runs before either: tapping Close (or the dialog closing on Escape) moves focus off the field, blur calls showRedactedKey(input, load()), which overwrites the field with the STORED key's redacted form (or empties it when nothing is stored) and sets dataset.redacted; keyFieldValue then returns null, so even the Claude-key save on Close never fires in the scenario it exists for. Only Escape pressed while the Claude field still has focus works (cancel fires before close). The Azure region box has the same shape: its blur handler resets it to the stored value.

**Evidence.**

```
app/js/app.js:981: `input.addEventListener('blur', () => showRedactedKey(input, load()));`
app/js/app.js:964-967 (showRedactedKey): `if (!k) { input.value = ''; ... return; } input.value = redactKey(k); input.dataset.redacted = '1';`
app/js/app.js:8424-8428 (Close): `const key = keyFieldValue(apiKeyInput); if (key !== null && key !== (storage.loadApiKey() || '')) { llm.setApiKey(key); storage.saveApiKey(key); }` - apiKeyInput only.
app/js/app.js:763-767 (Escape/cancel): same, apiKeyInput only.
app/js/app.js:7473-7475: `azureRegionInput.addEventListener('blur', () => { azureRegionInput.value = storage.loadAzureRegionSetting(); });`
```

**How it happens.** 1) Settings → Speech; an autofill or password-manager extension fills the Deepgram key box without dispatching 'input' (the case the Close handler's comment describes). 2) User taps Close. 3) Blur re-redacts the box to the old stored key (or blank); Close checks only the Claude field; nothing is saved. Next launch, Deepgram reports no key / rejected. Same for Azure, OpenAI, Google Cloud, ElevenLabs and, via its own blur handler, the Azure region.

> **Verifier correction to the trigger:** Only reachable when a key value is placed in a field without an 'input' event (an unusual autofill or extension), not by ordinary typing, the app's Paste buttons, or standard browser autofill.

**Suggested fix.** Move the safety net into wireKeyField's blur handler so it covers all six fields: `input.addEventListener('blur', () => { if (!input.dataset.redacted) { const v = input.value.trim(); if (v !== (load() || '')) { save(v); if (onChange) onChange(v); } } showRedactedKey(input, load()); });`. Do the same in the Azure region blur handler (save `azureRegionInput.value` via storage.saveAzureRegion if it differs from loadAzureRegionSetting() before resetting the box). The Close and cancel apiKey-only blocks can then stay as harmless backups or be removed.

**How to verify the fix.** Manual: open Settings, focus the Deepgram key box, run `const i=document.getElementById('deepgramKeyInput'); i.value='test-key-123456789012345';` in devtools (no input event), then click Close; reopen Settings and confirm the stored key is the new one (storage.loadDeepgramKey()). Repeat for azureKeyInput, a catalog key field and azureRegionInput.

**Do not break.** Never save the redacted placeholder (keep the dataset.redacted check). wireKeyField is currently re-run on every Settings open (already reported as listeners piling up), so the blur save would multiply until that is fixed; make the wiring idempotent at the same time. Keys must stay out of profiles/backups (PROFILE_EXCLUDE) - this changes only when they are saved, not where.

**Design reference.** CLAUDE.md 'API-key feedback: missing-key prompt, format warning, live Test button'; app.js comment at 8419-8423 ('Belt-and-suspenders ... Ken's bug 1').

**Verification notes.** The mechanism is real: wireKeyField's blur handler (app.js:981) calls showRedactedKey(input, load()), which on blur (activeElement is no longer the input) overwrites the field with the stored key's redacted form or empties it, so a value that arrived without an 'input' event is discarded before the Close handler (8418-8428) reads it, and Close/cancel only re-check apiKeyInput anyway. The Azure region blur handler (7473-7475) likewise resets to the stored value. What I could not confirm is that the trigger occurs in practice: Chrome/Edge autofill and mainstream password managers normally dispatch input events, and the app's own Paste buttons go through setKeyFieldValue, which dispatches 'input'. The Escape case with focus still in the Claude field works because cancel fires before blur.
