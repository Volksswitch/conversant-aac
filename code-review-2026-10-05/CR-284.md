# CR-284: An older copy of the app reseeds the panel from defaults if it reads a newer-version panel file

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/express-panel.js:71`
- **Also affects:** `app/js/express-panel.js:130-138`; `app/js/express-panel.js:248-261`
- **Source:** express-15

**What a user notices.** If one computer has been updated and another sharing the same data folder has not, the older one would show the starting phrases instead of the user's own, and the first edit made there would overwrite the user's panel in the shared folder.

**What is wrong.** normalize() treats any version other than MODEL_VERSION (2) as version 1 and returns defaults(). That is the intended one-time upgrade for version 1, but it also catches a future version 3 file. On the next setModel the defaults-based model is written back to express-panel.json, destroying the newer panel. Both machines read the same OneDrive folder; the service worker updates on launch, but a machine left open or offline runs the old build.

**Evidence.**

```
express-panel.js:71-73 `if (!raw || typeof raw !== 'object' || Array.isArray(raw) || raw.version !== MODEL_VERSION) { // Version 1 ... Reseed. return d; }`
```

**How it happens.** A later release bumps MODEL_VERSION to 3. Machine A updates and writes a v3 file. Machine B, still on the old build, opens Settings and edits one phrase: express-panel.json is replaced with the shipped defaults plus that one edit.

**Suggested fix.** Reseed only for genuinely old shapes: `if (!raw || typeof raw !== 'object' || Array.isArray(raw) || !(raw.version >= MODEL_VERSION))`. For `raw.version > MODEL_VERSION`, parse it as best-effort version 2 (the fields are additive) and set a module flag `readOnlyNewer = true` that makes writeDisk/syncToFolder skip writing, so an old build never overwrites a newer file.

**How to verify the fix.** Add to tests/express-panel-store.test.mjs: write `{version: 3, seed: 1, always:[{id:'w',type:'phrase',text:'mine'}], ...}`, load(), setModel(getModel()), and assert the file on disk still contains 'mine' and version 3.

**Do not break.** Version 1 files must still be discarded and reseeded once (Ken's August 23 2026 decision).

**Design reference.** express-panel.js header ('THE UPGRADE DISCARDS A VERSION-1 PANEL'); CLAUDE.md v0.2.25 'file in folder wins'

**Verification notes.** normalize returns defaults() for any version other than 2, so a hypothetical future version-3 file would be read as defaults by an older build and overwritten at that build's next setModel. MODEL_VERSION is 2 and nothing writes a version 3 today, so the trigger depends on a future bump plus a stale build sharing the folder. The service worker updates on launch, which narrows the window.
