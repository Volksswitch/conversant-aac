# CR-285: Weekly report bookkeeping is advanced before the report is safely queued, so a storage-full failure loses the report and its errors silently

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/weekly-send.js:295`
- **Also affects:** `app/js/weekly-send.js:413`; `app/js/weekly-send.js:417`; `app/js/storage.js:2588`
- **Source:** reporting-platform-11

**What a user notices.** On a device whose browser storage is full, a week's report and the errors in it can disappear without any record that they were never queued.

**What is wrong.** gatherPayload advances weeklyErrorMark (and the system-info hash) while building the payload; maybeSend then calls saveWeeklyQueue, which swallows quota errors, and then unconditionally advances weeklySendLastAt. If the queue write fails, the payload exists nowhere, yet the mark, hash and date all say it was handled, so those errors and that system info are never sent.

**Evidence.**

```
app/js/weekly-send.js:295: `storage.saveWeeklyErrorMark(newestErrorTs(fresh, ...));`
app/js/weekly-send.js:413-417: `storage.saveWeeklyQueue(enqueue(...)); ... storage.saveWeeklySendLastAt(now);`
app/js/storage.js (saveWeeklyQueue): `try { localStorage.setItem(WEEKLY_QUEUE_KEY, JSON.stringify(q)); } catch { /* quota - the queue is best-effort by design */ }`
```

**How it happens.** localStorage is near its quota (large metrics tally, error log, queued payloads). The weekly payload is built, the error mark advances, setItem throws QuotaExceededError and is swallowed, LastAt advances; next week's report omits those errors.

**Suggested fix.** Have saveWeeklyQueue return a boolean (true on success). In gatherPayload, return the pending mark/hash values instead of saving them; in maybeSend, only after `if (storage.saveWeeklyQueue(...))` succeeds, save the error mark, info hash, weeklySendLastAt and weeklyEndpoint. On failure, append a send-log entry 'could not be queued (storage full)'.

**How to verify the fix.** Add to tests/weekly-send-delivery.test.mjs: make localStorage.setItem throw for the queue key; after maybeSend the stored error mark and weeklySendLastAt must be unchanged and the send log must record the failure.

**Do not break.** Keep the mark advanced on ENQUEUE (not on delivery), as recorded in CLAUDE.md; this only moves it after a confirmed enqueue.

**Design reference.** CLAUDE.md 'Error reporting — audited' ('The mark is ... Advanced on ENQUEUE, not on delivery')

**Verification notes.** saveWeeklyQueue swallows quota errors (storage.js:2591-2594). gatherPayload has already advanced the error mark and the info hash, and maybeSend then advances weeklySendLastAt whether or not the queue write worked. If the write fails, the payload exists nowhere while every marker says it was handled. The trigger, localStorage near its roughly 5 MB quota, is possible (oversized problem reports kept in the 8-slot queue, per finding 01) but uncommon and not demonstrated.
