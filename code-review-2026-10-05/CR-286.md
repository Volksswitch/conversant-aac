# CR-286: Removing a learned voice example in About Me is permanent and has no confirmation or undo

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** data-loss
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/worldview-ui.js:576`
- **Also affects:** `app/js/worldview-ui.js:593`; `app/js/worldview-ui.js:600`; `app/js/worldview-ui.js:614`
- **Source:** x-rules-09

**What a user notices.** In About Me's 'What the app has picked up', one tap on the small '×' beside a sentence the user once wrote removes it permanently, and the screen says it 'will not come back'. An accidental tap, which this population makes often, cannot be undone.

**What is wrong.** buildHarvestSection() draws each harvested exemplar (the user's own composed words and reviewed sentences) and each repeated steer with a '×' button that calls voiceProfile.dismissExemplar() immediately and redraws. The dismissal is designed to be sticky (a later harvest must not restore it), so there is no way back from a mis-tap. CLAUDE.md treats the user's own composed prose as the scarcest voice evidence the app collects. The standing rule requires a confirmation (confirmDanger) for destroying significant work; elsewhere a single-item removal is either confirmed (Remove person, Delete this question) or recoverable (Undo for 'Prefer not to say'). This is borderline under the 'significant work' bar, so it is reported as a judgment for Ken rather than a clear violation.

**Evidence.**

```
app/js/worldview-ui.js:576-580: const removableRow = (label, onRemove, removeLabel) => el('div', ..., [ ..., el('button', { class: 'wv-entry-remove', text: '×', title: 'Remove this', 'aria-label': removeLabel, onclick: onRemove }) ]);
app/js/worldview-ui.js:593: 'Taken from your own conversations. Remove anything that does not belong — it will not come back.'
```

**How it happens.** Settings > About Me > Sound Check / voice section: tap the '×' beside one of your own sentences by mistake. It disappears and no harvest brings it back.

> **Verifier correction to the trigger:** A mis-tap does not delete the user's words. The sentence stays in the saved conversation file. What is lost permanently is only that sentence's use as an example of how the user talks, because the dismissed list is never cleared except by About Me's reset.

**Suggested fix.** Either wrap onRemove in a confirmDanger({ title: 'Stop using this?', body: `"${text}" will no longer be used as an example of how you talk. It will not come back.`, confirmLabel: 'Remove it', cancelLabel: 'Keep it' }) check, matching the 'Remove person' pattern at worldview-ui.js:745-754. Or add an Undo affordance that calls a voiceProfile 'undismissExemplar' for the last removed item until the next redraw. Raise with Ken before choosing, since the rule's bar is 'significant work'.

**How to verify the fix.** Manual: tap '×' and check that the red confirmation appears and Cancel keeps the sentence. Or: remove, then Undo, and check that the sentence is back and is used again by the next harvest.

**Do not break.** Must not use window.confirm (Rule: confirmDanger only). The dismissal must still be sticky once confirmed.

**Design reference.** CLAUDE.md Configurability philosophy: 'Confirm before destroying significant work (standing rule, Ken, June 15 2026)'

**Verification notes.** The mechanism is as described: the × at worldview-ui.js:576-580 calls voiceProfile.dismissExemplar immediately (voice.js:229 adds the sentence to a sticky dismissed list), with no confirmDanger and no undo. The permanence is a recorded design choice: the comment above buildHarvestSection and the on-screen text both say removed lines will not come back. The finding overstates the loss, though. Nothing is deleted from disk. The sentence stays in the user's conversation file, and only its use as a voice exemplar stops. Whether a one-item exclusion meets the 'significant work' bar for confirmation is Ken's judgment.
