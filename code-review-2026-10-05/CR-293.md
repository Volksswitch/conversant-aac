# CR-293: A quick double tap on Make a copy, Start from this person or Add scenario creates duplicate scenarios

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** race-condition
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/practice-editor.js:118`
- **Also affects:** `app/js/practice-editor.js:138-141`; `app/js/practice-editor.js:197-202`; `app/js/practice-editor.js:292-299`; `app/js/practice-library.js:167-173`
- **Source:** phrases-practice-10

**What a user notices.** A user with unsteady hands who taps 'Make a copy' twice gets two identical copies of the scenario in their list (likewise with 'Start from this person' and 'Add scenario').

**What is wrong.** These buttons await an async library call (addScenario -> save -> writeFile) before navigating away, and are not disabled meanwhile. Settings is exempt from the one-tap-or-two guard, so a second tap during the await runs the handler again and adds a second scenario with a new id. Only 'Write it for me' disables itself while working.

**Evidence.**

```
practice-editor.js:118-121 `button('Make a copy', async () => { const id = await library.copyScenario(s); if (id) goTo(...) })`
practice-editor.js:166-169 (contrast) `writeBtn.disabled = true;`
practice-library.js:167-172 `const s = normalizeScenario({ ...fields, id: newId() }); m.scenarios.push(s); await save();`
```

**How it happens.** Settings > Practice with a data folder connected; tap 'Make a copy' on 'A job interview' twice quickly; return to the list: two 'A job interview' entries under Your scenarios.

**Suggested fix.** In each of these handlers, disable the button on entry and re-enable in a finally block, mirroring writeBtn: `const b = e.currentTarget; if (b.disabled) return; b.disabled = true; try { ... } finally { b.disabled = false; }` (button() passes the click event to onclick).

**How to verify the fix.** Manual: double-tap each of the three buttons and confirm exactly one scenario is created.

**Do not break.** none

**Design reference.** CLAUDE.md UI Layout Rule 10 (this population taps imprecisely; Settings is exempt from the tap guard).

**Verification notes.** The 'Make a copy', 'Start from this person' and 'Add scenario' handlers await addScenario and then save and writeFile before navigating, and are never disabled. Settings is exempt from the tap guard (Rule 10). A second tap during the await would add a second scenario. Without a data folder, writeFile returns at once and the window is only microtasks, so in practice this needs a connected folder and a slow file write. Whether a double tap falls inside that window is timing-dependent and unverified.
