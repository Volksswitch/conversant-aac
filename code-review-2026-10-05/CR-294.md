# CR-294: Leaving a review starts a voice rebuild that can overwrite a backup restored moments later

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** race-condition
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/review-ui.js:181`
- **Also affects:** `app/js/voice-refresh.js:21-38`; `app/js/voice.js:116-121, 208-212`; `app/js/data-transfer.js:393-408`; `app/js/app.js:6514-6561`
- **Source:** review-backup-05

**What a user notices.** If someone leaves a review and promptly restores a backup, their restored "how I sound" answers can be replaced by the old ones when the app restarts.

**What is wrong.** leave() fires `void refreshVoiceHarvest()` without awaiting. That function reads every saved conversation (slow on a tablet with a long history - TODO.md notes leaving review may be slow) and then calls voiceProfile.setHarvest(), which saves the IN-MEMORY voice profile (loaded before the import) to both the cache and voice.json. leave() lands the user on Settings, where Backup > Import is reachable; applyPackage writes voice.json and aac_voice from the backup; offerRestart then waits for the user to tap Restart. If the harvest finishes in that window, save() writes the pre-import Sound Check answers, dismissed list and steers back over the restored file, and the reload loads them. The same applies to any import done while a harvest from About Me's 'Read my conversations' is in flight.

**Evidence.**

```
review-ui.js:179-181
    // ... Not awaited: reading every conversation must not hold the user on a screen they asked to leave.
```

**How it happens.** Tablet with 300 conversations. Finish a review, tap Settings (harvest starts, takes several seconds). Open the backup section, import a backup from another device, confirm, wait on the 'Restart to finish' card. Harvest completes and writes the old voice profile; tap Restart - the imported Sound Check answers are gone.

**Suggested fix.** In voice-refresh.js keep the in-flight promise (`let inFlight = null; export function refreshVoiceHarvest() { if (!inFlight) inFlight = run().finally(() => { inFlight = null; }); return inFlight; }` and `export function whenIdle() { return inFlight || Promise.resolve(); }`). In app.js importPackageText, `await voiceRefresh.whenIdle()` after the confirmation and before applyPackage (show the busy card first).

**How to verify the fix.** Unit test in tests/ that mocks a slow listConversationLogs, starts refreshVoiceHarvest, then awaits whenIdle and asserts it resolves only after setHarvest ran. Manual: the scenario above keeps the imported voice data.

**Do not break.** Leaving review must still not block on the harvest. Do not await the harvest inside leave().

**Design reference.** CLAUDE.md 'Conversation Review' (voice harvest runs when the user leaves a review); data-transfer.js 'import writes BOTH ... otherwise silently overwritten'

**Verification notes.** leave() fires `void refreshVoiceHarvest()` and then openSettingsAt('review'); refreshVoiceHarvest awaits listConversationLogs() and then voiceProfile.setHarvest(), whose save() writes the in-memory profile (loaded before the import) to both aac_voice and voice.json. applyPackage writes both from the backup, and offerRestart waits for a tap before reloading, so a harvest completing in that window would overwrite the restored voice data. The race is real in code, but the user must leave review, switch tabs, pick a file and confirm before a slow harvest finishes; the timing on a real tablet was not measured. Narrow trigger, so low rather than medium.
