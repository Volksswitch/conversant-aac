# CR-303: The non-destructive Back up confirmation uses the red danger card

Part of the [October 5, 2026 code review](README.md). Read its instructions before fixing.

- **Severity:** low
- **Category:** ui-inconsistency
- **Verdict:** plausible (skeptic: plausible)
- **Location:** `app/js/app.js:6615`
- **Also affects:** `app/js/confirm-dialog.js:1-15 (danger card is for destructive actions)`; `app/js/confirm-dialog.js:117-130 (neutralCard exists)`
- **Source:** app-e-12

**What a user notices.** Making a backup - which cannot harm anything - asks with the same red warning card used for deleting and replacing data, which teaches people to tap through the red card without reading it.

**What is wrong.** The export handler asks 'Back up your settings?' through confirmDanger (red title, warning mark, red confirm button). confirm-dialog.js says the danger card exists so a destructive action reads as dangerous and is not dismissed on autopilot; using it for a safe action dilutes that signal. A neutral card already exists (neutralCard / showNotice) but has no two-button confirm variant. The title also says 'settings' while the body says everything is backed up.

**Evidence.**

```
app/js/app.js:6615-6626
        if (!(await confirmDanger({
            title: 'Back up your settings?',
            body: 'Everything on this device goes into one file: ...',
            confirmLabel: 'Back up now',
            cancelLabel: 'Not now',
app/js/confirm-dialog.js:3-12 'Destructive actions ... must NOT use the native window.confirm() ... This renders a deliberately distinct modal — red danger styling ...'
```

**How it happens.** Open Settings > Backup, tap Export: a red warning card appears for a harmless action.

**Suggested fix.** Add a `confirmNeutral({ title, body, confirmLabel, cancelLabel })` to confirm-dialog.js built on neutralCard with Cancel and a `neutral-confirm` button (Cancel focused, Escape/backdrop cancel), and use it in the exportDataBtn handler. Retitle to 'Back up everything on this device?'. Leave the import (destructive) on confirmDanger.

**How to verify the fix.** Manual: Export shows a neutral card; Import still shows the red card. Run tests/ui-standards.test.mjs.

**Do not break.** Do not change any destructive confirmation; keep the busy and finished cards.

**Design reference.** CLAUDE.md 'Confirm before destroying significant work' (confirmDanger exists to make destructive actions read as dangerous).

**Verification notes.** The export handler (app.js:6612-6626) does use confirmDanger, and its title 'Back up your settings?' disagrees with a body that says everything is backed up. However, the comment above it records Ken's request (September 9 2026) that an export get 'the same pair of cards as an import' - which uses confirmDanger - so the red card may be intended. confirm-dialog.js has no two-button neutral confirm. The problem-report 'Send this report?' also uses confirmDanger for a non-destructive action. Whether this is a defect or a choice is Ken's call; the title mismatch is a plain wording fault either way.
